# 服务器管理模块 —— 完整开发计划

## 概述

**目标**：新建服务器管理模块，支持录入服务器（名称、用途、位置、IP/端口、简介、备注、状态），服务器下管理多个系统，系统下管理多个服务。服务可标记服务对象（设备/人员/组织），维护人员必须是工作台成员。

**类型规则**：服务器分单系统/多系统，创建后类型不可变；若需变更 → 标记"重新部署"状态。

## Server 模型字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID PK | — |
| name | VARCHAR(200) | 服务器名称 |
| purpose | VARCHAR(500) | 用途 |
| location | VARCHAR(200) | 位置 |
| ip | VARCHAR(45) | IP 地址 |
| port | INTEGER | 端口 |

| 字段 | 类型 | 说明 |

## API 端点设计

**Servers** (/api/v1/servers):
- `GET /` — 服务器列表（分页 + status 过滤）
- `POST /` — 创建服务器
- `GET /{id}` — 服务器详情
- `PUT /{id}` — 编辑服务器
- `DELETE /{id}` — 删除服务器
- `GET /{id}/systems` — 获取服务器的系统列表
- `PUT /{id}/change-type` — 变更类型 → PENDING_REDEPLOY

**Systems** (/api/v1/systems):
- `GET /?server_id=` — 系统列表（按服务器过滤）
- `POST /` — 创建系统
- `GET /{id}` — 系统详情
- `PUT /{id}` — 编辑系统
- `DELETE /{id}` — 删除系统

**Services** (/api/v1/services):
- `GET /?system_id=` — 服务列表（按系统过滤）
- `POST /` — 创建服务
- `GET /{id}` — 服务详情
- `PUT /{id}` — 编辑服务
- `DELETE /{id}` — 删除服务

## 前端页面

### 服务器列表页 /servers
- 标准 Table 管理页（container→header{Title+Space+新建按钮}→Table 分页→Modal 表单）
- 列：名称/用途/位置/IP/端口/状态/类型/部署状态/维护人数/创建时间/操作
- 新建/编辑弹窗：全部字段 + 维护人员多选
- server_type 编辑时 disabled

### 服务器详情页 /servers/:id
- 服务器信息卡片 + 维护人员 Tag 列表
- 单系统模式：系统设置卡片（名称/描述可编辑）+ 服务列表 Table
- 多系统模式：左侧系统树 + 右侧服务列表
- 服务弹窗：target_type 下拉 + target_name 输入 + 维护人员选择
- 部署状态管理按钮

## 约束与排除

**不会做**：
- 不建 Device/Personnel/Organization 独立管理页
- 不修改 Topology / Inventory 模型
- 不做服务器资源实时监控
- 不做 SSH/远程连接/命令执行
- 不改动基定文档
- 不引入新依赖

**必须遵守**：
- 维护人员必须是工作台成员（User 表）
- server_type 创建后不可变
- 所有图标用 @ant-design/icons
- 深浅色模式适配
- 统一响应格式 `{ code: 0, msg: "", data: {} }`
