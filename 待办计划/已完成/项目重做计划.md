# 项目模块全量重做计划

## 数据模型重做（全部重建，不考虑迁移）

### 核心表（7 张新表 + 1 张重建 Project 表）

**Project（重建）**：id / number(编号) / title / description / owner_id / member_ids(JSONB) / visibility / restricted_users / status(draft→ongoing→done→archived) / status_log / created_at / updated_at

**ProjectMember（新建）**：id / project_id / user_id / role_title(职务) / is_owner(bool，允许多个) / notes / is_active / left_at / joined_at。历史成员通过 is_active=false 查询折叠区展示。删除=软删除(is_active=false)。

**Proposal（新建）**：id / project_id / number(编号) / title / type(feature/bug/improvement/removal/other) / priority(P0-P4) / description / status(pending/approved/rejected/completed) / reject_reason / attachment_links(JSONB) / creator_id / assignee_id / created_at / updated_at

**MeetingRecord（新建）**：id / project_id / number(编号) / type(会议纪要/沟通记录+自由填写) / started_at / speaker(发言人) / participants(参会人JSONB) / content / notes(JSONB，后续追加的备注数组) / created_at

**ChangeRecord（新建）**：id / project_id / number(编号) / title / date / category_major(大类) / category_minor(小类) / category_detail(自由填写) / content / status / created_at

**TodoTask（新建）**：id / project_id / number(编号) / title / description / priority / status / assignee_id / creator_id / proposal_id(FK可空,双向关联) / due_date / created_at / updated_at

**ProjectEvent（新建）**：id / project_id / number / event_type(handover/archive/close/reopen/owner_change/other) / title / details(JSONB) / operator_id / created_at

### 关联规则
- 所有关联双向：A关联B → B也记录关联A
- 通过 link_relations 表(ID1, type1, ID2, type2) 实现通用双向关联
- 前端跳转：关联对象可点击直达对应 Tab 的具体条目

### 编号体系
`{类型前缀}-{项目编号}-{序号}`，自动生成：
- 提案: `PRP-项目编号-001`
- 会议: `MTG-项目编号-001`  
- 修改: `CHG-项目编号-001`
- 待办: `TOD-项目编号-001`
- 事件: `EVT-项目编号-001`
UUID 为内部主键，number 为对外唯一标识。

## Tab 顺序

```
项目信息 → 项目人员 → 项目进度 → 项目提案 → 待办任务 → 交流记录 → 修改记录 → 项目文档 → 项目事件
```

（按逻辑：信息→人员→进度把控→提案需求→执行待办→沟通→变更记录→交付文档→重大操作）

## 各 Tab 功能规格

### Tab2: 项目人员
- 字段：用户(Select从工作台)/职务(下拉+自由填写)/备注/是否负责人
- 创建者默认负责人，允许多个负责人
- 可移交负责人：原负责人→普通成员(职务待指定)
- private 项目：不允许添加项目人员
- 删除=软删除，历史成员折叠区展示

### Tab4: 项目提案
- 创建→待审核→已采纳/已拒绝(需填写理由)
- 已采纳→可关联执行人→已完成
- 附件：仅链接(不传文件)
- 保留所有提案(含未通过)，状态Tag区分
- 仅项目成员+负责人可见

### Tab5: 待办任务
- 执行层，可关联提案(双向)
- 字段：标题/描述/优先级/状态/指派人/截止日期
- 状态流转：待处理→进行中→已完成

### Tab6: 交流记录
- 每场/次为单位，可追加备注
- 字段：类型(下拉+自由填写)/时间/发言人/参与人(多选)/内容/备注列表
- 被其他Tab关联时显示关联来源，可跳转

### Tab7: 修改记录
- 纯记录(不是待办)，大类→小类→详细三级分类
- 大类：代码/文档/配置/其他
- 小类(代码)：前端/后端/数据库/部署
- 小类(文档)：基准文档/设计文档/API文档/运维文档
- 小类(配置)：环境变量/Docker/Nginx/依赖
- 第三级自由填写

### Tab9: 项目事件
- 重大操作：项目移交/归档/关闭/重启/负责人变更/其他
- 移交保留历史列表
- 移交表单：三方角色(移交/承接/监督)+交接类型+过渡期+四维度检查+资产清单+签字状态

## 权限模型

每个项目成员可单独设置对各分区的权限(负责人全权限)：

| 分区 | 默认(成员) | 负责人 |
|------|----------|--------|
| 项目信息 | 只读 | 编辑 |
| 项目人员 | 只读 | 管理 |
| 项目进度 | 只读 | 管理 |
| 项目提案 | 增删改查 | 全权限 |
| 待办任务 | 增删改查 | 全权限 |
| 交流记录 | 增删改查 | 全权限 |
| 修改记录 | 增删改查 | 全权限 |
| 项目文档 | 增删改查 | 全权限 |
| 项目事件 | 只读 | 管理 |

非成员：只看项目信息和进度(public时)，其他Tab不可见也不可访问(private时404)
