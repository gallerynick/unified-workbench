## 一、需求

1. **背景设定** — 支持纯色或图片作为工作台背景
2. **主题色切换** — 更换界面主色（当前为蓝色系），覆盖按钮、选中态、激活态等

## 二、已确定的设计决策

### 2.1 双层配置 + 逐项全局开关

配置归属分两层，各自独立设置：

| 层级 | 位置 | 角色 | 生效范围 |
|------|------|------|---------|
| 全站层 | 系统设置 → 应用配置 | 管理员 | 全体用户 |
| 个人层 | 侧边栏 → 用户个性化 | 每个用户 | 仅本人 |

每个配置项（背景、主题色）在全站层附带一个**「全局生效」开关**：

- 开关 **开** → 全站值优先，用户个性化中该项失效
- 开关 **关** → 以用户个性化为准

**默认值：「不全局」（尊重个性化）**。理由：上线后现有用户的已保存个性化不受影响，零回归；管理员显式打开才接管。反向默认会让所有用户无感丢失个性化设置。

### 2.2 未来整套主题包（后续阶段）

目标形态对标 Windows 个性化：

- 支持**逐项微调**（小项可单独调整）
- 支持**一键切换主题包**（整包应用组件样式、颜色、背景等）
- **互斥规则**：选择了主题包时，所有小项锁定不可调，界面仅显示主题包选择器

### 2.3 长期开发基准

除主题包/主题切换相关开发外，**所有开发一律以当前默认主题为基准**，遵循《项目基定/UI设计规范.md》。此约定已写入 AGENTS.md。

## 四、关键技术要点与陷阱

### 4.1 双轨蓝不同步（最高风险）

当前界面实际存在**两套蓝色**：

- 按钮/链接：`--color-primary` = `#0066cc`（行动蓝）
- 选中态/激活态：`--color-info` = `#1677ff`（AntD 默认蓝），深色模式 `#1668dc`

若仅修改 antd 的 `colorPrimary` 一处，结果是「按钮变色但侧边栏选中仍是旧蓝」的视觉割裂，比不做更糟。
**必须先完成蓝系收敛（合并 `--color-info` → `--color-primary`），再做主题色切换。**

### 4.2 背景被 Layout 铺死

`MainLayout` 已把整个视口覆盖：

```text
外层 Layout   background: var(--canvas-parchment)   ← 盖住 body
  ├── Sider    background: var(--sider-bg)（= --canvas）
  └── 内层 Layout background: var(--canvas-parchment)
        └── Content  background: var(--canvas) + 圆角卡片
```

`body { background-color: var(--canvas) }` 被完全覆盖，直接改 body 背景用户看不到任何东西。
背景设定必须先决定**哪一层透出**（整体透出 / 仅内容区透出 / 侧栏与顶栏保留底色、仅内容区替换），再实现。

### 4.3 `!important` 覆写会压过 antd token

`global.css` 50 处 `!important` 主要为深色模式适配（Tabs、Menu、Radio.Button、Checkbox、Select、Timeline、Progress 等）。这些覆写绑定 `var(--color-info)` 等变量，优先级高于 antd ConfigProvider token，token 合并时必须同步处理，否则深色模式选中态会回退到 antd 默认值。

### 4.4 深浅色双适配是基定硬约束

《项目基定/UI设计规范.md》要求所有组件适配深浅色模式。背景与主题色必须为深浅色各自定义。
**图片背景需特别处理**：用户上传亮图后切换深色模式，文字可读性会崩溃，需叠加遮罩或按主题分别指定图片。

### 4.5 图片背景的文件边界

存储走 `FILE_STORAGE_PATH`（年增量 < 500GB 预算内可控），但需新增：上传接口、类型白名单（PNG/JPG/WebP）、大小上限、尺寸约束、加载失败回退纯色。背景图为个人资产（个人上传）而非共享资产，避免累积与审批流程。

## 五、存储方案（无需数据库迁移）

| 数据 | 存储位置 | 现状 |
|------|---------|------|
| 个人偏好（含背景、主题色） | `user.preferences`（JSONB） | 已有字段，当前存 `page_zoom`、`theme_mode` |
| 全站配置（应用名、logo、favicon） | `system_config` 表，经 `PUT /system/custom-config` | 已有接口与 `useCustomization` hook |

两项均为现有机制扩展字段，**不需要 Alembic 迁移**。

## 六、分档计划

### A 档（建议恢复开发时先做）— 最小闭环

- 配置层：应用配置增加「背景」「主题色」两项 + 逐项「全局开关」+ 优先级判定
- Token 层：只做**蓝系收敛**——合并 `--color-info` → `--color-primary`（消除 99 处双轨），antd 配置中约 59 处蓝系 hex 改为引变量
- **不动**：约 180 处中性色、176 处 `!important`、主题包

### B 档 — 纯重构，可单独回归

- A 档之上，把约 180 处中性色、176 处 `!important`、3 个生产文件 hex 全部收敛
- 需逐条回归深浅色双模式全页面

### C 档 — 主题包（独立立项）

- 主题包数据模型、主题包注册表、「切包即锁定小项」的 UI 契约
- 三样都需单独评审，不与 B 档混在同一改动

## 七、非目标

- 不做任意取色器（自定义色值无法自动推导深色变体与对比度合规性）——用预设色板
- 不 token 化用户内容调色板（Tiptap 高亮色、表单分类色）
- 不在本期做主题包（C 档独立）
- 不改现有默认主题的任何视觉表现（蓝系收敛阶段为纯重构，视觉零变化）
