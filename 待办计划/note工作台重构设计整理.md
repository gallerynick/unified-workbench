## 〇、指导原则（2026-09-29 补充，优先级最高）

**当前处于开发阶段：一切合并，按最新开发目标与理念执行；原来的、以及已废弃的数据与部分，全部遗弃删除。**

由此推导：
- 不做数据迁移、不做兼容层、不留旧字段做回滚缓冲
- 废弃的列**直接删**（不是置 NULL 保留）
- 存量数据不必回填，可直接清理
- 验收以「新模型自洽」为准，不以「老数据还在」为准

## 一、已确认决策（用户已拍板）

### 1.1 侧栏：单一树形视图
- 只保留一个树形层级视图，**删除现有「树形/平铺」视图切换**
- 层级形态：文件夹（可展开/折叠）→ 笔记缩进挂在下面

### 1.2 侧栏顶级结构（重要）
- **不属于任何文件夹的笔记，作为顶级项直接垂在下方**，与文件夹**同级、一起排序**，不缩进
- 不做「未归档」虚拟分组，侧栏就是「文件夹 / 独立笔记」混排的平级列表
- 截图参照：文件夹1 → 笔记1（缩进）；笔记2（顶级，无缩进）

### 1.3 置顶笔记的展示
- 置顶笔记在侧栏显示为**链接式外观**：可用一个标记，或降低颜色深度变浅来表示
- 点击后跳转到该笔记
- 该笔记在**原始位置仍然保留**，点击同样跳转
- 即置顶笔记在侧栏出现两处：置顶展示处 + 原始位置处

### 1.4 排序
- **两层都排**：文件夹之间 + 每个文件夹内的笔记
- 顶级混排区（文件夹 + 独立笔记）适用同一排序规则
- 选项：名称（A-Z / Z-A）、更新时间（旧→新 / 新→旧）、创建时间（旧→新 / 新→旧）

### 1.5 搜索
- 现有常驻搜索输入框改为**搜索按钮**（图标）
- 点击后：顶部出现**搜索框**，下方原文件夹/笔记列表区**切换为搜索结果**
- 搜索范围：标题 + 正文 + 标签 + **文件夹名** + **文件夹简介**

### 1.6 筛选：删除
- **整个筛选功能删除**（漏斗按钮取消）
- 标签仍可在元信息维护、仍可被搜索，但不再作为筛选维度
- 「仅置顶」也不再需要，置顶由 1.3 的置顶区承担

### 1.7 侧栏顶部按钮（三个）
- **搜索** / **展开全部或收起全部文件夹** / **排序方式**
- 三个按钮同排在侧栏顶部一行，全部**单个图标**，节省空间

### 1.8 面板收纳
- 元信息、反向链接面板**默认全部收纳**
- 点击按钮后展开，**压缩中间编辑区**腾出一块区域
- 收纳后就是**一个图标按钮**，样式参考用户提供截图：**圆角方框 + 内侧一条竖条**
- **替换**现有页面右上角「面板显示」Dropdown，改为**两个独立按钮**：右侧边栏一个，左侧镜像（竖条在左边）

### 1.9 文件夹模型（核心变化）
- 文件夹是**独立实体**：要加表、加 API、加迁移
- 一篇笔记可进入**多个**文件夹 → 多对多关联
- **取消拖拽**，改为在元信息中**编辑多个父文件夹**（多选）
- 元信息中原「父笔记」**改为「父文件夹」**
- 文件夹**只允许有简介，不写正文**

### 1.10 笔记间关系
- 笔记之间的**父子嵌套废弃**，`parent_id` 列直接删除
- 层级关系改为**笔记间链接**（双链 `[[ ]]`），图谱即展示该关系

### 1.11 元信息面板
- **不精简**，反而要**更完整详细**
- 布局对调：**信息在上，配置项在下**（现状为配置项在上）

### 1.12 图谱
- 保留但**重做**，用途是展示笔记间链接，参考 Obsidian
- 尽可能把 Obsidian 功能做完，**前提是现有依赖能支撑**；不安装新包

### 1.13 编辑器（路线 A + Obsidian 式极简）
- **接上 SlashMenu**（`/` 与 `[[` 双触发），补齐工具条功能
- 按 Obsidian 式极简：**保持功能，但不把功能全摆在外面**，收纳
- 行内格式外露，块级功能收进下拉 / 走 `/` 菜单

### 1.14 明确不做
- 不安装任何新 npm 包
- 不改基定（如需改另行确认）
- 不做拖拽排序 / 拖拽入文件夹
- 不做筛选（已决定删除）
- 不做数据迁移与兼容层
- 图谱节点不画文件夹实体（只画笔记节点）

## 三、数据模型方案

### 3.1 新增表

**`note_folder`**（文件夹实体）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | |
| name | String(100) NOT NULL | 文件夹名 |
| description | Text NULL | 简介（文件夹只允许有简介，不写正文） |
| sort_order | Integer NOT NULL default 0 | 显示顺序 |
| owner_id | UUID FK user.id | 归属用户 |
| visibility | String(20) NOT NULL default private | 沿用 Visibility 枚举 |
| created_at / updated_at | DateTime | |

**`note_folder_membership`**（笔记 ↔ 文件夹 多对多）

| 字段 | 类型 | 说明 |
|---|---|---|
| note_id | UUID FK note.id ON DELETE CASCADE | |
| folder_id | UUID FK note_folder.id ON DELETE CASCADE | |
| created_at | DateTime | |

唯一约束 (note_id, folder_id)；note_id、folder_id 均建索引。

### 3.2 废弃列删除
- **删除** `note.parent_id` 列及外键、`Note.parent` / `Note.children` 关系、以及所有引用它的代码路径
- **删除** `note.category` 列及其筛选 / 响应字段
- `note_link` 保留（source_id / target_id + 唯一约束），双链边数据源不变
- `note_draft` 保留（草稿机制不变）

### 3.3 迁移
- 一个 Alembic 迁移：建两表 + 删两列 + 清理关联数据
- 按指导原则**不做回填**，不写兼容代码
- 迁移须幂等（可重复执行）

## 四、API 方案

沿用统一响应 `{"code":0,"msg":"","data":{}}` 与 Pydantic 模型。

**文件夹**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/notes/folders | 文件夹列表（含笔记数） |
| POST | /api/v1/notes/folders | 新建文件夹 |
| PATCH | /api/v1/notes/folders/{id} | 改名 / 改简介 |
| DELETE | /api/v1/notes/folders/{id} | 删除（笔记保留，解除关联） |

**笔记—文件夹关联**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/notes/{id}/folders | 查询某笔记所属文件夹 |
| PUT | /api/v1/notes/{id}/folders | 全量替换所属文件夹（传 id 数组） |

**既有接口调整**
- GET /api/v1/notes：新增可选 folder_id 过滤；移除 category、parent 语义
- 全文搜索：命中范围扩展到文件夹名与简介
- NoteResponse：新增 `folders`: [{id,name}]；移除 `parent` / `children` / `category`
- 移除所有以 parent_id 为参数的移动接口

## 五、前端方案

### 5.1 侧栏 NoteSidebar
- 结构（自上而下）：顶部工具条 → 置顶区 → 树列表（文件夹 + 独立笔记混排）
- 删除视图切换 Segmented、删除筛选漏斗、删除 rail 折叠态
- 置顶区：置顶笔记以链接式外观呈现（标记或浅色），点击跳转；原始位置不隐藏
- 树：文件夹可展开；顶级区按规则排序，文件夹内笔记按同一规则排序
- 搜索：点击搜索按钮后顶部出现搜索框，列表区切换为搜索结果

### 5.2 顶部工具条
- 三个 icon-only 按钮：搜索 / 展开收起全部 / 排序
- 按钮尺寸 small（24px），icon-only 一律带 Tooltip 保可发现性

### 5.3 面板收纳
- 右侧面板默认收纳
- 页面右上角工具条：删除「面板显示」Dropdown，改为两个自绘 SVG 图标按钮（右面板 / 左面板镜像）
- 图标需适配深浅色（currentColor）

### 5.4 元信息 NoteMetaPanel
- 布局对调：信息区在上，配置项在下
- 信息区补全：所有者、所属文件夹、字数、创建时间、更新时间、可见性、标签数、出链数、入链数
- 配置项：标题、**父文件夹多选 Select**（替换原父笔记 TreeSelect）、标签、置顶、可见性
- 删除 category 相关控件、删除拖拽相关代码

## 八、约束与风险

| 项 | 说明 |
|---|---|
| **依赖** | 不可安装新 npm 包。图谱必须基于现有 `react-force-graph-2d` 自绘实现；Obsidian 能力中「折叠节点」等无法做到，其余可实现 |
| **浏览器验证缺失** | 无登录凭证，全部阶段只能做构建 + 静态检查 + 线上资源可达性；**每阶段需用户浏览器实测** |
| **基线债** | 后端 pytest 25 failed / 77 passed（尾斜杠 307，非本轮引入）；`eslint src/` 41 个既有 error。验收以「零新增」为准 |
| **回滚** | 按指导原则不做兼容层，回滚只能靠 git revert；因此每阶段必须独立提交 |
| **删列风险** | `parent_id` / `category` 删除后不可恢复，需用户明确确认（见二 #2） |
| **并行工作** | 工作区存在其他会话的脏文件，提交必须带显式路径，禁止 `git add .` |
| **基定只读** | `项目基定/` 与 `项目架构/` 不改动；此前积累的三条 UI 约定（间距四规则、同组控件同尺寸、占位元素预留恒定空间）尚未固化，本次重构期间继续遵守 |
