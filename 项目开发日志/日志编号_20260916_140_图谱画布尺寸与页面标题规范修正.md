### 开发内容详述

**一、图谱画布尺寸不自适应（根因与修复）**

现象：切到「图谱」视图后，画布高度无论视口多高都停在 600px；视口矮时被裁，
视口高时下方留一大片空白。

根因是一条自引用链：
  .graphWrap   position:relative, flex:1, min-height:0   ← 高度由父级 .center 决定
  .graphContainer flex:1, min-height:400px                ← 但父级不是 flex 容器，flex:1 失效
  ForceGraph2D width/height = dimensions                    ← dimensions 来自 ResizeObserver
  ResizeObserver 观察的是 .graphContainer 自身             ← 量出的是上次传给画布的值

即画布高度由「画布自己告诉父级的高度」反推，而父级不是 flex 容器所以不接管高度，
于是尺寸永远等于初始 state 的 800x600，ResizeObserver 回调拿到同样的值、不再触发
更新，形成死锁。

修复：把画布的尺寸来源交给父级决定，画布只负责「读出来传给 ForceGraph2D」：
- GraphView.module.css 的 .graphContainer 改为 position:absolute; inset:0，
  删掉 flex:1 与 min-height:400px。父级 .graphWrap 已是 position:relative + flex:1
  + min-height:0，画布因此精确铺满可用区域。
- .emptyState 同样由固定 height:400px 改为 position:absolute; inset:0。
- 新增 .orphanHint 样式：原代码引用了 styles.orphanHint 但 CSS 中从未定义，
  导致孤立节点提示以未样式化的裸 Alert 叠在画布上。改为绝对定位浮层，
  不占布局空间、不挤压画布。

**二、图谱渲染性能**

1. 首帧闪动与无效布局：dimensions 初始为 800x600，ForceGraph2D 会先按错误尺寸
   跑一轮力导向布局，等 ResizeObserver 回调后再跳变。
   改用 useLayoutEffect（在浏览器绘制前执行）同步量一次 getBoundingClientRect，
   再挂 ResizeObserver 跟踪后续变化。首次绘制拿到的就是真实尺寸，无闪动、
   无一次无效布局。同时把 ResizeObserver 回调改为遍历全部 entries
   （原来只取 entries[0]）。

2. 每次渲染重算主题 token：readTokens() 与 CATEGORY_PALETTE.map(resolveCssVar)
   原先写在组件函数体里，每次渲染都执行，合计调用十余次
   getComputedStyle(document.documentElement)。且 tokens 每次都是新对象，
   导致 nodeCanvasObject / linkCanvasObject / nodePointerAreaPaint 三个回调的
   useCallback 依赖变化、身份改变，ForceGraph2D 每帧重注册绘制函数。
   改为 useMemo 并以 useTheme().isDark 作为依赖——token 只随主题切换重算。

3. 删除 500ms 假加载：组件内有个 setLoading(false) 的 500ms 定时器加一个 Spin
   覆盖层，与父级 NoteWorkspace 已有的 graphLoading Spin 重复，且数据早已就绪
   仍空转 500ms。整段删除，同时移除未再使用的 Spin 引入。

4. 尺寸未就绪时不挂载 ForceGraph2D：dimensions 初始改为 0x0，加条件渲染，
   避免以 0 尺寸实例化力导向图。

**三、页面标题与头部违反全站统一规范**

全站 30+ 个管理页（TemplateManagement、TagManagement、ContactManagement、
ReminderManagement、NotificationsCenter 等）统一采用同一套结构与类名：

    <div className={styles.container}>
      <div className={styles.header}>
        <Title level={4} className={styles.title}>用户标签分类</Title>
        <Space> ... </Space>
      </div>
    </div>

对应的 CSS 约定（见 TemplateManagement.module.css）：
  .container  display:flex; flex-direction:column; gap:var(--spacing-card-gap)
  .header     display:flex; align-items:center; justify-content:space-between;
             gap:var(--spacing-card-gap); min-height:var(--spacing-xxl)
  .title      margin:0 !important; font-weight:600; white-space:nowrap

而 P3 的 NoteWorkspace 自成一套，偏离点有 5 处：
  1. 容器类名用了 .workspace，而非全站统一的 .container
  2. 头部用了语义标签 <header class="toolbar">，而非 <div class="header">
  3. 标题外面包了一层 .brand 并前置 <FolderOutlined /> 图标，
     全站没有标题前置图标的先例（见《术语定义》3.3.2 的 DOM 定位示例）
  4. 标题类名用了 .brandTitle，而非 .title；且额外覆写了 color 与 font-size:16px
  5. 工具按钮区用了自建的 .toolbarRight 裸 div，而非全站惯用的 <Space>
  另：.toolbar 还自带 background:var(--card-bg) 与 border-bottom，画了一条
  别的页面都没有的横杠——操作区本身已有底色，重复了。

修复：NoteWorkspace.tsx 的头部重写为与全站一致的 .container > .header > 
(Title + Space) 结构，删除 FolderOutlined 引入；NoteWorkspace.module.css 的
.container / .header / .title 三个类照抄全站约定，删除 .workspace / .toolbar /
.brand / .brandTitle / .toolbarRight 五个自建类。

注意 .container 在保留约定属性的同时额外加了 flex:1 与 min-height:0——
三栏布局必须填满 MainLayout 的 transitionWrapper（该 wrapper 是 flex:1 + 
flex-direction:column）才能拿到真实高度，否则后续所有 flex:1 的列都会塌成 0。
这是在全站约定之上为「撑满型页面」加的必要补充，不影响标题与头部的统一性。

同时补上了 @media (max-width: 767px) 响应式处理（全站约定都有此段）：
头部改为纵向排列、容器加内边距、三栏改为纵向堆叠。

**四、硬编码字号与间距全部落到 token**

按 AGENTS.md「颜色与尺寸一律引用 token.css 的 design token」，清理笔记模块
CSS 中所有阶梯外取值：

  font-size: 11px / 12px / 13px  ->  var(--text-body-xs-size)  (12px)
  font-size: 20px                ->  var(--text-heading-3-size) (20px)
  padding: 40px 12px             ->  var(--spacing-xl) var(--spacing-sm)
  padding: 40px var(--spacing-sm) ->  var(--spacing-xl) var(--spacing-sm)
  top: 4px / right: 4px          ->  var(--spacing-xxs)         (4px)

11px 与 13px 不在 typography.css 的字号阶梯（10/12/14/17/18/20/21/24/32）上，
归一到 12px 后视觉差 1px 以内，换来的是全模块字号收敛到同一阶梯。
布局类 px（列宽 280/320、断点 767、max-width 80/220）与焦点环的 1px/2px
保持不变——仓库其它页面同样以 px 表达列宽与断点，属既有惯例。

### 遇到的问题与解决

- 问题：GraphView 的 orphanHint 类名在 CSS 中不存在
  解决方案：用脚本对 pages/notes 下所有 TSX 引用的 styles.X 与 CSS 中定义的
  类名做差集比对，精确找出唯一缺口 orphanHint，并补上样式。
  该检查确认了模块内不存在其他「引用了但没定义」的类名。

- 问题：useMemo 依赖 isDark 触发 react-hooks/exhaustive-deps 警告
  解决方案：readTokens() 从 :root 读取 CSS 变量，随 data-theme 属性切换而变化，
  isDark 是这条变化的唯一信号，eslint 无法穿透读取到。按仓库既有做法加
  eslint-disable-next-line 并写明原因（仓库内 NoteEditor、NoteMetaPanel、
  Profile 等已有同类注释）。

- 问题：修复中又写出 600 权限文件
  解决方案：write 工具新建文件默认 600，写完立即 chmod 644。
  本轮 start.sh 的 normalize_source_modes 步骤也已就位，部署时会兜底归一化。
