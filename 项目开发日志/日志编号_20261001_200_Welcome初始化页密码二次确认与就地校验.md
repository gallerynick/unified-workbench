### 开发内容详述
**1. 密码二次验证（确认密码）**
- 新增 confirmPassword 表单字段，dependencies={['password']} 保证修改密码后确认框自动重校
- 自定义 validator：两次输入不一致时就地提示「两次输入的密码不一致」

**2. 密码强度就地校验**
- 密码字段改为 Form.Item + rules：required / min: 8 / pattern: /^(?=.*[a-zA-Z])(?=.*\d).+$/
- 错误在字段下方就地红字显示，输入框自动变红（antd 默认行为，深浅色自动适配）
- extra 常驻提示「密码长度至少 8 位，必须包含字母和数字」
- 校验规则与后端 core/security.py 的 validate_password_strength（≥8 位、含字母、含数字）完全对齐

**3. 步骤流转拦截**
- 新增 handleNext：离开「创建管理员」步骤（currentStep===1）时先 form.validateFields()，校验失败停留当前步骤并就地显示错误
- handleComplete 提交前同样 validateFields()，通过后从 Form 实例取值（getFieldValue）组装请求体；后端契约不变（username/password/nickname）

**4. 状态管理迁移**
- 原 adminUser/adminPass/adminName 三个 useState 改为由 Form 实例统一管理，删除手写 if (!adminUser || !adminPass) 空值检查
- 「完成」步骤摘要页管理员字段改从 form.getFieldValue('username') 读取

### 遇到的问题与解决
- 问题：会话初始文件策略为只读，写入被沙箱拦截；随后策略放宽为 danger-full-access 后正常写入。
- 问题：首次尝试带 sandbox_permissions 写入时因审批等待超时（600s 上限）两次失败；确认审批策略后改为直接写入成功。
- 解决方案：无代码层面问题；本轮未改动后端，前端 API 契约不变。
