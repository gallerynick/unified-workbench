### 开发内容详述

#### 一、两个问题其实同一个根：这台机器的 Docker 虚拟机只有 5.8 GB

排查第一步是量环境，结果如下：

- 宿主机：Apple M5 / 10 核 / 16 GB / arm64 / Metal 4
- `docker info MemTotal` = 6,212,771,840 ≈ **5.8 GB**——Docker Desktop 给虚拟机分配的上限
- 容器内 `free -m`：total 5924 MB，swap 1023 MB 已用 1009 MB（几乎用满）
- `ollama ps`：`qwen3.5:4b … 100% CPU`——**纯 CPU 推理**
- `docker run --gpus all` → `no known GPU vendor found`
  ——**Docker Desktop 根本不支持把 GPU 透传给容器**，Metal 和 NVIDIA 两条路都试了，都失败
- compose 里加 `driver: metal` 或 `driver: nvidia` 都会让整个 compose 起不来

所以这台机器上 ollama 只能跑 CPU，而且 5.8 GB 的虚拟机要同时装 4B 模型（约 3.7 GB）和
ASR 四件套（约 2.1 GB），根本装不下。

#### 二、AI 测速 12.6 tokens/s：一半是量错了，一半是真慢

**量错了的部分**：旧算法是

```python
total_tokens = result.get("prompt_eval_count", 0) + result.get("eval_count", 0)
tokens_per_second = total_tokens / total_time   # total_time 是墙钟时间
```

墙钟时间里包含了**权重加载时间**和 prompt 前向时间。实测 qwen3.5:4b 光加载就 4.09 秒，
这 4 秒被摊进分母，把速率拉低将近一半。

Ollama 自己返回了 `eval_duration`（纯解码耗时），直接用它算才是生成速率：

```python
tokens_per_second = eval_count / (eval_duration / 1e9)   # 25.74 tok/s
```

同一台机器、同一个模型、同一个 prompt，旧算法给 12.6，新算法给 **25.7**——差一倍。

**真慢的部分**：25.7 tok/s 就是 4B 模型在这台机器上纯 CPU 的真实速率，想更快只有三条路：

| 方案 | 效果 | 代价 |
|---|---|---|
| Docker Desktop → Resources → Memory 提到 10 GB | qwen3.5:4b 能装下，约 24 tok/s | 改 Docker 设置 |
| 换成 qwen2.5:0.5b | **实测 176 tok/s**（7 倍），397 MB | 模型能力下降 |
| 宿主机原生装 ollama（brew install ollama） | 自动走 Metal GPU | 不用容器的 ollama |

**CPU 不涨**也解释得通了：容器跑在 Docker Desktop 的 Linux 虚拟机里，宿主机 Activity Monitor
看不到它，只有 Docker Desktop 的 Containers 面板能显示 per-container CPU。而且 qwen3.5:4b
生成 200 个 token 里有 681 字全是思考过程、可见输出 0 字（`response_chars=0`），
它烧的算力全花在思考上了。

#### 三、ASR 测试慢：正常，但会 OOM 杀容器

`_test_local_asr` 第一次调用要顺序加载 4 个模型（paraformer-zh 952 MB + ct-punc 1.1 GB +
campplus 27 MB + fsmn-vad 1.7 MB），实测耗时 18 秒左右。`init_asr_model` 有
`_model_initialized` 标志位，第二次调用直接返回——**慢只在第一次**。

但问题是：这套模型吃满内存后，**backend 容器会被 OOM 杀掉**，实测日志里能看到

```
INFO: Loading pretrained params from .../punc_ct-transformer.../model.pt
Killed
```

`restart: unless-stopped` 会自动拉起容器，但模型要重新加载一遍。
这就是「测试可用但时间偏长」的真实含义——不是慢，是**跑一次就可能重启一次**。

#### 四、顺手把模型选择器加上

之前模型写死在 `PRESET_AI_MODEL.ollamaName = 'qwen3.5:4b'`，用户想换个小模型都没地方换。
现在本地模式下加了一个 `Select`，选项来自 `/config/ollama/models`，显示每个模型的实测体积，
切换即重查状态。下载、删除、测速、状态检查全部改读表单里选中的模型，不再写死预设值。

#### 五、错误信息变得可操作

测速请求失败时，旧代码只回「生成请求失败：500」。现在把 ollama 响应体读出来，
识别 `killed` / `out of memory` 并翻译成「模型加载失败（进程被系统杀掉，通常是内存不足）」。

### 遇到的问题与解决

- **问题**：compose 里加 `driver: metal` / `driver: nvidia` 后 `docker compose up` 直接失败
  （`could not select device driver`）。
  - **解决方案**：两种 driver 在 Docker Desktop 上都不可用。改成注释块说明 Linux+NVIDIA 怎么加，
    macOS 用户去宿主机原生跑 ollama。
- **问题**：ASR 测试端点返回 502。
  - **解决方案**：不是代码 bug，是 backend 容器被 OOM 杀掉（Docker VM 只有 5.8 GB）。
    `restart: unless-stopped` 会拉起，但模型得重新加载。已确认日志里的 `Killed` 记录。
- **问题**：`docker run --gpus all alpine` 报 `failed to discover GPU vendor from CDI`。
  - **解决方案**：确认这台机器无法给容器透传 GPU，不再尝试，改在文档里说明限制。
- **问题**：qwen3.5:4b 生成 200 token，`response_chars=0`、`thinking_chars=681`。
  - **解决方案**：这是思考型模型的特性，不是 bug。前端加了「思考过程 X 字，可见输出仅 Y 字」提示，
    让用户明白为什么感觉模型没在干活。
- **遗留问题**：Docker Desktop 的虚拟机内存上限（5.8 GB）在 macOS TCC 保护目录里
  （`~/Library/Group Containers/group.com.docker/`），即使给了完整权限也读不到，
  只能让用户自己去 Settings → Resources 改。
