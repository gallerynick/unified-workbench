### 开发内容详述

#### 一、start.sh 重构：五步流程 + 前端自动构建

**根因**：`frontend/Dockerfile` 直接 `COPY dist`（容器内不跑 npm，规避构建期网络
不可达），而原 `start.sh` 只跑 `docker compose up -d --build`。dist 过期时
`--build` 命中缓存、静默复用旧产物，脚本照打印「全部服务已启动」——改动根本没进去。
日志 130 的 Tab 功能首次部署不生效就是这个原因。

新流程 5 步，每步独立标题：

    [1/5] 环境检查   docker / docker compose / daemon
    [2/5] 前端构建   dist 缺失或过期时自动 npm run build
    [3/5] 启动服务   docker compose up -d --build
    [4/5] 健康检查   等待容器就绪，异常服务打印尾部日志
    [5/5] 汇总       访问地址 / 入口校验 / 服务状态 / 耗时

关键实现：

**新鲜度判定（跨 macOS / Linux）**

- `stat_epoch()` 用 `uname -s` 分派 BSD `stat -f "%m"` / GNU `stat -c "%Y"`
- `newest_epoch()` 遍历 `find` 结果取最大 mtime；无文件时返回 0
- 比对 `frontend/src` 加 `vite.config.ts` / `tsconfig.json` / `package.json`
  与 `frontend/dist` 的最新 mtime，源码更新则触发构建
- 依赖缺失时先 `npm install` 再构建

**降级而非阻塞**：node 缺失但 dist 存在 → 警告并沿用现有产物，不阻断部署；
dist 也不存在才非零退出。避免开发机没装 node 就完全起不来。

**启动后健康验证**：轮询 `docker compose ps --format` 输出，命中
`unhealthy` / `Restarting` / 行首 `Exited` / `health: starting` 视为未就绪；
`HEALTH_TIMEOUT`（默认 120s）内未全绿则打印异常服务清单加
`compose logs --tail=25`，然后非零退出。不再「打印成功就完事」。

**入口校验**：curl 检查 `https://localhost/` 与 `/api/v1/health`，非 200 给出提示
（不 fail，部分服务可能仍在初始化）。

新增参数：`--skip-build`（跳过前端构建）、`--rebuild-frontend`（强制重建），
及环境变量 `SKIP_FRONTEND_BUILD` / `FORCE_FRONTEND_BUILD` / `HEALTH_TIMEOUT`。
`--help` 打印用法。

#### 二、Windows 侧 .bat 反斜杠字节损坏修复

排查发现 4 个 `.bat` 存在同类损坏，特征是**反斜杠被当成转义序列吃掉**：

| 文件 | 损坏内容 | 触发原因 | 正确值 |
|---|---|---|---|
| start.bat / stop.bat / reset.bat | `%~dp0scriptsdocker-detect.bat` | `\d` → `d` | `%~dp0scripts\docker-detect.bat` |
| docker-detect.bat | `%ProgramFiles%DockerDocker<CR>esources<BS>indocker.exe` | `\D`→`D`、`\R`→CR(0x0d)、`\b`→BS(0x08) | `%ProgramFiles%\Docker\Docker\resources\bin\docker.exe` |
| reset.bat | `data<BS>ackups*` / `data<FF>iles*` | `\b`→BS、`\f`→FF(0x0c) | `data\backups*` / `data\files*` |

实际影响：

- `call "%~dp0scriptsdocker-detect.bat"` 指向不存在的文件 → Windows 上永远报
  「未找到可用的 docker」，三个脚本全都起不来
- docker-detect.bat 的 PATH 兜底路径带 CR / BS 控制字节 → `if exist` 永不匹配，
  docker 没进 PATH 的 Windows 机器完全无法探测
- reset.bat 的删除目标变成 `data<BS>ackups*` / `data<FF>iles*` → 备份与上传文件
  实际删不掉，而脚本声称已删除

全仓库扫描确认无残留：`scriptsdocker` / `DockerDocker` 签名 0 命中；
5 个项目 `.bat` 的 CR / BS / FF / NUL 控制字符均为 0。

#### 三、start.bat 补齐前端构建

与 start.sh 对齐：补 `cd /d "%~dp0"`（原来缺，只能在脚本目录运行）、
改成 `[1/3] 环境检查` → `[2/3] 前端构建` → `[3/3] 启动服务`，
支持 `--skip-build` 与 `SKIP_FRONTEND_BUILD`。

### 遇到的问题与解决
- 问题：写 start.sh 时 bash 的 `${VAR:-default}` 与 JS 模板字符串插值冲突
  解决方案：改写 bash 尽量用 `$VAR` 形式，仅保留 6 处必需的花括号展开并显式转义
- 问题：`$HEALTH_TIMEOUTs` 被 bash 当成变量名 `HEALTH_TIMEOUTs`（s 是合法变量名
  字符），首版运行显示「超时 」空值
  解决方案：改为 `${HEALTH_TIMEOUT}s`
- 问题：首版字节扫描只查 CR / BS，漏掉 FF(0x0c)，reset.bat 的 `data\files*` 未修
  解决方案：扩展扫描至 BS / VT / FF / CR / NUL 全量控制字符，并做全仓库签名扫描
- 遗留问题 / 待办：
  - `.bat` 文件当前为 LF 行尾，Windows 惯例 CRLF。本次只做字节级内容修复、
    未统一行尾，建议后续单独处理
  - 前端新鲜度判定按 mtime 比较，`git checkout` 切分支后 mtime 可能失真，
    必要时用 `--rebuild-frontend` 强制重建
