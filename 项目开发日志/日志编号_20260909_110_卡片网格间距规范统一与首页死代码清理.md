### 开发内容详述

#### 一、卡片网格间距的规范冲突（本轮核心）

用户提问「首页小组件之间的间隙是否规范」，核查结论如下。

现行实现：.widgetGrid 使用 var(--spacing-card-gap) = 16px。容器内产物已验证 gap:var(--spacing-card-gap)，token.css:111 定义为 16px。

该值有三重依据，判定为规范：

1. 规范 L223 定义了专门的卡片间距 token：card-gap: 16px，与实现逐字一致
2. 全工作台既定标准：--spacing-card-gap 在 60 个 *.module.css、160 处使用（settings 38 / projects 31 / servers 18 / streaming 10 / content 7 / forms 6 / members 6，其余 topology / notes / secrets / votes / templates / inventory / tasks / contacts / reminders / file-share / notifications / finance / announcements / public / dev / home 等），首页改值反而会成为 60 个文件里的唯一异类
3. 符合规范 L831 间距系统：基础单元 8px，结构性布局对齐至 8/12/16/20/24，16px 在结构对齐列表上

列数亦符合规范 L841「主页偶发分区使用 2 列并排区块」，实现为 768px 起 2 列。

但规范本身存在三处互相矛盾的卡片网格间距取值：

| 位置 | 值 | 说明 |
|---|---|---|
| L223 spacing.card-gap | 16px | 专门命名的卡片间距 token，现行实现 |
| L388 components.card-grid.gap | {spacing.sm} = 12px | YAML 组件定义，紧跟 card / card-hover 之后 |
| L842 布局章节正文 | 20–24px | 明确限定「工具网格中」，即 {component.utility-card} 网格 |

第三行讲 Apple 式工具/配件网格，不适用于功能型页面，可排除。真正冲突的是前两行。

判断：card-gap 是专门为卡片间距命名的 token，而 card-grid.gap 填 {spacing.sm} 属抄写笔误。按「有专门 token 即以 token 为准」，16px 为正解，规范那一行为笔误。代码不应为迁就一处疑似笔误而与其余 160 处不一致。

处置（经用户确认）：规范 L388 由 {spacing.sm} 改为 {spacing.card-gap}，取值不变，代码零改动。

说明：项目基定/ 目录在 AGENTS.md 中标注为只读「非经用户确认不修改」，本次修改已获用户明确确认。

#### 二、首页网格死代码清理

Home.module.css 中 @media (min-width: 1200px) 段与 768px 段内容完全相同（均为 grid-template-columns: repeat(2, 1fr)），永远不会产生任何视觉差异，属死代码。已删除并留注释说明原委，避免后续开发者误以为预留了 3 列断点。

另记录一项未处置的写法差异（不影响观感，仅备案）：规范 L387 card-grid.grid 写为 repeat(auto-fill, minmax(300px, 1fr))，实现为固定 repeat(2, 1fr)。在首页当前宽度下两者结果相同（均 2 列），故不改。
