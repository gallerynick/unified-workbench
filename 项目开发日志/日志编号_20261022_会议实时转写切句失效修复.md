## 关联基定

《开发基准文档》实时语音听写相关约定

## 开发目标

用户反馈：说话结束后长时间不出字，之后一次性蹦出一大段转写内容。

## 问题证据（实测）

用户当场会议的录音文件 `b5a236c0`：

| 项 | 实测值 |
|---|---|
| 录音时长 | 166.4 秒（后续仍在增长至 447 秒） |
| 转出段落 | **仅 1 条** |
| 该段时间戳 | 0 → 113000ms（**113 秒一句话**） |
| 该段字数 | 113 字（多句糊在一起） |
| webrtcvad 模式 2 判定 | **69.3% 的帧被判为"有人在说话"** |
| 最长连续静音 | 恰好 1.50 秒（正好卡在切句阈值边界） |

## 根因

三个因素叠加：

1. **麦克风底噪使 VAD 过度判定语音**：信号峰值 32680/32767（已在削波边缘），
   webrtcvad 模式 2 把 69.3% 的帧判成语音，静音计时器几乎攒不满。
2. **切句只有"静音超时"一个条件**，且没有任何最大句长兜底 → 一旦静音条件
   不成立，`speech_buffer` 无限增长。
3. **浮点边界脆弱**：`silence_timer += 0.02` 累加 75 次再比 `1.5`，
   正好在浮点误差边界上，可能差一帧就永不触发。

## 开发内容详述

### 1. 实时切句加"单句硬上限"
`meeting_ws.py` 的 `_run_vad_frames` 增加第二个切句条件：当前句累计帧数达
`max_sentence_seconds`（默认 12 秒）时无条件强制切句。保证"无论 VAD 怎么判，
最多 12 秒一定出一段"。

### 2. 帧计数替代浮点秒
把 `silence_timer`（浮点累加）改为 `cur_silence_frames` / `cur_speech_frames`
（整数帧），切句阈值换算成帧数比较，彻底消除浮点边界误差。

### 3. 静音阈值 1.5s → 0.8s
中文正常停顿 0.3~0.6s，1.5s 会让"说完话"到"出字"多等近一秒。
服务端默认值、Schema 默认值同步改为 0.8。

### 4. VAD 灵敏度模式 2 → 3
模式 3 更激进地过滤非语音。实测同一段录音：中位切句时长 3.0s → 1.7s，
被硬上限强切次数 11 → 3（详见下表）。

### 5. 离线切句同样加兜底
`asr_engine.segment_audio` 增加 `max_duration`（默认 20 秒）参数。会后
（离线）转写路径实测出现过 **34 秒单段**，同样属于静音条件不成立的失控累积。

### 6. 暂停/结束时超大缓冲切分
`_flush_speech_buffer` 对超过单句上限的缓冲按上限切分后再逐段送 ASR——
原实现会把模型加载期间囤积的整段音频（可达数分钟）一次性丢给识别。

|---|---|---|---|---|---|

## 测试情况

- 静态：`py_compile` 全部通过
- 部署：9 服务全部 healthy
- 实时端到端（WebSocket 真实推流 60 秒音频）：
  - 修复前：1 段 / 最长 113 秒
  - 修复后：**5 段 / 最长 12.0 秒 / 0 段超过 12 秒**
- 离线切句：最长 34s → **20.0s 封顶**，0 段超过 20 秒
- 文本样本已能按句分离（"什么就看视吗in。" / "斌就直接看吧。" 等独立成段）
- 测试会议数据已全部清理

## 一致性确认

- 无 schema 破坏：新增参数均有默认值，旧配置继续可用
- 无前端改动（参数由后端下发）
- 新增配置项 `max_sentence_seconds` 可通过配置 API 调整，未暴露到设置页 UI

## 遗留说明

对于"长时间连续说话、几乎无停顿"的音频，切句节奏仍以 12 秒上限为准
（本次实测该录音即属此类）。要做到"边说边出字"的即时感，需要引入
**实时中间结果（partial）通道**——属下一阶段改造，不在本次修复范围。
