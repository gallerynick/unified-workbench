### 开发内容详述
**选型依据**：Ollama 镜像内置 4 个版本 NVIDIA CUDA（3.55 GB），本机 Apple Silicon 完全用不到；
二者实为同一引擎（Ollama 内部就是 llama.cpp）。llama.cpp 官方 server 镜像纯 CPU、零 GPU 库，
压缩后 297 MB（实测磁盘 1.18 GB）。

**架构**：新增 `services/llama_cpp.py` 作为引擎唯一接入点，收敛全部 URL 与接口；
llama.cpp 以 router 模式运行（不带 `-m`），按请求模型名动态载入/卸载，`--sleep-idle-seconds 300`
实现空闲自动释放内存。

**API 映射**：`/api/tags`→`GET /models`；`/api/ps`→`/models` 状态；卸载从 `keep_alive:0` 副作用
改为显式 `POST /models/unload`；下载从解析 NDJSON 改为直连 HuggingFace 流式下载 +
HTTP Range 断点续传 + `.part` 原子改名。

**前端**：`api/ollama.ts`→`api/local-model.ts`，状态机对齐 llama.cpp 五态，
补「模型载入中」过渡态处理（503 不误报为服务异常）。

**配置迁移**：数据库 `ai_provider` 未存 base_url（走代码默认值），仅需迁移模型名；
`warmup.ai=true` 保留，自热备语义由 llama.cpp 的 load/sleep 机制实现。

### 遇到的问题与解决
| 问题 | 解决 |
|------|------|
| 「载入」按钮只校验文件存在、不真正载入 | 非测速分支改为显式 `POST /models/load` |
| `load` 不幂等：已载入时返回 400 | 先查状态；对该 400 容错 |
| `load`/`unload` 异步，返回时状态未落定 | 新增 `wait_for_status()` 轮询等待 |
| `DEFAULT_MODEL = "qwen2.5:14b"` 从未下载（既有缺陷） | 改为默认模型常量 |
| `getattr(settings, "OLLAMA_URL", ...)` 设置未定义（既有缺陷） | 移除死配置 |
| 构建失败：前端新类型字段名不匹配 | `message`→`reason`，补 loading 分支 |
