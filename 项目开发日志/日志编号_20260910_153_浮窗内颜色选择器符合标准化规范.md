### 开发内容详述

#### 一、原实现的两处违规

日志 151 用 `Radio.Group` + `Radio.Button` 做颜色选择器，并写了：

```css
.colorDot {
  box-shadow: inset 0 0 0 1px var(--border-primary);
}
```

两处都不合规：

1. **装饰性 box-shadow**。规范明令「浮窗内部所有交互项禁止使用 box-shadow」，
   而颜色色块正位于 Modal 内。inset 描边阴影属于装饰，不在「功能性 Focus
   Ring」例外范围内——例外要求形如 `0 0 0 Npx` 的形态（spread > 0、
   blur = 0、无 X/Y 偏移），inset 不满足。
2. **组件模式不在规范清单内**。规范只列了「选择卡片」与「列表项」两种
   交互模式，`Radio.Button` 属第三种，其 hover / selected 视觉由 antd
   内部样式注入，无法保证走规范的 border-color + scale 反馈。

#### 二、改为规范的「选择卡片」模式

用原生 `<button>` 自建选择卡片，逐项对齐规范固定值：

| 状态 | border-color | transform | background |
|------|-------------|-----------|------------|
| 默认 | `var(--border-primary)` | `scale(1)` | `transparent` |
| 悬浮 | `var(--color-primary-hover)` | `scale(1.02)` | `transparent` |
| 选中 | `var(--color-info)` | `scale(1)` | `var(--color-info-bg)` |

`transition: border-color 0.2s, background-color 0.2s, transform 0.2s`，
`border-radius: var(--rounded-sm)`（= 8px，与规范的 8px 一致）。

色块改用 `border: 1px solid var(--border-tertiary)` 取代 box-shadow 描边，
视觉等价但完全避开禁阴影规则。

键盘焦点用 `outline` 而非 box-shadow 实现，同样不受禁阴影约束：

```css
.colorOption:focus-visible {
  outline: 2px solid var(--color-info);
  outline-offset: 1px;
}
```

同时删掉了原先隐藏 antd 勾选框的 hack（`.ant-radio-inner` 设为隐藏）
—— 不再用 Radio 组件，该 hack 失去意义。

无障碍保留：容器 `role="group"` + `aria-label`，每个按钮 `aria-pressed`。

#### 三、顺带补上缺失的 token

规范要求的悬浮色 `#4096ff`（深色 `#3c89e8`）在 token.css 里**没有任何
对应 token**。而 `TopologyManagement.module.css` 已经写了
`var(--color-primary-hover)` —— 一个指向不存在 token 的空引用，其 hover
描边实际取不到值。

补齐：

```css
/* 浅色 */
--color-primary-hover: #4096ff;
/* 深色 */
--color-primary-hover: #3c89e8;
```

token 自带深浅色映射，因此本次无需再写任何深色模式分支，也满足「不得新增
硬编码 hex」—— hex 只出现在 token.css 的定义处。

#### 四、未改动

标记色数据机制（`task.color` → 调色板 key → design token）、后端、API
契约、权限逻辑、版本号均无改动。

### 遇到的问题与解决
- 问题：规范给的 `#4096ff` 无对应 token，硬编码又违反基定
  解决方案：在 token.css 补 `--color-primary-hover`（含深色值），
  既精确满足规范色值，又保持 token 单一来源
- 问题：焦点态需要视觉反馈，但浮窗内禁止 box-shadow
  解决方案：改用 `outline`，规范未禁止 outline，且现代浏览器 outline
  会跟随 border-radius
