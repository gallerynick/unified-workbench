### 开发内容详述

#### 1. pg_dump_service.py 新建
封装 pg_dump / pg_restore / psql 子进程调用，统一连接参数（从 DATABASE_URL 解析），
PGPASSWORD 走环境变量避免命令行泄露。stdin 必须用 DEVNULL（继承父进程 stdin 会导致 pg_dump 挂起）。
DROP/CREATE DATABASE 必须分两次独立调用（单条 -c 内多语句被 PG 包进隐式事务，CREATE/DROP DATABASE 不允许）。

#### 2. Dockerfile 加 PG15 客户端
Debian 13 默认仓库只有 PG17，其 pg_restore 初始化时执行 SET transaction_timeout = 0（PG17+ 参数），
PG15 服务端不识别导致恢复失败。通过 PGDG 仓库安装 postgresql-client-15 与服务端版本匹配。

#### 3. startup_migrate.py 三层重构
- 第一层：从 Base.metadata 动态派生 13 个 PG 枚举类型（CREATE TYPE 不支持 IF NOT EXISTS，先查 pg_type）
- 第二层：逐表对比模型与实际库，自动补齐缺失列（三类处理：可空单条 ADD / NOT NULL 有默认值 / NOT NULL 无默认值三步）
- 第三层：手工特例（存量回填、列改名、索引、废弃列删除）
- 修复：engine 加 pool_pre_ping=True（陈旧连接导致 sa.inspect 挂起）
- 验证：全新库建出 48 表 + 13 枚举 + 0 缺失列；旧库删除 21 列后重跑全部补齐

#### 4. backup.py 重写
- 加密：pyzipper AES-256，密钥由 ENCRYPTION_MASTER_KEY 经 HMAC-SHA256 派生（服务端自持，无人工介入）
- 完整性：manifest 内含 database_sha256 + files_sha256，恢复前自动校验
- 恢复流程：解压校验 → 快照当前库与文件 → DROP/CREATE → pg_restore → 文件解压 → 失败自动回退
- 阶段分离：解压校验失败（Phase 1）不做回退；快照恢复失败（Phase 2）自动回退

#### 5. data_export.py / data_import.py 重写
- 导出：pg_dump 全库转储 → 复制用户文件 → manifest → AES-256 加密 ZIP（用户密码短语 + pepper + salt）
- 导入：解密 → SHA256 校验 → 同版本校验 → 快照 → DROP/CREATE → pg_restore → 文件解压 → 失败回退
- 删除 data_migrations 整个目录和 MIGRATION_CHAIN（同版本迁移，不做跨版本转换）
- 删除 total_rows（pg_dump 不提供行数统计）

#### 6. 前端适配
- DataManagement：去 total_rows 展示、去表级进度、同版本校验提示
- BackupManagement：恢复前管理员密码二次验证弹窗、表格增加校验和/表数/文件数列

### 遇到的问题与解决
- 问题：pg_dump 子进程挂起
  - 解决方案：asyncio.create_subprocess_exec 的 stdin 改用 DEVNULL（原来继承父进程管道）
- 问题：pyzipper setpassword 要求 bytes 不接受 str
  - 解决方案：backup_password() 直接返回 HMAC 原始 32 字节，不做 base64 编码
- 问题：DROP/CREATE DATABASE 报 cannot run inside a transaction block
  - 解决方案：psql 单条 -c 内多语句被 PG 包进隐式事务，改为两次独立调用
- 问题：pg_restore 17 报 unrecognized configuration parameter "transaction_timeout"
  - 解决方案：Debian 13 默认 PG17 客户端与 PG15 服务端不兼容，改从 PGDG 仓库装 PG15 客户端
- 问题：import_all 的 DROP/CREATE 断开传入的 SQLAlchemy session
  - 解决方案：import_all 内部用 isolated_session() 自建连接获取 pepper，不接收外部 session
- 问题：docker cp 后容器仍跑旧代码
  - 解决方案：每次测试前 docker cp 宿主文件 + chmod 644（docker cp 保留宿主权限，workbench 用户读不到 600）
