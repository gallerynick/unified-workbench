### 开发内容详述

#### 一、结构改造（本轮主体）

改造前是「双外壳」结构：SortableWidget 渲染 .widgetWrapper + .widgetHeader（拖拽/移除），6 个小组件各自再套一层 <Card size="small">，其 .ant-card-head 承载标题、.ant-card-body 承载内容。为此 Home.module.css 需要 4 条 :global(.ant-card*) 覆盖规则去压制 antd 的边框、圆角、背景、内边距与底部分隔线。

改造后：SortableWidget 独占外壳并统一渲染标题行，小组件只返回内容。

```
改造前：.widgetWrapper > .widgetHeader + .widgetBody > .ant-card > (.ant-card-head + .ant-card-body)
改造后：.widgetWrapper > .widgetHeader + .widgetTitle + .widgetBody
```

**关键取舍 — 标题仍独占一行，未合并为单行头部。** 用户要求「改结构，视觉保持不变」，若把标题并入 .widgetHeader 与拖拽手柄同行，视觉必然改变。故保留「拖拽行 + 标题行 + 正文」三行结构，仅把标题行的渲染权从各小组件的 <Card> 收归 SortableWidget。真正的单行头部合并仍属未实施项。

#### 二、标题排版逐像素复刻

标题行不再借用 antd .ant-card-head，需自行复刻其观感。从 antd 5.29.3 源码 card/style/index.js 的 genCardHeadStyle 与 genCardSizeStyle 读出 size="small" 的实际取值，并逐项对应到项目 token：

| 属性 | antd 派生值 | 新实现 |
|---|---|---|
| fontSize | 14px（headerFontSizeSM = token.fontSize） | var(--text-caption-strong-size) = 14px |
| fontWeight | 600（fontWeightStrong） | var(--text-caption-strong-weight) = 600 |
| color | rgba(0,0,0,0.88)（colorTextHeading） | var(--text-primary) = #1d1d1f |
| minHeight | 38px（headerHeightSM） | 32px（108 轮已定为规范结构对齐值） |
| padding | 0 12px（headerPaddingSM） | var(--spacing-xxs) var(--card-padding) 0 = 4px 16px 0 |
| borderBottom / marginBottom | 1px solid colorBorderSecondary / -1 | 无 |
| extra fontWeight / fontSize | normal / 14px | var(--text-body-weight) 400 / var(--text-caption-size) 14px |
| 标题溢出 | textEllipsis（overflow hidden + ellipsis + nowrap） | .widgetTitleMain 同款三连 |

字号与字重选用 caption-strong 一组的原因：现有 typography token 中唯一同时满足 14px 且 600 的组合，无需引入新 token。

色值的说明：#1d1d1f 与 rgba(0,0,0,0.88) 在白色底上分别渲染为 rgb(29,29,31) 与 rgb(30,30,30)，逐通道差 1 级，视觉不可分辨；改用 token 后深色模式才真正正确（此前 .ant-card-head 取 antd 的 colorTextHeading，深色下与项目 --text-primary 并不同源）。

#### 三、标题注册表 WIDGET_META

标题与右侧动作从各小组件上移至 Home.tsx 的 WIDGET_META：Record<WidgetType, { title; extraPath? } >。

其中「查看全部」原本以 <Card extra={<a>查看全部</a>}> 形式存在，涉及 4 个小组件（近期日程 → /calendar、最新公告 → /announcements、通知提醒 → /notifications、待办事项 → /tasks）。现由 Home.tsx 用同一个 <a onClick={() => navigate(extraPath)}> 统一渲染。数据概览与快捷入口无右侧动作。

- Todos / Announcements / Notifications / Calendar：删除 <Card title size="small" extra>，保留 <List size="small">；移除各自的标题图标 import（CheckSquareOutlined / SoundOutlined / BellOutlined / CalendarOutlined）
- QuickLinks：删除 <Card>，保留 <Space wrap style={{ gap: 'var(--spacing-xs)' }}>；移除 AppstoreOutlined
- Stats：删除包裹 <Card>（loading 分支亦由 <Card><Spin /></Card> 改为 <Spin />，与其他 5 个小组件的 loading 表现一致）；**内部 4 张统计小卡保留 <Card hoverable>** —— 它们需要独立圆角与 hover 交互，不是外壳

#### 五、CSS 收敛

Home.module.css 删除 4 条 antd 覆盖规则，新增 3 条自有规则：

删除：
  - .widgetBody > :global(.ant-card)
  - .widgetBody > :global(.ant-card) > :global(.ant-card-head)
  - .widgetBody > :global(.ant-card) > :global(.ant-card-body)

同时 .widgetBody 内边距由 0 var(--card-padding) var(--card-padding) 改为 var(--spacing-xs) var(--card-padding) var(--card-padding) —— 原先的 8px 顶部间距来自 .ant-card-body 的覆盖值，现由 .widgetBody 自身承担。内容相对外框的最终位置不变。

#### 六、List-in-Card 缩进修复上移至 global.css（顺带消解 113 轮遗留项）

#### 七、DebugModeOverlay 字面量收敛

border-radius: 8px → var(--rounded-sm)。该项目此前无 --font-* / --rounded 之外的字号字面量治理，此处为 DebugModeOverlay 模块内唯一的 8px 圆角字面量。

#### 八、设计规范 L842 对齐 token

原文「工具网格中卡片间距 20–24px」—— 20 与 24 虽同属规范 L831 的结构对齐列表，但项目 token 体系中不存在 20px（--spacing-md 为 17px，--spacing-lg 为 24px），「20–24」这个区间无法被任何 token 表达。

改为「工具网格中卡片间距 {spacing.lg}（24px）」。取 24 而非 20：24 有现成 token（--spacing-lg）且在结构对齐列表上，可直接落地；20 无 token 支撑，保留只会继续漂移。

说明：UI 设计规范属 项目基定 只读目录，本次修改已经用户在本轮交互中明确确认。

#### 九、后端崩溃循环（阻塞项，顺带处理）

部署后 backend 容器进入 Restarting 崩溃循环，日志：

PermissionError: [Errno 13] Permission denied: '/app/app/services/form_export.py'

定位：项目文件/backend/app/services/form_export.py 是并行会话新建的文件（git 状态 untracked，创建时间 14:27），权限 -rw-------（600），而同目录其他文件均为 644。后端 Dockerfile 执行 USER workbench 以非 root 运行，COPY . . 保留原始模式且属主为宿主机 uid 501，容器内 workbench 用户无读权限，进程启动即失败。

处置：chmod 644 后重部署。同时扫描 项目文件/ 下所有非 644/755 文件，确认前端侧虽有数十个 600 文件（ErrorBoundary.tsx、各 Modal 等），但前端构建阶段以 root 执行、nginx 阶段读取的是 root 属主的 dist 产物，不受影响；.buildx/ 下的 600 文件属 BuildKit 内部状态，正常。真正有影响的仅后端这一处。

该文件内容由并行会话写入，本日志不改动其内容、也不纳入本日志的改动清单，仅记录本次 chmod 对部署的影响。

### 遇到的问题与解决

- 问题：Home.module.css 首次 edit 仅替换到 .widgetWrapper { 选择器行，原属性行未包含在 old_string 内，导致属性块重复、PostCSS 报 Unexpected }。
- 解决：读取实际文件后删除重复块，构建恢复。

- 问题：Home.tsx 中 navigate(meta.extraPath) 报 TS2769，string | undefined 不能赋给 To。属性访问的类型收窄不会进入闭包，onClick 内退化为 string | undefined。
- 解决：先取出局部变量 const extraPath = meta.extraPath，再在闭包内引用，收窄得以保留。

- 问题：docker exec <container> grep 检索中文文案返回 0 命中，一度误判产物缺内容。
- 解决：docker cp 出 assets 后本地 grep，6 个标题与「查看全部」均在 index-d03FP-ev.js 中。判定为 docker exec 层的中文字符串传参假象，非产物问题。

- 问题：ask_user_question 请求结构改造范围确认时超时未获回复。
- 解决：未擅自实施大范围结构改动；用户随后重新提问并明确选择「改结构，视觉保持不变」，据此实施。
