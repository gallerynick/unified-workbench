### 开发内容详述

**1. 根因定位（实测确认，非推断）**

- 提交 `6fb46ab`（2026-09-27）把 `app/services/stream_room.py` 的 `get_room_urls` 从绝对地址
  `http://{host}:8889/{room_id}/whip` 改为相对路径 `/live/{room_id}/whip`（改为经 nginx 同源访问）。
- 前端 `WhipClient.postOffer` 执行 `new URL(location, url)`：base 参数 `url`（即 `room.push_url`）是相对路径，
  而 `new URL()` 要求 base 必须是绝对 URL → 抛 `Failed to construct 'URL': Invalid base URL`。
  `WhepClient.postOffer`（第 202 行）存在完全相同的隐患。
- 第二层问题：nginx `location /live/` 用 `proxy_pass http://mediamtx:8889/;` 剥掉 `/live/` 前缀转发，
  而 mediamtx 返回的 WHIP/WHEP `Location` 是相对其根路径的（实测 `/testroom1/whip/{session}`，不含 `/live/` 前缀）。
  即便只修 base，浏览器解析出的 resource URL 也会丢失 `/live/`，ICE trickle PATCH 与结束 DELETE 会 404。

**2. 修复（两处归属明确的改动）**

- nginx（/live/ 前缀映射的归属方）：在 `location /live/` 块内新增 `proxy_redirect / /live/;`，
  把 mediamtx 回包的根相对 Location 补回 `/live/` 前缀。实测回包变为
  `https://localhost/live/{room_id}/whip/{session}`（nginx 自动补全 scheme/host），浏览器可直接访问。
- WhipClient/WhepClient（URL 解析的归属方）：postOffer 中先用 `new URL(url, window.location.origin)`
  把（可能相对的）端点 URL 归一为绝对 URL，再作为 `new URL(location, baseUrl)` 的 base。
  对已绝对化的 URL（如 StreamWatch 直连 `:8889` 的地址）此归一化是无操作，保持兼容。

**3. 明确未改动**

- 后端 `stream_room.py` 的相对 `push_url`/`watch_url` 保持不变（走 nginx 同源 HTTPS 是本意，且后端无法可靠取得公网 host）。
- `StreamWatch.tsx` 仍直连 `http://{hostname}:8889/{room_id}/whep`（非本次崩溃路径，属既有不一致，另记待办）。
