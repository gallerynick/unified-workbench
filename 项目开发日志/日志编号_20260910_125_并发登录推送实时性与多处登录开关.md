### 开发内容详述

#### 1. F1 并发登录改为推送实时

纯轮询下 F1 的消失要等下一个轮询周期（最长 10s），用户感知为「不刷新就一直在」。

后端在四个会话变更点向该用户全部在线连接推送 `session_alert`（`core/websocket.py` 的模块级常量，类型 `session_alert`，无负载）：

| 事件 | 位置 |
|---|---|
| 新登录落库 | `services/auth.py` 的 `_issue_tokens` |
| 主动登出 | `api/auth.py` 的 `logout_endpoint` |
| 撤销单个会话 | `api/user_sessions.py` 的 `revoke_session` |
| 按设备批量注销 | `api/user_sessions.py` 的 `revoke_device` |

推送用 `try/except` 包裹，失败不影响主流程——推送只是体验优化，登出与撤销本身不依赖它。

前端 `useStatusProbes.ts` 新增订阅注册表：`subscribeConcurrentChange(fn)` / `emitConcurrentChange()`。F1 的 effect 同时挂 `subscribeConcurrentChange` 与 10s 定时器，任一触发都立即执行一次 F1 探测。`useWebSocket.ts` 收到 `session_alert` 时调用 `emitConcurrentChange()`。

#### 2. WebSocket 支持同用户多连接（架构修复）

这是「A 看不到并发提示」的根因。原 `ConnectionManager._connections` 为 `dict[UUID, WebSocket]`，每个用户只保留一条连接：同一用户开多个标签页时（`MainLayout` 与 `NotificationsWidget` 各实例化一次 `useWebSocket`），新旧连接每 3s 交替互相踢断；另一端登录时本端唯一连接正被另一个标签页抢走，`session_alert` 送不出去。

| 成员 | 改动 |
|---|---|
| `_connections` | `dict[UUID, set[WebSocket]]`，同一用户多条连接并存 |
| `connect(user_id, ws)` | 只添加，不再关闭旧连接 |
| `disconnect(user_id, ws=None)` | 传 `ws` 只移除该条；不传则清空该用户全部连接 |
| `send_to_user(user_id, msg)` | 遍历该用户全部连接，返回实际送达数 |
| `send_to_user_except(user_id, msg, except_ws)` | 新增，推送时排除发起方自身 |
| `user_connection_count(user_id)` | 新增，单用户连接数 |
| `active_connections` | 返回总连接数（原为用户数） |
| `active_users` | 新增，有连接的用户数 |

`api/ws.py` 的断连分支改为 `manager.disconnect(user_id, websocket)`，避免误清同用户其他连接。消息模型不变：仍按用户投递，只是收件人集合从「至多一条」变为「该用户全部在线连接」。

#### 3. 「允许多处同时登录」开关

存储复用 `user.preferences` JSONB 列的 `allow_multiple_logins`（布尔，缺省视为开启），不新增表或列，因此不涉及 `startup_migrate.py` 与 alembic。

`services/auth.py` 新增 `_enforce_single_device(db, user, allow_multiple_logins)`，在 `_issue_tokens` 中于本会话落库前调用：关闭时把该用户全部未撤销会话置为 `is_revoked = True`，返回 `(other_session_count, revoked_session_count)` 写入 `LoginResponse`。

放在 `_issue_tokens` 而非路由层的原因：普通登录、TOTP/恢复码二次验证、WebAuthn 二次验证三条路径都汇聚到此，一个位置即可覆盖全部登录方式。

统计范围是全部未撤销会话，不做 30 分钟窗口过滤：这里判断「该账号当前还有别的登录」，与 F1 的「最近活跃的其他会话」是两套语义，窗口过滤只在状态指示侧有意义。

接口：`GET /api/v1/users/me/preferences` 返回该字段；`PUT` 接收 `allow_multiple_logins`（可空）。可空的必要性——个性化页调用 `PUT` 时只传缩放与主题，后端只合并实际传入的键；若把默认值写回，改一次页面缩放就会悄悄把单设备策略打开。

实现改用 ORM 属性赋值 + `flag_modified`，不再拼 jsonb SQL。

前端：`SecuritySettings.tsx` 新增「登录策略」卡片与开关；`Login.tsx` 按 `revoked_session_count > 0` 显示「已按仅允许一处登录下线其他设备」，否则按 `other_session_count > 0` 显示「已在其他 N 个设备登录」，两者均为 0 时显示普通成功提示。两个字段缺省按 0 处理，兼容旧后端响应。

### 遇到的问题与解决

1. **`text()` 里 `:patch::jsonb` 导致 UPDATE 500**
   起初用参数化 jsonb 合并替换原先的 f-string 拼 SQL，结果 `PUT /users/me/preferences` 返回 500，后端报 `PostgresSyntaxError: syntax error at or near ":"`，实际 SQL 为 `|| :patch::jsonb WHERE id = $1`——`:user_id` 被正常替换成 `$1`，但 `:patch` 原样残留。原因是 SQLAlchemy 把 `:patch::jsonb` 中的 `::` 识别为 PostgreSQL 类型转换符，导致 `:patch` 不被解析为绑定参数。改为 ORM 属性赋值加 `flag_modified(current_user, "preferences")`，由 ORM 发出整列 UPDATE，彻底避开该歧义。

2. **同用户多标签页互相踢断，推送无法送达**
   即第 2 节的架构修复。表现为：A 端登录后 B 端有提示、A 端没有；A 端登出后 B 端提示不消失。旧实现下同一用户的两条 WebSocket 每 3s 交替重连（前端 `setTimeout(connect, 3000)`），任何时刻只有一个标签页真正连着，`session_alert` 大概率落空。改为多连接并存后问题消失。

3. **`Switch` 属性名大小写**
   antd 的关闭态子元素属性是 `unCheckedChildren`（C 大写），写成 `uncheckedChildren` 时 `tsc` 报 `Property 'uncheckedChildren' does not exist`。修正后通过。

4. **验证脚本误判**
   初版验证脚本的 `login()` 在真正登录前多打了一次不带设备头的登录请求，导致每个登录动作实际产生两条会话，计数断言全部偏移（期望 2 实测 6）。删除多余请求后断言恢复。

5. **测试会话残留**
   多次运行验证脚本后 admin 账号积累了十余条未撤销会话，`/me/sessions` 一次取不全导致清理不彻底。改为部署后用数据库直接批量撤销（`UPDATE user_session SET is_revoked=true WHERE ...`）再跑断言。
