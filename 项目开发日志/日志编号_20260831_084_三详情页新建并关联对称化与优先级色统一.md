### 开发内容详述

**1. 优先级 Tag 颜色统一（按 UI 设计规范语义化）**
- UI 设计规范状态色体系：成功绿 / 警告橙 / 错误红 / 信息蓝。优先级映射沿用 Ant Design 色阶梯度：P0 紧急→red、P1 高→volcano、P2 中→orange、P3 低→gold、P4 待定→default
- 项目文件/frontend/src/constants/project.ts 已存在该映射，本次删除 ProposalDetailPage 与 ProposalTab 的重复定义（已在上轮完成），并统一 TodoTaskTab.tsx 使用共享常量，消除 P2=gold/P3=default 的旧不一致映射

**2. 后端：待办/提案 新增 meeting_id 双向关联**
- 迁移脚本 043（alembic）：project_todo、project_proposal 表各新增 meeting_id（UUID，nullable，FK → project_meeting.id，ondelete SET NULL）
- ORM 模型：ProjectTodo、ProjectProposal 新增 meeting_id 列与 meeting 关系（TYPE_CHECKING 中 import ProjectMeeting）
- Pydantic schemas：ProjectTodoCreate/Update/Response 与 ProjectProposalCreate/Update/Response 各新增 meeting_id 字段
- 业务服务：create_project_todo / update_project_todo / create_project_proposal / update_project_proposal 各增加 meeting_id 处理（create 时接收，update 时按字段集更新）
- Dockerfile CMD 增加启动时增量迁移钩子：create_all 建表 → alembic stamp head（无 alembic_version 时）→ alembic upgrade head（执行 043）→ uvicorn 启动
- db_migrate.py：幂等迁移脚本，检测 alembic_version 表存在性并据此 stamp/upgrade，保证已有环境与新环境均可正确初始化 meeting_id 列

**3. 前端：类型与模态组件**
- types/project-todo.ts 与 types/project-proposal.ts：ProjectTodo/ProjectTodoCreate/ProjectTodoUpdate/ProjectProposal/ProjectProposalCreate/ProjectProposalUpdate 各新增 meeting_id?: string | null
- TodoModal.tsx：新增 initialMeetingId prop 与 TodoFormValues.meeting_id；新建时 initialMeetingId 写入 payload，编辑时保留回填
- ProposalModal.tsx：新增 initialMeetingId prop；新建时写入 payload（编辑无需，因关联字段仅新建时预置）

**4. 前端：MeetingDetailPage 补齐两个「新建并关联」方向**
- 已存在：MeetingModal 编辑交流 + 添加已有提案/待办
- 新增：MeetingModal 之外挂 TodoModal（initialMeetingId=meeting.id）与 ProposalModal（initialMeetingId=meeting.id），按钮标签「新建并关联」置于「添加已有」之侧，与 ProposalDetailPage 的「添加已有+新建并关联」双按钮范式一致
- 状态：createTodoVisible、createProposalVisible

**5. 三详情页「新建并关联」方向对照（最终对称表）**
| 页面 | 待办方向 | 交流方向 | 提案方向 |
|------|---------|---------|---------|
| TodoDetailPage | — | MeetingModal（initialTodoId）✅ | 添加已有 ✅（已有 TodoModal 无 proposal_id 双向）|
| MeetingDetailPage | TodoModal（initialMeetingId）✅ | — | ProposalModal（initialMeetingId）✅ |
| ProposalDetailPage | TodoModal（initialProposalId）✅ | MeetingModal（initialProposalId）✅ | — |

关联「添加已有/断开」逻辑在三页完全对称，均为「仅一个关联 + Modal.confirm 二次确认」。

### 遇到的问题与解决
- 问题：TodoFormValues 缺少 meeting_id 字段导致 TS2353
  - 解决方案：TodoModal.tsx 的 TodoFormValues 增加 meeting_id?: string
- 问题：Dockerfile CMD 字符串含反引号，run_code 模板字符串内难以精确 edit
  - 解决方案：用 write 工具整体重写 Dockerfile 文件
- 问题：Alembic 增量迁移在 create_all 已建表且无 alembic_version 指针的环境下会尝试从 001 全量执行而失败
  - 解决方案：db_migrate.py 先检测 alembic_version 存在性，不存在则 stamp head 将指针打到最新，再 upgrade head 只运行新增增量迁移
- 遗留问题 / 待办：本次仅做「新建并关联」方向。编辑模式下 TodoModal/ProposalModal 是否应回填 meeting_id、以及关联字段是否应在表单中展示为 Select，属于交互设计，未做
