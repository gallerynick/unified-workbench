### 开发内容详述

**1. /auth/me 500（PendingRollbackError）**

现象：nginx 日志中 `GET /api/v1/auth/me` 返回 500，referer 为 `https://localhost/lock`（锁定页）；后端日志为
`ValidationError: 10 validation errors for UserResponse`，每条均为 `Error extracting attribute: PendingRollbackError
…Original exception was: greenlet_spawn has not been called; can't call await_() here.`

根因链：
- `UserResponse`（`from_attributes=True`）含 `tags: list[TagResponse]` 关系字段；
- 各查询（`get_current_user`、users 服务层）取 User 时均未预加载 `tags`；
- Pydantic 序列化在事件循环中同步执行，访问未加载关系触发 async 惰性加载 → `greenlet_spawn` 错误；
- 该错误把 AsyncSession 事务置为 rollback-pending，随后所有字段的取值都抛 `PendingRollbackError` → 10 连错；
- 原有 `handle_lazy_tags` 守卫是"先访问再捕获"，拦不住会话污染。

修复（查询层预加载 + 守卫改进 + 防过期）：
- `deps.py` / `services/user.py`：所有取 User 用于 UserResponse 的查询加 `.options(selectinload(User.tags))`；
- `services/user.py` `create_user` / `update_user`：标签经 UserTag SQL 直接增删，返回前 `db.refresh(user, attribute_names=["tags"])` 重载关系集合；
- `auth.py` PUT /me：全量 `db.refresh` 会过期关系属性，改为仅重载 tags；
- `schemas/user.py`：`handle_lazy_tags` 改为先用 `inspect(data).attrs["tags"].loaded` 检查加载状态，未加载才置空，不再触发惰性加载。

**2. B3「正在通过公网访问」误报 + 说明**

现象：内网 DNS 名（如 `workbench.company.com` 解析到内网）持续误报 🟡。原因：原规则「域名一律按公网处理」，
浏览器无法解析 DNS，无法区分内网 DNS 域名与穿透域名。

修复：`isPrivateHost` 布尔判定改为三态 `classifyHost`（private / public / unknown）：
- private：localhost、::1、私网 IPv4、ULA/链路本地 IPv6、裸主机名（无点号）、.local / .arpa；
- public：其余 IPv4/IPv6 字面量（确凿公网）；
- unknown：带点可解析域名（浏览器无法判定解析结果）→ **不提示**。

文案补充说明：提示时显示「正在通过公网访问（访问地址为公网 IP）」，说明提示依据是 IP 而非域名。
代价：穿透域名部署不再提示公网访问；换来内网 DNS 部署不误报（用户本轮明确要求"尽可能减少误报"）。

**3. 后端 Dockerfile apt 修复落盘 + PGDG key 拉取修复**

- `Acquire::IndexTargets::deb::Packages:: "no";` 写入两阶段（builder / runtime）apt 配置；
  让 apt 不再请求 Debian InRelease 广告但已不提供的 56MB 未压缩索引（全镜像 404），直接拉 .xz 压缩索引。
- PGDG key 拉取：构建网络透明代理对 `https://www.postgresql.org` 的 TLS 握手持续断连（`curl: (35) unexpected eof`，
  两次构建均卡死此步）；改为 `http://apt.postgresql.org/pub/repos/apt/ACCC4CF8.asc`（该主机 HTTP 在构建网络内实测通畅）
  + `--retry 5 --retry-all-errors`。
- 两处「超时调优」根因注释更正为核实结论（404 非超时问题，IndexTargets 才是正解）。
