### 开发内容详述

**一、F1 永不消失的根因**

后端没有任何登出端点（`grep -rn "logout" app/` 为 0 命中）。前端登出只清 localStorage，`user_session.is_revoked` 保持 false。而 F1 的统计口径是「30 分钟内未撤销的其他会话」，因此被登出的会话一直被计入，直到离开 30 分钟窗口。不是刷新慢，是永远不会消失。

修复分两半：

1. 新增 `POST /api/v1/auth/logout`（`app/api/auth.py`）：按 JWT 的 `jti` 找到当前会话，置 `is_revoked=True`。幂等——会话不存在或已撤销时同样返回成功，登出不应因重试报错。
2. 新增 `frontend/src/utils/auth.ts` 的 `logout()`：先 POST 撤销，再 `clearTokens()`。撤销请求失败（断网）时仍继续清本地令牌，避免用户被卡在无法登出的状态。

`utils/auth.ts` 是登出的唯一入口，3 处调用点全部改接：`layouts/MainLayout.tsx`（右上角菜单）、`components/AuthGuard.tsx`（维护模式 403 页）、`pages/DebugModePage.tsx`（调试模式页）。

`pages/settings/DevicesPage.tsx` 未改：它的两处「注销设备」先调 `DELETE /me/devices/{token}`（服务端已撤销），再清本地令牌，语义已正确。

**二、刷新节奏：F1 拆出独立 10s 轮询**

原实现把 F1 挂在 `/system/status` 上，而那个端点除了查库还要做 `os.statvfs` + 真实写入探针、mediamtx 连通性探测。60s 一次合理，10s 一次会白做三次无谓的存储写入与推流探测。

拆分后：

| 端点 | 用途 | 节奏 |
|---|---|---|
| `GET /api/v1/system/status` | C3/C4/C5 服务状态 | 60s |
| `GET /api/v1/me/concurrent` | F1 并发统计 | 10s |

`/me/concurrent` 只有一条按 `user_id` 的索引查询，无存储写入、无推流探测，支撑 10s 轮询没有额外负担。

统计逻辑抽到 `app/services/session_activity.py`（`get_current_session` / `count_concurrent` / `CONCURRENT_RECENT_MINUTES`），被 `/system/status` 与 `/me/concurrent` 共用，避免出现两套口径。`api/status.py` 删除了自己的一份拷贝，连同 `decode_token`、`UserSession`、`select`、`timedelta` 等不再需要的导入一并移除。

前端 `useStatusProbes.ts` 相应调整：F1 从 `compute()` 移出，`probeConcurrent()` 单独实现，独立 `useEffect` + `setInterval(run, 10_000)`，结果存 `concurrentIssues` 状态，最后并入 `merged`。探测失败时保留上一次结果——瞬时网络抖动不应让告警消失。

**三、小灯闪烁一致性（非缺陷）**

16 个状态里 6 个 critical（红）会闪烁、10 个 warning（黄）静态，这是 `StatusIndicator.module.css` 的有意设计：

- `.critical` 带 `animation: status-pulse 2s var(--anim-ease-in-out) infinite`（不透明度 1 → 0.45 → 1）；
- `.warning` 只有 `background: var(--color-warning)`；
- `@media (prefers-reduced-motion: reduce)` 下两者都停。

红色表示需要立即处置（数据库不可用、后端不可达、维护模式），闪烁是刻意的注意引导；黄色表示知情即可。若要统一闪烁，给 `.warning` 加同一个动画即可（一行 CSS），但不建议：黄色项数量多且多为长期状态（如「实时提醒不可用」），全部闪烁会形成视觉噪音。

### 遇到的问题与解决

1. **新文件权限 600 导致容器内 PermissionError**：`app/services/session_activity.py` 以 `0600` 创建，容器内以非 root 用户运行，导入即 `PermissionError: [Errno 13] Permission denied`，后端无限重启、全站 502。`chmod 644` 后正常。这是本仓库用编辑器直接落盘新建文件的通病。

2. **端点路径写错导致 F1 实际 404**：`user_sessions_router` 挂载时无 prefix（`api/router.py`），实际路径是 `/api/v1/me/concurrent` 而非 `/api/v1/auth/me/concurrent`。前端与文档最初都写成后者，导致前端 F1 探测恒为 404、提示永不出现。核对线上 bundle 内容才发现。

3. **误判批量 DELETE 失败**：验证脚本一次性 DELETE 上百个历史会话后计数不变，一度怀疑 DELETE 不生效。实际是单条 DELETE 生效——问题在于撤销当前会话会立即失效自己的令牌，后续调用变成 401。改用 SQL 批量撤销后取得干净基线。

4. **测试脚本路径写错**：`/auth/me` 属于 auth 路由（带 prefix），验证脚本写成无 prefix 形式导致 404，非代码缺陷。
