### 开发内容详述

**一、闪烁：5 个叠加成因**

| # | 成因 | 位置 | 表现 |
|---|---|---|---|
| 1 | `probeDb()` 传输层失败返回 `false`，与真实 DB 异常无法区分 | useStatusProbes | 一次网络抖动即点亮 C2「数据服务暂时不可用」，显示满 60s，下次成功又消失 |
| 2 | A2 用 `Math.max(窗口)` 判定 | useStatusProbes | 窗口内**任意一次**慢请求就点亮，且需等 5 轮（5 分钟）才熄灭 |
| 3 | A3 直接读 `wsConnected`，而它的初始值就是 `false` | useWebSocket / useStatusProbes | 每次进页面必先闪一次「实时提醒不可用」再消失；WS 断线重连（3s 退避）同样闪 |
| 4 | `compute()` 每个巡检周期都返回新数组 → `sorted` 重算 → `setIndex(0)` | StatusIndicator | 每 60s 轮播索引被重置，文字跳回第一条 |
| 5 | `<Text key={current.id}>` 强制重挂载 + `status-swap` 从 `opacity: 0` 起淡入 | StatusIndicator / module.css | 每次轮播是「瞬间消失 + 从全透明淡入」，读起来像闪 |

**二、悬停不显示**

`StatusIndicator.tsx` 原有提前返回：

    if (sorted.length === 1) return place(body);

**只有一条异常时根本不渲染 Popover**，而 `onMouseEnter`/`onMouseLeave` 挂在 body 上、
只服务于 Popover 与轮播暂停——于是单条异常时鼠标悬停触发的是空操作。
两条以上才弹列表，单条完全无反应，观感就是「悬浮没显示」。

**三、修复**

1. `probeDb()` 传输层失败改为返回 `null`（返回类型 `Promise<boolean | null>`），
   交给 A1「网络已断开」判定；不把网络抖动误报成数据库故障。
   `C2` 判定只对 `false` 累加，`null` 既不计入异常也不清零。
2. `C2` 增加抖动抑制：连续 `FLAP_GUARD = 2` 次异常才提示，连续 2 次正常才恢复。
3. `A2` 判定改为「窗口内超阈值样本数 ≥ FLAP_GUARD」，替代 `Math.max`。
4. `A3` 增加 `WS_GRACE_MS = 10s` 宽限期：断连累计超过 10 秒才通告。
   进页面时的初始 `false`、3 秒级重连都不会再闪。
   复用 E1 已有的 1s tick（`getIdleMsLeft()`），不新增定时器；
   `wsConnected` 经 ref 读取，避免把它放进 effect 依赖导致计数每次重启清零。
5. 新增 `sameIssues(a, b)` 内容比较（id/level/text 三元组），
   `setProbeIssues(prev => same ? prev : next)`——内容不变时复用旧引用，
   React 跳过重渲染，`sorted` 不再重算。
6. `StatusIndicator` 新增内容签名 `signature = sorted.map(i => i.id).join('|')`，
   索引重置的 effect 依赖改为 `signature` 而非 `sorted`。
7. 去掉单条提前返回，**一条或多条都套 Popover**。
8. `status-swap` 淡入起点从 `opacity: 0` 改为 `0.35`、位移 2px 改为 1px。
   key 变更会卸载旧节点，从完全透明起跳视觉上就是一次闪烁；
   保留残余可见度让轮播变成「平滑过渡」而不是「闪断」。

**四、有意为之、不改的部分**

- `E1`「即将自动锁定」在活动后消失是正确语义（预警已解除），不做滞回。
- `C1` 系统维护中是管理员显式开关，单次读取即可信，不做抖动抑制。
- `A1` 原本已有 `HEALTH_FAIL_THRESHOLD = 3` 连续失败判定，无需改动。
- `C3/C4/C5` 服务级探测失败时 `probeServices()` 返回 `null`，
  既不告警也不误报，行为本就正确。

### 遇到的问题与解决
- **问题：改 `probeDb` 返回类型后 tsc 报错**
  - `TS2322: Type 'null' is not assignable to type 'boolean'`
  - 解决：把声明同步改成 `Promise<boolean | null>`。
- **问题：memo 依赖已换、条件未换**
  - 第一次编辑把 `useMemo` deps 从 `wsConnected` 改成 `wsDown`，
    但判定条件还写着 `if (authed && !wsConnected)`，会造成条件与依赖不一致。
  - 解决：补一次编辑把条件同步为 `wsDown`，并新增 `wsDown` state。
- **问题：验证脚本的 grep 反复误报（延续 102 号日志的教训）**
  - `grep -c -F 'width:6px'` 在管道里偶发无输出；
    CSS 模块类名会被哈希成 `_headerIconButton_18y4p_149` 之类，
    用源码类名直接 grep CSS 会漏判。
  - 解决：改用「规则内容片段」而非类名来校验（如
    `width:var(--avatar-size);height:var(--avatar-size)`），
    并统一用 `grep -c -F` 加显式 `--` 分隔。
