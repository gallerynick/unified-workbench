#### 2. 一键新建并关联
- 关联待办/交流区按钮区分「添加已有」（原多选弹窗）与「新建并关联」（新表单）

#### 3. 断开二次确认
- `handleDisconnectTodo` / `handleDisconnectMeeting` 改为 `Modal.confirm`（危险按钮），确认后才执行断开

#### 4. 后端修复（冒烟发现）
- **问题**：`ProjectMeetingCreate` schema 与创建 service 均不支持 `proposal_id`（只有 update 支持），导致一键新建交流无法直接关联提案
- **修复**：schema 新增 `proposal_id: uuid.UUID | None = None`；service 创建时 `proposal_id=data.get("proposal_id")`，与 `create_project_todo` 的既有模式对齐

### 遇到的问题与解决
- 问题 1：模板字符串嵌套反引号导致 edit 解析失败
  - 解决方案：改用数组 join("\n") 传递 old_string/new_string
- 问题 2（冒烟发现）：交流创建的 proposal_id 未生效（todo 正常）
  - 解决方案：核实为后端 ProjectMeetingCreate 缺字段，修复 schema + service 后重部署，冒烟通过
- 问题 3：部署命令曾因环境原因中止（abort）
  - 解决方案：重试 start.sh 成功
- 问题 4（部署后用户反馈）：提案详情页报 React error #310（Rendered more hooks than during the previous render）
  - 根因：`renderDescriptionBlock` 用了 `useCallback`，但定义在 `if (!proposal) return null` 条件返回**之后**——首帧 proposal 为 null 提前返回时 hooks 未执行，数据加载后再渲染时执行到该 hook，两次渲染 hook 数量不一致
  - 解决方案：将 `renderDescriptionBlock` 改为普通函数（不依赖 hook 状态，与 `renderDefItem` 一致）；grep 确认 660 行（`if (loading)`）之后无任何 hooks；tsc 零错误、build 通过、重新部署（新 bundle ProposalDetailPage-BGwxOY0D.js）
