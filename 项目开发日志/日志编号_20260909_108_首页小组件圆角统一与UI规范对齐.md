### 开发内容详述

#### 一、问题根因

首页小组件由两层圆角矩形嵌套构成：

| 层级 | 元素 | 圆角来源 | 值 |
|------|------|---------|-----|
| 外框 | .widgetWrapper | var(--rounded-sm) | 8px |
| 内层 | .ant-card（各小组件自带） | contexts/ThemeContext.tsx 的 Card.borderRadiusLG | 18px |

同时 .widgetBody 带 12px 内边距、antd Card 自带 1px 边框，形成「8px 圆角外框 + 12px 间隙 + 18px 圆角内卡 + 两条独立边框」的嵌套结构，内角明显大于外角，视觉不和谐。

「统计概览」组件额外嵌套一层 Row/Col 小卡，同样为 18px 嵌在 8px 外框内，二级冲突同源。

首页 6 个小组件（统计概览 / 日程日历 / 最新公告 / 通知提醒 / 待办事项 / 快捷入口）结构一致，全部存在该问题，非仅第 6 个组件。

#### 二、实现方案

按 UI 设计规范 {component.card}，确立「外框为唯一视觉容器」模型：

1. **外框承担容器职责**：.widgetWrapper 改用 token.css 组件级 token——background: var(--card-bg)、border: var(--card-border)、border-radius: var(--card-rounded)（8px），以语义化 token 引用取代原先散落的 var(--bg-primary) / 字面量 1px solid。
2. **内层 Card 退让**：.widgetBody > .ant-card 通过负边距（margin: 0 calc(var(--card-padding) * -1)）顶格铺满外框内容盒，同时移除自身 border / border-radius / box-shadow / background，容器视觉不再重复。
3. **栅格对齐**：Card 头部 padding 与 .widgetHeader（拖拽/隐藏操作条）统一为 var(--spacing-xxs) var(--card-padding) 0，使拖拽手柄、标题、正文内容共用同一 16px 水平栅格；移除 Card 头部默认分隔线与下边距（UI 规范要求无装饰性边框）。
4. **次级卡片统一**：.widgetBody .ant-row .ant-card 强制 8px 圆角，消除「统计概览小卡 18px 嵌于 8px 外框」的二级冲突。
5. **过渡 token 化**：transition 由字面量 0.2s ease 改为 var(--anim-normal) var(--anim-ease)。

#### 三、关键决策

- **纯 CSS 方案**：未改动任何 TSX，6 个小组件组件无需感知外壳变化，改动面收敛到单个样式文件。
- **内层 Card 保留组件语义**：头部图标+标题、extra「查看全部」链接、body 列表全部保留，仅视觉退让，交互结构不变。
- **不改全局 Card.borderRadiusLG**：ThemeContext 中该值影响全站所有默认 Card，本次仅解决首页作用域内的冲突，避免未经评估的全站波及。
- **不加 overflow: hidden**：内层 Card 已透明无边框，无溢出风险；加 overflow 会静默剪掉小组件内可能新增的下拉/浮层，属维护隐患。

### 遇到的问题与解决

- 问题（本次最关键）：在 CSS Module 中直接写 `.ant-card` 等 antd 类名，Vite/Lightning CSS 会按 CSS Modules 规则把这些「未知类」作用域化为哈希类（实际产物为 `._ant-card_rh2xb_78`），选择器与 antd 运行时的真实类名完全不匹配，规则静默失效——圆角/边框退让全部不生效。
- 解决方案：改用 `:global(.ant-card)`，与代码库既有约定一致（见 layouts/MainLayout.module.css、pages/content/ContentEditor.module.css、pages/streaming/RoomListPage.module.css 共 45 处）。修复后校验容器内产物：`_ant-card` 残留 0 次，全局 `.ant-card` 7 次，选择器正确落地。
- 经验教训：本仓库 Home.module.css 此前从无 antd 类覆盖，本次是该文件首次写 antd 选择器，踩中了 CSS Modules 默认作用域化行为。凡是在 *.module.css 内覆盖第三方组件类名，必须用 `:global()`；若要全局生效且不属于某个模块，应写入 global.css。

- 问题：antd v5 通过 CSS-in-JS 哈希类 + 类名组合设置 Card 的 border-radius / background，特异性与手写规则可能持平，生效取决于源码顺序。
- 解决方案：关键属性使用 !important，与 global.css 既有的 antd 覆盖写法保持一致。

- 问题：执行 start.sh 重部署时，docker buildx 报「failed to update builder last activity time: operation not permitted」，容器未重建。
- 解决方案：申请宽沙箱权限后重试；后续又因 PATH 中缺少 docker-credential-osxkeychain 导致「error getting credentials」，手动补全 PATH 并预先拉取 python:3.11-slim / nginx:1.25-alpine 两个基础镜像后重新部署。

- 问题：首次写日志时按会话初印象估算序号为 087，而并发会话已将日志推进至 107，且 098 已引入原子取号规范。
- 解决方案：调用 sh 项目文件/scripts/claim_log_number.sh 取得 108，重命名日志文件并改写标题为「## [日志编号 108] - YYYY-MM-DD HH:MM」格式，删除误建的 087 文件后 git add 并释放锁目录。

- 遗留问题 / 待办：
  - 全局 Card.borderRadiusLG: 18 使全站默认 Card 为 18px，与 UI 设计规范 {component.card} 的 8px 定义不一致，建议后续统一评估是否收敛为 8px（影响面大，需单独排期）。
