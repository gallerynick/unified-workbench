### 开发内容详述

#### 一、会议音频流（后端 `meeting_ws.py` + 前端 `useAudioCapture` / `useMeetingWebSocket`）

- 端点 `/ws/meetings/{meeting_id}?token=*** WebSocket 握手时校验 JWT
  （query token 形式，因浏览器 WebSocket 无法自定义 Header），并校验会议归属，
  用 `_ws_connections` + `_ws_lock` 限制同一会议同一用户单连接。
- 前端 `useAudioCapture` 采集麦克风 16 kHz / 16-bit / 单声道 PCM，分片后经 base64 编码
  通过 `audio_chunk` 消息推送；采样率与声道数随消息体下发供服务端写 WAV。
- 服务端按收到的音频字节流顺序落盘为 WAV（44 字节标准头 + 数据段），
  结束时用 `update_wav_header` 回填 RIFF / data chunk 长度。
- VAD 静音检测驱动断句：连续语音累积到缓冲区，静音超过阈值即触发一次异步转录，
  结果以 `transcript_segment` 消息推回前端，并累计 `buffer_offset_ms` 保证时间轴连续。
- 前端 `useMeetingWebSocket` 负责连接、断线重连与消息分发；
  由页面根据会议状态（recording / paused）传入 `shouldConnect`，用 ref 同步避免闭包过期。
- 消息类型全部走强类型联合 `MeetingWebSocketMessage`
  （`transcript_segment` / `status_update` / `processing_update` / `warning` / `error`），
  `switch` 按 `type` 判别式收窄，代码中不出现 `as any` 断言。

#### 二、会议笔记自动保存

- 会议记录新增 `notes` 文本字段（模型 / schema / 迁移三处一致），
  前端 `MeetingRecordUpdate` 同步开放 `notes?`。
- `MeetingRoom` 的笔记输入框防抖 2 秒后 `PATCH /meetings/{id}` 写回，
  状态机 `idle → saving → saved / failed`，界面回显「已保存 HH:mm:ss」。
- 修正原先「AI 纪要 summary 被写进 `notes` 字段」的错误绑定：
  笔记编辑区只承载用户手记，AI 纪要仍在独立的 `meeting_minutes` 表。
- 保存状态提示原先用 `✓` 文本字符充当图标（违反「禁止 Emoji / 文本符号图标」规范），
  改为 `<CheckCircleOutlined />`，颜色取 `var(--color-success)`。

#### 三、会后处理任务（`meeting_process.py`）

- Celery `shared_task` 入口保持同步签名，内部 `asyncio.run` 驱动异步实现，
  与 `backup` / `calendar_reminder` / `reminder` 等既有任务保持同一模式。
- 数据库会话一律 `async with isolated_session()`（该上下文是 `@asynccontextmanager`，
  不能用于同步 `with`，见「五、阻断项 1」）。
- 流程：读取会议 → 读已落盘 WAV → 全量转录 → LLM 生成结构化纪要 →
  写入 `meeting_transcript_segment` / `meeting_minutes` → 会议状态置 `completed`。
- 失败路径把 `minutes_status` 置 `failed`，按 `max_retries=3` / `countdown=60` 重试，
  全部失败后返回 `{"status":"error","message":...}`，不静默吞掉。

**阻断项（会导致运行时报错或功能不可用）**

1. **`meeting_process.py` 用同步 `with` 调用 `@asynccontextmanager`**
   `isolated_session` 只有 `async with` 可用，原实现写 `with isolated_session() as db:`，
   任务一旦被调度必然抛 `AttributeError`。
   改为同步入口 + `asyncio.run` + `async with`；AST 校验确认同步 `with` 数量为 0。
2. **`meeting_minutes.py` 的 Ollama 地址写死 `http://localhost:11434`**
   容器内该地址指向 backend 容器自身而非 ollama 容器，纪要生成必然失败。
   改为 `http://ollama:11434`，并保留 `settings.OLLAMA_URL` 可覆盖。
3. **`meeting_minutes.py` 代码块正则写坏**
   原式 `r'```(?:json)?s*([sS]*?)```'` 无法匹配 JSON 代码块（`[sS]*?` 只匹配字面 s/S）。
   改为 `r'```(?:json)?\s*(.*?)\s*```'`，并保留花括号兜底提取。
4. **`meeting_ws.py` 嵌套函数用 `global` 访问外层协程局部变量**
   `transcribe_async` 内 `global is_processing` 会让变量落到模块级命名空间，
   外层 `if not is_processing` 的互斥判据失效；而 `segment_count` / `buffer_offset_ms`
   既未 `global` 也未 `nonlocal`，增量赋值直接抛 `UnboundLocalError`，
   导致「实时转录线程第一次断句即静默死亡」。
   统一改为 `nonlocal is_processing, segment_count, buffer_offset_ms`。
5. **`end_meeting_record` 在事务提交前就 `process_meeting.delay`**
   会后处理任务用独立连接重新读取会议记录，主事务未提交时可能读到旧的
   `status` / `ended_at` / `audio_file_path`。
   入队前增加 `await db.commit()` 收敛竞态；同时删除无意义的
   `item.audio_file_path = item.audio_file_path` 自赋值与冗余 `db.flush()`。
6. **`MeetingRoom` 笔记自动保存是空实现**
   `handleNoteChange` 的 2 秒防抖回调里只有一句 `// TODO: 调用后端 API 保存笔记`，
   用户手记刷新即丢。补齐 `PATCH` 调用与保存状态回显。
