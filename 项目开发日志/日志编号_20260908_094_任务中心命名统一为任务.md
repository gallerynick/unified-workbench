### 开发内容详述

#### 一、命名混用问题

盘点发现「任务中心」模块（pages/tasks/）内部同时使用两种名称：
- 「任务」8 处：侧边栏「任务中心」、页面标题、任务已创建/更新/删除等提示、删除确认
- 「待办」14 处：弹窗标题「新建待办/编辑待办」、表单标签「待办标题/待办描述」、
  占位符、校验消息、主按钮「新建待办」、权限说明 6 段全用「待办」

更关键的是：**「待办」已被项目管理模块占用，指另一套独立概念**——
项目待办任务（编号 TOD-项目号-序号，TodoTaskTab / TodoModal / TodoDetailPage，
带提案与交流关联）。任务中心若也叫「待办」，用户无法分辨两处「待办」是否为同一事物。

**统一结论（用户已确认）**：任务中心统一为「任务」。理由：
1. 页面名与侧边栏已是「任务中心」
2. 代码标识符全为 Task*（Task / TaskStatus / TaskPriority / TaskModal / listTasks / createTask）
3. 「待办」在项目模块已有明确所指，避免跨模块同名混淆
4. STATUS_MAP 中 todo → '待办' 为**状态标签**（待办/进行中/已完成/已取消），
   与名词无关，保留不动

#### 三、顺带修复：前端构建阻塞

执行 `npx tsc -b --force` 时发现既有错误阻塞 `npm run build`
（构建脚本为 `tsc -b && vite build`）：

- 问题：MemberDirectory.tsx 第 44 行向 `ListParams` 传入 `search: searchText || undefined`
  与 `role: undefined`，在 `exactOptionalPropertyTypes: true` 下报错 TS2379
  （可选属性不允许显式赋 undefined）
- 解决：改为条件式构建参数对象，与 TaskManagement.tsx 中 fetchTasks 的既有写法一致：

```tsx
const params: ListParams = { page, page_size: pageSize };
if (searchText) params.search = searchText;
if (roleFilter !== 'all') params.role = roleFilter;
const res = await listUsers(params);
```

同时在类型导入中补充 `ListParams`。
