## 开发内容详述

### 高危修复（4）
1. **P1**：`get_memory_info()` 引用未定义 `config`，NameError 被吞——「缓存齐了不警告」从未生效，是用户反复反馈误报的根因。签名加可选 `db`，容器内实测警告逻辑恢复正常。
2. **P5**：Celery beat 自热备因 `asyncio.run` 事件循环即开即关，后台加载任务被取消。抽出可等待的 `_prepare_asr_loaded()`，实测 celery 进程 2.3s 完成模型加载。
3. **M1**：结束会议时 WS 转录线程与 Celery 整表重写竞态。WS 'end' 分支 join 全部在途线程（timeout 30s），前端加 500ms 缓冲。容器内 websocket 端到端实测通过。
4. **M2**：卸载页面时 pause 因 React cleanup 逆序 + WS close 时序永远发不出。改为同步直接发送。

### 中危修复（11）
- **P3** asr_loaded 语义净化（缓存完整不再虚增 loaded_mb）
- **P4** 内存阈值 3000→800 MB、文案 2.1GB→0.5GB（前后端同步）
- **P6** 后台加载失败经 `load_error` 字段数秒内暴露给前端
- **P7** 模型加载期间囤积音频：时长漏计修复、回放改走逐帧 VAD、加 20MB 上限
- **P8** buffer_offset_ms 时间戳推进移到事件循环线程
- **P9** `_ws_lock` 持锁期间 await 全部移出锁外
- **M3** 音频导入：扩展名白名单 + 500MB 流式上限 + 处理中 409 + 旧文件清理（实测 400/400/409）
- **M5** 暂停/恢复统一「先 WS 后 REST」，恢复后音频不再丢失
- **M6** 录音期间 WS 片段直接并入本地列表，消除每句一次全量 GET
- **M7** 笔记保存统一走 /autosave 单路径
- **M8** 转录去重 useMemo + O(n) 相邻比较 + 判重收紧（长度比 1.15 + 前 6 字符 ≥4 同）

### 低危修复（12）
P2（轮询单请求）、P10（task 强引用）、P11（test_asr 委托统一）、P12（parse_qs）、P13（VAD 残帧缓冲）、P14（旧 warmup 配置幂等迁移）、P15（lint 三处）、M4（status_update 补 segment_count×4）、M9（会议列表分页器）、M10（改名后提示重生成纪要）、M11（分离子进程 JSON 解析倒序扫描，含数组形态）、M12（导出 audio 返回下载端点 + 文档缺纪要明确说明）

## 遇到的问题与解决

1. **M11 首版解析器自身有 bug**：只认 `{` 开头的行，而空结果 `json.dumps([])` 是合法的 `[]`——实测分离子进程输出空数组被误判失败。补上 `[` 分支后实测通过。教训：修复解析健壮性时必须覆盖"合法但空"的输出形态。
2. **前端 TS6133**：M7 移除 `updateMeetingRecord` 双路径后 import 残留导致部署构建失败——删除后重验。
3. **文件版本冲突**：MeetingRoom.tsx 两次编辑间被外部改动，按 fs 观察策略重读后重放改动。
