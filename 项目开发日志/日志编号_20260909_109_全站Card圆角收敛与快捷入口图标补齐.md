### 开发内容详述

#### 一、全站 Card 圆角收敛

上一份日志（108）提出的遗留项 1：主题中 Card.borderRadiusLG 为 18，而 UI 设计规范的 {component.card} 定义为 8px。

本次调研确认的事实（逐条查证，非推测）：

| 项 | 结论 |
|---|---|
| Card 使用规模 | 64 处，分布于 36 个文件 |
| size="small" 是否改变圆角 | **否**。查 antd 源码 node_modules/antd/es/card/style/index.js 的 genCardSizeStyle，.ant-card-small 仅设 minHeight / padding / fontSize，完全没有 borderRadius |
| 全站实际圆角 | 除登录页外全部 18px |
| 登录页为何是 8px | global.css:411 有 .login-page .ant-card 手工覆盖（历史单点补丁，说明问题早被观察到但未全局解决） |
| 手写 CSS 的取向 | 30 余个 *.module.css 清一色 --rounded-sm (8px)，零处使用 --rounded-lg (18px) |
| 同主题其他容器 | Modal.borderRadiusLG: 8、Drawer.borderRadiusLG: 0、Card.borderRadiusLG: 18 —— Card 是唯一的 18px 异类 |
| 18px 是否本身违规 | 否。规范中 {component.utility-card}（工具/配件网格卡片）定义为 rounded.lg 18px，属合法值；但工作台无工具网格页，全部为功能型页面 |

结论：这不是 64 个 Card 各自写错样式（它们一行圆角样式都没写），而是 ThemeContext 一处 token 配错，把 64 处一起带偏。改 1 行即可全部归正。

改动范围与安全性：Card.borderRadiusLG 是 **Card 组件级 token**，只作用于 Card，不影响 Button / Table / Select / Modal 等其他组件的同名 token。Card 内部所有使用 borderRadiusLG 的位置（.ant-card 容器、.ant-card-head 上两角、.ant-card-body 下两角、.ant-card-cover 顶角、.ant-card-actions 底角、.ant-card-contain-grid）会一致跟随，不会出现上角 8px 下角 18px 的半残状态。

#### 二、快捷入口标题图标补齐

首页 6 个小组件中，待办 / 日程 / 公告 / 通知 4 个的标题为「图标 + 文字」结构，统计概览无标题行，快捷入口为纯文字标题。本次为快捷入口补 AppstoreOutlined（网格/应用图标，语义贴合「快捷入口」），与其余组件写法完全一致（span 包裹 + marginRight 间距 token）。

### 遇到的问题与解决
- 问题：需要确认 size="small" 的 Card 是否也走 18px，否则收敛后仍可能残留两套圆角。
- 解决方案：直接查 antd 组件样式源码而非凭印象判断，确认 small 变体不含 borderRadius 设置，因此所有 Card 统一受 borderRadiusLG 控制。
- 遗留问题 / 待办：
  - 遗留项 2（首页小组件单行头部结构改造）经用户确认暂不实施，本轮未动 SortableWidget 及 6 个小组件的结构。
  - 遗留项 4（统计概览补标题）本轮按住未做。原因：统计概览当前是唯一完全没有标题行的组件，它直接渲染 Row/Col 四个数字小卡；要给它补标题必须为其内容包一层 Card（改变该组件 DOM 结构），属于结构性改动，与「结构改造暂不实施」相冲突。若要执行，为单文件 3 行改动，可下一轮单独处理。
  - 本轮收敛后有两处覆盖变为冗余（用户选择「只改不顺手清理」，故保留未删）：global.css:411 的 .login-page .ant-card 8px 覆盖；Home.module.css 的 .widgetBody :global(.ant-row) :global(.ant-card) 8px 覆盖。两者均无害，可在后续清理轮次一并移除。
