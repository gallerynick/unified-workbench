### 开发内容详述

#### 一、原实现的问题

MemberDirectory.tsx 原实现为：

```tsx
const res = await listUsers({ page: 1, page_size: 100 });  // 写死
```

- 后端 page_size 上限 `le=100`，前端刚好取满 → **成员超过 100 人时，第 101 人起被静默丢弃**，
  界面不报错、不显示总数、无下一页
- 搜索框与角色 Segmented 是**前端过滤**（useMemo 在已取回的 100 条上筛），
  后端 `search` 参数在该页面从未使用；一旦分页化，前端过滤会退化为「只筛当前页」
- 后端返回的 `res.data.total` 从未被渲染

#### 二、后端：role 筛选与确定性排序

`list_users` 新增 `role` 参数，沿用既有 search 的白名单思路：

```python
#: 角色筛选白名单：仅接受已知角色，未知取值一律忽略（等价于不筛选）
USER_ROLE_FILTERS: dict[str, UserRole] = {
    "admin": UserRole.ADMIN,
    "member": UserRole.MEMBER,
}
```

未知取值不报错、不按空筛选，与全站其他列表接口「无效筛选值忽略」的既有行为一致。

**排序缺陷修正**：原 `order_by(User.created_at.desc())` 在 created_at 相同的行之间
无确定顺序，同一批数据翻页时会出现「某行在第 1 页与第 2 页重复出现」，导致
全量遍历条数多于 total、且漏掉另一行。加主键兜底：

```python
query.order_by(User.created_at.desc(), User.id.desc())
```

#### 三、前端：服务端分页

- 新增 total / page / pageSize 状态，`fetchUsers` 依赖四者，筛选变化时 `setPage(1)` 归位
- 搜索与角色筛选均走后端参数；'all' 映射为不传 role
- 分页器与全站其他列表页（ServerManagement / AnnouncementManagement）同款：
  showSizeChanger + showQuickJumper + showTotal
- 每页数量选项 `[12, 24, 48]`，默认 24：卡片网格 minmax(280px,1fr)，
  选项均为 4 列的整数倍，翻页时不会留下半空行；最大 48 仍在后端 le=100 上限内
- 空态区分：有筛选条件时显示「未找到匹配的成员」，否则「暂无成员」
- 参数对象改为条件式构建（而非 `key: value || undefined`），
  因为 tsconfig 开启 `exactOptionalPropertyTypes: true`，显式赋 undefined 会报 TS2379

#### 四、分页器 CSS

新增 `.pagination`（右对齐 + 上边距），`.header` 加 `flex-wrap: wrap`
避免窄屏下标题与筛选区挤压，`.container` 补 `width: 100%`。

### 遇到的问题与解决
- 问题：created_at 相同的行翻页重复（55 条同批插入的测试用户复现）
- 解决方案：排序键追加 `User.id.desc()` 作为确定性兜底，已回归验证无重复
- 问题：tsconfig 开启 exactOptionalPropertyTypes，`search: x || undefined` 触发 TS2379
- 解决方案：改为条件式构建 ListParams 对象
- 遗留问题 / 待办：
  - 全站约 20 个列表服务同样只按 `created_at.desc()` 单键排序，存在同类翻页不确定性，
    建议后续统一追加主键兜底
  - ruff/black 在 user.py / api/users.py 上仍有 3 处**既有**告警（E501 第 111 行、
    两处 I001 导入排序），非本次改动引入，未一并处理以保持 diff 干净
