### 开发内容详述

#### 一、症状

用户反馈两个问题：

1. 收纳后点恢复按钮，面板该按按钮在哪个角出现在哪个角，现在不会
2. 面板会超出下边界；不确定其他方向是否也会越界，要求统一修复

#### 二、根因：两套问题，一处共同点

**问题 1 —— 恢复位置与按钮脱钩：**

恢复按钮只记录「左 / 右」两侧（`panelOnLeft`），点击时却只做
`setMinimized(false)`，让面板回到**上一次拖拽的 pos**（可能在上屏任意位置），
和按钮停的角毫无关系。按钮在左下、面板从右上弹出来，视觉上是断裂的。

**问题 2 —— 用固定常量当面板高度：**

上一版（日志 190）钳制下边界用的是魔法常量：

- 拖拽时 `maxY = innerHeight/z - 60`
- 恢复时 `maxY = innerHeight/z - 120`

面板真实布局高度约 175~275px（取决于是否在选择模式、选择器文本是否换行），
远大于 60 / 120。于是允许 `pos.y` 一直走到 `innerHeight/z - 60`，面板底边
**必然穿透视口下边界**。以 z=0.8、视口 900 高、面板高 200 为例：旧公式算出的
布局 maxY 是 1065，视觉底边落在 1012px —— **穿透 112px**。

这一条是日志 190 里我刻意「保持原样、不夹带改动」留下的债，本次还清。

#### 三、修复：一条边界保护链，四个入口共用

确立单一约定：**位置与尺寸一律用布局坐标；面板宽高一律用实测值，禁止常量。**

新增两个模块级助手：

- `viewportSize()`：把 `innerWidth/innerHeight` 换算为布局坐标。全文件视口读取
  收敛到这一处（grep 复核：仅剩 `viewportSize` 内部与一处注释引用原始属性）。
- `clampPos(x, y, width, height)`：上下左右四向钳制，四个方向完全对称，
  不再区分 X / Y 用不同常量。注释里写明 width/height 必须传实测值的原因。

四个可能越界的入口，全部收敛到 `clampPos`：

| 入口 | 改动 |
|------|------|
| 拖拽移动 | `startDrag` 捕获**实测布局宽高**；`onMove` 直接 `setPos(clampPos(...))` |
| 收纳→恢复 | 新增 `pendingRestore` 状态 + `useLayoutEffect`，按按钮角计算 `x/y` 后 `clampPos` 落位 |
| 面板挂载 / 首次加载 | 新增统一 `useLayoutEffect`，挂载即 `reclamp()`（覆盖 localStorage 里的历史脏数据） |
| 运行期变化 | 同一 `useLayoutEffect` 内挂 `ResizeObserver` + `resize` + `zoom-changed`，任何变化都重新钳制 |

**统一边界保护的关键设计：**

- 用 `ResizeObserver` 观察面板自身，而不是靠枚举内容状态。面板高度会随
  「选择元素」按钮 → 标签行 → 选择器文本框 → 三个操作按钮的切换而变化，
  枚举必漏。`ResizeObserver` 只响应尺寸变化、不响应位置变化，因此
  `setPos` 引起的位移不会触发回环。
- `rAF` 合并 + `posRef` 读最新位置：监听器只在 `enabled/minimized` 变化时
  重建一次，不随每次 `setPos` 反复订阅。
- 用 `useLayoutEffect` 而非 `useEffect`：首次挂载在**绘制前**纠正越界位置，
  不会出现「闪一下穿到屏外再弹回来」。

**收纳→角落位的实现：**

点击恢复按钮时先把目标角记入 `pendingRestore`（`'left' | 'right'`）再
`setMinimized(false)`。落位推迟到 `useLayoutEffect`：因为收纳状态下面板未挂载、
`containerRef` 为空，量不到真实高度；而 layout effect 在绘制前执行，两阶段
合并对外只有一帧，用户看不到中间态。

角落位的稳定性：左角落位后 `pos.x = EDGE`，面板中心落在左半屏，重新收纳时
按钮仍停左下；右角同理。收纳→恢复→再收纳是**可逆且稳定**的。

#### 四、刻意不改之处

- **不改 CSS**：`.container` 的 `right/bottom: 16px` 与 `.highlight` 的
  `position: fixed` 本就是 CSS 长度，浏览器自动换算，无需干预。
- **不改 `usePageZoom`**：日志 190 已确认它是正确上游。
- **不迁移 `STORAGE_KEY`**：历史脏位置由挂载时的 `reclamp()` 兜住，无需清库；
  迁移等于让所有用户丢位置，代价更高。

`viewportSize` / `clampPos` / 角落位逻辑，穷举 zoom × 视口 × 目标位置组合。

| 场景 | 结果 |

### 遇到的问题与解决
- 问题：收纳状态下面板未挂载，量不到真实高度，无法直接算角落位
  解决方案：引入 `pendingRestore` 意图状态，落位推迟到 `useLayoutEffect`；
  layout effect 绘制前执行，两阶段对外合并为一帧，无中间态闪烁
- 问题：上一版遗留 `-60` / `-120` 魔法常量（日志 190 为保持最小改动刻意未动）
  解决方案：本次按要求统一修复，四个方向全部改用实测布局尺寸；常量仅剩
  `PANEL_HEIGHT_FALLBACK = 240`，且仅用于首次测量未完成即起拖的极端路径，
  随后会被 `reclamp()` 纠正
- 遗留问题 / 待办：
  - 缩放比例在「已锁定某元素之后」变化，`picked.rect` 不自动刷新（日志 190
    已记，本次未处理）
  - 本机无浏览器，缩放/边界行为均为数值推演，需人工实测确认
