### 开发内容详述

#### 1. 问题背景
- 本机 `/usr/local/bin/docker`、`/usr/local/bin/docker-compose` 是指向 `/Applications/OrbStack.app`（未安装）的死符号链接，导致任何脚本直接调用 `docker` 都报 "No such file or directory"；
- 原 `start.sh` / `stop.sh` / `reset.sh` 及对应 .bat 全部硬依赖 PATH 上的 `docker`，换一台环境（未把 docker 加入 PATH、或同样存在死链）就会失败。

#### 2. 共享探测库 docker-detect.sh（macOS/Linux）
- 探测顺序：PATH 上的 docker → 常见安装路径（Docker Desktop：`/Applications/Docker.app/Contents/Resources/bin/docker`；OrbStack：`/Applications/OrbStack.app/Contents/MacOS/xbin/docker`；Homebrew：`/opt/homebrew/bin/docker`、`/usr/local/bin/docker`；Linux：`/usr/bin/docker`、`/snap/bin/docker` 等）；
- 用 `docker version`（不需要 daemon 运行）校验二进制可用，并显式跳过**死符号链接**（`[ -L bin ] && [ ! -e bin ]`）；
- 区分两类错误：未找到 docker（指引安装 Docker Desktop/OrbStack/Docker Engine）vs daemon 未运行（指引先启动）；
- 提供 `dw()`（等价 docker）与 `dw_compose()`（等价 docker compose，插件不可用时自动回退独立 `docker-compose`）。

#### 3. 共享探测 docker-detect.bat（Windows）
- 探测顺序：PATH 上的 docker → `%ProgramFiles%\Docker\Docker\resources\bin\docker.exe` → `%ProgramFiles(x86)%\...`；
- 不用 setlocal，`DOCKER_BIN` 变量回传到调用方；三个 .bat 脚本通过 `call` 引入。

#### 4. 各脚本改造
- start：探测 docker → 校验 compose → 校验 daemon → 注入 HOST_IP → 复制 .env → up -d --build；
- stop：未检测到 docker 时友好提示并正常退出；daemon 未运行时降级为警告继续；
- reset：要求 docker 在场，其余逻辑不变；`xargs` 管道改用 `$DOCKER_BIN` 直调。

### 遇到的问题与解决
- **JS 模板字符串转义**：写入含 `${...}`/bash 语法的脚本时，模板字面量的 `${}` 会被 JS 当作插值，需转义 `\${}` 后写入；
- **沙箱只读 / buildx 写 home 目录**：本机验证部署时以 `DOCKER_CONFIG` 重定向到工作区 + 软链 compose/buildx 插件，仅 workspace-write 即可完成，无额外审批。
