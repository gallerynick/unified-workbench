## 三、开发内容详述

### 3.1 数据模型

**`note_folder` 表**

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | |
| `name` | varchar(100) | NOT NULL | |
| `description` | text | NULL | 文件夹只允许简介，不写正文 |
| `sort_order` | integer | NOT NULL，默认 0 | 服务端原样保存前端提交的排序值 |
| `owner_id` | uuid | FK user.id，有索引 | |
| `visibility` | varchar(20) | NOT NULL，server_default `'private'` | 复用全局可见性三态 |
| `restricted_users` | jsonb | server_default `'[]'` | |
| `created_at` / `updated_at` | timestamptz | server_default now() | |

**`note_folder_membership` 表**：复合主键 `(note_id, folder_id)`，两端外键 `ondelete="CASCADE"`，`folder_id` 有索引。复合主键天然去重，无需额外唯一约束。

**`note` 表变更**：删除 `parent_id`（含自引用外键 `fk_note_parent`）与 `category` 两列，不保留兼容。`Note.folders` 声明为 `secondary="note_folder_membership", viewonly=True, lazy="selectin"`。

**与计划的偏离（2 处）**：

1. 计划 §3.1 只写了文件夹 `visibility` 一列；实际补了 `restricted_users`，否则 `check_visibility` 无法复用为通用过滤器，且受限制可见性的文件夹会缺列报错
2. 计划 §3.1 描述为「独立 id + 唯一约束」，实际实现为复合主键，语义等价且少一列

### 3.2 API（挂载在 `api_router` 的 `/notes` 下）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/notes/folders` | 列表 + 可见笔记数 |
| POST | `/notes/folders` | 新建 |
| PATCH | `/notes/folders/{folder_id}` | 改名/简介/排序 |
| DELETE | `/notes/folders/{folder_id}` | 删文件夹，关联清除，笔记保留 |
| GET | `/notes/{note_id}/folders` | 查询笔记所属文件夹 |
| PUT | `/notes/{note_id}/folders` | 全量替换归属；空列表 = 移出全部文件夹 |

**路由顺序**：字面量路径 `/folders`、`/folders/{folder_id}` 必须声明在 `/{note_id}` 之前，否则被路径参数吞掉。已在 `api/notes.py` 中显式分组并加注释。

**统一响应**：全部返回 `UnifiedResponse[T]`（`{code, msg, data}`）。

**权限**：文件夹的可见性过滤与笔记一致（`check_visibility`）；写操作走 `_require_manage_permission`。

### 3.3 服务层要点

- `set_note_folders`：入参 folder_ids 逐个校验可见性与可管理权限，任一不合法抛 400「文件夹不存在或无权访问」；用 `dict.fromkeys` 按出现顺序去重；先 `delete` 旧关联再逐条 `add`
- `delete_note`：显式 `DELETE FROM note_folder_membership WHERE note_id = :id`，不依赖 ORM cascade
- `list_notes`：`folder_id` 过滤用 `Note.id.in_(select(NoteFolderMembership.note_id))`；文件夹搜索用 `exists()` 子查询（`NoteFolder.name.ilike` OR `description.ilike`），不用 join 以免放大 count 与产生重复行
- 默认排序 `is_pinned DESC, updated_at DESC`，不再区分根笔记

### 3.4 异步会话两个坑（实测踩到）

**坑一：`Session.refresh()` 不加载关系。** 直接读 `note.folders` 触发惰性加载，在 async 会话中报 `MissingGreenlet`。改用重新 `select`。

**坑二：身份映射缓存返回旧关系。** 普通 `select(Note)` 在实例已在会话中时直接返回旧对象，**不会重新执行 selectin 加载**，导致 `folders` 仍是替换前的空列表（测试实锤：PUT 后回显 `folders: []`）。必须加 `.execution_options(populate_existing=True)`。

`services/note.py` 的 `_reload_note` 与 `services/note_folder.py` 的 `set_note_folders` 均已加该选项并留注释。

### 3.5 迁移双通道

线上库未初始化 `alembic_version`，实际生效的是 `app/startup_migrate.py` 的幂等 SQL（`Dockerfile` CMD 先跑它再启动 uvicorn）。因此 051 同时写入 `alembic/versions/051_add_note_folder.py`（可审阅、可回滚）与 `startup_migrate.py`（实际执行）：

```sql
CREATE INDEX IF NOT EXISTS ix_note_folder_owner_id ON note_folder (owner_id);
CREATE INDEX IF NOT EXISTS ix_note_folder_membership_folder_id ON note_folder_membership (folder_id);
ALTER TABLE note DROP CONSTRAINT IF EXISTS fk_note_parent;  -- 必须先删外键再删列
ALTER TABLE note DROP COLUMN IF EXISTS parent_id;
ALTER TABLE note DROP COLUMN IF EXISTS category;
```

删除段按列是否存在分支，保证幂等。两个新表由 `Base.metadata.create_all` 创建；但 create_all 不会给已存在的表补索引，所以两个索引必须在此显式补建。

### 3.6 图谱载荷

`note_link.get_graph` 原来读 `note.category`，删列后会 `AttributeError`。改为附带 `folders`（该笔记所属文件夹名，已排序）与 `tags`，为阶段五「按文件夹/标签着色 + 图例」预留。

## 四、遇到的问题与解决

### 4.1 本地无法跑 pytest

`asr_engine.py` 第 17 行硬编码 `os.environ["MODELSCOPE_CACHE"] = "/home/workbench/.modelscope"` 并立即 `os.makedirs`，macOS 下 `/home` 不可写，报 `OSError [Errno 45] Operation not supported`。改为在 backend 容器内跑测试（容器内 `/home/workbench` 真实存在）：临时建 `--system-site-packages` venv 装 `pytest / pytest-asyncio / aiosqlite / httpx`，从仓库 tar 出源码进容器执行。

### 4.2 `docker cp` 覆盖不到已有目录

`docker cp <src> container:/app/app` 返回 0 但内容未更新（层文件系统不覆盖），导致容器仍是旧代码、测试报 `note.category` AttributeError。改用 tar 中转：宿主机 `tar -czf` → `docker cp` 到 `/tmp` → 容器内 `tar -xzf`，属主为容器用户 uid 999。

### 4.3 改列被 pg_dump 的 ACCESS SHARE 锁阻塞

线上库 `note` 表上有 24 个未授权锁，`ALTER TABLE note` 静默挂起（psql 输出为空、退出码 0，极易误判为「执行成功」）。定位为周期性备份的 `pg_dump` 持有 ACCESS SHARE。先 `pg_cancel_backend` 清掉 36 个会话，再执行 ALTER；并加 `lock_timeout` 兜底。已把同样幂等的删列逻辑写入 `startup_migrate.py`，后续部署会自动生效。

### 4.4 bash 工具的单引号坑

本会话的 bash 通道对**独立使用**的单引号包裹 SQL 会静默失败（输出空、退出码 0），双引号包裹则正常。已统一改用双引号。
