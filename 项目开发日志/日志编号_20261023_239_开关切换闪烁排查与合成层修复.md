### 关联基定
- 用户反馈：切换开关时「侧栏显示项」区块闪烁

### 开发目标
1. 排查开关切换引起的重绘/重栅格化可能路径
2. 消除开关上的合成层诱因

### 涉及模块 / 文件
- 修改文件：项目文件/frontend/src/components/AppSwitch/AppSwitch.module.css

### 排查过程

1. **页面状态变化路径**：用户个性化页的开关只改本地 state（`setLocalAutoCollapse`），不触发保存、不广播全局事件，保存才 dispatch。因此不是数据刷新导致的重挂载。
2. **路由过渡动画**：MainLayout 的 `.transitionWrapper` 带 `animation: routeFadeIn 300ms` + `will-change: transform, opacity`，但它以 `key={location.pathname}` 包裹，路由不变就不会重播；同时它是整页淡入，不是单块。
3. **侧栏飞入动画**：`.sidebar-entered:not(.sidebar-entry-done) .ant-menu-item` 有 300ms 飞入，且由 `sidebar-entry-done` 一次性兜住，`sidebarEntered` 只在挂载时置位，不会因开关切换重播。
4. **开关自身的合成层**：原实现 `.switch:hover { filter: brightness(0.96) }`。`filter` 会强制元素单独成层；其祖先（路由容器）已有 `will-change: transform, opacity`，两层叠加时浏览器可能整层重栅格化，表现为大面积闪烁。

### 修复

- 移除 `.switch:hover` 的 `filter`，改为底色微调（`--divider-soft`）；开启态悬停维持 `--switch-track-on`；禁用态 `:hover` 复位为 `--switch-track-off`
- 给 `.switch` 加 `contain: paint`，把开关自身的绘制隔离在本元素内，避免向上层传播重绘

### 测试情况
- 测试方式：tsc -b → start.sh 重建部署 → 产物核对
- 测试结果：通过（产物中开关规则含 `contain:paint`，`:hover` 已无 `brightness`）
- 未覆盖：真实页面复现（缺登录凭据）；需用户确认闪烁是否消失

### 用户确认（2026-10-23 10:36）

用户实测反馈：**开关切换闪烁已消失**。据此确认根因就是合成层叠加——

- 开关上的 `filter: brightness(0.96)` 使其强制单独成层
- 祖先 `.transitionWrapper` 带 `will-change: transform, opacity`
- 两者叠加时浏览器对整层重栅格化，表现为「侧栏显示项」等区块的闪烁

修复手段（移除 hover 的 filter 改用底色、给 .switch 加 contain: paint）有效，结案。
