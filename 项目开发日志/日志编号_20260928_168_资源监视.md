### 开发内容详述

**后端**

- `metrics.py` 全部为纯函数且不 import psutil，使压力规则、cgroup 解析、降采样等可在无采集依赖环境下完整验证。等级阈值硬编码为 `<60 正常 / 60–80 偏高 / 80–95 紧张 / >95 过载`，成因阈值为 60。
- 压力指数取四个维度的最大值：CPU 取 `max(total, iowait)`（等待 IO 同样占用算力）、内存取 `(total - available) / total`（用 available 而非 free，因为 cache 可回收）、负载取 `load1 / cores`、交换仅在 `swap_total > 0` 时参与。容器 CPU 节流次数不计入指数，只作为提示。
- `sampler.py` 用 `asyncio.to_thread` 在后台线程采样，避免阻塞事件循环；`deque(maxlen=600)` 存 10 分钟历史，**不写数据库**（避免与「审计日志只增不改不删」的语义混淆）。
- 容器检测读 `/sys/fs/cgroup` 与 `/proc/self/cgroup`；cgroup v2 优先读 `cpu.max` / `cpu.stat` / `memory.max` / `memory.current` / `memory.events`，v1 回退，均为非 root 可读。
- 累计计数器（磁盘、网络）首次采样无基准时返回 0，且检测到计数器回退（容器重启）时返回 0，不产出负速率。
- `GET /system/monitor` 复用 `HTTPBearer(auto_error=False)` + `require_admin`，`minutes` 约束 `ge=1, le=10`、`processes` 约束 `ge=1, le=50`；路由不带尾斜杠，与 `/system/status` 同风格。

**前端**

- 拆成外壳 `ResourceMonitor`（fetch + 权限门禁 + 轮询）与内容 `MonitorContent`（memo 计算 + 渲染），避免早返回之后调用 `useMemo` 造成 Hooks 顺序违规。
- 轮询 2s；标签页不可见时暂停；手动刷新按钮复用 `resource-monitor-refresh` 事件。
- CPU 总量用环形图按 使用者/系统/I/O 等待/虚拟化/闲置 五段拆分；扇区数少于 2 时改用原生 `<circle>` 绘制 360° 弧（recharts 无法画满圆）。每核心占用以条状栅格逐行列出，`repeat(auto-fill, minmax(280px, 1fr))`，**不按核心数做任何分支**。
- 图表颜色集中在 `useChartColors.ts`：recharts 把 `fill`/`stroke` 输出为 SVG presentation attribute，无法解析 `var(...)`，故必须在运行时解析为具体值；token 来源表 `COLOR_SOURCES` 只允许 token.css 中已存在的变量名。此做法沿用 `notes/GraphView.tsx` 的既有范式。
- 已知边界在 UI 中显式声明：内核限制导致非 root 无法读取进程级磁盘 IO；进程列表仅为后端容器自身进程；macOS/Windows 的 Docker Desktop 场景下读到的「运行环境」是 Docker VM。容器配额未设置时显示「未设配额」并以提示指出在 `docker-compose.yml` 补充 `deploy.resources.limits`。

**规格记录的三个取舍**

1. 卡片圆角采用 `--card-rounded`（8px）而非 UI 规范文档中的 18px 数值——以现存实现为准。
2. 图表颜色由共享 hook 从 token 运行时解析，未改动 `FormResponses.tsx` 中既有的硬编码 `CHART_COLORS`（避免波及无关模块）。

### 遇到的问题与解决

- 问题：`exactOptionalPropertyTypes: true` 下 Vite 的 `CSSModuleClasses` 索引签名使每个 `styles.x` 为 `string | undefined`，`<Title className={styles.title}>` 等 8 处报 TS2375。
- 解决方案：按项目既有约定统一改为 `styles.x ?? ''`。

- 问题：`<Area stackId={stacked ? 'total' : undefined}>` 触发 TS2375（禁止在可选属性上显式传 `undefined`）。
- 解决方案：改为条件展开 `{...(stacked ? { stackId: 'total' } : {})}`。

- 问题：recharts `Pie` 的 `startAngle`/`endAngle` 类型为 `number`，传字符串 `"90"` 报 TS2769；原生 `<circle strokeWidth="16">` 同理报 TS2769。
- 解决方案：改为数字字面量 `startAngle={90}`、`endAngle={-270}`、`strokeWidth={16}`。

- 问题：`MonitorContent` 拆分后早返回块被遗漏，出现 `MonitorData | null` 赋值错误与重复函数定义。
- 解决方案：按行切片重建文件，将 `!isAdmin()` / `loading` / `!data` 三段早返回放回外壳组件，内容组件只接收已确认非空的 `MonitorData`。

- 问题：`useChartColors.ts` 中 `isDark` 作为 `useMemo` 依赖但回调未引用，eslint 报 unnecessary dependency 与 unused disable directive。
- 解决方案：在回调中显式 `void isDark;` 并注释原因——CSS 变量随 `data-theme` 切换，`antdToken` 的更新时机不保证早于 CSS 变量生效；同时删除多余的 disable 注释。

- 问题：API 测试写成同步 `def` + `client.get(...)`，而 conftest 的 `client` fixture 是 `httpx.AsyncClient`，运行时报 coroutine 没有 status_code 属性。
- 解决方案：5 个用例改为 `async def` + `await client.get(...)`；其中把 `await client.get(...).status_code` 的断言单独拆成两行，避免 await 优先级问题。

- 问题：`npm run build` 因 `MeetingDetailPage.tsx`、`MeetingRoom.tsx`、`EventDetailPage.tsx` 中共 7 个编译错误而失败，阻塞本次功能部署。这些错误来自并行的改动，且其中 `PlayCircleOutlined` 未导入属运行时级缺陷。
- 解决方案：做最小化修复（未改动任何业务逻辑）：删除未使用的 `Dayjs` 类型导入与未使用的 `title` 解构；`setContentBody` 改为实际存在的 `setEditContentBody`；给已废弃的 `MeetingModal` 补上必需的 `existingMeetings={[]}`；补 `PlayCircleOutlined` 导入；`<Text>{todo}</Text>` 改为 `<Text>{todo.content}</Text>`（todo 结构已从字符串变为 `{content, source_quote}`）；`details.transition_days` 显式断言为 `number | string | undefined`。
- 遗留问题 / 待办：`router.py` 与 `main.py` 上仍有 4 个 ruff 报错（I001 导入排序 ×2、E501 行过长 ×2），均为改动前已存在，本次未触碰。
