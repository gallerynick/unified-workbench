### 开发内容详述

**1. 现状盘点（改动前的实测结论）**

全仓 `pauseIdleTimer` 仅 3 个调用点：

| 位置 | 触发条件 | 问题 |
|------|----------|------|
| `MainLayout.tsx` | 顶栏手动开关 | 正常 |
| `StreamStudio.tsx:207` | `useEffect(..., [])` 进入页面即暂停 | 未推流也暂停，人离开工位不锁屏 |
| `StreamWatch.tsx:56` | 同上，进入页面即暂停 | 仅观看也暂停 |

会议记录 `MeetingRoom.tsx` **完全没有**暂停逻辑（该文件中 grep 到的 5 处 `idle` 均为 `noteSaveState === 'idle'` 的误命中）。录音中一旦超时锁屏，LockGuard 会跳 `/lock`，页面卸载导致 `shouldConnect`（`isRecording || isPaused`）的实时转录 WebSocket 断开。

**2. 核心改造：单一布尔 → 原因集合**

`useIdleTimer.ts` 原实现 `let idlePaused = false`，`resumeIdleTimer()` 无条件置 `false`。现在改为：

```ts
export type IdlePauseReason = 'manual' | 'stream-studio' | 'stream-watch' | 'meeting-recording';
const pauseReasons = new Set<IdlePauseReason>();
export function pauseIdleTimer(reason: IdlePauseReason) { pauseReasons.add(reason); }
export function resumeIdleTimer(reason: IdlePauseReason) { pauseReasons.delete(reason); }
export function isIdlePaused() { return pauseReasons.size > 0; }
```

任一方恢复只移除自己的原因。`isIdlePaused()` 统一替换原先对内层变量的 3 处直接读取（`getIdleMsLeft`、`handleLock`、`resetTimer` 的暂停分支）。

**3. 手动暂停优先级最高**

`'manual'` 只允许顶栏开关自己添加与移除，任何页面的 effect 清理都不得触碰。据此不会出现「手动暂停 → 进一次直播工作室 → 出来暂停被解除」。

**4. 三处调用点收窄**

- `StreamStudio`：空依赖 → `[isStreaming]`，仅在推流中暂停
- `StreamWatch`：空依赖 → `[status]`，仅在 `status === 'playing'` 时暂停
- `MeetingRoom`：新增，依赖 `[isRecording]`。**只认 `recording`，不含 `paused`**——用户主动暂停录音期间可能已离开工位，应正常锁定

**5. 顺带修复：setState 更新函数内的副作用**

`MainLayout.toggleIdlePause` 原先把 `pauseIdleTimer()` / `resumeIdleTimer()` 与 `sessionStorage.setItem` 写在 `setIdlePaused(prev => ...)` 的更新函数里。React 在 StrictMode 下会重复调用更新函数，副作用会执行两次。改为在更新函数外先算 `next`，再执行副作用与 `setIdlePaused(next)`，依赖数组补 `[idlePaused]`。

**6. 顺带修复：双向对齐，消除反向不一致**

`MainLayout` 的初始化原先只在 `stored === 'true'` 时调 `pauseIdleTimer`，否则什么都不做。由于模块级集合存活于整个单页应用期间，若 `sessionStorage` 被清空而集合仍残留 `'manual'`，会出现「顶栏显示未暂停、实际永不锁定」的安全洞。现改为双向对齐：`stored` 为真则加、为假则显式 `resumeIdleTimer('manual')`。

已核实当前唯一的 `sessionStorage.clear()`（`DataManagement.tsx:390`）后面紧跟 `window.location.href = '/login'` 整页重载，该洞目前不可达；此改动是把不变式就近固化，不再依赖远处调用点。
