### 开发内容详述

#### 1. 后端导出服务（project_export.py）
- **权限**：导出入口 `export_project` 复用 `require_project_member`（项目成员 / 负责人 / 管理员可导出，非成员 403/404），与项目各分区查看权限一致。
- **数据收集**：`_collect_export_data` 一次性查询项目基本信息 + 六张子表（成员/提案/待办/会议/修改/事件），并对所有涉及用户（负责人、成员、提案创建人/执行人、待办指派人/创建人、事件操作人）批量加载 `User` 生成 `user_id → 昵称/用户名` 映射，导出时展示可读姓名。
- **Word 生成**（`_build_docx`）：python-docx 构建，默认中文字体（微软雅黑 + eastAsia 设置），标题 + 七个章节，各分区用表格呈现，提案描述/拒绝理由以段落补充。状态、类型枚举映射为中文（如 `draft→草稿`、`feature→功能需求`）。
- **Excel 生成**（`_build_xlsx`）：openpyxl 构建，7 个工作表（项目信息 / 项目人员 / 项目提案 / 待办任务 / 交流记录 / 修改记录 / 项目事件），表头加粗、列宽自适应、冻结首行。
- **对外入口**：`export_project(db, project_id, current_user, fmt)` 返回 `(BytesIO, 文件名, content_type)`，文件名形如 `{项目标题}_{项目编号}.docx/.xlsx`。

#### 2. 后端 API 端点（projects.py）
- 新增 `GET /projects/{project_id}/export?format=docx|xlsx`，`format` 用 `Query(pattern="^(docx|xlsx)$")` 约束。
- 返回 `Response`（二进制内容），Content-Type 按格式设置；`Content-Disposition` 遵循 RFC 5987：`filename*` 携带 UTF-8 编码的中文文件名，`filename` 提供 ASCII fallback。
- 路由顺序：`/{project_id}/export` 为两段路径，与单段 `/{project_id}` 无冲突（FastAPI 按路径结构匹配）。

#### 3. 前端
- **API 封装**（projects.ts）：`exportProjectFile(id, fmt)` 使用原生 fetch（带 Bearer token）获取文件流 blob，因导出返回二进制不走 `request` 的 JSON 解析；从 `Content-Disposition` 解析文件名（优先 RFC 5987 `filename*`，回退 ASCII `filename`），`createObjectURL` + 临时 `<a>` 触发浏览器下载。
- **导出按钮**（ProjectDetailPage.tsx）：原占位按钮改为 AntD `Dropdown` 下拉菜单，两项「导出 Word 文档」（FileWordOutlined）/「导出 Excel 表格」（FileExcelOutlined），点击调用 `handleExport` 并反馈成功/失败消息。图标全部来自 @ant-design/icons（无 Emoji）。

### 遇到的问题与解决
- 问题 1：`_load_users` 初版缺少 `await db.execute`，会触发 SQLAlchemy async 惰性执行错误。
  - 解决方案：改为 `async def` 并 `await`；同步修正 `_collect_export_data` 中的调用处。
- 问题 2：`Content-Disposition` f-string 内嵌套双引号导致 SyntaxError；修复后又出现 ruff E501 超长（107 字符）。
  - 解决方案：f-string 内引号转义为 \"，并将头部构造改为多行括号连接满足 100 字符限制。
- 问题 3：前端 tsc 报正则捕获组索引类型 `string | undefined`（noUncheckedIndexedAccess）。
  - 解决方案：对 `star[1]` / `plain[1]` 增加非空判断。
- 问题 4：系统 `python3`（3.9）py_compile 写入缓存目录被拒（PermissionError）。
  - 解决方案：使用项目自带 `.venv/bin/python` 编译与导入检查（与日志 024 已知做法一致）。
- 问题 5：部署时 docker buildx 写入 `~/.docker` 被沙箱拦截（workspace-write 不够）。
  - 解决方案：以 `danger-full-access` 重试 `./start.sh` 部署。
- 问题 6：首次部署后后端容器循环重启，日志报 `PermissionError: /app/app/services/project_export.py`。
  - 原因：沙箱创建的新文件权限为 `600`，而容器以非 root 的 `workbench` 用户运行，COPY 后无法读取。
  - 解决方案：`chmod 644` 该文件后重新部署，容器恢复 healthy。
- 问题 7：冒烟测试发现 xlsx 请求返回的却是 docx 内容（大小与 Content-Type 均与 docx 一致）。
  - 原因：后端端点参数名为 `fmt`，而前端与测试传的是 `format`，FastAPI 未匹配查询参数，始终走默认 docx。
  - 解决方案：将端点参数统一改为 `format`（与前端一致），重新部署后回归验证 docx/xlsx 均正确返回。
- 遗留问题：PDF 格式因 `weasyprint` 未安装暂未纳入（基定技术栈列有 WeasyPrint 但当前依赖不含）；如需可后续新增依赖实现。
