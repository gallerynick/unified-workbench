### 开发内容详述
1. **`Project` 模型扩展**：保留全部现有字段不动，新增：
   - `number`：项目编号，`String(50)`，可空默认 None（与现有 `project_id` 写法一致，避免存量数据迁移失败）
   - `member_permissions`：成员权限配置，`JSONB`，默认 `{}`
2. **新建 7 张表**，全部遵循既有代码风格（`Mapped`/`mapped_column`、`from __future__ import annotations`、UUID 主键、`DateTime(timezone=True)` + `server_default=func.now()`、中文 `comment`）：
   - `project_member`：成员，`UniqueConstraint(project_id, user_id)`，`project_id`/`user_id` 外键 CASCADE，`is_owner`/`is_active` 布尔，`joined_at`/`left_at` 可空
   - `project_proposal`：提案，`project_id` CASCADE，`type` 默认 `feature`，`priority` 默认 `P2`，`status` 默认 `pending`，`attachment_links` JSONB 默认列表，`creator_id` 外键 CASCADE、`assignee_id` 可空外键 SET NULL
   - `project_meeting`：会议，`started_at` 必填带时区，`speaker` 可空，`participants`/`notes` JSONB 默认列表
   - `project_change`：变更，`category_major` 必填、`category_minor`/`category_detail` 可空，`status` 默认 `pending`
   - `project_todo`：待办，`priority` 默认 `P2`，`status` 默认 `pending`，`assignee_id` 可空外键 SET NULL，`creator_id` CASCADE，`proposal_id` 外键 SET NULL（删除提案不删待办），`due_date` 可空
   - `project_event`：事件，`details` JSONB 默认 `{}`，`operator_id` 外键 CASCADE，仅 `created_at`（事件表只增不改）
   - `link_relation`：通用关联，`source_type`/`source_id`/`target_type`/`target_id`，无外键，仅 `created_at`
3. **关系定义**：按既有模式（如 `Project.owner`）为各模型添加了 `lazy="selectin"` 的单向关系（`user`/`creator`/`assignee`/`operator`/`project`/`proposal`），`proposal`/`todo` 中同表多外键的 User 关系用 `foreign_keys=[...]` 显式指定
4. **`__init__.py`**：按字母序插入 7 个新模型的导入与 `__all__` 条目

### 遇到的问题与解决
- 问题：本机无 `python` 命令，仅 `python3`；SQLAlchemy 全局为 2.0.48 可直接用
- 解决方案：改用 `python3`，导入验证使用项目自带 `.venv/bin/python`（依赖完整）
