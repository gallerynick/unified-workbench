### 开发内容详述

**1. 声明的现象**
- 某测试会议转录 4 段：空洞句（"对的现在对于我们这个来讲说的是。"）、单标点 "."、语气词 "Yeah."、
  以及可读句"这个会议的主题是测试。"。
- v3 输出：summary=「本次会议内容较少，无实质性讨论」，完全吞掉了主题句。

**2. 根因**
- v3 规则 5 让模型在「内容短」时一律走模板；模型面对「短内容 + summary 需 200-500 字」的两难，直接逃到兜底文案。
- key_points 下限 3 条对短会议不可达，模型索性全空，进一步强化「无内容」观感。

**3. v4 修复（确定性代码 + prompt 双层）**
- 新增 `_is_substantive()`：过滤纯净标点 / 单字符 / 纯语气词（嗯/呃/好的/yeah 等）的噪声片段。
  有任一可读句就进入 LLM；全部无实质则不调模型、直接返回确定性兜底（零成本、永不空屏）。
- `generate_minutes()` 只在 substantive 片段上构建 transcript 文本。
- prompt v4：
  - 规则 2：key_points 内容极少时至少 1 条，宁缺毋滥；明确点明会议主题的句子必须作为第一条要点。
  - 规则 5：只要存在可读内容，summary 必须如实概括事实，明确禁止「本次会议内容较少，无实质性讨论」模板；
    内容少时 summary 可 20-50 字。
  - 新增短会议示例：转录「这个会议的主题是测试。」→ 输出点明主题 + 1 条 key_point。
- `_STRIP_CHARS` 包含 ASCII 双引号时曾引起字符串字面量断行，已转义修复。

### 遇到的问题与解决
- 问题：`_STRIP_CHARS` 字符串未转义内部双引号导致 SyntaxError。
  解决：转义为 \" 后 py_compile 通过。
- 问题：v4 首版（示例 key_points 为空）仍不提炼主题。
  解决：示例改为「点明主题 + 至少 1 条要点」并追加显式规则后，模型输出
  summary=「会议讨论了测试相关事宜，未形成其他明确结论。会议主题为测试。」，key_points=[「会议主题为测试」]。

### 测试情况
- 测试方式：py_compile；.venv 单测 `_is_substantive` 边界（纯标点/语气词→False，正常句→True）；
  宿主机 venv 直连模型真实调用（该会议 4 段原文）；bash start.sh 重建；真实会议 f442e15d 端到端重跑落库。
- 测试结果：**通过**
