### 开发内容详述

【图表方案替换：@ant-design/charts → recharts】

@ant-design/charts 2.6.7 是 G2 5.x 的上层封装，一次引入就带来 86 个包（含 @antv/g2、g-canvas、g-dom-matrix 等）。实测统计页 chunk 为 1459 KB（gzip 429 KB），远超项目 500 KB 的 chunk 告警线，也把包体积压力全部压在这一个路由上。

换成 recharts 3.10.1 后只增 14 个包，统计页 chunk 降到 397 KB（gzip 114 KB），缩减 73%，回到告警线以下；npm audit 从 36 个降到 30 个，G2 相关漏洞全部消失。recharts 是纯 React 声明式组件，渲染产物是 SVG，不再引入独立渲染引擎，因此与 React 18 调和流程的耦合面显著缩小——这也是本次 #426 排障的切入点。

UI 观感保持一致的处理：

1. 抽出一个共用的 ChartFrame 组件承载柱状图的通用骨架（CartesianGrid 虚线网格、X 轴标签、Y 轴整数刻度、Tooltip、柱顶数值标签、圆角柱顶、36px 柱宽）。选项字段的计数图与数字字段的分箱分布图共用同一个组件，只传 data / height / labelKey。
2. 颜色全部取自 theme.useToken() 的 token.colorBorderSecondary / colorTextSecondary / colorFillTertiary，深浅色模式自动跟随，不写死十六进制值；只有数据系列色用固定色板（SVG 表现层属性不解析 CSS 变量 var()，写 var() 会静默失效）。
3. 字段卡片、概览卡片、明细表、返回按钮、导出按钮一律未动，页面结构完全保留。

【新增占比饼图】

选项类字段（select / radio / checkbox）的统计卡片改为左右两栏：左栏「各项计数」柱状图，右栏「占比分布」环形饼图（innerRadius 52 / outerRadius 86 / paddingAngle 2）。饼图配色与柱状图共用同一条色板并按选项序号对齐，两个图看同一个选项是同一种颜色，便于对照。零回复时饼图不渲染（所有扇区为 0 的环图没有信息量），改为 dashed 边框的空状态占位「暂无数据，收到回复后展示占比」；柱状图仍完整渲染 0 值柱子，保持与既有「零值也画出来」的约定一致。

991px 以下两栏退化为单栏，沿用页面已有的响应式断点。

### 遇到的问题与解决

- 问题：统计页运行时报「Minified React error #426」，即「对象不能作为 React 子节点」。
  排查过程：先定位 React 抛错点（react/cjs/react.development.js 第 1127 行，仅在 children 既不是数组、也没有迭代器、且类型为 object 时抛出），排除自己代码——三个改写文件里所有 JSX 表达式子节点逐一核对，输出均为 string / number / 元素，未发现对象泄漏。再排查 @ant-design/charts 的错误边界：BaseChart 把 errorTemplate 透传给 ErrorBoundary，默认值 undefined 走 falsy 分支渲染 h5，本身安全。
  解决方案：无法在压缩产物中复现完整堆栈，且该库正是本轮要替换的重依赖，遂直接移除。@ant-design/charts 及其传递依赖（@ant-design/charts-util / @ant-design/plots / @antv/g2）共 86 个包已全部卸载，node_modules 中已无该错误边界文件，这条风险面随之消失。
  遗留问题 / 待办：若替换后 #426 仍复现，说明来源在前端其它位置，需在开发环境（非压缩）下取完整错误消息中的 object keys 才能精确定位。请反馈验证结果。

- 问题：recharts 3 的 Cell fill 在 noUncheckedIndexedAccess 下类型是 string | undefined，与 exactOptionalPropertyTypes 冲突报 TS2375。
  解决方案：抽出 chartColor(index) 辅助函数，用 ?? '#1677ff' 兜底返回 string。

- 问题：SVG 表现层属性（stroke / fill）不解析 CSS 自定义属性 var()，写 var(--border-primary) 会静默失效。
  解决方案：图表配色一律走 theme.useToken() 的 token 值，仅数据系列色用固定色板。

- 遗留问题 / 待办：npm audit 仍有 30 个漏洞（29 moderate / 1 high），主要为 react-router 等既有依赖，非本次引入，建议在下次版本安全体检统一处理。
