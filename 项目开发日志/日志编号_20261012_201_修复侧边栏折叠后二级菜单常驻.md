### 开发内容详述

**现象**：侧边栏折叠后，「系统设置」子菜单的二级项仍常驻显示，未随折叠收起。

**根因**（代码定位）：

1. Menu 的 `openKeys` 由 React state 受控（`MainLayout.tsx` 第 535 行 `openKeys={openKeys}`）
2. `openKeys` 的来源有两个：
   - **localStorage 持久化**（`workbench_menu_open_keys`，第 259-263 行初始化恢复）
   - **路由自动展开**（第 308-310 行：只要 `pathname.startsWith('/settings')` 就把 `/settings` 加进 openKeys）
3. **折叠（collapsed）时没有任何对 openKeys 的抑制**——`/settings` 一直留在受控 openKeys 里
4. antd 5.x 在 inline + collapsed 模式下，受控 openKeys 含子菜单 key 时，子菜单弹出层会保持打开状态 → 表现为「折叠后二级菜单常驻」

**修复**（两处）：

1. **传给 Menu 的 openKeys 在折叠时清空**：
   ```tsx
   openKeys={collapsed ? [] : openKeys}
   ```
   折叠时子菜单不再受控展开，由 antd 标准 hover 弹出接管。

2. **路由自动展开 effect 在折叠时跳过**（避免折叠状态下仍往 state 写入 `/settings`，且展开侧边栏时不突兀）：
   ```tsx
   useEffect(() => {
     if (collapsed) return;
     // ...原有逻辑
   }, [location.pathname, openKeys, collapsed]);
   ```

**影响面**：仅菜单折叠/展开行为。展开状态下 `openKeys` 行为不变（持久化 + 路由自动展开均保留）。

### 遇到的问题与解决
- 问题：需确认「常驻」是 antd 行为而非 CSS 覆盖导致。
- 解决：grep 全部前端 CSS（MainLayout.module.css 与全局样式），确认无 `inline-collapsed` 覆盖；antd 版本 ^5.22.0，符合受控 openKeys 在 collapsed 下弹出层保持打开的行为特征。据此修复 JS 层。

## 修订（同日二次提交）

**问题**：第一版用 `openKeys={collapsed ? [] : openKeys}`，折叠时受控 openKeys 恒为空数组，
antd 5 的点击/hover 弹出被受控值锁死 → 折叠状态下点「系统设置」二级菜单完全不显示。

**修正**：折叠时**完全不传 openKeys 属性**（非受控，由 antd 内部状态接管弹出）：

```tsx
<Menu
  mode="inline"
  selectedKeys={[selectedKey]}
  {...(collapsed ? {} : { openKeys })}
  ...
/>
```

展开时仍为受控 openKeys（持久化 + 路由自动展开逻辑不变）。

**实现细节**：项目开启 `exactOptionalPropertyTypes`，显式传 `undefined` 会报 TS2375，
故用条件展开对象（`{...(collapsed ? {} : { openKeys })}`）让属性在折叠时完全缺席。

**验证**：`tsc -b` exit 0；部署 50s，前端 200 / 后端 200。
