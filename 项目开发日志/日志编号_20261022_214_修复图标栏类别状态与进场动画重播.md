### 开发内容详述

**1. 图标栏不再撤销用户的类别整理**

上一轮（日志 212）为了让图标栏「不丢模块」，刻意让它忽略 collapsedGroups、显示全部可见项。
但这造成反向问题：用户先在展开态收起若干类别，再收起侧栏，那些类别又被摊开，
等于做过的整理被撤销。

修复：图标栏遵守同一份折叠状态。

```tsx
visibleCategories
  .filter((cat) => !collapsedGroups.includes(cat.key))
  .map((cat, index) => ( ... ))
```

语义变为「图标栏 = 展开态的图标版」，状态只有一份，不再出现两套视图各说各话。
需恢复某类别时展开侧栏点击类别头即可。

**2. 分隔线不再参与点击命中**

.railDivider 补 `pointer-events: none`。分隔线是纯装饰元素，
任何鼠标命中都不应落在它上面，避免「鼠标停在线上能触发收叠展开」的错觉与误触。

**3. 进场动画改为一次性，与侧栏滑动解耦**

现象：点收起 / 展开侧栏时，侧栏宽度是平滑滑动的（antd Sider 0.2s），
但里面的图标却在重新逐个飞入（300ms + 40ms 步进错峰），两种节奏互相打架。

根因：进场动画的 effect 依赖里含 `collapsed`，且 CSS 的 `menuItemFlyIn` 是
「只要节点挂载就播」。收起 / 展开会让整批菜单节点重挂载，于是每次都重播。

修复（两侧同时约束）：

- TS：effect 依赖收敛为 `[sidebarEntered]`，进场动画只在「进入工作台」时算一次延迟
- TS：动画播完的 timeout 回调里置 `entryAnimDone = true`（不在 cleanup 里置位，
  否则 StrictMode 的立即 cleanup 会提前置位、跳过进场动画）
- CSS：两条规则组都加 `:not(.sidebar-entry-done)` 约束
  - 预置态 `opacity: 0; translateX(-16px)` 在播完后失效，否则后挂载节点会一直不可见
  - 播放态 `animation` 在播完后失效，新挂载节点直接呈现最终态

结果：进场时整条侧栏连同类别头、未显示项、设置区一次性飞入；
之后收起 / 展开侧栏只剩宽度平滑过渡，不再有二次飞入。

顺带把「系统设置子项错峰」effect 加了 `entryAnimDone` 守卫——进场结束后已无动画，补延迟无意义。

### 遇到的问题与解决

- 问题：如何在不引入「永久隐藏」风险的前提下关掉后续动画。
- 处理：动画与预置态必须成对关闭。只关 animation 不关 opacity:0，会让新节点永久不可见；
  只关 opacity 不关 animation，则新节点仍会飞入。因此两条规则组统一加同一个 :not() 约束。

- 问题：StrictMode 下 effect 会「挂载→立即清理→再挂载」，若在 cleanup 里置位会误判动画已结束。
- 处理：只在 timeout 回调里置 `entryAnimDone`，cleanup 仅 clearTimeout。
