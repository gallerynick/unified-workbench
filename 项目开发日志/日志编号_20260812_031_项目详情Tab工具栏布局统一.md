### 开发目标
统一项目详情页各 Tab 顶栏的"搜索/筛选（左）+ 操作按钮（右）"布局，参考 `ProjectDocumentTab` 的 `.listToolbar` 模式：
1. 左分组：搜索 Input（variant="filled" + SearchOutlined prefix + allowClear + max-width 320px + rounded-pill）紧邻分类/筛选 Segmented 或 Select，包在 `<Space>` 内
2. 右分组：操作按钮包在 `<Space>` 内
3. 容器保持 flex + space-between + 合适下间距
4. 搜索框统一为 `prefix={<SearchOutlined style={{ color: 'var(--text-secondary)' }} />}` 的普通 Input（替代 `Input.Search`）

### 开发内容详述
1. **ProjectMemberTab**：`Segmented(当前/历史成员)` + 搜索 Input 包在左 `<Space>`；"添加成员"按钮包在右 `<Space>`；搜索框由 `Input.Search` 改为普通 `Input`（prefix 统一样式）。CSS 删除 `.toolbarActions`（含移动端规则），`.toolbar` 补 `flex-shrink: 0`，移动端 `.searchInput` 直接 100%。
2. **ProposalTab**：搜索 Input（保留 width:240 原行为，仍受 max-width:320 约束）+ 类型/优先级/状态 3 个 Select 包在左 `<Space>`；"新建提案"按钮进右 `<Space>`（原 `<div style={{flex:1}} />` 撑开写法移除）。CSS：`.header` 补 `margin-bottom: var(--spacing-card-gap)` 与 `flex-shrink: 0`（该 Tab 容器为 Fragment，无 wrapper gap）；`.searchInput` 补 `border-radius: var(--rounded-pill)` 对齐参考模式。
3. **MeetingRecordTab**：`Segmented(全部/会议纪要/沟通记录)` + 搜索 Input 包在左 `<Space>`；"新建记录"按钮进右 `<Space>`；`.listToolbar` 原本已符合参考模式（margin-bottom + flex-shrink:0），仅删除 `.listToolbarActions` 及其移动端规则，改为 `.searchInput` 直接 100%。
4. **ChangeRecordTab**：大类筛选 Select + 搜索 Input 包在左 `<Space>`；"新建记录"按钮进右 `<Space>`；搜索框改普通 Input。CSS 删除 `.headerActions`，`.header` 补 `flex-shrink: 0`（间距由 `.container` 的 gap 提供）。
5. **ProjectEventTab**：左侧统计信息（共 N 条）+ 搜索 Input 包在左 `<Space>`；"新增事件"按钮进右 `<Space>`。CSS 删除 `.toolbarActions`，`.toolbar` 补 `flex-shrink: 0`。
6. **TodoTaskTab**：左标题信息保持不变，右侧改为 `<Space>` 包裹搜索 Input + "新建待办"按钮；补 `Space` import。CSS 删除 `.toolbarActions` 及移动端规则。

关键决策：
- 全部 Tab 搜索框统一为普通 `Input` + `prefix={<SearchOutlined style={{ color: 'var(--text-secondary)' }} />}`（参考 ProjectDocumentTab），保持跨 Tab 视觉一致。
- 已有 `.toolbar`/`.header`/`.listToolbar` 类且语义相近的 Tab 优先复用并微调样式，不强制新增 `.listToolbar` 类（遵循任务说明）。
- 容器本身有 `gap: var(--spacing-card-gap)` 的 Tab（Member/Change/Event）不重复加 margin-bottom，避免间距翻倍；容器为 Fragment 的 ProposalTab 在 `.header` 上补 margin-bottom。
- 严格保留既有 `styles.xxx ?? ''` 兜底模式（本项目 CSS Modules 类型为 `string | undefined`，配合 `exactOptionalPropertyTypes` 必须保留）。

### 遇到的问题与解决
- 问题：首次改写将新 JSX 的类名写为 `styles.xxx`（去掉 `?? ''`），`npx tsc -b` 报 `Type 'string | undefined' is not assignable to type 'string'`（ChangeRecordTab Select className + 各 Tab Input className）。
  - 解决方案：确认本项目 CSS Modules 类型声明为 `string | undefined` 且 `exactOptionalPropertyTypes: true`，全部改回 `styles.xxx ?? ''`；同时 TodoTaskTab 补 `Space` import（原文件未导入）。
- 遗留问题：无。

### 测试情况
