### 开发内容详述

**一、两种触发方式**

1. URL query（可复制地址栏直接分享，刷新后仍生效）：

       https://localhost/?status_demo=all              全部 15 条
       https://localhost/?status_demo=public,db        指定条目
       https://localhost/login?status_demo=ws,lock     登录页同样生效

2. DevTools Console（演示中途实时切换，无需刷新）：

       __statusDemo('all')            全部
       __statusDemo('public,db')      逗号分隔
       __statusDemo(['ws', 'lock'])   数组
       __statusDemo(null)             关闭，回到真实探测

**二、15 个可演示条目**

- critical（红点 + 呼吸）5 条：backend 网络已断开｜maintenance 系统维护中｜db 数据服务暂时不可用｜version 版本不匹配，请刷新｜storage 文件服务暂时不可用
- critical 1 条：unsafe 非安全环境，直播等能力不可用（也是检验 240px 省略号的用例）
- warning（黄点，静止）9 条：latency 网络延迟较高｜insecure 未启用 HTTPS｜public 正在通过公网访问｜clock 本机时间不准｜browser 浏览器能力不完整｜ws 实时提醒不可用｜stream 直播服务暂时不可用｜tasks 提醒服务暂时不可用｜lock 即将自动锁定

**三、设计取舍**

1. **URL 是单一事实来源。** Console 调用只是改写 URL（history.replaceState）再广播事件，
   不存在两套状态打架；演示完关闭参数即恢复真实探测，不留残留。
2. **演示条目覆盖真实探测，而非追加。** 覆盖保证演示内容确定、可复现，
   不会被本机真实网络状态污染；真实探测仍在后台运行（定时器不拆除），
   关闭演示即回到真实结果，无需重新加载。
3. **演示 id 统一前缀 demo-，** 与真实条目 id（a1-backend、c2-db 等）不冲突，
   轮播索引与悬停列表按 id 组织的逻辑无需改动。
4. **不隐藏入口、不区分构建环境。** 这是内部工具，演示发生在部署实例上；
   入口本身就是显式的 URL 参数与 Console 调用，正常用户不会误触。
5. **用 import type 避免循环依赖。** useStatusDemo.ts 从 useStatusProbes.ts 引入类型、
   useStatusProbes.ts 从 useStatusDemo.ts 引入函数——类型导入在编译期擦除，运行时无环。

**四、接入点**

useStatusProbes 末尾：

    const merged = useMemo(() => { /* A3 / E1 合并 */ }, [...]);
    const demoIssues = useStatusDemoIssues();
    return demoIssues ?? merged;

由于 header、登录页、锁定页三处都经 useStatusProbes 取数，一处接入即三处生效。

### 遇到的问题与解决
- **问题：接入时漏加 import**
  - 先改了 useStatusProbes.ts 的三处调用点，再 grep 检查 import 段才发现缺了
    useStatusDemoIssues 的导入。
  - 解决：补上后 tsc 通过。
- **问题：循环依赖风险**
  - 两个 hook 互相引用。
  - 解决：把 useStatusDemo.ts 侧的 StatusIssue / StatusLevel 改为 import type，
    编译期擦除后运行时无环；vite build 未报循环依赖警告。
