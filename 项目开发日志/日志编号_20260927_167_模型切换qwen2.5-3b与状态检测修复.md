#### 二、模型选择后自动检测状态

**问题**：用户切换模型后，「已就绪」状态不会自动更新。

**原因**：`Select` 的 `onChange` 调用 `checkOllamaStatus()`，
但 `checkOllamaStatus` 内部读 `form.getFieldValue` 取模型名——
antd Form.Item 的 onChange 可能在表单值更新之前就触发了，导致读到旧值。

**修法**：`checkOllamaStatus` 增加 `modelOverride` 参数，
`Select` 的 `onChange` 直接传入新选中的模型名，跳过表单读取。

同时把描述文字从写死的 `PRESET_AI_MODEL.description` 改为从 `MODEL_INFO`
按选中模型动态取，切换模型后描述也会跟着变。

#### 三、修掉模型删除接口的 500 错误

**问题**：`DELETE /config/ollama/models/{name}` 返回 500。

**根因**：`_ollama_request` 里 `client.delete(url, json=data)`——
HTTPX 的 `AsyncClient.delete()` 不支持 `json` 参数，直接 TypeError。

**修法**：改用 `client.request("DELETE", url, json=data)`，
Ollama 的 DELETE 接口要求 JSON body 传模型名，不是 query string。

同时修了 Ollama DELETE 返回空响应体导致 `response.json()` 抛 JSONDecodeError 的问题。

### 遇到的问题与解决

- **问题**：Ollama 模型下载卡在 82-91%，速度 1 KB/s，所有分片反复 EOF 重试。
  - **原因**：registry.ollama.ai（Cloudflare R2）间歇性连接失败，已知问题。
  - **解决方案**：host ollama 持续重试中；同时确认 host ollama 和 Docker 容器
    通过 11434 端口共享同一个实例。
- **问题**：模型删除 500 → TypeError（HTTPX delete 不支持 json 参数）。
  - **解决方案**：改用 `client.request("DELETE", url, json=data)`。
- **问题**：模型删除 500 → JSONDecodeError（Ollama 返回空响应体）。
  - **解决方案**：`_ollama_request` 检查响应体是否为空，空则返回 `{"status": "ok"}`。
