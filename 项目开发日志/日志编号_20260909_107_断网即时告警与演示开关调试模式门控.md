### 开发内容详述

**一、断网不告警的缺陷：三个叠加成因**

| # | 成因 | 说明 |
|---|---|---|
| 1 | 只发了请求头 `no-cache`，没设 `cache` 选项 | `Cache-Control: no-cache` 作为**请求头**的语义是「重新校验」，浏览器仍可能命中磁盘缓存。而 `/api/v1/health` 后端**不带任何 Cache-Control 头**（见 app/api/health.py），断网后浏览器可能直接返回缓存副本 → 探测「成功」→ `failCount` 被清零 → A1 永远不出现 |
| 2 | A1 阈值 3 × 巡检周期 60s = 最长 3 分钟 | 即使没有缓存问题，断网后要连续 3 次巡检失败才告警。用户断开网络后等不了那么久，观感就是「没有指示」 |
| 3 | 完全没有监听 `navigator.onLine` | 浏览器在断网瞬间就知道，前端却只靠 60 秒轮询被动发现 |

**二、修复**

1. 四个探测请求全部补上 `cache: 'no-store'`（`/health`、`/health/db`、
   `/system/site-config`、`/system/status`）——这是真正绕过缓存的开关，
   与请求头是两个机制。

2. 新增 `browserOnline` 状态 + `online`/`offline` 事件监听：

       const [browserOnline, setBrowserOnline] = useState<boolean>(() =>
         typeof navigator === 'undefined' ? true : navigator.onLine,
       );

   `offline` 触发即置 false，`online` 触发即置 true 并清空 `failCountRef`
   （避免离线期积累的失败数在重连后立刻误报）。

3. A1 从「巡检后写入」改为「即时合并」。合并点改成按 id 去重的累加器：

       if (!browserOnline) {
         add({ id: 'a1-backend', level: CRITICAL, text: '网络已断开' });
       }
       probeIssues.forEach(add);

   去重是必须的——离线时巡检同样会累计出 `a1-backend`，两处会撞。
   断网瞬间指示器立即出现，不再依赖 60 秒轮询。

4. 巡检逻辑保持原样作为兜底：网络在线但后端不可达（例如后端重启）时，
   仍走连续 3 次失败阈值，避免瞬时抖动误报。

**三、演示开关接入调试模式**

`useStatusDemoIssues()` 新增 `debug` 状态，启动时 `await isDebugModeEnabled()`，
未开启时 `useMemo` 直接返回 null，演示条目一律不产出：

       return useMemo(() => {
         if (!debug || keys.length === 0) return null;
         ...
       }, [debug, keys]);

`setStatusDemo()` 保留同步写入 URL 与打印结果，另起异步校验，
调试模式未开启时 `console.warn` 明确指出「不会显示」及开启路径，
避免使用者对着空白界面困惑。

调试模式开关本身是项目既有能力（站点设置里的 `debug_mode`，
读自后端 site-config，带模块级缓存），本次只是复用它作为前置条件，未新增配置项。

### 遇到的问题与解决
- **问题：`grep -c -F "'online}'` 匹配 0，误判监听器未生效**
  - 压缩器把字符串字面量统一转成双引号，源码里的单引号形式在产物中不存在。
  - 解决：改用双引号形式复核，`"online"` 与 `"offline"` 各命中 2 处
    （`addEventListener` 与 `removeEventListener` 各一）。
- **问题：`Promise.all` 并发编辑同一文件时，一处 old_string 不匹配导致后续编辑全部跳过**
  - 原因是把日志里的措辞「（定时器不拆除）」当成了源码内容。
  - 解决：改成顺序编辑，并在编辑前以 `read` 核对实际文本。
- **问题：`run_code` 里用模板字符串承载含反引号的 markdown 会触发解析异常**
  - 用 `\|` 转义或 `` 占位符后再 `replaceAll` 处理，可稳定通过。
  - 已在演示开关说明文档与本文档中使用该方法。
