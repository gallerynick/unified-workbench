### 开发内容详述

**1. 问题诊断**

上一版是「内缩发丝线 + 类别名 + 悬停箭头」：整行是一条横线，文字压在线下方的行里。
两个毛病：

- **笨重**：横线本身承担分隔职责，5 条线横切侧栏，形成 5 个「段落感」；行高 + 线宽叠加后视觉重量集中
- **易混淆**：底部「模块 / 设置」那条也是横线，两者只差颜色深浅（#f0f0f0 vs #d9d9d9）。同一形态、只差明度，人眼几乎必然把它们读成同一类元件

**结论：仅靠「深浅」区分同形态的两条线是不成立的，必须换形态。**

**2. 新形态：类别名 + 右侧延伸细线**

```
协作办公 ─────────────────────
```

- 不再有独立于文字的横线；线从类别名之后开始，向右延伸到右内边距
- 读作「带文字的标题」而非「结构分隔线」
- DOM 增加 `<span class={categoryRule} />`（`flex: 1`、`height: 1px`、`--divider-soft`）

**3. 两类线的区分口径（性质不同，不只是颜色不同）**

| | 类别标记 | 模块/设置分隔线 |
|---|---|---|
| 文字 | **有**（类别名） | 无 |
| 起止 | 从文字之后起，右侧留 16px | **通栏**（margin 0） |
| 颜色 | `--divider-soft` #f0f0f0 | `--border-primary` #d9d9d9 |
| 语义 | 分组标题 | 结构分隔 |

底部线同时把 `margin` 从 `8px 16px` 改为 `10px 0`（通栏），进一步加强「结构级」观感。

**4. 尺寸与状态细节**

- 行内布局改为 flex：`label`（`flex: none`）+ `caret` + `rule`（`flex: 1`）
- 内边距 `8px 16px 2px`，无固定高度——由字号决定，不再是一个「条」
- 箭头 `font-size` 9→8px，`flex: none`；**opacity 为 0 时仍占位**，所以悬停显隐不会导致细线左右跳动
- 收起态仍强制显示箭头（`categoryCaretShown`），保留折叠状态可读性

**5. 清理死配置**

迭代过程中新增的两个 token 最终没有任何引用，一并删除：

- `--sider-category-divider`（原内缩线的颜色/线宽）
- `--sider-section-divider`（原计划给底部线用，最终直接引用 `--border-primary`）

另删除已失效的 `.categorySection:first-child .categoryHeader::before` 规则（伪元素线已不存在）。
保留 `--sider-category-label` / `--sider-category-label-size`（仍在使用）。

### 遇到的问题与解决

- 问题：底部线与类别线同形态，仅深浅不同，用户明确反馈「混淆」。
- 解决方案：放弃「同形态不同深浅」的思路，改为**有文字 / 无文字**、**起止位置不同**、**通栏 / 内缩**三重区分。形态差异比明度差异更可靠。

- 问题：箭头用 opacity 0 隐藏，担心悬停时出现导致右侧细线位置跳动。
- 核实：`opacity` 不参与布局，且已设 `flex: none`，箭头始终占位，细线起点稳定，无跳动。

- 遗留：`--sider-menu-item-height` 同样是无人引用的既有 token（行高实际由 ConfigProvider 的 `itemHeight` 控制）。非本次引入，未动。
