## 三、开发内容详述

### 3.1 阶段二：侧栏重写

**顶部工具条**：4 个 icon-only 按钮（24px，全部带 Tooltip），左到右为 搜索 / 展开收起全部 / 排序 / 新建文件夹。搜索按钮在搜索打开时为 `type="primary"`，作为视觉锚点。

**搜索**：点击搜索按钮后工具条下方出现搜索输入框（`autoFocus`、`variant="filled"`、`allowClear`），列表区切换为搜索结果。300ms 防抖，走后端 `GET /notes?search=`，命中范围已含标题、正文、标签、文件夹名与简介（阶段一实现）。结果区保留笔记行的置顶标记与右键菜单。

**置顶区**：置顶笔记以链接式外观呈现于列表区顶部（`--color-info` 色 + 图钉标记），下方仍按原位置出现，点击任一处均跳转。空置顶笔记时该区不渲染。

**树形结构**：文件夹与「不属于任何文件夹的笔记」作为顶级项混排，同一条比较函数排序；文件夹可展开，其下笔记缩进 16px。笔记归入多个文件夹时在每个文件夹下都出现，只要至少属于一个文件夹就不进入顶级。

**排序**：6 种（名称 A→Z / Z→A、更新时间 新旧、创建时间 新旧），文件夹与笔记共用同一套规则，当前项用 `CheckOutlined` 标记。置顶恒在各自分组内最上，不参与排序比较。

**文件夹管理**：行内 `MoreOutlined` 悬浮菜单提供「重命名 / 编辑简介」与「删除文件夹」；删除用 `Modal.confirm`，文案明确「其下 N 篇笔记不会受影响，只会移出该文件夹」。

**已删除**：视图切换（树形/平铺 Segmented）、筛选漏斗、`collapsed` 参数、`allNotes` 参数、`category` 相关分支、`moveNote` 调用。

### 3.2 阶段三：元信息面板 + 面板收纳

**布局对调**：信息区在上，配置区在下。

**信息区（只读）**：所有者（本人/他人）、可见性、所属文件夹（chip 展示）、字数（`plain_text` 长度）、标签数、出链数、入链数、创建时间、更新时间。出链数由正文 JSON 递归统计 `wikilink` 节点数得到，与后端图谱边口径一致；入链数调 `GET /notes/{id}/backlinks`。

**配置区**：所属文件夹（`mode="multiple"` 的 `Select`，调 `setNoteFolders` 全量替换）、标签、受限标签、置顶 `Switch`。删除了原「父笔记」`TreeSelect` 与 `category` 控件。

**面板收纳**：页面右上角原「面板显示」Dropdown 删除，改为两个自绘 SVG 图标按钮——圆形方框 + 内部竖条，右面板按钮竖条在右、左面板按钮镜像在左。图标用 `currentColor` 描边，深浅色自动切换。侧栏 60px rail 折叠态（`leftCollapsed`）一并删除，不再保留。右侧面板 `rightCollapsed` 初始值为 `true`，即默认收纳，点开后压缩中间编辑区。

### 3.3 阶段四：编辑器

**接线 SlashMenu**：`components/ContentEditor/extensions/SlashMenu.tsx`（约 500 行，`/` 与 `[[` 双触发、16+ 命令、内含笔记选择器与图片弹窗）此前**完整实现但从未被引用**，导致工作台没有任何 UI 入口能插入内部链接，而图谱完全依赖 wikilink 出边。本次在 `ContentEditor.tsx` 挂载。

**挂载方式与计划的一处偏离**：计划写「在 `ContentEditor.tsx` 的 editable 分支挂载」，但 `ContentEditor` 被 content 模块、模板、提案、项目文档等多处复用，且菜单内的「内部链接 / 笔记内嵌」是笔记专属命令，无条件挂载会让其他模块拿到一个半残菜单。故新增 `slashMenu?: boolean` prop（默认 `false`），仅 `NoteEditor` 开启，content 模块保持完全不受影响。

**工具条 Obsidian 式收纳**：

- **外露**：粗体（⌘B）、斜体（⌘I）、下划线、高亮、撤销（⌘Z）、重做（⇧⌘Z）
- **收进「更多」下拉**（`EllipsisOutlined`，`placement="bottomRight"`）：正文段落 / 标题 1-3、无序列表 / 待办列表 / 引用 / 代码块 / 分割线、提示块 4 种、图片 / 内部链接 / 笔记内嵌、字号 9 档
- **文字颜色**保留外露（带当前色指示条），颜色板从 40 收到 12，全部走 design token（`--ink` / `--color-red` / `--color-orange-bright` / `--color-lime` / `--color-success` / `--color-cyan` / `--color-info` / `--color-indigo` / `--color-violet` / `--color-magenta` / `--color-rose`，另加 `#fadb14` 金色与清除按钮）
- 字号 `Select` 从工具条移除，改为「更多」下拉内的子菜单

**命令安全执行**：新增 `runCommand(editor, name, ...args)`——提示块、图片、双链、内嵌、高亮等命令只有注入对应扩展后才注册，`content` 模块复用本组件时并未注入。执行前先 `typeof chain[name] === 'function'` 探测，再包一层 try/catch，避免非笔记编辑器抛 `Command not found`。下拉内的提示块组与插入组也据此条件渲染。

**副作用清理**：`NotePickerModal` 内的分类标签（`note.category`）改为文件夹标签（取前 2 个）。

### 3.4 阶段五：图谱重做

基于现有 `react-force-graph-2d`，未引入新依赖。

- **按文件夹着色**：`colorMode` 可在「按文件夹 / 统一色」间切换；每个文件夹名映射到调色板中的一个 token 色，未分类笔记用 `--text-secondary`
- **图例**：左下角卡片，列出分组与对应色块（最多 12 项，超出显示「还有 N 组」），分组键取自全量节点，避免搜索过滤后颜色漂移
- **搜索聚焦**：工具条内置搜索框（250ms 防抖），命中的节点与其一阶邻居保持正常不透明度，其余节点与边压暗（节点 alpha 0.18，边 0.08），并显示匹配数
- **hover 高亮相邻**：悬停节点时邻居加粗、其余弱化，边带箭头方向
- **节点半径**：`Math.log(degree + 2) * 4 + 6`，按链接数对数增长，孤立节点保持最小可读尺寸
- **交互**：节点拖拽、滚轮缩放（0.1–10）、画布平移、`zoomToFit`

`GraphNode` 载荷由阶段一的后端改为 `folders: string[]` + `tags: string[]`，分组取 `folders[0]`；图谱节点不画文件夹实体（只画笔记节点），符合计划的「明确不做」项。

## 四、遇到的问题与解决

### 4.1 `Input` 的 ref 类型

首次实现时给搜索框传了 `useRef<HTMLInputElement | null>`，`tsc` 报 `TS2322`：antd 5 的 `Input` 期望 `InputRef`（含 `input` / `nativeElement`），不接受原生 `HTMLInputElement`。改用 `autoFocus` 属性解决，少一个 ref 依赖。

### 4.2 `Collapse` 里 `Input` 是否算作已使用

删掉元信息面板的输入控件后 `tsc` 报 `Input` 未使用。排查发现元信息面板本来就只有 `Select` / `Switch`（文件夹描述编辑在侧栏的 Modal 里），`Input` 确实是多余 import，删除即可。

### 4.3 `ContentEditor` 的命令存在性

`content` 模块复用 `ContentEditor` 时没有注入 `noteExtensions`，直接 `editor.chain().setHighlight()` 会抛 `Command not found`。用 `runCommand` 统一探测 + try/catch 兜住，工具条上的高亮按钮与下拉里的提示块/插入两组菜单也按探测结果条件渲染。

### 4.4 正则字面量里的转义括号

`GraphView.tsx` 的 CSS 变量解析正则最初写成 `/^var\((--[^)])+)\)$/`，字符类里多打了一个 `)`，`tsc` 报 `TS1508 Unexpected ')'`。已修正为 `[^)]`。
