### 开发内容详述

#### 1. 提案信息 Tab 展示重构（定义列表 + 段落区块）
- 移除 `Descriptions bordered` 单表格，改为：
  - **状态 Steps**（顶部）：pending→approved→in_progress→completed 四步，`current` 高亮当前状态；rejected 时 `status="error"`
  - **定义列表**（renderDefItem）：编号/标题/状态/类型/优先级/创建人/执行人/创建时间
  - **描述区块**（renderDescriptionBlock）：富文本用 ContentEditor 只读渲染，纯文本直接显示（兼容旧数据）
  - **附件区块**：链接列表（地址+说明）
  - **废弃原因区块**：红色文本（rejected 时）
- 复用 `ProjectInfoTab.module.css` 的展示范式（defItem/defLabel/defValue/textBlock/textLabel/textBody），新建于 `ProposalDetailPage.module.css`

#### 2. 状态流转可视化（Steps）
- 新增 `statusStepIndex` 映射与 `currentStep` 计算；`stepStatus` 在 rejected 时为 error，其余走默认 process
- Steps 置于「提案信息」Tab 顶部，直观展示提案全流程与当前位置（状态操作按钮保留在「提案操作」Tab）

#### 3. 提案描述升级 Tiptap 富文本
- **存储约定**：description 字段（后端 Text 无长度限制）存储 Tiptap doc 的 JSON 字符串；纯文本旧数据仍为普通字符串
- **模块级工具**：
  - `parseDescription(value)`：尝试 JSON.parse，若为 `type==='doc'` 的 Tiptap 结构则返回对象，否则 null（纯文本）
  - `wrapPlainTextToDoc(text)`：纯文本包装为段落 doc（供编辑器回显旧数据）
- **编辑端**：编辑 Modal 的 description 从 `TextArea` 换为 `ContentEditor`（forwardRef 富文本组件，`getValueFromEvent={(v)=>v}` 透传 doc 对象）；`openEdit` 时旧纯文本包装为 doc、富文本 JSON 解析为 doc；`submitEdit` 时 doc 对象 `JSON.stringify` 存储
- **展示端**：`renderDescriptionBlock` 解析 description——富文本用 `<ContentEditor value={doc} editable={false} minHeight={80} />` 只读渲染，纯文本直接显示
- **未改动**：后端无任何改动（description 仍是字符串字段，兼容两种格式）

#### 4. 撤销了评论/讨论区
- 按用户最终选择（展示重构+状态可视化+富文本），撤销了先前按推荐默认加入的评论功能代码（import/state/函数），保持本轮范围聚焦

### 遇到的问题与解决
- 问题 1：ContentEditor 相对路径写错（`../../content` → 应为 `../content`），tsc 报 `Cannot find module`
  - 解决方案：修正为 `../content/ContentEditor`
- 问题 2：Steps `status` 属性在 `exactOptionalPropertyTypes` 下不接受 `undefined`（tsc TS2375）
  - 解决方案：条件展开 `{...(stepStatus === 'error' ? { status: 'error' as const } : {})}`，非 error 时不传 status（走默认 process）
- 问题 3：`renderTextBlock` 声明后未使用（展示重构后描述走 renderDescriptionBlock）
  - 解决方案：删除未使用函数
- 问题 4：冒烟脚本首次断言 `startswith('{"type":"doc"')` 返回 False
  - 解决方案：核实为 json.dumps 带空格格式（`{"type": "doc"`）与断言无空格不匹配，非数据问题；修正断言后确认富文本 JSON 往返正确（可解析、含 bold 标记）
- 遗留问题：富文本描述无字数限制（TextArea 原有 maxLength=2000 已移除）；如需要可后续限制
