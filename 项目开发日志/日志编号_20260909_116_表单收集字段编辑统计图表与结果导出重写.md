### 开发内容详述

【字段结构创建后不可修改】
用户确认的取舍是「轻改，仅前端交互改版」，但字段结构一旦锁定，创建弹窗的字段编辑器就失去了二次调整的意义，因此把「字段创建后不可修改」明确成后端契约并在前端两处提示。

后端新增 FormUpdate 模型，刻意不包含 fields 字段；services/form.py 的 update_form 再做一层防御，收到 fields 直接抛 ValueError（表单字段结构创建后不可修改），由 API 层转为 400。可编辑元数据仍包括标题、描述、可见性、允许匿名、启用状态、受限用户、受限标签。

前端在创建弹窗字段区标题行常驻一行提示「字段创建后不可修改，请仔细核对」，并显示已添加 N / 50 的上限计数；编辑弹窗改为只读的字段列表（序号 + 类型标签 + 字段名 + 必填标记），标题行提示「字段创建后不可修改」。

【字段编辑器卡片化】
原实现是密集堆叠的输入框，项与项之间没有呼吸。新实现把每个字段做成一张 fieldCard：bg-secondary 底 + card-border 描边 + rounded-sm 圆角，卡片之间 spacing-sm 间距，字段区整体在 320px 上限内纵向滚动，避免弹窗被撑到屏外。

卡片头部是单行栅格：24px 圆形序号徽标、132px 固定宽度的类型下拉、弹性字段标签输入框、必填开关、以及三个上移/下移/删除文字按钮。第二行 fieldSub 用左侧缩进（24px 徽标 + spacing-sm）与头部错开层级：文本/段落/数字显示「输入提示」，下拉/单选/多选显示「选项（至少 2 个）」，选项是一行行内输入框加删除图标，末尾是 dashed 的添加选项按钮。底部是 dashed 的添加字段按钮，达到 50 个上限时自动禁用。

字段类型收敛为六类：文本、段落、数字、下拉、单选、多选。选项类类型统一走 OPTION_TYPES 集合判断，避免散落的字符串比较。

【统计页重写】
统计页是这次改动里用户反馈最集中的地方，整页重做：

1. 返回按钮。头部左侧新增 ArrowLeftOutlined 返回按钮，回到 /forms，不再是「进了统计出不来」。
2. 概览卡片。四项：回复总数、匿名回复、首次提交、末次提交，四列栅格，991px 以下两列，767px 以下单列。
3. 按字段统计。每个字段一张卡片，头部显示字段名、必填/选填标记、已填写 n / 总数（xx%）填写率。选项类字段（select/radio/checkbox）渲染计数柱状图，数字字段渲染六项描述统计（有效数值/均值/中位数/最小值/最大值/标准差）加五箱分布柱状图，文本类字段给出「文本类字段仅统计填写率」的说明，避免空白感。
4. 零回复完整渲染。这是用户明确提出的诉求。get_form_stats 在无回复时返回全零骨架（每个字段 answered_count 0、answer_rate 0、option_counts 保留选项但计数为 0），前端因此照常渲染全部图表与明细表格，只额外加一条 Alert「暂无回复，以下图表与明细以 0 值展示，收到回复后会自动更新」。不再用 Empty 把整页顶掉。
5. 明细表。提交时间 + 各字段 + 提交者；提交者改为后端下发的昵称/用户名，匿名显示「匿名」，不再截断显示 UUID 前八位。

图表使用新引入的 @ant-design/charts 2.6.7（内置 G2），Column 组件按 xField / yField / height 配置。该包使统计页 chunk 约 1.46 MB（gzip 429 kB），但统计页本身是路由级懒加载，只在进入统计页时才拉取，不影响首屏。

【权限修复】
两处真实的授权缺口：

1. 标签授权完全失效。后端 restricted_tags 存的是 tag name，而 VisibilitySetting 组件把 tag id 回传，交集判断永远为空，标签形同虚设。修复方式是让 VisibilitySetting 新增 tagValueMode 属性（id / name，默认 id 保持既有调用方不变），表单收集传 name；同时后端 normalize_restricted_tags 对形如 UUID 的历史值做兜底解析回 name，两种写法都能存对。
2. 提交接口越权。submit_form_response 原先不校验可见性，任何登录用户都能向任意启用表单提交。现在复用 can_access_form 统一判断，无权返回 404（不泄露表单存在性），账号停用返回 400。

can_access_form 的统一语义：public 任何人可填；restricted 命中 restricted_users 或 restricted_tags 与用户标签名交集可填；private 仅创建者（历史数据保留）。

【可见性收敛为两态】
按用户确认「这个表单收集只有两个，一个是公开一个是受限」，新表单不再提供私有：表单创建默认 restricted，VisibilitySetting 新增 hidePrivate 属性把私有项从选项里摘掉。
历史 private 表单不做数据迁移：types/form.ts 里 Item.visibility 保留宽类型（含 private）以兼容存量数据，新建/更新走窄集合；列表页对 private 表单隐藏「填写」与「分享」入口。

【结果导出】
新增 form_export.py，与项目既有 project_export 同构：导出函数返回 (BytesIO, filename, content_type)，API 层负责 RFC 5987 的 Content-Disposition。xlsx 两个工作表——回复明细（冻结首行、列宽按内容估算且上限 50）与统计汇总（含每字段填写率、选项分布、数字统计）；csv 带 UTF-8 BOM 以便 Excel 直接打开中文。权限与列表页一致：仅创建者或管理员可导出。

【填充页只读回显】
按「填写者看自己填写的内容」的权限模型，填充页加载时先查 getMyResponse：已提交过的登录用户直接看到 Descriptions 只读回显与提交时间，不再重填一次；未提交或匿名访客走原表单。每人在同一表单仅允许一次提交，该约束由后端唯一索引保证，前端用本地状态复用同一份回显视图。

### 遇到的问题与解决

- 问题：ruff 的 --fix 会把带转义双引号的 f-string 里的反斜杠去掉，导致 filename 拼接处出现语法错误。
  解决方案：不再在 f-string 里写转义引号，改为先把带引号的 ASCII 文件名拼成变量，再拼接 disposition 字符串。

- 问题：mypy 报 list[object] 与 list[str] 的不变性冲突（给空表头行追加元素时）。
  解决方案：改用 append / extend 逐步构造，不写带类型标注的字面量。

- 问题：前端 tsconfig 开了 noUncheckedIndexedAccess 与 exactOptionalPropertyTypes，数组下标访问与可选字段赋值都会报错。
  解决方案：移动字段前先取出 current 与 neighbor 两个变量并做空值守卫，用局部变量互换代替原地赋值；创建表单的受限字段用条件展开，避免显式传 undefined。

- 问题：visibility 类型一开始收窄成只含 public / restricted，但存量数据里仍可能有 private，赋值与比较都会失败。
  解决方案：存储类型保留宽集合以兼容历史数据，新建/更新的窄约束放在 UI 层（hidePrivate）与后端校验，不在存储类型上强行收窄。

- 问题：npm install 安装 @ant-design/charts 后 npm audit 显示 36 个漏洞。
  解决方案：未处理。该库依赖 G2 图形栈，内网部署且统计页数据均为站内自有数据，暂不升级；建议在下次版本安全体检时统一评估。这是遗留待办。

- 问题：npm run build 报 Home.module.css 第 45 行 Unexpected }
  解决方案：该文件是本次未触碰的文件，工作树里有一处逐字复制却丢失选择器的孤儿重复块，属并发改动遗留的破损；已在修复后重新构建通过。本次未对该文件做其它修改。

- 遗留问题 / 待办：历史 private 表单未做数据迁移，行为仍是仅创建者可见；若需要统一收口到两态，需单独做一次 Alembic 迁移。
