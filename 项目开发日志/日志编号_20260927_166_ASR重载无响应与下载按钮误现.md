### 开发内容详述

#### 一、ASR 重载「按了没反应」：两个原因

**原因 1：按钮没有 loading 状态。**
`handleReloadASR` 本身是对的——调 `reloadASRModel()`、判 `success`、回 message。
但重载要顺序加载 4 个模型（paraformer-zh + fsmn-vad + ct-punc + cam++），
实测 18 秒左右。这段时间按钮没有任何视觉反馈，用户以为按了没反应。

现在加了 `asrReloading` 状态，按钮带 `loading`，转起来。

**原因 2：后端可能被 OOM 杀掉，请求 502。**
上一版日志确认过 backend 容器会被 Killed（Docker VM 只有 5.8 GB，装不下 ASR 四件套 + qwen3.5:4b）。
`restart: unless-stopped` 会拉起容器，但请求已经断了。旧代码只是 `message.error(errorMessage(err))`，
用户看到一条看不懂的错误。

现在 catch 里识别 502 / Bad Gateway，翻译成「后端正在重启，请稍后重试」。
成功时顺手 `checkASRStatus()` 刷新状态。

#### 二、「下载模型」按钮不该出现：状态检查和后端重启冲突

**复现路径**：
1. `/asr/status` 返回 `status: downloaded`（4/4 就绪）——实测确认
2. 但如果此刻 backend 容器被 OOM 杀掉、正在重启，`getASRModelStatus()` 抛异常
3. 旧 `checkASRStatus` 的 catch 无条件 `setAsrModelStatus('not_downloaded')`
4. 前端于是显示「下载模型」按钮
5. 用户点击 → 后端已恢复 → 返回 `success: true, message: "ASR 模型已就绪，无需下载"`
6. 用户困惑

**修法**：
- `checkASRStatus` 的 catch 不再无条件改成 `not_downloaded`——如果当前已经是 `downloaded`，保持不变
- `handlePreloadASR` 收到后端「已就绪」响应后，直接 `checkASRStatus()` 刷新 +
  `message.info('ASR 模型已就绪')` 返回，不再往下走轮询逻辑

#### 三、删除 AI 卡片头部的测速按钮和蓝色 tag

AI 卡片的 `Card extra` 里有一个小号「测速」按钮和一个蓝色速度 tag，
和卡片体内 `aiModelStatus === 'downloaded'` 区块里的「测速」按钮 + Progress 条重复。
把整个 `extra` 删掉，只保留卡片体内的入口。

### 遇到的问题与解决

- **问题**：tsc 报 `Property 'downloaded' does not exist on type ...`——
  `TestConnectionResponse.details` 没有 `downloaded` / `total` 字段，但 ASR 预热接口用同一个类型。
  - **解决方案**：在 `details` 类型里补 `downloaded?: number` 和 `total?: number`。
- **问题**：ASR 重载 18 秒无反馈。
  - **解决方案**：加 loading 状态；同时处理 502（后端重启中）的场景。
- **遗留问题**：backend 容器 OOM 被杀是 Docker Desktop 内存上限（5.8 GB）导致的，
  不是代码问题。建议把 Docker Desktop → Resources → Memory 提到 10 GB。
