### 开发内容详述
1. **LockContext**：`isLocked` 状态经 `sessionStorage`（key `workbench_locked`）持久化，刷新不丢锁定态；提供 `lock()` / `unlock()`，两者同步内存态与存储。
2. **LockGuard**：`isLocked` 为 true 时 `<Navigate to="/lock" replace />`，否则 `<Outlet />`。作为 AuthGuard children 包装全部工作台路由。
3. **LockPage**：公开路由（AuthGuard 外），居中卡片展示 80px 头像 + 昵称 + 密码输入 + 解锁按钮。调 `POST /auth/verify-password`（request 自动携带 Bearer token），`code === 0 && data.valid === true` 才解锁（后端密码错误时返回 code=0/valid=false）。解锁后 `unlock()` 并依据 `history.state.idx > 0` 判断 `navigate(-1)` 还是 `navigate('/')`（避免 replace 覆盖历史后回退到空白页）。user 未加载时主动 `refreshUser()`（直接刷新到 /lock 的场景）。
4. **useIdleTimer**：`handleLogout`（清 token + sessionStorage.clear + API logout + replace /login）改为 `handleLock`（调用 `lock()`），token 保留供解锁时 verify-password 认证。移除已无用的 clearTokens/request 导入。
5. **MainLayout**：`useEffect` 监测 `isLocked` → `navigate('/lock')`（第二道防线，与 LockGuard 互补）；顶栏新增手动锁定按钮（LockOutlined，Tooltip "手动锁定工作台"，位于 idleToggle 旁）；原 idleToggle 文案更新为 "空闲 5 分钟自动锁定"/"已暂停自动锁定"（功能保留）。
6. **router.tsx**：新增 `/lock` 公开路由（/welcome 同级）；AuthGuard children 内嵌 LockGuard 层。
7. **main.tsx**：`LockProvider` 插在 `UserProvider` 内、`RouterProvider` 外（LockPage 需 useUser 获取头像名称）。

关键决策：
- 采用 LockGuard 组件（而非 MainLayout 内单一监测）做路由级重定向，保证任何工作台子路由都受保护。
- 解锁判定用 `data.valid === true`（后端 verify-password 返回 `{valid: bool}`，密码错误为 code=0 但 valid=false）。
- 解锁回跳用 `history.state.idx` 而非 `history.length`（LockGuard 的 replace 导航会压缩历史栈，length 判断在刷新直入锁屏页时会误回退到 about:blank）。

### 遇到的问题与解决
- 问题：手动锁定后 `navigate('/lock')` 为 push；但刷新直入 /lock 或 Guard replace 跳转时历史栈无前序工作台页，`navigate(-1)` 会回退到 about:blank 白屏。
  - 解决方案：改用 `history.state.idx > 0` 判断是否有可回退的前页，否则 `navigate('/', { replace: true })`。
- 问题：错误密码解锁时后端返回 HTTP 200 + code=0 + valid=false（非 401），仅按 code 判断会误解锁。
  - 解决方案：额外校验 `data.valid === true`。
- 遗留问题：无。
