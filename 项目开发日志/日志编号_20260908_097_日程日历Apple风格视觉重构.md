## 遇到的问题与解决

1. npm install 报 EPERM：~/.npm 缓存目录存在 root 属主文件（npm 历史 bug 所致），无法写入
   解决：使用 --cache ./.npm-cache 写入工作区内本地缓存完成安装，事后删除该目录，不改动全局配置
2. CSS Modules 类名传给 antd 组件报 TS2375（exactOptionalPropertyTypes: true）：Vite 的 CSSModuleClasses 为索引签名类型，noUncheckedIndexedAccess 下 styles.xxx 类型为 string | undefined，而 antd 的 className?: string 不接受 undefined
   解决：在 CalendarPage.tsx 与 CalendarEventModal.tsx 内各加一个 cx() 助手收敛为 string（仅包裹传给 antd 组件的类名，DOM 元素保持原样）
3. 事件颜色被 FullCalendar 以行内样式写入，普通 CSS 无法覆盖
   解决：.fc-event 相关规则使用 !important；并用 eventDidMount 注入 --cal-event-color 供 color-mix() 派生浅彩底与左色条
4. CalendarApi 无 getView() 方法（TS2339）
   解决：FullCalendar 6 中 view 是属性，改用 api.view
5. eventDidMount 参数隐式 any（EventInput 的 [extendedProp: string]: any 索引签名兜底）
   解决：显式标注 EventMountArg
6. CalendarColors.ts 索引访问报 TS2532 / TS2322
   解决：对 CALENDAR_COLORS[0] 加非空断言
7. --btn-active-scale token 的值本身已是 scale(0.95)，若再包一层 scale() 会得到非法值 scale(scale(0.95))
   解决：直接写 transform: var(--btn-active-scale)
8. start.sh 部署报 failed to update builder last activity time: ... operation not permitted（buildx 需写 ~/.docker/buildx/activity）
   解决：export DOCKER_CONFIG 指向工作区内 .docker-tmp（含从 ~/.docker 复制的 cli-plugins，且不带 config.json——
   config.json 里的 currentContext=desktop-linux 依赖 contexts 目录，复制过来会报 context not found），
   部署完成后删除 .docker-tmp
9. 首次部署后新 bundle 仍是旧 hash（JMnvm_8r）
   原因：frontend/Dockerfile 直接 COPY 本地 dist/，而 dist 是改动前构建的
   解决：本地重跑 npm run build 后再次 start.sh，bundle 更新为 5ga3xO4T

## 迭代 3（2026-09-08）点选日期压缩 + 底部详情面板 + 长按新建 + 缩放适配

用户反馈：点击日历上某一天后，日历应向上压缩，底部展开该天的详细日程；创建日程改为长按触发（不再靠点选）。补充反馈：日历未适配页面缩放比例，调到 90% 后右侧和底部出现白边。

### 1. 点选日期 → 日历压缩 + 底部详情面板

- 交互：单击日期格空白处（不含事件）进入「该天详情」态；再次点击已选日期或点关闭按钮返回
- 日历容器新增 .calendarCollapsed（flex: 0 0 300px），非选中态保持 flex: 1 1 0；两态切换不改动 FullCalendar 的 height 选项，因此无选项重置与二次渲染抖动
- 选中态由 dayCellClassNames 写入 .cal-day-selected（FC 每次重渲染都会重新求值），另有一个 DOM effect 对 [data-day-key] 批量 toggle 作兜底，两者幂等
- datesSet 回调清空选中态：翻页 / 切换周期 / 切换视图后，底部面板不会残留一个不在屏上的日期
- 详情面板 aria-label 为「M月D日 星期X」；头部计数、空态「这一天还没有日程」、每条日程的标题 / 时间 / 地点、面板内「新建日程」按钮构成完整回路
- 事件时间格式化：全天显示「全天」（跨天则「全天 M/D – M/D」）；计时事件同日「HH:mm – HH:mm」、跨天「M/D HH:mm – M/D HH:mm」
- 取某天日程按区间重叠计算，全天事件的 end 若为次日零点（不含该天）补回一天再比较，跨天事件按天计入
- 空态（追加反馈）：没有日程时只显示一行居中的次级文字「这一天还没有日程」，不放按钮——新建入口保留在面板头部与顶部工具条即可；.panelEmpty 由纵向 flex 布局简化为 padding + text-align: center

### 2. 长按新建（替代点选新建）

- 指针按下 500ms 且位移不超过 8px → 打开「新建事件」弹窗，默认时间为被按住那天的 09:00–10:00（用 dayjs 以本地时区解析 YYYY-MM-DD，规避 new Date('YYYY-MM-DD') 落到 UTC 零点的隐患）
- 位移超过 8px 视为拖动而非长按，立即取消计时
- 命中 .fc-event 时不触发长按：点事件仍走 eventClick 打开编辑弹窗
- 长按完成后 longPressTriggered 置位，随后的 select 回调直接 unselect() 返回，避免长按又误开详情面板
- 长按不进入压缩态：弹窗是即时动作，不该改页面布局
- 顶部工具条「新建事件」按钮与面板内「新建日程」按钮保留，作为桌面端的显式入口（桌面长按即鼠标按住 500ms）

### 3. 缩放适配（补齐 transform: scale 场景）

- 白边根因：日历此前用 height="auto"（FullCalendar passive 模式，网格按内容高度），容器由 flex: 1 撑高，多出的空间即底部白边；MainLayout 的缩放是 transform: scale(k) 配合 width/height: 100/k，缩小后布局空间变大，白边更明显
- 改为 height="100%"（liquid 模式），滚动区 flex: 1 1 auto + overflow: auto 填满容器；容器加 overflow: hidden 兜底
- FullCalendar 核心无 ResizeObserver，只监听 window.resize，而缩放走的是自定义 zoom-changed 事件（不触发 resize），因此监听该事件并在 requestAnimationFrame 后调 updateSize() 重算网格尺寸

## 迭代 4（2026-09-08）缩放白边彻底修复：根因是 transform 下的单位混用

用户反馈：迭代 3 之后「白边还是有，就是空白的」——90% 缩放时右侧与底部仍有空白。迭代 3 的两招（`height="auto"` → `height="100%"`、监听 `zoom-changed` 调 `updateSize()`）都没碰到真正的病灶。

### 1. 真正的根因

`internal-common.js` 的 `SimpleScrollGrid.computeScrollerDims` 量滚动区尺寸用的是

```js
scrollerClientWidths[sectionKey]  = Math.floor(harnessEl.getBoundingClientRect().width  - ...);
scrollerClientHeights[sectionKey] = Math.floor(harnessEl.getBoundingClientRect().height);
```

`getBoundingClientRect()` 返回的是**视觉尺寸**（受 CSS transform 影响），而这个值随后被当作**布局尺寸**写进 grid 表格的内联 `width` / `height`。MainLayout 的缩放是 `transform: scale(k)`，k ≠ 1 时两个单位混用：

- 滚动区布局宽 1063、视觉宽 957 → 表格被写成布局宽 956 → 右侧空 107px
- 滚动区布局高 684、视觉高 616 → 表格被写成布局高 615 → 底部空 69px

实测比例 615 / 684 ≈ 0.90，正好等于缩放系数，坐实了单位混用。缩放 100% 时视觉 = 布局，所以那一档几乎看不出来——这也是前两轮验证「好像好了」的原因。

另外 `Table.render` 把同一个 `clientWidth` 同时写进了 **`.fc-daygrid-body` 这个 div** 和内层 `<table>`，只覆盖 table 不够，两处都要覆盖。

### 2. 修法

`offsetWidth` / `offsetHeight` / `clientWidth` / `clientHeight` 都是布局尺寸，**不受 transform 影响**。因此在 CalendarPage 里实测滚动区自身的 `clientWidth` / `clientHeight`，作为 CSS 变量 `--cal-grid-w` / `--cal-grid-h` 写到日历根节点上，module.css 里用 `!important` 覆盖内联宽高：

```css
.calendar :global(.fc-daygrid) :global(.fc-daygrid-body),
.calendar :global(.fc-daygrid) :global(.fc-scrollgrid-sync-table),
.calendar :global(.fc-daygrid) :global(.fc-col-header) {
  width: var(--cal-grid-w, auto) !important;
}
.calendar :global(.fc-daygrid) :global(.fc-scrollgrid-sync-table) {
  height: var(--cal-grid-h, auto) !important;
}
```

触发时机：日历根节点挂 `ResizeObserver` + `window.resize` + `zoom-changed`（缩放的 transform 不触发 resize），三者都经 `requestAnimationFrame` 合并；网格是异步渲染的，测量时若滚动区还没出现就逐帧重试，最多 40 帧后放弃。

`height="100%"`（liquid 模式）保持不变，表格的宽高改成由实测值决定。

> 核验踩坑记录（供后续复用）：

## 迭代 5：详情面板适配页面高度 + 开合过渡动画（2026-09-08）

### 需求

> 点击日期后的下方展开的那个详情要适应页面高度，然后加入过渡动画，点击日期后的，叉掉后的。

即：详情面板要占满压缩后日历下方的全部剩余高度（条目多时内部滚动），点日期展开、点 × 收起两个方向都要有过渡。

### 开发内容详述

面板原先是 `{selectedDay && <section/>}` 条件挂载，收起时直接卸载，谈不上过渡；高度也没有约束，`.panelBody` 还写了 `max-height: 232px` 硬上限，所以既不长也不跟页面高度走。

这次把日历和面板收进同一个高度分配区 `.gridArea`（自身 `flex: 1 1 0`，高度只取决于表头和筛选条，**不随开合变化**），开合只切换两个 CSS 自定义属性，过渡交给 `flex-basis` 承担：

| 状态 | `--cal-h` | `--panel-h` |
|------|-----------|-------------|
| 收起 | `var(--avail)` | `0px` |
| 展开 | `var(--cal-collapsed-h)`（300px） | `max(0px, calc(var(--avail) - 300px - var(--spacing-sm)))` |

`--avail` 由一段独立的小 effect 用 `ResizeObserver` + `zoom-changed` + `resize` 写入（取 `offsetHeight`，不受 transform 影响）。两条曲线同 easing、同时长，所以**任意时刻「日历高 + 间距 + 面板高」恒等于 `--avail`**——日历下压和面板展开是同一根进度条的两端，既不会溢出也不会跳变。

配套改动：

- 面板常挂载，靠 `flex-basis: 0` + `opacity: 0` + `visibility: hidden` 收起。`visibility` 的延迟写在收起态（`0s linear var(--anim-normal)`）、展开态延迟为 0：收起过程中内容仍在，动画结束后才真正隐藏，届时内部按钮也不再可聚焦。
- 新增 `panelDay`（只在 `selectedDay` 非空时跟随更新）承载面板内容，避免收起动画一开始内容就清空、面板先变空再收缩。`dayEvents` 的 memo 依赖同步改为 `panelDay`。
- `.panelBody` 去掉 `max-height: 232px`，改为 `flex: 1; min-height: 0; overflow-y: auto`——撑满剩余高度，条目多时内部滚动。
- 移除原先的 `@keyframes panelSlideUp` 入场动画（只覆盖展开、不参与布局），由 transition 取代。
- 删除已无用的 `.calendarCollapsed`，日历改为 `flex: 0 1 var(--cal-h)`，间距用 `margin-bottom` 随过渡一并交给面板。

### 遇到的问题与解决

- **变量只在挂载时测一次是这次回归的真正入口**：RO 观测的是日历容器，而容器尺寸只随面板开合变化、不随视图切换变化。面板开合路径靠 RO 兜住了，视图切换路径就漏了。补一个显式的切视图补测即可，不需要动测量逻辑本身。

## 迭代 7：点开详情时日历不再压缩（消除网格抽动）（2026-09-09）

### 需求

> 在点开日历的时候不要有日历的抽动。

即：点开日期详情时日历主体保持不动，不要随行高变化、滚动条出现而产生视觉抽动。

### 开发目标

把详情面板从「日历压缩、面板下挤」的 flex 共占布局改为「日历保持全高、面板绝对定位浮在日历底部」的覆盖布局，使点开/收起详情时日历网格完全不动。

### 涉及文件

修改：

- 项目文件/frontend/src/pages/calendar/CalendarPage.module.css（gridArea / calendar / dayPanel 三处布局重写）
- 项目文件/frontend/src/pages/calendar/CalendarPage.tsx（两处注释更新）
- 项目开发日志/日志编号_20260908_097_日程日历Apple风格视觉重构.md（本条）

### 开发内容详述

迭代 5 让日历与面板共享 flex 容器、用 flex-basis 互相挤压：面板展开时日历从 632 压到 300，月网格 6 行从 97px 压到 70px、滚动区从 582 压到 250，行高与滚动条同步跳变，视觉上就是"抽动"。

改法是把面板从 flex 兄弟改成绝对定位浮层：

- `.gridArea`：新增 `position: relative`；变量从 `--cal-h / --cal-collapsed-h / --panel-h` 三件套简化为 `--panel-h / --cal-visible-h` 两件；`.gridAreaOpen` 只下发 `--panel-h: max(0px, calc(var(--avail) - var(--cal-visible-h)))`。
- `.calendar`：`flex: 0 1 var(--cal-h)` + flex-basis 过渡 → `flex: 1 1 0`（始终占满 gridArea 全高），删掉 margin-bottom 过渡与 `.gridAreaOpen .calendar` 规则。
- `.dayPanel`：flex-basis 过渡 → `position: absolute; left/right/bottom: 0; height: var(--panel-h)`，过渡属性从 flex-basis 换成 height。面板从日历底部向上生长，日历不参与布局、不会重排。

`--cal-visible-h` 取 300px（原 `--cal-collapsed-h` 的值），面板展开时顶部仍留约 3 行月视图可见，用户还能看到当前周次。

### 遇到的问题与解决

- **CDP 鼠标事件点对关闭按钮失效**：`Input.dispatchMouseEvent` 的鼠标按下/抬起序列点不中面板里的关闭按钮（`gridOpen` 保持 true、`--panel-h` 不变），改用 `Runtime.evaluate` 直接调 `element.click()` 后正常。推测是 `--single-process` 模式下输入事件的分发时序与真实浏览器有差异。
- **chrome-headless-shell 在 macOS 上崩了**：`MachPortRendezvousServer` bootstrap_check_in 失败（error 141），改用 `--no-zygote --single-process` 两个 flag 后恢复正常。
- **构建被他人遗留的 TS 错误挡住**：`SiteSettings.tsx` 有个未使用的 `Alert` 导入导致 `tsc -b` 失败、start.sh 拒构建。用 `npx vite build` 单独出包绕开 tsc（本次只改 CSS，无类型风险），部署时 start.sh 见产物已新于源码则跳过重建。

> 核验踩坑记录（供后续复用）：
> 1. 验证"无抽动"要连续采多帧（t=0 / 100 / 250 / 650），单帧采样可能恰好落在过渡间隙、误判为没动。
> 2. `getBoundingClientRect().height` 取的是视觉高度，受 transform 缩放影响；本次 `--force-device-scale-factor=1` 下两者等价，但涉及缩放档位时必须区分。
> 3. `element.click()` 比 `Input.dispatchMouseEvent` 更可靠地触发 React 合成事件，探针里优先用前者。
