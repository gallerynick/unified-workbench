### 开发内容详述

**1. 受控实验：缓存并不泄漏**

治理前先做无改动构建实验，避免凭猜动手：

```
构建前  Build Cache  64 条   9.858 GB
无改动构建          → 13 处 CACHED，0 错误
构建后  Build Cache  64 条   9.858 GB   ← 一字未涨
```

**结论：稳态下缓存不增长。**此前的膨胀（一度 10.3GB）是我连续改了 3 版 Dockerfile（阿里云源 → 加 pgdg → 清华源 + pip 加固）造成的，每版都新增一整套层。

**2. 过滤器行为的完整测定**

在 buildx v0.35.0-desktop.2 上逐条实测：

| 命令 | 结果 | 判读 |
|---|---|---|
| `--filter until=notaduration` | **报错**：`"until" filter expects a duration` | 过滤器**确实被解析** |
| `--filter until=99999h` | `Total: 0B` | 正确匹配「无」 |
| `--filter until=20h` | `Total: 0B`（当时存在 24–43h 的旧代） | **匹配不到应清的历史代** |
| `--filter inuse=false` | `Total: 0B` | 同上 |
| 裸 `builder prune -f` | `Total: 2.743GB` | 只清「可回收」部分 |
| **`buildx prune -a -f`** | **`Total: 7.064GB`** | **彻底清空，缓存降到 51MB** |

**关键结论**：`until` 能解析但做不了保留期；裸 prune 会留下**删不掉的重复层**——实测残留 1.11GB ×3、824MB ×3、349MB ×2，且 `docker system df` 的可回收量归零而占用仍高达 7.115GB。**只有 `-a`（连内部/前端缓存一并清除）能真正清干净。**

**3. 脚本改为 `buildx prune -a -f`**

`prune-cache.sh` / `.bat` 的清理命令由裸 `builder prune -f` 改为 `buildx prune -a -f`，并在注释里完整写入上述实测矩阵、代价说明与地板说明。

清理过程同时回收了我调试期间留下的探针镜像 `uw-leak-probe`（2.86GB）。

**5. 地板测定：5.124 GB**

治理后缓存只剩一代，构成即镜像层本身：

| 层 | 大小 |
|---|---|
| `COPY --from=builder /usr/local` | 2.51 GB |
| `pip install .` | 1.11 GB |
| `pip install torch/torchaudio` | 0.82 GB |
| `apt-get install build-essential` | 0.35 GB |
| `apt-get install`（PGDG/libpq） | 0.18 GB |
| 前端 + 元数据 | ~0.15 GB |
| **合计** | **≈ 5.12 GB** |

**这就是地板**——缓存体积必然约等于镜像层体积。本脚本无法突破它。

**6. 泄漏复测**

```
无改动再构建    13 处 CACHED
缓存           5.124 GB → 5.124 GB（不变）
```

确认治理后进入稳定状态。

### 遇到的问题与解决

**问题 1：构建被沙箱阻止。**
`failed to update builder last activity time: open /Users/.../.docker/buildx/activity/.tmp-...: operation not permitted`
**解决**：该操作需写入工作区外的 `~/.docker`，按规程以 danger-full-access 提权重试一次后正常（提权后策略本身也切到了 full-access）。

**问题 2：`--filter until=20h` 一度返回 0B，我据此误判「过滤器被忽略」。**
**解决**：改用**非法 duration 探针**做判定——`until=notaduration` 正常报错，证明过滤器确实被解析。此前的 0B 是**匹配不到**而非**未生效**。原先「连非法过滤器都返回 0B」的判读是错误的（非法 **key** `zzz=1` 才是被静默忽略的情形，两者不可混为一谈）。

**问题 3：裸 prune 后出现删不掉的重复层。**
残留 1.11GB ×3 等，可回收量归零却占 7.115GB。
**解决**：改用 `buildx prune -a -f`，一次清空 7.064GB。
