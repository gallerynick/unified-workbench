### 开发内容详述

**1. 根因定位（nginx 访问日志）**

用户浏览器实际请求的是 `GET /testpage`，而不是 `GET /dev/testpage`：

```
16:13:25 "GET /testpage"  200  ← 用户输入
16:13:18 "GET /404"       200  ← 前一步落点
```

`/testpage` 不在路由表内，React Router 落到 `path: '*'` 通配路由，`<Navigate to="/404" />` 把它带到 404 页——表现就是"打不开 testpage"。服务端一直正常（SPA fallback 恒返回 200），所以从 nginx 侧看是 200，从浏览器侧看是 404。

**2. 别名路由**

新增 `TestPageAlias`：读取当前 pathname，把开头的 `/testpage` 替换为 `/dev/testpage` 后 `<Navigate replace>`，保留 query。注册 `/testpage` 与 `/testpage/:key` 两条，位于 AuthGuard/LockGuard 之内、与 `/dev/testpage` 同级。静态段路由优先级高于 `*`，因此不再落 404。

**3. 空白页兜底**

原实现：`isDebugModeEnabled()` 抛错时 `debugEnabled` 永远停在 `null`，组件 `return null` → 整页空白，用户无法区分"没权限""加载失败""还没加载完"。改为：

- 读取中：居中 `<Spin size="large" />`
- 读取失败：`Result` 提示"无法读取站点配置" + "重试"（递增 reloadToken 重跑 effect）+ "返回工作台"

### 遇到的问题与解决

- **问题**：登录态验证受 AuthGuard 遮挡——未登录时任何路径都被导到 /login，无法区分"路由匹配成功"与"落到通配"。
- **尝试**：用本地 SECRET_KEY 临时签发 access token + 无头浏览器注入，验证真实登录态下的路由。
- **结果**：被后端会话表校验拒绝（jti 不在 user_session），需要写库才能造会话，遂停止该路线；临时脚本含密钥，已删除。未对数据库做任何写操作。
- **最终依据**：用户自己的浏览器流量已证明"未注册路径 → 通配 → /404"这条链路成立；别名路由为静态段，按 React Router 优先级必然先于通配匹配，且构建产物中已确认包含 `"/testpage"` 与 `dev/testpage` 两条。
