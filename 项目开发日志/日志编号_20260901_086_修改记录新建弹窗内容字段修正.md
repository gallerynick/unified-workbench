### 开发目标
按用户反馈「修改记录也同样的，不要在新建的时候填写内容，所有内容和正文都是在进入后的详情页去做添加修改编辑等操作」，修正「新建修改记录」弹窗中「内容」字段的必填与展示逻辑：新建时仅填元数据（标题/日期/大类/小类/详情/状态），内容留待编辑模式填写。

### 开发内容详述

**1. ChangeFormValues.content 改为可选**
- 原 `content: string` → `content?: string`，并加注释「正文（可选）；新建时不展示，留待编辑模式填写」

**2. 「内容」Form.Item 条件渲染**
- 新建模式（editingChange=null）：不渲染「内容」Form.Item，表单仅含元数据字段
- 编辑模式（editingChange 非空）：渲染「内容」Form.Item（仍保留 required 规则，因编辑时应填写完整内容）

**3. 提交逻辑：条件包含 content**
- 新建与编辑两个 payload 构造中，将 `content` 从直接赋值改为 `if (content) payload.content = content`，与已有的 category_minor / category_detail 条件赋值模式一致
- 新建模式 values.content 为 undefined → 不发送 content 字段 → 后端默认 None
- 编辑模式 values.content 为 string（可能为空串）→ 发送 content 字段 → 后端存实际值

**4. 后端零改动**
- ProjectChangeCreate 与 ProjectChangeUpdate 的 content 字段已是 `str | None = None`（可选）
- 前端类型 ProjectChangeCreate / ProjectChangeUpdate 已是 `content?: string`（可选）
- 无需迁移

### 遇到的问题与解决
- 问题：exactOptionalPropertyTypes 下 `content: values.content`（string | undefined）直接赋值给 payload 会报错
  - 解决方案：改用 `if (content) payload.content = content` 条件赋值，与已有 category_minor / category_detail 模式一致
