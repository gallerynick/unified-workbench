### 开发内容详述

**一、根因：不是对齐属性，是基线**

上一轮给 antd Space 加了 `align="center"`，但实际无效——排查 antd 源码发现
（`node_modules/antd/es/space/index.js`）：

    const mergedAlign = align === undefined && direction === 'horizontal' ? 'center' : align;

水平方向 Space 的 `align` **默认就已经是 center**，所以上一轮那个改动是冗余的，
从来就不是偏高的原因。

真正原因是基线（baseline）：

1. antd Space 会把每个子元素包进 `<div class="ant-space-item">`，该 div 是
   `display: block`
2. 块级容器内的 inline 层级盒子按**基线**对齐，而不是按盒子中心
3. 图标按钮是 `display: inline-flex`，其基线取自内部图标字形的**文字基线**
   （略高于盒底，下方留 descent 空间）
4. antd Avatar 是 `display: inline-block` 且内部是图片/图标、**没有行内文字**，
   按 CSS 规范这类盒子的基线就是**盒子底边**
5. 两者基线相差约一个 descent（14px 字号约 2-3px）→ 按钮整体比头像高 2-3 像素

这就是「比头像和名字高」的直接来源。上一轮的 `align="center"` 只能让
`.ant-space-item` 这些 div 互相居中，管不了 div **内部**的基线对齐。

**二、修复：改用原生 flex，按盒子中心对齐**

1. 外层 `<Space size="middle" align="center">` 换成原生
   `<div className={styles.headerActions}>`：
   `display: flex; align-items: center; gap: var(--spacing-card-gap);`
   —— flex 容器的 `align-items: center` 是按**盒子中心**对齐子项，不涉及基线。
2. 新增 `.headerIconButton`，显式锁定 32×32（= `var(--avatar-size)`）并
   `display: inline-flex; align-items: center; justify-content: center; padding: 0`。
   按钮自身成为 flex 容器后，内部图标由 flex 居中，不再依赖 antd 的行内布局。
3. 头像组同样把 `<Space align="center">` 换成 `<div className={styles.headerUser}>`
   （`display: flex; align-items: center; gap: var(--spacing-sm)`），
   头像与昵称按盒子中心对齐。
4. 三个按钮与铃铛共用同一个 `.headerIconButton` 类，NotificationBell 新增
   `buttonClassName?: string` 属性由 MainLayout 传入，保证四处规格一致。
5. 图标字号改写在**图标元素本身**上：`<LockOutlined style={{ fontSize: 'var(--header-icon-size)' }} />`。
   排查确认 antd 的 token 是 `onlyIconSize: 'inherit'`，即
   `.ant-btn-icon-only .anticon { font-size: inherit }`，
   上一轮写在 Button 上的字号其实生效了（图标不是本次问题所在）；
   但直接写在图标上更明确，也避免将来 antd 调整该 token 时失效。

**三、类型系统**

`styles.x` 在 `noUncheckedIndexedAccess` 下是 `string | undefined`，
而 antd `ButtonProps.className` 声明为 `string`（不含 `undefined`），
`exactOptionalPropertyTypes` 会拒绝显式传 `undefined`。
按本项目既有写法（`MainLayout.tsx` 的 `styles.lockOverlay ?? ''`）统一用
`?? ''` 兜底，共 4 处。

### 遇到的问题与解决
- **问题：`align="center"` 改了没用**
  - 定位方法：直接读 antd 源码 `space/index.js` 与 `space/style/index.js`，
    确认默认 align 就是 center，且 `ant-space-item` 是 block 级。
  - 解决：不再依赖 antd Space 的对齐能力，换原生 flex 容器。
- **问题：误判图标字号被 antd 覆盖**
  - 起初以为是 `.ant-btn-icon-only .anticon { font-size: 16px }` 覆盖了 Button 的字号，
    并在 CSS 注释里这么写了。查 `button/style/token.js` 后确认实际是
    `onlyIconSize: 'inherit'`，注释不成立。
  - 解决：已把注释改为真实原因（依赖继承链，直接写死更明确），不留错误结论在代码里。
- **问题：`npx tsc -b` 在管道里返回 1 但无输出**
  - `npx tsc -b 2>&1 | head -10` 后取 `PIPESTATUS[0]` 得到 1，但无任何错误信息；
    去掉管道直接跑 `npx tsc -b` 退出码为 0，
    `npx tsc --noEmit -p tsconfig.app.json` 也为 0。
  - 判断为管道取退出码方式的误报（或增量 tsbuildinfo 状态问题），
    以「无管道直接跑」的结果为准。后续验证应直接跑，不经 head 管道。
