### 开发内容详述

#### 一、修正 112 号日志的错误判断

112 号日志记录：「itemPaddingSM（8px 16px）仅作用于 .ant-list-bordered.ant-list-sm，本项目列表无 bordered，故取 12px」。此判断**错误**。

重新核查 antd 5.29.3 源码 node_modules/antd/es/list/style/index.js 后确认，存在两条独立规则：

- L33：[`${listBorderedCls}${componentCls}-sm`] —— 作用于 .ant-list-bordered.ant-list-sm 的 item / header / footer
- **L297：[`${componentCls}-sm ${componentCls}-item`] —— 无条件作用于所有 .ant-list-sm .ant-list-item**

二者都赋 padding: itemPaddingSM。因此 size="small" 的列表无论是否 bordered，列表项内边距均为 8px 16px。112 号日志中「列表项 → 列表项 = 12px」的实测结论应为 **8px（垂直）/ 16px（水平）**。

本日志为修正记录，112 号日志原文不改动，以保留审计轨迹。

#### 二、由此暴露的水平缩进缺陷（本轮实际修复项）

首页 4 个列表组件（Todos / Announcements / Notifications / Calendar）均为 <List size="small"> 且嵌于 Card 内。逐层追踪左内边距：

| 层级 | 左内边距 | 内容相对外框左缘位置 |
|---|---|---|
| .widgetHeader（拖拽手柄） | 16px（--card-padding） | +16px |
| .ant-card-head（标题） | 16px（108 号日志覆盖） | +16px |
| .ant-card-body | 16px（108 号日志覆盖） | +16px |
| .ant-list-item | **16px（antd itemPaddingSM）** | **+32px** |

标题与拖拽手柄在 +16px，列表内容在 +32px —— 列表内容相对标题向右缩进 16px，属标题与正文左缘不对齐的视觉缺陷。

修复：新增

.widgetBody :global(.ant-list) :global(.ant-list-item) {
  padding: var(--spacing-xs) 0;
}

垂直取 8px（= --spacing-xs，同时沿用 antd 小列表原有密度，不做无谓改变）；水平归零，交由 .ant-card-body 的 16px 统一控制左缘。修复后列表内容与标题、拖拽手柄三者左缘齐平于 +16px。

说明：原计划的 padding: var(--spacing-sm) 0 会把垂直密度从 8px 改为 12px，属额外的视觉变更，故未采用，仅做水平对齐修正 + token 绑定。

#### 三、快捷入口间距显式覆盖

QuickLinksWidget 的 <Space wrap> 未指定 size，走 antd 默认 small，其间距由全局 token paddingXS（= 8px）派生，属巧合对齐。

改为 <Space wrap style={{ gap: 'var(--spacing-xs)' }}>。

选择内联 style 而非 size 属性的原因：已核实 antd 的 _util/gapSize.js 中 isValidGapNumber 要求 typeof size === 'number'，不接受 CSS 变量字符串；若传 'var(--spacing-xs)' 会被判定无效而不写入 gap，退化为 0。故必须走内联 style。
