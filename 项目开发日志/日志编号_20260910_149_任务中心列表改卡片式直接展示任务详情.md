### 开发内容详述

#### 一、为什么换

原表格版每行只有标题加若干标签，任务的 description 字段完全不出现在列表里。
看一条任务写了什么，必须点「编辑」打开弹窗——而弹窗是编辑入口，只读成员
（非创建者）连点都点不了，等于公开任务里他人的内容对非创建者是不可见的，
与「列表可见即详情可见」的直觉相反。

卡片式把标题、描述、状态、优先级、可见性、截止日期、标签、时间全部平铺在
一张卡片上，一眼看完，编辑弹窗只作为修改入口保留。

#### 二、卡片结构

```
┌──────────────────────────────────────────────────────────────┐
│▍ [状态 ▾]  标题                    [优先级][可见性]  编辑 删除 │
│                                                              │
│  任务描述直接展示，超过 3 行折叠，可「展开 / 收起」              │
│                                                              │
│ ─────────────────────────────────────────────────────────── │
│ 📅 截止 09-20 · 🏷 #标签 #标签 · 🕐 创建 ... · 更新 ...        │
└──────────────────────────────────────────────────────────────┘
```

- **左侧状态色条**：3px 竖条，颜色随状态切换——待办 `--text-tertiary`、
  进行中 `--color-info`、已完成 `--color-success`、已取消 `--color-error`，
  扫一眼列表就能分辨状态，不用逐个读标签
- **状态选择器内联保留**：非创建者行 `disabled`，改状态不必进弹窗
- **描述折叠按实测溢出决定**：新增 `TaskCard` 组件，
  `useLayoutEffect` 里比较 `el.scrollHeight > el.clientHeight + 1`，
  **只有描述确实被 `-webkit-line-clamp: 3` 截断时才渲染「展开」按钮**，
  短描述不会冒出一个点了没反应的按钮
- **空描述有占位**：无 description 时显示「未填写任务描述」，
  而不是留一块空白让人以为渲染出错
- **元信息行**：截止日期（`CalendarOutlined`）、标签、创建时间、
  更新时间（仅当 `updated_at !== created_at` 才显示），与内容区用
  `--border-tertiary` 分隔线分开

#### 三、权限与后端未改动

列表接口本就返回 description / tags（`TaskResponse` 已含这两个字段），
所以本次**不需要任何后端改动**。

权限口径保持：`canManage = task.owner_id === currentUserId`，
管理员无额外权限，与后端 403 一致。非创建者卡片显示「只读」。

#### 四、可维护性

`STATUS_OPTIONS` / `PRIORITY_OPTIONS` 提为模块级常量，避免每次渲染重建；
`formatDateTime` / `formatDate` 收敛日期格式化；`TaskCard` 独立成组件，
折叠状态内聚在卡片自身，父组件只管数据与回调。

### 遇到的问题与解决
- 问题：描述折叠按钮如果无条件显示，短描述卡片会出现一个点了没反应的「展开」
  解决方案：`useLayoutEffect` 实测 `scrollHeight` 与 `clientHeight`，
  仅溢出时渲染按钮；展开后依赖数组含 `expanded`，会自动重算
- 问题：`assigned_to` 是 UUID，列表里直接显示是串数字，比不显示更糟
  解决方案：本次不显示该字段，见遗留问题
- 遗留问题 / 待办：
  - `assigned_to` 需要用户名映射才能可读展示。列表接口目前只回 UUID，
    需要后端在 `TaskResponse` 加 `assigned_to_name` 或提供批量用户名查询
  - 卡片式在任务量大时首屏信息密度低于表格，若后续需要可加「卡片 / 表格」视图切换
