### 开发目标
1. 新增服务器管理模块：服务器（名称/用途/位置/IP/端口/简介/备注/状态）
2. 服务器分单系统/多系统两种类型，创建后不可更改，变更需标记"重新部署"状态
3. 服务器下管理多个系统（System），系统下管理多个服务（Service）
4. 服务可标记服务目标（设备/人员/组织，组合字段）
5. 维护人员必须是工作台成员（关联 User 表）

### 开发内容详述

#### 数据库
- 新增 servers/systems/services 三表，外键 CASCADE 级联删除
- server_type 使用 CheckConstraint（String(20)）而非 sa.Enum，因 PG15 不支持 CREATE TYPE IF NOT EXISTS

#### 后端
- owner 权限隔离：System/Service 通过 join 链校验 Server owner
- log_audit 审计记录
- SINGLE 类型自动创建默认系统，命名规则为 f"{server.name}-系统"

#### 前端
- 标准管理页模式（与 ContentManagement 同构）
- 单系统直接展示服务列表
- 多系统使用 antd Tree + 服务 Table
- deploy_status 状态机：NORMAL → PENDING_REDEPLOY → REDEPLOYING → NORMAL
- 维护人员 Select multiple，从 /users 拉取成员

### 遇到的问题与解决
- 问题1：根 tsconfig.json 是 project-references 壳（files:[]），`npx tsc --noEmit` 是假阳性
  - 解决方案1：真实检查以 `npm run build` 的 `tsc -b` 为准
- 问题2：本地 alembic shebang 指向旧路径
  - 解决方案2：使用 `python -m alembic` 执行迁移
