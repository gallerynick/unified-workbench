### 开发内容详述

#### 根因
Vite 产物按内容哈希命名，每次部署重新构建后旧哈希 chunk 已不存在。
长时间闲置的标签页内存里仍是部署前的 entry bundle（记录旧哈希），
回来后点击尚未加载过的模块时 React.lazy 的 import() 请求旧 chunk 得到 404，
抛出 TypeError: Failed to fetch dynamically imported module，
命中 React Router 内置默认错误页。刷新后因 index.html 为 no-store 而拿到新 manifest 恢复。

已加载过的模块代码在内存中不再请求，故不受影响——这正是"点其他模块才崩"的来源。

线上实测证实该机制：用户报错的 NotificationsCenter-DY3fFVsG.js 返回 HTTP 404
（响应体是 nginx 的 153 字节 404 HTML，Content-Type 为 text/html），
而当前版本的 NotificationsCenter-BS93JGVB.js 返回 200。

#### 主动探测（startBuildWatcher）
index.html 在 nginx 中是 no-store，manifest 内 entry 脚本名带内容哈希。
每 60 秒轮询一次，并在 visibilitychange 恢复可见与 window focus 时立即检查；
探测到哈希变化只置内存标记，不主动刷新，由下一次懒加载消费。
开发模式无哈希产物时自动跳过。

#### 被动兜底（lazyChunk）
新增 lazyChunk，签名与 React.lazy 一致。router.tsx 中改为
「import { lazyChunk } from './utils/chunkGuard';」加「const lazy = lazyChunk;」两行，
47 处 lazy(() => import(...)) 调用零改动获得保护。

import() 失败且错误信息匹配 chunk 失效特征时自动 reload 一次，
并返回永不 resolve 的 Promise 让 React 保持 Suspense，等待整页刷新完成。
sessionStorage 记录刷新时间戳，2 分钟保护窗口内不重复刷新；
sessionStorage 不可用时放弃自动刷新、把异常交给错误页，避免无限循环。

判定正则刻意收窄：不匹配离线的 "NetworkError when attempting to fetch resource."，
因为离线时刷新无意义，反而会占用 2 分钟保护窗口、让随后的真实 chunk 失效无法自动恢复。

#### 全局错误边界（ErrorBoundary + RouteErrorElement）
- ErrorBoundary（类组件）：在 main.tsx 中包裹 App / UserProvider / LockProvider / RouterProvider，
  使其继承 ConfigProvider 的深浅色模式。承接路由树之外的未捕获异常
  （路由守卫、上下文 Provider、布局容器、React Router 自身初始化阶段）。
- RouteErrorElement（函数组件）：挂在 router.tsx 全部 8 个顶层路由的 errorElement 上。
  这是替换 "Unexpected Application Error!" 的关键——React Router 在路由组件渲染失败时
  由路由级错误边界接管，外层 ErrorBoundary 拿不到该错误，只有 errorElement 能覆盖。
- 两者共用 ErrorResult 渲染：antd Result + 「重新加载页面」按钮（ReloadOutlined 图标，
  符合禁 Emoji 规范），按 chunk 失效 / 业务异常给出不同文案，控制台输出完整错误栈。

### 遇到的问题与解决
- 问题：外层 ErrorBoundary 无法替换 "Unexpected Application Error!"
- 解决方案：新增 RouteErrorElement 并挂到 8 个顶层路由的 errorElement，
  覆盖全部路由（含 /login、/welcome、/lock、/debug-mode、/stream/watch、share、forms/fill
  与 AuthGuard 子树）。
- 问题：tsc 报 TS4114（noImplicitOverride）
- 解决方案：为 ErrorBoundary 的 state / componentDidCatch / render 补 override 修饰符。
- 问题：全量类型检查 tsc -b --force 报 2 个错误，与本次改动无关
  - src/pages/forms/FormFill.tsx(50,19)：FormPublic 的 description 为 string | null，
    与 FormPublicData 的 string 不兼容
  - src/pages/forms/FormManagement.tsx(49,9)：Visibility 的 'private' 与 FormVisibility 不兼容
- 解决方案：确认 git status / git diff 对 forms 目录为空，这两处是 HEAD 中已存在的存量问题，
  此前被增量的 .tsbuildinfo 掩盖。未擅自修改他人模块，改用 npx vite build 出包；
  全量检查中本次改动的 4 个文件零错误。建议在表单模块收尾时一并修复。
- 问题：从仓库根目录执行 bash 项目文件/start.sh 报
  "项目文件/scripts/docker-detect.sh: No such file or directory"
- 解决方案：start.sh 先 cd "$(dirname "$0")"，随后仍用 $(dirname "$0") 拼接脚本路径，
  两次解析不一致。改到脚本所在目录执行（cd 项目文件 && bash start.sh）即可。
  遗留：建议把 start.sh 内的路径拼接统一为 cd 之后的相对路径，避免根目录执行失败。
