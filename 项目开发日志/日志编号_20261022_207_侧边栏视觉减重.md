### 开发内容详述

**1. 默认只展开「常用」，其余类别折叠**

这是最大的一处减重，同时回到最初需求原话「保留用户常用项避免臃肿，剩余项折叠、点击折叠按钮展开」。首次访问时 `collapsedGroups` 初始化为除 `group:pinned` 外的全部类别，侧栏首屏由 21 项降到 4 项 + 5 个类别路标。

配套解决「选中项可能藏在收起组里」的问题：新增 effect，当前路由所属类别自动展开。**不写 localStorage**——用户手动收起当前组时不能被立刻弹开，只在切换页面时再展开一次。

**2. 分隔线从通栏实线改为内缩发丝线**

原 `border-top` 横贯整个侧栏宽度，5 条实线把侧栏切成碎片。改为 `::before` 伪元素，左右各缩进 16px，并与菜单项左右边界对齐。线色从 `--border-tertiary` 再降一档到 `--divider-soft`（浅色 #f0f0f0）。

底部「个人区 / 系统设置」那条线保持 `--border-primary`（#d9d9d9）不变，层级差进一步拉开。

**3. 类别头减重**

| 项 | 改前 | 改后 |
|----|------|------|
| 高度 | 26px | 20px |
| 上边距 | 6px | 2px |
| 字号 | `--text-body-xs-size` | 同（11px 档），但 `line-height: 1` 收紧 |
| 字距 | 0.02em | 移除 |
| 箭头 | 常驻 opacity 0.6 | 默认 opacity 0，仅悬停/聚焦显示 |

**4. 菜单密度下调**

`Menu.itemHeight`：舒适 40 → **36**，紧凑 32 → **30**。同时清掉多段 Menu 叠加产生的默认内边距（`.ant-menu-inline { padding: 0 }`）与重复的 `border-inline-end`。

**5. 折叠状态可见性补偿**

箭头改为悬停才显示后，收起的组会「看不出是收起的」。因此收起态额外挂 `categoryCaretShown`（opacity 0.45 + 旋转 −90°），保证「已折叠」这一状态始终可辨识——减重不能牺牲状态可见性。

### 遇到的问题与解决

- 问题：箭头默认隐藏会让折叠态失去视觉提示。
- 解决方案：新增 `categoryCaretShown` 修饰类，仅在组已收起时强制显示；展开态仍靠悬停提示。四处渲染点（桌面类别 / 桌面未显示桶 / 抽屉类别 / 抽屉未显示桶）统一替换。

- 问题：多段 `<Menu>` 叠加后，antd 默认 `ul` 内边距与 `border-inline-end` 累积成多余留白与竖线。
- 解决方案：在 `.categorySection` 作用域内清零 padding 并去除 `border-inline-end`。

- 遗留：`assignMenuAnimDelays` 的依赖里含 `collapsedGroups`，切换分组会重算延迟。因 CSS 动画只在节点首次挂载播放，重设延迟不重放动画，视觉可接受。
