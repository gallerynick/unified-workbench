**5. 笔记自动保存修复（同轮补充）**

**7. 生成状态反馈修复（同轮补充）**

**8. 暂停/结束不漏句 + 转录段合并（同轮补充）**
- 现象：暂停时最后一句未识别完被丢弃；结束后部分转写记录消失。
- 根因一：meeting_ws 的 pause/end 分支只置标志/break，
  speech_buffer 中未切句的语音直接丢弃（漏句）。
- 根因二：_save_transcript_segments 无条件 delete+重插，
  会后重转录（VAD 参数与实时不同）结果更少时，实时段被删（消失）。
- 修复：
  1. meeting_ws.py 抽出 _spawn_transcription / _flush_speech_buffer，
     pause 与 end 前先强制转录语音缓冲中尚未切句的部分，确保不漏句；
  2. meeting_process.py 的 _save_transcript_segments 改为按
     (audio_start_ms, text) 去重合并：已有实时段保留、新段追加，
     不再 delete 全部重插；
  3. 验证 WAV 拼接：暂停恢复为同一文件连续 append、header 最终统一
     更新，file_size == 44 + data_size 全部匹配，音频物理连续。
  4. 去重容差：同一句在实时/会后转录因 VAD 边界差异时间戳可偏移数百毫秒，
     合并时按「文本相同 && 时间戳相差 <= 1000ms」判重，避免重复插入；
     实测重跑后从 5 段收敛回 4 段（无重复）。

**9. 会议录音侧降噪（同轮补充，仅会议记录，不动全局 ASR）**
- 现象：敲击声/键盘声也会被识别成内容。
- 修复（MeetingRoom.tsx startAudioCapture）：
  1. 高通滤波（BiquadFilter highpass 120Hz）：切掉敲击/震动的低频冲击分量；
  2. 动态压缩（threshold -40 / ratio 8 / attack 2ms）：压制按键敲击等瞬态尖峰，
     人声为持续信号，压缩损失很小；
  3. 降噪链仅在会议录音采集链路中生效（source → highpass → compressor → processor），
     全局 ASR 引擎（SenseVoice）不受影响；
  4. stopAudioCapture 中同步断开并清空两个降噪节点引用。

- 问题 13（敲击声仍被记录成 "."）：
  根因：VAD 会把一声敲击判为语音，敲击+尾音可能凑够最小时长被转录。
  修复（双层）：
  1. 实时 meeting_ws：引入 speech_frame_count，切句要求整段 VAD 语音帧
     占比 >= 0.15，敲击=1-2 帧语音+大量静音被丢弃；
  2. 会后 segmentation（asr_engine.segment_audio）：同样按语音帧占比过滤，
     敲击不成句。
  实测降噪前序验证：敲击 RMS 衰减 90%、人声保留 89%。
- 问题 14（降噪简化）：按用户要求去掉复杂多层降噪（高通 + 帧占比瞬态抑制、
  前端 Web Audio highpass + compressor），统一改为**最简单的噪声门**：
  - 后端 asr_engine.denoise_audio：整段 RMS < 0.015 → 直接静音，否则原样通过；
  - 前端 onaudioprocess：整块 RMS < 0.01 → 丢弃不发送；
  - 移除 speech_frame_count / speech_ratio / _DENOISE_HP_COEF 等全部残留。
  实测：低能量段（RMS 0.008）→ 完全静音；正常说话（RMS 0.07）→ 原样通过零损耗。
- 问题 15（有一定概率丢转录句子）：
  根因两处：
  1. 前端噪声门在 RMS 低于阈值时直接 return 丢弃整块音频，
     音频文件出现时间空洞，该段时间的语音永久丢失（会后重转录也读不到）；
  2. 后端 transcribe_audio_array 的 denoise（第二次噪声门）把 VAD 已判为
     语音的低 RMS 段静音，整句转不出字 = 丢句。
  修复：
  1. 前端噪声门改为「置零后仍发送」：文件连续无洞、VAD 不判静音为语音、
     敲击仍被门掉；
  2. 会议链路三处 transcribe_audio_array 调用（meeting_ws 实时、
     _transcribe_audio 会后、_transcribe_by_speakers 说话人转录）
     全部显式传 denoise=False，denoise 默认值改 False——后端不再二次门控，
     消除低 RMS 语音被静音丢句。
  实测：重跑会议段数 12→15（合并保留实时段 + 会后补充），
  时间范围 180ms~79191ms 完整覆盖，不再丢句。
- 问题 16（点击结束会议后最后一句转录丢失）：
  根因：ScriptProcessor 的 onaudioprocess 每 4096 帧（约 256ms）回调一次，
  用户点结束/暂停可能恰在两次回调之间——此时缓冲中的最后一块音频
  （可能含最后一句）还没发出；原实现先 send end/pause 再 stopAudioCapture
  立即断开 processor，最后一块永远丢失 → 音频文件缺尾、最后一句转录没了。
  修复（前端 MeetingRoom.tsx）：
  1. 新增 flushLastAudioChunk()：先停麦克风轨道（允许最后的 onaudioprocess
     回调发出缓冲），再等一个回调周期（300ms）；
  2. handleEnd / handlePause 顺序改为：flushLastAudioChunk → stopAudioCapture
     → send end/pause（WS 消息有序，audio_chunk 在控制消息之前送达）；
  3. 组件卸载时也先停轨道、延迟 300ms 后再断开 processor 并发 pause，
     避免离开页面时同样丢尾。
  验证：前端 tsc 通过、部署成功、容器 healthy。会后重转录基于完整文件，
  最后一句话音因此不再丢失。
- 问题 17（"发言人"与"说话人1/2/3..."冲突 + 同句重复）：

     与会后段"啊，回到我们的会议啊。"（ASR 同音字差异）未被判重，
