### 遇到的问题与解决

- **git 非 ASCII 路径转义导致跟踪状态误判**：git status --porcelain 与 git ls-files 的默认输出均按 octal 转义中文路径，据此判定「是否已跟踪」会全部失败，进而把已跟踪文件交给 os.rename 而非 git mv，产生 6 处「删除+新增」而非重命名。解决：改用 git ls-files 配合 -c core.quotepath=false 精确比对。

- **重复执行导致标准标题行被多次插入**：第一遍执行中途失败后重试，update_heading 的匹配分支未覆盖「序号已改、文件名未改」的中间态，被判为「无标题」而重复插入标准标题行。解决：先 git reset --hard 回到干净基线，再从空跑快照一次性重建；并让标题匹配覆盖中间态，最终校验幂等性全 0。

- **并发会话在途日志的处理**：重排期间另一个会话正在提交自己的日志（4 份未跟踪 + 1 份已跟踪未提交）。解决：以执行前快照为唯一内容来源重建全部 98 份文件，在途内容一并保留；6 份本应 git mv 的文件已按重命名方式恢复，git 历史记录完整可追溯。
