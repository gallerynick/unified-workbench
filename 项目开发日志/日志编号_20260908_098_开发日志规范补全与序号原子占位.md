#### 三、序号原子占位脚本

新增 项目文件/scripts/claim_log_number.sh。核心机制：用 `mkdir` 对同名目录
做原子占位——POSIX 保证多个会话同时抢占同一序号时恰好只有一个成功，
不需要任何会话间通信，因此适用于会话之间完全不联系的场景。

配套规则：
- 占位成功后该序号归本会话独占，写完日志并 `git add` 后 `rm -rf` 释放
- 遗留锁按目录 mtime 判定（默认 24 小时），崩溃会话留下的锁可被自动回收
- 锁目录 `项目开发日志/.locks/` 已加入 .gitignore

#### 四、已知边界

原子 mkdir 依赖同一文件系统。若多个会话运行在不同机器或不同 git 克隆上，
锁文件不共享，本机制失效——此时必须改为串行写日志，或由一位维护者统一编号。
该边界已写入基定。

### 遇到的问题与解决
- 问题：`n=$((max + 1))` 在 max=087 时报「value too great for base」
- 解决方案：加 `10#` 前缀强制十进制，避免前导零被当八进制解析
- 问题：TOCTOU 竞态——原设计用 `claimed_at` 文件内容判遗留锁，
  「目录已建、文件未写」的窗口期会被其他会话误判为陈旧锁并把新锁 `mv` 走，
  导致两个会话拿到同一序号（40 并发实测复现）
- 解决方案：改用目录 mtime 判定遗留锁（`find -mmin +1440`）
- 问题：`LOG_DIR=$1` 在 `set -u` 下未传参数时直接报 unbound variable
- 解决方案：改为默认值 `LOG_DIR=项目开发日志` + `[ $# -ge 1 ]` 判断
- 遗留问题 / 待办：94 个历史日志的撞号 / 断号 / 格式问题尚未重排（见「下一步计划」）
