### 开发内容详述

**一、根因（按真实像素算，不是估算）**

侧栏宽 280px，控件区四周内边距 12px，实际可用宽度只有 256px。

筛选按钮的构成：按钮左右内边距 14px + 筛选图标 14px + 图标间距 8px +
「筛选」两个汉字 28px。视图切换 Segmented（small，两项各含图标+文字）
约 136px。两控件之间的间距 12px。

徽标此前的写法是「有数量才渲染」，而且内边距与最小宽度各自撑开，
实际占位 = 左边距 8 + 最小宽 17 + 左右内边距 16 = 41px；箭头再占 20px。

  - 无筛选时：按钮 64px，整行 64 + 12 + 136 = 212px ✓ 在 256px 内
  - 有筛选时：按钮 125px，整行 125 + 12 + 136 = 273px ✗ 超出 17px

也就是说整行本来只剩十几个像素余量，徽标一出现就吃掉 61px，
把 Segmented 顶过侧栏右边界、越过与编辑区之间的分割线——正是现象本身。

**二、修法**

1. 徽标占位恒定：数量为 0 时同样渲染占位，只是 visibility: hidden。
   按钮宽度在筛选前后完全一致，不再有任何横向位移。
2. 徽标压窄：去掉左右内边距与最小宽度，改为固定 width: var(--spacing-md)
   （17px，可容纳两位数字），垂直居中改用 inline-flex + align-items: center，
   并加 overflow: hidden 防止极端数字溢出。占位从 41px 降到 25px。
3. 去掉按钮上的 FilterOutlined 图标：占位恒定之后图标纯属装饰，
   且它额外占用 22px，正是 256px 预算下真正卡住的那一块。
   换成 Tooltip「筛选笔记」保留可发现性，aria-label 不变。
4. 箭头保留（与页面右上角面板按钮一致的下拉语义），
   控件间距由 12px 收窄到 8px（本模块已确立的最小档）。
5. 兜底：控件行加 min-width: 0，两个子项加 flex-shrink: 0。
   空间再紧张时也不许 Segmented 被压缩变形，只能保持自然宽度。

改造后按钮 = 内边距 14 + 筛选 28 + 徽标 25 + 箭头 20 = 87px，
整行 = 87 + 8 + 136 = 231px，在 256px 内余 25px。

### 遇到的问题与解决

- 问题：一开始按经验估算行宽，得出「无徽标 220px、有徽标 235px，都没超过
  256px」的结论，与用户实际看到的溢出矛盾。
  解决方案：改为按 antd 5.29 的实际度量重算——按钮 small 内边距 0 7px、
  Segmented small 项内边距 0 8px、轨道内边距 2px，得出 Segmented 实测约
  136px、有徽标按钮 125px，整行 273px，确实超出 17px，与现象吻合。
  教训是像素预算必须用组件真实度量，不能用「大概」估。

- 问题：ant d 的 segmentedPaddingHorizontalSM 等度量在源码里没有字面量，
  全仓库 grep 只能定位到引用点，取不到数值。
  解决方案：改用 antd 官方稳定的基础 token 约定（paddingXS 8 / paddingSM 12 /
  controlHeightSM 24 / trackPadding 2）推算，并在日志中把估算值写明，
  便于后续用浏览器实际量取时校正。
