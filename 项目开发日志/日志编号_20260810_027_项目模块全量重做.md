### 开发内容详述
1. **数据库层（迁移 034）**
   - 重建 `project` 表：`number`（项目编号）、`member_ids`（JSONB 成员列表）、`visibility`（可见性）、`status`（项目状态）、`status_log`（JSONB 状态变更日志）、`member_permissions`（JSONB 9 分区权限配置），对齐《Project_开发手册/Ver.1》字段体系。
   - 新建 7 张子表，外键统一 `ondelete="CASCADE"`（`assignee_id` / `proposal_id` 等语义上应保留数据的按 SET NULL），并为高频查询列（`project_id`、`user_id`、`source_type+source_id` 等）建立索引。
2. **后端（8 模型 + 8 Schema + 8 Service + 8 API）**
   - 模型与 Schema 一一对应，遵循既有代码风格（`Mapped` / `mapped_column`、`from __future__ import annotations`、UUID 主键、`DateTime(timezone=True)` + `server_default=func.now()`、中文 `comment`）。
   - 路由采用 flat 前缀：`/project-members`、`/project-proposals`、`/project-meetings`、`/project-changes`、`/project-todos`、`/project-events`、`/link-relations`，统一经 `api/router.py` 注册。
   - `services/project_common.py` 提供通用校验：`get_project_or_404`（项目存在性）、`is_project_member`（成员判定）、`require_project_member`（非成员 403）、`require_project_section_permission`（按分区校验 readonly 写操作 403）。
3. **前端（9 Tab 详情页 + 编号体系 + 权限面板 + 移交表单）**
   - 详情页重构为 9 Tab：信息 / 人员 / 进度 / 提案 / 待办 / 交流 / 修改 / 文档 / 事件，统一数据加载与权限上下文。
   - 编号体系对齐手册：提案 `PRP-{项目编号}-{序号}`、会议 `MTG-`、变更 `CHG-`、待办 `TOD-`、事件 `EVT-`，前端按 `total+1` 生成并 `padStart(3, '0')`，项目编号为空时回退 `project.id` 前 8 位大写。
   - `ProjectPermissionsModal`：9 分区权限配置面板，owner / admin 可配置，其余成员只读查看。
   - 移交表单（对接《Project_开发手册/Ver.1》交接表规格）：三方角色（移交人 / 接收人 / 见证人）、四维度检查清单、资产清单、双方签字确认。
4. **分区权限模型**
   - `member_permissions` 9 分区：`info` / `members` / `progress` / `proposals` / `todos` / `meetings` / `changes` / `documents` / `events`，每分区取值 `readonly` 或 `manage`。
   - owner 与 admin 全权；默认（无分区配置）成员增删改查，与重做计划默认行为一致。
   - 后端 `require_project_section_permission` 拦截 readonly 分区的写操作返回 403；前端对应操作按钮渲染为 disabled + Tooltip「只读权限」，双层拦截。

### 遇到的问题与解决
- 问题 1：T1 并行任务执行时 T2 的模型文件尚未落盘，T3 以模型为源重建 Schema 时读到旧结构。
  - 解决方案：等 T2 模型文件合并后，T3 重新以最终模型为准重建 Schema，确保 8 组模型 / Schema 一一对应。
- 问题 2：`models/project.py` 残留旧 `project_id` 列，与 034 迁移重建冲突。
  - 解决方案：删除残留列，并同步清理三处 schema / service 中对旧 `project_id` 的引用。
- 问题 3：冒烟测试发现 033 迁移的 `down_revision` 链断裂（既有缺陷，非本次引入）。
  - 解决方案：以手动 SQL 直接应用 034 迁移，并将 `alembic_version` 置为 034；该既有缺陷记录在案，另行排期修复迁移链。
- 问题 4（缺陷 #1）：前端 `ProjectPermissionsModal` 提交 `member_permissions`，但后端 `ProjectUpdate` schema / service 不处理该字段，导致配置无法持久化。
  - 解决方案：schema 补 `member_permissions` 字段，`update_project` 增加写入处理；热部署后复测 PUT 持久化通过。
- 问题 5（缺陷 #2）：迁移 034 的 `project_member` 表缺 `created_at` 列，与模型定义不一致。
  - 解决方案：在迁移文件中补 `created_at` 列，与模型对齐。
- 问题 6：既有健康检查缺陷（nginx / celery healthcheck 误报），本次冒烟中再次暴露，非本次引入。
  - 解决方案：仅记录不修复，排期另行处理。
