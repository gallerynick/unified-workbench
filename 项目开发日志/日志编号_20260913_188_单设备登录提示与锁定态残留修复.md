### 开发内容详述

#### 1. 问题根因（三个因素叠加）
- **幽灵会话累积**：开启「允许多处登录」期间，同一浏览器反复重新登录（token 过期跳登录页再登录等）会留下多个未撤销会话行（未走 logout）；关闭开关后某次重新登录，`_enforce_single_device` 把这些旧会话（**包括用户自己同一浏览器的旧会话**，原实现不区分 device_token）全部下线并计入 `revoked_session_count` → 前端提示「该账号已在 N 个设备登录」（误导：其实是自己的旧会话）。
- **锁定态残留**：`Login.finishLogin` 登录成功后未清除 `workbench_locked`（sessionStorage）→ 路由到 `/` 时被 `LockGuard` 拦回 `/lock` → 「到锁定页要再来一遍」。
- **token 过期链**：锁定/闲置期间 access token 过期，解锁时请求 401 → refresh 失败（会话被下线或 refresh token 过期）→ 整页跳 `/login` → 「也可能要再登录一遍」。

#### 2. 修复方案
- **后端** `_enforce_single_device` 增加 `device_token` 参数：返回的「其他设备会话数」只统计 device_token 与本次登录**不同**的会话（无 device_token 的历史会话计入，防漏报）；下线行为不变（单设备模式下全部下线，保持严格语义）。`_issue_tokens` 传入本次登录的 device_token（login / verify-2fa / WebAuthn 三路统一汇聚）。
- **前端** `Login.finishLogin`：
  - 登录成功后调用 `unlock()`（清除锁定态），重新登录直接进入工作台；
  - 提示逻辑精确化：仅当 `revoked>0 且 others>0`（真实其他设备被下线）才提示「已在其他设备登录」；同一浏览器遗留旧会话被下线（revoked>0 且 others=0）时不再误报，仅显示登录成功。

### 遇到的问题与解决
- 问题：后端测试导入 `app.main` 时失败（`ModuleNotFoundError: No module named 'webauthn'`）—— 工作区已引入 WebAuthn（pyproject 已声明 webauthn>=2.0），但测试 venv 未安装；沙箱无外网（PyPI/清华镜像均连接失败），且容器内 cbor2 为 Linux C 扩展无法跨平台拷贝。
  - 解决方案：单设备测试改为 **service 层单测**（直接调用 `_enforce_single_device`，不经过 app.main，绕开 webauthn 依赖）；真实运行环境（容器内依赖完整）另行通过真实 API 完成端到端验证。
  - 遗留：测试环境后续需要网络可用时 `pip install webauthn` 补齐依赖，既有 test_auth 等 client 级测试方可运行（环境问题，与本次改动无关）。
