### 开发内容详述

#### 一、根因：状态接口查的是不存在的目录

这是「测试 / 删除按钮不出现」的唯一原因。按钮不是被删了，而是被一个永远为假的判断挡住了：

```tsx
{asrModelStatus === 'downloaded' && (
  <Space>
    <Button onClick={handleTestASR}>测试识别</Button>
    <Button onClick={handleReloadASR}>重载模型</Button>
    <Button danger onClick={handleDeleteASRModel}>删除模型</Button>
  </Space>
)}
```

而 `asrModelStatus` 来自 `/asr/status`，后端是这么查的：

```python
asr_model_dir = "/data/asr-models"          # ← 这个目录从头到尾不存在
main_model = os.path.join(asr_model_dir, "paraformer-zh")
punc_model = os.path.join(asr_model_dir, "ct-punc")
spk_model  = os.path.join(asr_model_dir, "campplus")
```

两处都不对：

1. **路径错** — FunASR / ModelScope 把权重缓存在 `$MODELSCOPE_CACHE/models/`
   （容器里是 `/home/workbench/.modelscope/models/`），实际已占用约 3.0 GB。
   `/data/asr-models` 从未被任何代码写入过，所以状态永远是 `not_downloaded`。
2. **名字错** — 缓存目录名是 ModelScope 的仓库 ID
   （如 `iic--speech_seaco_paraformer_large_asr_nat-zh-cn-16k-common-vocab8404-pytorch`），
   不是配置里填的 `paraformer-zh` / `ct-punc` / `campplus`。就算路径对了也匹配不上。

于是「模型已就绪」永远不成立，三个按钮永远不渲染，界面上只剩一个 `disabled` 的「下载模型」。

#### 二、别名解析交给 FunASR 自己的表，不自己维护

不自己写一份「别名 → 仓库 ID」映射，避免它随 FunASR 升级而漂移：

```python
from funasr.download.name_maps_from_hub import name_maps_ms

def _repo_id_for(name: str) -> str:
    alias = _modelspec_alias(name)      # campplus / cam / cam+ → cam++
    return name_maps_ms.get(alias) or name_maps_ms.get(name) or alias
```

实测解析结果：

| 配置名 | 解析出的仓库 ID |
|---|---|
| `paraformer-zh` | `iic/speech_seaco_paraformer_large_asr_nat-zh-cn-16k-common-vocab8404-pytorch` |
| `fsmn-vad` | `iic/speech_fsmn_vad_zh-cn-16k-common-pytorch` |
| `ct-punc` | `iic/punc_ct-transformer_cn-en-common-vocab471067-large` |
| `campplus` | `iic/speech_campplus_sv_zh-cn-16k-common` |

顺手修掉一个隐患：配置里 `spk_model` 默认填的是 `campplus`，而 FunASR 的别名表里只有
`cam++`。原代码把 `campplus` 直接透传给 `AutoModel`，会被当成仓库 ID 去下载并失败。
现在统一在入口处归一化。

#### 三、「就绪」判据用 config.yaml，不用 model.pt

四个模型快照里的权重文件名各不相同：三个是 `model.pt`，campplus 是
`campplus_cn_common.bin`。所以不能用权重文件名做统一判据。四个快照根目录都有的只有
`config.yaml`，于是用它：

```python
def _model_ready(cache_dir: str) -> bool:
    snap = _snapshot_dir(cache_dir)
    if not snap:
        return False
    cfg = os.path.join(snap, "config.yaml")
    return os.path.isfile(cfg) and os.path.getsize(cfg) > 0
```

另外顺手区分了两种「体积」：
- 展示用 `_top_level_size_bytes` 只算快照第一层的普通文件。快照里的 `example/`、`fig/`
  是官方样例数据，算进去会把小模型报成大模型。
- 删除用 `_dir_size_bytes` 递归统计，因为删掉的是整个目录。

#### 四、「测试识别」真的测了，不再是一句空话

原实现：

```python
if asr_config.mode == "local":
    return TestConnectionResponse(
        success=True,
        message="本地 ASR 服务配置正常",   # ← 什么都没做
    )
```

现在真的加载模型并跑一遍流水线：构造 0.5 秒 440Hz 音调（16kHz、int16），
走 VAD → ASR → 标点 → 声纹全链路。音调本身不会识别出文字，
所以这里验的是「流水线能跑」，不是「识别准」。

冷启动加载四个模型实测 **25.7 秒**，之后实例常驻内存，第二次点击只跑一遍前向（约 1 秒）。
`request.ts` 没有配 fetch timeout，不会被中途掐断。

#### 五、「重载模型」真的重载了

原实现同样只回一句「已重载」，什么都没做。现在先 `shutdown_asr_model()` 释放内存实例，
再按当前配置重新 `init_asr_model()`。这样改了配置里的模型名之后，重载才真正生效。

#### 六、「删除模型」改删真实缓存，并加了保护

原实现是 `os.listdir("/data/asr-models")` 然后遍历 `rmtree` —— 目录不存在时返回「无需删除」，
但一旦路径写错就会把别的东西一起删掉。现在：

- 只删当前配置里这几个模型各自的 `snapshots/<revision>` 目录
- 先 `shutdown_asr_model()` 卸载内存实例，避免持有已删文件的句柄
- 不动 `credentials/`、`.lock/` 等公共内容
- 返回真实释放量，例如「已删除 4 个模型，释放 2200 MB」

前端弹窗也从一句「删除后将需要重新下载」改成带上真实模型数与体积。

#### 七、「下载模型」从 disabled 变成真的预热入口

新增 `POST /config/third-party/asr/preload`。它在后台线程里跑 `init_asr_model()` ——
缓存里没有的会由 FunASR 自动从 ModelScope 拉下来，接口立刻返回，不阻塞请求：

```python
threading.Thread(target=_run, name="asr-preload", daemon=True).start()
```

前端随后每 5 秒轮询一次 `/asr/status`，模型齐了就停，最长等 3 分钟。
定时器用 `useRef` 持有、卸载时清理（沿用 162 里踩过的闭包坑，不重犯）。

面板现在还会显示每个模型的缓存明细和总体进度条，用户可以看见「4 个模型里齐了 3 个」。

### 遇到的问题与解决

- **问题**：想用 `modelscope.hub.snapshot_download(..., local_files_only=True)` 探缓存，
  但实测对 `paraformer-zh` 等别名一律抛 `CacheNotFound` —— 它按仓库 ID 建索引，
  缓存里存的也是仓库 ID，别名查不到。
  - **解决方案**：不用 `snapshot_download`，改为「别名表解析出仓库 ID → 直接拼
    `$MODELSCOPE_CACHE/models/<owner>--<name>`」，纯文件系统判断，零网络依赖、零下载副作用。
- **问题**：`ThreadPoolExecutor` 用 `with` 时退出会 `shutdown(wait=True)`，
  把「后台执行」变成「同步阻塞」。
  - **解决方案**：改用 `threading.Thread(daemon=True).start()`。
- **问题**：`ct-punc` 报 1131.6 MB，看起来像 bug。
  - **解决方案**：核查后确认是真实的 —— `model.pt` 本身就是 1.1 GB
    （CT-transformer，词表 471067）。`example/`、`fig/` 已排除，这个数字没有水分。
- **遗留问题**：`test_asr_service`（不带 config 的那个入口）仍走旧的 `test_asr_api_service`，
  只查连通性。面板上的「测试识别」走的是 `test_asr_with_config`，已修好。
