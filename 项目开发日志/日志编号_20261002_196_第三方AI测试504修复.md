### 开发内容详述
1. 现象复现：nginx access log 出现
   `POST /api/v1/config/third-party/ai/test → 504`，错误为
   `upstream timed out (110: Operation timed out) while reading response header from upstream`。
2. 根因：nginx `location /api` 块的 `proxy_read_timeout 60s` 过短。
   该端点在本地模型模式下会：
   - 载入模型（后端 `load_model` 超时 600s，冷启动读取 GGUF 可能数十秒~数分钟）
   - 测速时生成 200 tokens（后端 httpx 超时 300s，实测 3B 模型单次生成 40~120s+）
   后端超时预算远大于 nginx 的 60s → nginx 提前掐断连接返回 504，前端表现为「测试失败」。
3. 修复：仅放宽 `proxy_read_timeout` 至 600s（与后端 load_model 超时对齐），
   `proxy_connect_timeout / proxy_send_timeout` 维持 60s 不变，避免扩散影响；
   补充注释说明原因，防止后续被改回。

### 遇到的问题与解决
- 问题：docker run 校验 nginx 配置时路径与镜像默认不一致（upstream 报错/找不到 include）。
  解决：按项目 Dockerfile 的实际布局（nginx.conf → conf.d/default.conf，includes/ → /etc/nginx/includes/）
  挂载后 `nginx -t` 通过。
