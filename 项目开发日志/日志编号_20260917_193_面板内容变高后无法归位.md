### 开发内容详述

#### 一、真因：日志 191 引入的回归

用户原话「选择后，清除，需要归位，而不是停留在上面」中，**「停留在上面」是位置义**
—— 面板停在了**上移之后**的位置；不是收纳（日志 192 判错）。

根因在 135 新加的统一边界保护：`ResizeObserver → reclamp()` 会**回写 `pos`**。

面板是 `top` 锚定（拖拽后 `bottom: 'auto'`），高度变化不自动顶底，所以：

1. 点「选择元素」→ 锁定某元素：面板内容变高（175 → 275 布局 px）
2. `ResizeObserver` 触发 `reclamp()`，为防止穿底把 `pos.y` **改写成**更高的值
3. 点「清除」：面板内容变矮回 175，但 `pos.y` 已被改写，钳制变成空操作
4. **面板永久停在顶高后的位置**，回不去

数值对照（z=0.8，视口 1920×900 → 布局视口 2400×1125，意图 y=1000）：

| | 短态 175 | 长态 275 | 清除回短态 175 |
|---|---|---|---|
| 旧（135 回写 pos） | 934 | 834 | **834** ← 卡住，顶高 100px |
| 新（意图/渲染分离） | 934 | 834 | **934** ← 归位 |

#### 二、修复：意图位置与渲染位置分离

确立单一约定：**`pos` 只存用户意图（拖到哪就记哪），边界钳制只作用于渲染层，绝不回写。**

```ts
// 意图位置 → 渲染位置：只算不写
const renderPos = pos
  ? clampPos(pos.x, pos.y, panelSize.width, panelSize.height, viewport)
  : null;

// 容器样式用渲染位置，持久化用意图位置
style={renderPos ? { left: renderPos.x, top: renderPos.y, bottom: 'auto' } : undefined}
```

这样「归位」是免费得到的：**同一个意图位置，内容变高时被顶上来，内容变矮后不再需要上移，
面板自动回到原位。** 不需要任何「记住原位置」的额外状态。

#### 三、配套改动

| 项 | 改动 | 原因 |
|---|---|---|
| `clampPos` | 改为纯函数，显式接收布局视口 `vp` | 不再自己读全局状态，副作用归零 |
| 尺寸获取 | 新增 `panelSize` 状态，`ResizeObserver` + `MutationObserver` + `resize` 三路喂入 | 钳制搬到渲染层后，需要实时尺寸驱动重算 |
| 视口 | 新增 `viewport` 状态，同上三路喂入 | 同上 |
| `MutationObserver` | 观察 `documentElement` 的 `style` 属性 | **`usePageZoom` 首屏异步下发 zoom 那次不派发 `zoom-changed` 事件**，只监听事件会漏掉首屏；观察 style 变更可覆盖所有写入方 |
| `posRef` / `reclamp` | 删除 | 不再需要回写，自然消失 |
| `dragRef` | 只保留 `offsetX/offsetY` | 拖拽时不再需要捕获尺寸 |
| `onMove` | 只写意图，不钳制 | 越界时渲染位置被 `clampPos` 收住；内容变矮后自动归位 |
| `pendingRestore` | 直接设意图为角落值 | 角落本身在界内，渲染层钳制是空操作 |
| `PANEL_BOX_WIDTH = 368` | 新增 | 替代用 `PANEL_WIDTH=340` 当 border-box 宽（`width:340px` 是 content-box，左右 padding 各 14） |
| `clearPicked` | **回退 136 的 `setMinimized(true)`** | 判读错误，用户明确「不是收纳起来」 |

#### 四、为什么 `MutationObserver` 比监听 `zoom-changed` 更稳

`hooks/usePageZoom.ts` 的首屏路径是 `getUserPreferences().then(scale => applyZoom(scale))`，
**不派发 `zoom-changed`**；该事件只在用户手动改缩放时被 `UserPersonalization` 派发。

若只监听事件：首屏带缩放的场景下，`viewport` 停留在未缩放值，而 CSS `left/top`
已按缩放渲染 —— 面板落位偏差，且要等用户下一次手动改缩放才会被纠正。

观察 `documentElement` 的 `style` 属性则覆盖 `applyZoom` 的所有调用（首屏、手动、清除），
且 `refresh()` 幂等 + 状态更新带相等性守卫，不产生回环。

#### 五、刻意不改之处

- **不改 CSS**、**不改 `usePageZoom`**、**不迁移 `STORAGE_KEY`**：同 135。
- **不重置 `pos`**：位置记忆是功能；归位指「渲染位置回到意图位置」，不是清意图。

### 遇到的问题与解决
- 问题：需求一句话有层叠义 / 位置义两种读法，136 判错并按层叠义实现
  解决方案：用户澄清「不是收纳起来，只是不要向上位移」后回退 136，按位置义定位真因；
  判错过程保留在 136 顶部标注中，未抹除
- 问题：`ResizeObserver` 回写 `pos` 造成的「单向棘轮」—— 内容变高被改写，变矮回不去
  解决方案：意图位置与渲染位置分离，钳制只算不写；回写点全部删除
- 问题：钳制搬到渲染层后，`resize` 事件不再触发 React 重算（窗口变窄时面板尺寸
  的布局值不变，`setPanelSize` 命中相等性守卫直接 bail）
  解决方案：把视口提升为 `viewport` 状态，与尺寸同源更新
- 遗留问题 / 待办：
  - 本机无浏览器，缩放/归位行为均为数值推演，需人工实测确认
  - 日志 190 遗留：缩放后已锁定元素的高亮框不自动跟随
