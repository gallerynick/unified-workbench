### 开发内容详述

#### 一、色条形状：左矩形、右圆角

上一轮把整条色条删了（日志 150）。这次按要求的形状加回来：

    .card  { border-radius: 0 var(--card-rounded) var(--card-rounded) 0; border-left: none; }
    .accentBar { width: 6px; border-radius: 0 var(--card-rounded) var(--card-rounded) 0; }

- 卡片**左边取直角且去掉左边框**（`border-left: none`），让色条直接构成卡片的
  左边缘——形成「矩形衔接」，中间没有一条描边线隔开
- 卡片**右边保留 `--card-rounded` 圆角**，与主体一致
- 色条只在**右侧**取圆角，形成与主体一致的过渡；左侧保持直角与卡片左边缘齐平
- 宽度由原来的 3px 提到 6px——3px 几乎看不出颜色，作为标记色偏细

⚠️ 注意 `.card:hover` 也必须补 `border-left: none`：hover 时 `border` 简写会
把左边框重建出来，破坏衔接。

#### 二、颜色作为数据

新增 `task.color`，存**调色板 key 字符串**而非 hex：

| key | 标签 | design token |
|---|---|---|
| blue | 蓝 | `--color-primary` |
| cyan | 青 | `--color-cyan` |
| green | 绿 | `--color-success` |
| orange | 橙 | `--color-orange` |
| red | 红 | `--color-red` |
| purple | 紫 | `--color-purple` |
| pink | 粉 | `--color-magenta` |
| gray | 灰 | `--text-tertiary` |

存 key 的好处：前端 `taskColorValue()` 解析成 `var(--token)` 渲染，
**深浅色模式与主题切换自动适配**，数据库里不落任何 hex。
未指定颜色时默认 `blue`。

调色板集中定义在 `pages/tasks/taskColors.ts`（`TASK_COLORS` /
`DEFAULT_TASK_COLOR` / `taskColorValue()`），后端 `VALID_COLORS` 与之对齐，
两处必须同步。

#### 三、后端

- `models/task.py`：`color: Mapped[str]`，`String(20)`，`nullable=False`，
  `server_default="blue"` + Python 侧 `default="blue"`（与 `visibility` 字段
  的建模方式一致）
- `schemas/task.py`：新增 `VALID_COLORS` 集合 + `validate_color` 校验器，
  非法取值直接抛 `ValidationError`（与 status / priority 校验一致）；
  `TaskCreate.color = "blue"`、`TaskUpdate.color = None`、`TaskResponse.color`
- `services/task.py`：创建时 `color=request.color or "blue"`；
  更新时 `if request.color is not None` 才写，符合部分更新的语义
- 迁移 `048`：`ADD COLUMN color VARCHAR(20) NOT NULL DEFAULT 'blue'`，
  PostgreSQL 会在加列时把存量行统一回填为 `blue`
- `startup_migrate.py` 同步一条幂等 SQL
  （`ADD COLUMN IF NOT EXISTS`）——线上库未初始化 `alembic_version`，
  alembic 不会自动执行，这是实际生效的路径

#### 四、前端

- `TaskModal.tsx`：新增「标记颜色」表单项，用 `Radio.Group` +
  `Radio.Button` 渲染 8 个色块（圆点 + 中文标签）。用 antd Radio 而非自写
  button，键盘导航与无障碍属性由组件自带。隐藏了 antd 自带的方形勾选框
  （`.ant-radio-inner` → `display: none`），选中态改由按钮描边表达，
  避免「方框 + 色点」两个视觉元素打架
- `TaskCard`：色条 `background` 取 `taskColorValue(task.color)`，
  列表与表单天然同源，不可能不一致
- `types/task.ts`：`Task.color` 设为可选（`color?: string`），因为旧数据
  与旧接口响应可能缺失该字段

#### 五、存量数据

`ADD COLUMN ... NOT NULL DEFAULT 'blue'` 由 PostgreSQL 在加列时直接回填，
无需额外回填脚本。存量任务「装配服务器」已确认为 `blue`。
