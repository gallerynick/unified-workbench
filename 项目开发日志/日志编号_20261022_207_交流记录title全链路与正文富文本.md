## 四、开发内容详述

### title 全链路
主题不再挤在 `content` 里与正文拼接。表单、列表、详情一律读 `meeting.title`；
`content` 只承载正文，语义单一。

### 正文富文本
正文存储为 Tiptap doc JSON 字符串；历史纯文本由 `parseDescription` 识别为 null 后
经 `wrapPlainTextToDoc` 兜底渲染，与提案描述字段同一套约定。

- 只读：`<ContentEditor value={doc} editable={false} minHeight={100} />`
- 编辑：切换为可编辑 + 保存/取消按钮
- 提交：`serializeDescription(doc ?? undefined) ?? ''`

### 备注 CRUD
追加、编辑、删除均通过 `updateProjectMeeting(id, { notes })` 整体提交数组。
编辑时保留原 `author` / `created_at`，缺失时兜底空串。
删除经 `Modal.confirm` 二次确认。权限由 `canManageMeetings` 控制。

### 列表页原则
- 会议列表：移除行内编辑/删除，仅保留整行点击进入详情
- 修改记录 / 项目事件：移除「操作」列；两模块详情页与路由本就存在（`change/:changeId`、`event/:eventId`），整行点击进入
- 提案 / 待办：原本即无删除/编辑按钮，无需改动

## 五、遇到的问题与解决

| 问题 | 解决 |
|------|------|
| 计划假设 alembic 044 会执行，实际从不执行 | 改为依赖 `startup_migrate.py` 的动态补列；044 保留为文档 |
| 会话上下文中「已完成」结论与磁盘实际状态不符 | 逐项 grep 核对后按实际状态重做，未采信既有结论 |
| `edit` 工具多次报「file changed since it was read」 | 重新读取后再改；大段删除改用 read → splice → write |
| JSX 反引号与 `run_code` 模板字符串冲突 | 用数组 `join('\n')` 构造字面量替代模板字符串 |
| `tsc` 报 TextArea / Modal / Tooltip 等未使用 | 逐一清理别名与 import |
