### 开发内容详述

**1. 系统设置收不起来——路由同步 effect 与用户操作打架**

原实现里有两个缺陷叠加：

- **openKeys 在依赖数组里**：用户收起 → setOpenKeys([]) → effect 因 openKeys 变化立刻重跑 → 又把 /settings 推回去 → 永远收不起来
- **判定用 startsWith(/settings)**：连 /settings/personalization（用户个性化，属个人区而非该子菜单）也会触发。用户刚好在个性化页调侧栏，于是必现

修复后：

```ts
useEffect(() => {
  if (collapsed) return;
  const inSettingsChild = SETTINGS_SUBMENU_CHILD_KEYS.some(
    (key) => location.pathname === key || location.pathname.startsWith(key + "/"),
  );
  if (!inSettingsChild) return;
  setOpenKeys((prev) => (prev.includes("/settings") ? prev : [...prev, "/settings"]));
}, [location.pathname, collapsed]);
```

- 依赖去掉 openKeys，只在换页时跑一次 → 用户收起后不会被弹开
- 判定改为命中真正的子页 key → 个人区路由不再误触发

**2. 设置子项清单抽出为单一数据源**

为避免「菜单渲染」与「路由自动展开判定」各写一份而漂移，抽出三个模块级常量：
SETTINGS_SUBMENU_ENTRIES（11 项定义）、SETTINGS_SUBMENU_CHILDREN（供 Menu）、SETTINGS_SUBMENU_CHILD_KEYS（供路由判定）。

**3. 设置项没有动画——子项是展开时才挂载的新节点**

排查过程：

- 先核对编译产物，确认 .sidebar-entered .ant-menu-item 规则完整、未被 CSS Modules 或全局样式破坏（全仓无 ant-menu 覆盖）
- 所以「个人区 5 项 + 系统设置标题」这些始终存在的节点本就在动画内
- 真正缺位的是系统设置展开后才挂载的 11 个子项：主延迟分配 effect 只在进组 / 折叠态 / 密度变化时运行，展开子菜单不会触发它。这些新节点因此没有错峰，整块同时出现，与侧栏其余部分依次飞入的节奏明显不一致

修复：新增只针对子菜单子项的错峰 effect，查询 .ant-menu-sub .ant-menu-item，按组内序号设 40ms 步进。

关键决策：**从 0 起算而不是沿用全局序号**。子项在 DOM 中排在第 20 位之后，若沿用全局序号要等 0.8~1.2 秒才出现；组内起算则展开瞬间即可连贯飞入。

**4. 未改动原有动画**

keyframes menuItemFlyIn、300ms、ease-out、40ms 步进全部保持不变，仅补上遗漏节点的延迟。
