### 开发内容详述

**一、根因**

上一轮做收纳时，把 --spacing-xxs（4px）当成了默认结构间距在用，
全模块共 23 处。4px 用在「图标与文字」「文字与分割线」「列表项之间」
这类语义上需要呼吸的位置，视觉上就是挤。另外 12px 字号（
--text-body-xs-size）没有配套行高，多行文本纵向也紧。

间距阶梯本身没有问题（4/8/12/17/24/32/48），问题在于选档：4px 应当只用于
紧贴型装饰，不该承担结构间隔。

**二、统一执行的四条间距规则**

  1. 文字与文字（图标与文本、标签与值、相邻文本）：最小 --spacing-xs（8px）
  2. 文字与分割线/边框：--spacing-sm（12px）
  3. 组件块与组件块（字段之间、面板段落之间）：--spacing-sm ~ --spacing-md
  4. 12px 字号一律带 line-height: var(--text-body-xs-line)（1.4）

改造后 notes 模块内 --spacing-xxs 的使用次数为 0。

### 遇到的问题与解决

- 问题：用 bash heredoc 里嵌 Python 多行字符串，规则里的 \n 被 JSON 转义
  成真实换行，Python 报 SyntaxError，且脚本未执行任何替换。
  解决方案：改为用 write 工具落地脚本文件，多行字符串改用
  chr(10).join([...]) 构造，完全不出现反斜杠转义。

- 问题：脚本内一条规则（GraphView 空态行高）的锚点写反，把「} 之后的双空行
  + 注释」当作 .emptyState 的结尾，匹配 0 次，该条失败但文件其余替换仍写入。
  解决方案：重读文件确认真实结构（双空行与注释在 .emptyState 之前，而非
  之后），拆成两条独立 edit 分别补行高与清双空行。脚本对每条规则断言
  期望出现次数，因此这类锚点错误会被立刻暴露而不是静默通过。

- 问题：校验脚本用 -c 统计 --spacing-xxs 时，GraphView 报 0 但脚本报失败，
  两者看似矛盾。
  原因：-c 统计的是文件内的最终状态，而失败的那条规则本来就不含
  --spacing-xxs，改的是行高与空行。属统计口径不同，非真实冲突。
