### 开发内容详述

**1. 收起态此前是「一个扁平 Menu」**

原实现：`collapsed ? <Menu items={所有可见项扁平列表}/> : 分类渲染`。
收起后所有图标连成一列，既没有类别名，也没有任何分隔，无法判断分组边界。

**2. 改为「每类别一个 Menu + 类别间短横线」**

```tsx
visibleCategories.map((cat, index) => (
  <div key={cat.key}>
    {index > 0 && <div className={styles.railDivider} data-rail-divider="" aria-hidden />}
    <Menu mode="inline" selectedKeys={[selectedKey]} items={toMenuItems(cat.items)} ... />
  </div>
))
```

分隔形态的选择：**居中 28px 短横线**，而不是通栏线。
理由：80px 宽的通栏线会把图标栏切成一个个「格子」，笨重且与展开态的通栏感重复；
短横线只作为视觉锚点，符合「优雅」诉求，也与展开态「类别名 + 延伸细线」的细线语言同源。

```css
.railDivider { width: 28px; height: 1px; margin: 8px auto; background: var(--divider-soft); border-radius: 1px; }
```

**3. 底部区块的分隔线同宽化**

收起态给底部区块加修饰类 `.settingsSectionRail`，把其 `ant-menu-item-divider` 也收窄为 28px 居中。

颜色不降级：仍沿用 `--border-primary`（深），与类别短横线的 `--divider-soft`（淡）保持层级差——
即「形态统一、权重不同」，与展开态两条线的关系一致。

**4. 分隔线纳入同一条进场动画**

给短横线加 `data-rail-divider`，并把它加入 `MENU_ANIM_SELECTOR` 以及 CSS 的预置态 / 播放态规则组。
否则会出现「图标在飞、分隔线已就位」的脱节——与上一轮修类别头时同类问题。

**5. 收起态仍显示全部已勾选项**

不套用展开态的 `collapsedGroups`。理由：图标栏是临时紧凑视图，若隐藏被折叠组的项，
用户在收起状态下会找不到模块，且无法从栏内判断原因。保持「栏 = 全部模块」更可预期。

### 遇到的问题与解决

- 疑虑：多个 Menu 实例在 Sider 内是否都能正确进入 inline-collapsed。
- 核实：antd 的 Menu 通过 SiderContext 读取 `siderCollapsed`，多个消费者各自生效，无需显式传 `inlineCollapsed`。

- 问题：长分隔线在 80px 内视觉过重。
- 处理：改用 28px 居中短横线，并与底部结构线保持「同形态、不同权重」。
