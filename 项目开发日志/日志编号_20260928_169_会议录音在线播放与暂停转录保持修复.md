### 开发目标
- 让会议房间的录音文件支持在线播放，而不是只展示“已保存”
- 修复暂停后转录内容被覆盖的问题，避免恢复时清空实时转录
- 保持原有 Tabs 视觉风格，避免不必要的样式切换

### 开发内容详述
1. 会议房间录音页调整
   - 将录音页文案由“录音文件已保存”改为“在线播放”
   - 使用原生 <audio> 控件直接播放会议音频
   - 音频地址改为后端认证接口 /api/v1/meetings/{meeting_id}/audio
   - 通过 query token 支持浏览器原生 audio 直接访问，不依赖 Authorization 请求头

2. 会议音频接口增强
   - 在 GET /api/v1/meetings/{meeting_id}/audio 中支持 query token 认证
   - 新增 _get_current_user_from_bearer_or_query 与 _resolve_user_from_token
   - 保持原有 Authorization Bearer 头路径可用，同时允许浏览器音频元素直接请求

3. 转录内容保持修复
   - 新增 mergeServerSegments，将服务端 segments 与前端已有转录合并去重
   - fetchMeeting 改为合并而不是整体替换 transcript，避免暂停/恢复后清空实时内容

4. 交互样式回退
   - 保持原有 Ant Design Tabs 风格
   - 不将 Tabs 改成自定义按钮，维持用户已接受的视觉一致性

### 遇到的问题与解决
- 问题：暂停后转录内容会丢失。
- 解决方案：将 fetchMeeting 的 transcript 更新从“替换”改成“合并”，并增加稳定 key 去重。
- 问题：浏览器原生 audio 元素无法直接携带 Authorization 头。
- 解决方案：后端音频接口支持 token query 参数，便于 <audio> 直接播放。
- 问题：用户不接受“录音文件已保存”这种文案，因为尚未下载。
- 解决方案：录音页改为“在线播放”，下载仍保留为显式下载动作。
