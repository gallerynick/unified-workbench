## 一、结论摘要

| 问题 | 表面现象 | 真实根因 | 定性 |
| --- | --- | --- | --- |
| 句尾标点重复 | `。。` `？？。` | `ct-punc` 叠加在 SenseVoice 的 `<\|withitn\|>` 富文本输出上做**二次标点恢复**；且富文本标签被拆成 `S pe ech` / `withi tn` 未被清洗 | 配置错误，**可完全修复** |
| 椅子晃动声被录 | 噪声触发识别 | 用固定阈值 RMS 当 VAD，能量门限无法区分语音与宽带冲击 | 算法选型错误，**可大幅改善** |

**两个都不是模型能力问题**，而是链路配置与端点检测的问题。这一点很重要——它意味着不需要换模型，也不需要微调。

**核心动作三条**：

1. SenseVoice 不再叠加 `punc_model`（`withitn` 已自带标点），Paraformer 保留 `ct-punc`
2. 端点检测从「固定阈值 RMS」升级为「webrtcvad + 频谱平坦度 + 峰值因子」三层门控
3. 会议场景参数独立成 `meeting_profile.py`，通用场景不受影响

## 二、现场日志取证

从你贴的运行日志里，可以直接读出五条关键信息：

~~~
OK  < | zh | > < | NEUTRAL | > < | S pe ech | > < | withi tn | >现在，我是你们的爸爸。。
rtf_avg: 0.573: 100%|████████████████████| 1/1 [00:00<00:00,  1.71it/s]
rtf_avg: -0.168: 100%|███████████████████| 1/1 [00:00<00:00,  5.93it/s]
~~~

### 取证 1：每次识别输出**两行** `rtf_avg` —— 坐实两阶段 pipeline

第一行是 ASR（rtf 0.139~0.573，正常），第二行恒为 `-0.168 / 5.9x it/s` 且耗时极短 —— 这是 **`ct-punc` 标点模型的独立推理阶段**。

**这就是双标点的物理来源**：句子经过了**两次**标点恢复。

### 取证 2：标签被拆成 `S pe ech` / `withi tn`

原始应为 `<\|Speech\|>`、`<\|withitn\|>`。ct-punc 在富文本标签的**字符之间插入了空格**，导致原脚本的清洗正则失效。

原脚本用的是：

~~~python
text = re.sub(r'<\|[^|]*\|>', '', text)
~~~

`[^|]*` 遇空格不报错但匹配到 `< | S pe ech | >` 时，`[^|]*` 能匹配空格，理论上能匹配……但 `withi tn` 这类被插入空格后，`[^|]*` 仍可匹配。实际失效的原因在于：标签形态已经是 `< | zh | >`（尖括号与竖线间也有空格），而 `<\|` 要求 `<` 紧跟 `|`，**匹配不上**。

修复：正则改为 `<\s*\|[^>]*?\|\s*>`，宽容所有空格形态。

### 取证 3：`EMO_UNKNOWN` 与 `NEUTRAL` 混现

同一段会议里情感标签在变，说明每次送入的音频段边界不稳定——间接印证 VAD 分段不干净（段边界抖动会导致模型对同一说话人给出不同情感判断）。

### 取证 4：句尾 `。。` 稳定复现于每一句

~~~
今天我们这个会议的主题是，首先。。
现在，我是你们的爸爸。。
对于现在这个次数来。。
首先，怎么去对于这个班位进行修改呢？？。
~~~

100% 复现，非偶发。符合「双标点来源」的确定性特征。

### 取证 5：`？？。` 三连是逗号+问号+句号

`呢？？。` 的形态说明：ASR 输出 `呢？`，ct-punc 又加了 `？。`，再叠加原句可能的标点。修复需同时处理「重复折叠」与「句末前逗号吞并」。

## 三、问题一：句尾标点重复

### 3.1 根因链

~~~
SenseVoice 输出 <|zh|><|NEUTRAL|><|Speech|><|withitn|>今天天气很好。
                                          ↑ withitn 已含标点
        ↓ 叠加 punc_model='ct-punc'
ct-punc 在已带标点的文本上再做一次标点预测
        ↓
输出 .. 。。 / ？？。   ← 你看到的形态
        ↓ 同时 ct-punc 在标签字符间插空格
< | zh | > < | S pe ech | > < | withi tn | >   ← 清洗正则失效
~~~

**关键认知**：`use_itn`（逆文本归一化）与**标点**是 SenseVoice 富文本输出的一部分，`<\|withitn\|>` 标记即代表已启用 ITN。再看 `ct-punc` 的职责——它是给**无标点输出**（如 Paraformer）补标点的。给 SenseVoice 叠 `ct-punc` 属于重复劳动。

### 3.2 修复方案

**配置层**（`live_asr_v3.py::Transcriber`）：

~~~python
# SenseVoice 的 <|withitn|> 已含标点，再叠 ct-punc 会产生 "。。" "？？。"
# Paraformer 输出无标点，需要 ct-punc。
self.use_punc_model = (engine == "paraformer")
~~~

**清洗层**（`meeting_profile.py::strip_rich_tags`）：

~~~python
# 匹配全部空格插入形态：<|zh|>  < | zh | >  < | S pe ech | >  < | withi tn | >
TAG_RE = re.compile(r"<\s*\|[^>]*?\|\s*>")
~~~

用 `[^>]*?` 而非 `[^|]*?`，避免被插入的字符截断匹配。

**标点规范化层**（`meeting_profile.py::normalize_punctuation`）：

| 规则 | 示例 |
| --- | --- |
| 折叠连续重复 | `。。`→`。`，`？？`→`？` |
| 吞掉句末前逗号 | `，。`→`。`，`、？`→`？` |
| 相邻多句末标点 | `。！`→`。` |
| 去句首标点 | `。今天…`→`今天…` |
| 句尾逗号改句号 | `主题是，`→`主题是。` |
| 句尾补句号 | `好`→`好。` |

### 3.3 实测结果

用你日志里的真实输出做回归：

~~~
'今天我们这个会议的主题是，首先。。'      → '今天我们这个会议的主题是，首先。'
'首先，怎么去对于这个班位进行修改呢？？。' → '首先，怎么去对于这个班位进行修改呢？'
'<|zh|><|NEUTRAL|><|S pe ech|><|withi tn|>对于现在这个次数来。。' → '对于现在这个次数来。'
'现在，我是你们的爸爸。。'               → '现在，我是你们的爸爸。'
'好。'                                  → '好。'
~~~

全部通过。

## 四、问题二：非语音被收录

### 4.1 根因链

原实现用**固定阈值 RMS 能量门限**当 VAD：

~~~python
def detect_speech(audio, sample_rate, threshold=VAD_THRESHOLD):
    return calculate_rms(audio) > threshold     # rms > 0.006 即判为"说话"
~~~

三个致命缺陷叠加：

1. **能量门限不区分信号类型**。椅子晃动、键盘敲击、关门、翻页的 RMS 都可能超过 0.006；安静环境下轻声说话反而可能低于它。
2. **阈值固定，不随环境自适应**。会议室 A 和家里书房的底噪完全不同。
3. **还有个隐性 bug**：`threshold=VAD_THRESHOLD` 是默认参数绑定，`--vad-threshold` 命令行参数**完全无效**（详见 §6.3 的实测），所以你连手动调高阈值的路都被堵死了。

### 4.2 为什么频谱特征能区分（实测）

用合成信号验证两类信号的判别力：

| 信号 | 频谱平坦度 | 峰值因子 | RMS |
| --- | --- | --- | --- |
| 浊音（150Hz 谐波） | **0.130** | 2.00 | 0.150 |
| 带共振峰语音 | **0.294** | 3.34 | 0.090 |
| 椅子晃动/撞击 | **0.833** | **9.90** | 0.256 |
| 慢衰减撞击 | **0.845** | 5.73 | 0.439 |
| 稳态白噪声 | **0.855** | 3.34 | 0.049 |

**频谱平坦度**（几何均值/算术均值）区分度近 3 倍：语音有谐波与共振峰结构 → 频谱**尖锐** → 平坦度低；冲击/噪声 → 频谱**均匀** → 平坦度高。

**峰值因子**（peak/rms）区分快速冲击：语音约 2~4，快衰减撞击可达 10。

### 4.3 三层门控设计

| 层级 | 判据 | 解决什么 |
| --- | --- | --- |
| **L1 块级声学门** | 平坦度 ≤0.55 且 峰值因子 ≤6.5 | 挡掉宽带冲击与稳态噪声 |
| **L2 起音去抖** | 连续 2 块判为语音才确认起音 | 挡掉单次撞击（通常只占 1 块） |
| **L3 段落级统计** | 语音块占比 ≥0.30 且 绝对数 ≥3 且 纯语音时长 ≥min_speech | 兜底防误杀（清音"丝""f"频谱接近噪声） |

**为什么必须做段落级判决**：清音（如"丝"、"f"、"sh"）的频谱接近噪声，若逐块硬拒会误杀。**但一段真实说话中必然包含浊音块**，用统计占比判定即可稳判——这是本方案的关键设计权衡。

### 4.4 场景回归测试（6/6 通过）

~~~
[PASS] 纯语音 1.5s          → 有输出
[PASS] 句中夹 0.2s 椅子声    → 有输出（不切断，段内吞掉）
[PASS] 独立椅子声 0.5s      → 无输出 ✓
[PASS] 独立键盘声 0.8s      → 无输出 ✓
[PASS] 句中夹 0.5s 噪声      → 有输出（不切断）
[PASS] 极短语音 0.2s        → 无输出 ✓
~~~

关键点：**句中夹噪声不切断**（保证句子完整），**独立噪声整段拒绝**（保证不产生垃圾输出）。

### 4.5 附带修复：尾部静音裁剪

原实现 `SILENCE_TIMEOUT=1.5s` 意味着**每段音频末尾都挂着 1.5 秒静音**才触发识别。长静音尾巴送进 ASR 也是句尾异常标点的诱因之一。

新增 `hangover_s=0.25`：只保留句末 0.25s，其余静音裁掉。

| Profile | 裁剪前 | 裁剪后 |
| --- | --- | --- |
| 会议（语音1.5s+静音2.0s） | 2.60s | **1.70s** |
| 通用（语音1.5s+静音2.5s） | 2.10s | **1.75s** |

## 五、会议场景优化方案

### 5.1 为什么独立出来

会议场景与通用听写在关键参数上**存在方向性冲突**：

| 参数 | 通用听写 | 会议场景 | 冲突原因 |
| --- | --- | --- | --- |
| `silence_timeout` | 0.6s | **1.0s** | 会议发言停顿更长，0.6s 会把一句切成两句 |
| `min_speech_s` | 0.3s | **0.5s** | 会议需过滤短促噪声，0.3s 太宽松 |
| `pre_roll_s` | 0.3s | **0.4s** | 会议开场词更容易被吞 |
| 冲击噪声门控 | 不需要 | **需要** | 椅子/键盘/翻页/空调是会议特有干扰 |
| `min_voiced_ratio` | — | 0.30 | 会议室混响更重，需更严格 |

若把参数硬塞进主程序，通用场景会被会议参数拖累（延迟变高、短句被吞）。**独立成模块，通过 `--profile meeting` 切换**是唯一干净的做法。

### 5.2 模块职责边界

~~~
meeting_profile.py          ← 会议场景专属，零 funasr/sounddevice 依赖，可单测
  ├─ MeetingConfig          参数容器（dataclass，全部可调）
  ├─ MeetingGate            三层门控状态机（feed / should_emit / take / drain）
  ├─ strip_rich_tags        富文本标签清洗
  ├─ normalize_punctuation  标点规范化
  └─ spectral_flatness / crest_factor  声学特征

live_asr_v3.py              ← 主程序
  ├─ EndpointDetector       通用场景 VAD（webrtcvad → 自适应 RMS 降级）
  ├─ Transcriber            引擎路由 + punc 策略 + ITN
  ├─ Session                profile 分发（general / meeting）
  └─ CLI
~~~

`meeting_profile.py` **不 import funasr / sounddevice**，只依赖 numpy —— 这样它可以被独立单元测试，也能被未来其他场景复用。

### 5.3 MeetingConfig 参数表

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `silence_timeout` | 1.0 | 静音多久判定一句话结束 |
| `min_speech_s` | 0.5 | 最短有效语音 |
| `max_segment_s` | 25.0 | 单段上限 |
| `hangover_s` | 0.25 | 句末保留时长 |
| `pre_roll_s` | 0.4 | 句首保护 |
| `flatness_max` | **0.55** | 频谱平坦度上限（语音实测 ≤0.3） |
| `crest_max` | **6.5** | 峰值因子上限（撞击可达 10） |
| `onset_blocks` | 2 | 起音去抖块数 |
| `min_voiced_ratio` | **0.30** | 段落内语音块占比下限 |
| `min_voiced_blocks` | 3 | 语音块绝对数下限（≈300ms） |
| `base_threshold` | 0.006 | 能量兜底门限 |
| `noise_k` | 4.0 | 底噪倍数（自适应阈值 = floor × k） |

命令行可覆盖：`--flatness-max` / `--crest-max` / `--min-voiced-ratio` / `--silence-timeout` / `--min-speech` / `--max-segment`。

### 5.4 会议场景推荐起步命令

~~~bash
# 标准会议室
python live_asr_v3.py --profile meeting

# 嘈杂会议室 / 开放式办公区（误触发多）
python live_asr_v3.py --profile meeting --vad-aggressiveness 3 --flatness-max 0.45

# 安静小会议室（漏字多，放宽）
python live_asr_v3.py --profile meeting --min-voiced-ratio 0.25 --silence-timeout 1.2

# 离线处理会议录音
python live_asr_v3.py --profile meeting --file meeting.wav
~~~

## 六、依赖安装方案

### 6.1 依赖分层

| 层 | 包 | 必需性 | 说明 |
| --- | --- | --- | --- |
| 数值 | numpy, scipy | 必需 | 特征计算 |
| 采集 | **sounddevice** | 必需 | 麦克风输入 |
| 读写 | soundfile | 必需（仅 `--file` 模式） | 音频文件 |
| VAD | **webrtcvad** | 强烈推荐 | 缺失时降级为自适应 RMS |
| ASR | funasr, torch | 必需 | 识别引擎 |
| 可选 | sherpa-onnx | 可选 | 官方 INT8 路线，替代 funasr |

### 6.2 关键坑：sounddevice 不自带 PortAudio（实测确认）

这是一个反直觉的点，值得单独标注：

- `soundfile` 的 pip 轮子 **自带** libsndfile → 无需系统库 ✅
- `sounddevice` 用 cffi 加载 **系统** libportaudio，轮子 **不自带** ❌

缺库时的表现：

~~~
OSError: PortAudio library not found
~~~

修复命令：

~~~bash
# Ubuntu/Debian
sudo apt install libportaudio2 portaudio19-dev
# macOS
brew install portaudio
# Fedora
sudo dnf install portaudio portaudio-devel
~~~

脚本的体检环节会**自动识别该错误**并打印对应平台的修复命令。

### 6.3 另一个坑：webrtcvad 是 C 扩展

需要编译器 + Python 头文件。装不上时脚本**自动降级**（不中断安装），程序会退化为自适应底噪 RMS VAD —— 功能可用但抗噪能力弱一些。

补齐依赖：

~~~bash
# Linux
sudo apt install build-essential python3-dev
# macOS
xcode-select --install
# Windows
# 安装 Visual Studio Build Tools（勾选「C++ 桌面开发」）
~~~

### 6.4 脚本用法

~~~bash
./install_deps.sh                  # 默认：建 .venv + 音频层 + FunASR(CPU) + webrtcvad
./install_deps.sh --mirror         # 国内网络走清华源（推荐）
./install_deps.sh --system         # 装进当前 Python，不建 venv
./install_deps.sh --sherpa         # 额外装 sherpa-onnx（官方 INT8 路线）
./install_deps.sh --no-asr         # 只装音频层，不装 torch/funasr
./install_deps.sh --warmup         # 装完预热下载模型
./install_deps.sh --check          # 只体检不安装
~~~

**健壮性设计**：

- `set -euo pipefail` + ERR trap：pip 失败会提示换源而非静默退出
- 系统库安装失败只 warn 不阻塞（apt 网络受限场景）
- 已装 GPU torch 则跳过 torch 安装
- 结尾强制体检，未通过返回非零退出码

### 6.5 麦克风权限

| 平台 | 操作 |
| --- | --- |
| macOS | 系统设置 → 隐私与安全性 → 麦克风，勾选终端/IDE；首次调用会弹窗 |
| Linux | 确认用户在 `audio` 组，PulseAudio/PipeWire 正常运行 |
| Windows | 设置 → 隐私 → 麦克风，开启「允许桌面应用访问麦克风」 |

## 八、调参与验收手册

### 8.1 症状 → 动作对照表

| 症状 | 首选动作 | 次选动作 |
| --- | --- | --- |
| 椅子/键盘/翻页声被收录 | `--vad-aggressiveness 3` | `--flatness-max 0.45` |
| 句尾仍有 `。。` | 确认引擎为 sensevoice 且未叠加 punc | 检查是否误加 `--no-normalize` |
| 短句被吞（"好"、"是"漏识别） | `--min-speech 0.3` | `--min-voiced-ratio 0.25` |
| 一句被切成两句 | `--silence-timeout 1.5` | — |
| 延迟太高 | `--silence-timeout 0.8` | 缩短发言停顿 |
| 句首第一个字被吞 | `--profile meeting`（pre_roll 0.4s） | — |
| 说话人被打断/串句 | 已修复（无条件 flush） | — |
| 全场安静但持续出垃圾文本 | `--flatness-max 0.40` | 检查底噪，调 `--rms-threshold` |

### 8.2 验收标准

| 项 | 标准 |
| --- | --- |
| 标点 | 连续 20 句无 `。。` `？？。` 等重复标点 |
| 噪声拒识 | 独立椅子声/键盘声/关门声 → 零输出 |
| 噪声鲁棒 | 说话中夹 0.2s 噪声 → 句子不被切断、不重复 |
| 短句 | "好"、"是"、"对" 能被识别 |
| 长句 | 连续说 20s 不出现串句、不漏字 |
| 延迟 | 句末停顿后 ≤1.5s 出结果 |

### 8.3 调参顺序（重要）

~~~
1. --vad-aggressiveness (0→3)     # 先定误触发基线
2. --flatness-max (0.55→0.40)     # 再收紧噪声门
3. --silence-timeout (1.0→1.5)    # 再调切句节奏
4. --min-voiced-ratio (0.30→0.25) # 最后放宽兜底
~~~

不要跳序。前两项决定「什么时候不该识别」，后两项决定「什么时候该识别」。

## 九、风险与未验证项

### 9.1 必须说明的验证边界

| 项 | 状态 |
| --- | --- |
| 富文本标签清洗 | ✅ 用真实日志输出回归通过 |
| 标点规范化 | ✅ 6 个真实样例全部通过 |
| 三层门控场景测试 | ✅ 6/6 合成信号通过 |
| 尾部裁剪 | ✅ 会议 2.60→1.70s，通用 2.10→1.75s |
| 安装脚本 | ✅ bash 语法通过，体检/降级逻辑实测 |
| **端到端实机录音** | ❌ **未验证** |
| **funasr/torch 实际安装** | ❌ **未验证**（网络受限） |

沙盒环境无麦克风、npm 与 PyPI 受限（403），因此**未跑过真实录音**。频谱平坦度阈值（0.55）与峰值因子阈值（6.5）来自合成信号实验，真实会议室的椅子声频谱特征可能与之有偏差——**首次实机使用时请优先调 `--flatness-max`**。

### 9.2 已知残留风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 平坦度阈值对混响敏感 | 会议室混响会抬高语音的平坦度，可能误拒 | 漏字时调高 `flatness_max` 至 0.65 |
| 远场麦克风信噪比低 | 桌面麦拾音弱时 VAD 漏检 | 用指向性麦或 `--vad-aggressiveness 0` |
| 清音为主的语言 | 如大量"丝""四"，段落统计可能低于阈值 | 调低 `min_voiced_ratio` 至 0.25 |
| 说话人重叠 | 会议中两人同时说话，VAD 会判为一段 | 阶段三加说话人分离 |
| 非流式延迟 | 当前是 VAD 分段 + 离线整段识别 | 阶段三换流式模型 |

### 9.3 关于"实时"的预期校准

当前架构**不是流式识别**，而是「VAD 分段 + 离线整段识别」：

~~~
延迟 = 说话时长 + silence_timeout + 推理时间
~~~

日志中 `rtf_avg` 在 0.14~0.57 之间，即推理本身约为实时的 1/7 到 1/2，**推理不是延迟瓶颈**；瓶颈在 `silence_timeout`（会议场景 1.0s）。

若要真正的边说边出字，需换 `paraformer-zh-streaming` 或 FunASR 的 Runtime WebSocket 服务，这属于阶段三范围。
