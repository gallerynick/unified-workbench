# 项目开发日志格式

> 本文件定义 `项目开发日志/` 下每份开发日志的**文件名规则**、**序号取号规则**、
> **并发取号规则**与**正文模板**。所有 agent 写日志前必须遵守，尤其是多会话并发开发时。

---

## 一、文件名规则

    日志编号_YYYYMMDD_NNN_简述.md

| 字段 | 说明 |
|------|------|
| `日志编号_` | 固定前缀，不得省略、不得改写 |
| `YYYYMMDD` | 本次开发日期（8 位数字，与正文标题中的日期一致） |
| `_NNN_` | 全局序号，3 位零填充，前后各一个下划线 |
| `简述` | 开发内容简述，简短中文，不含 `/` 等路径分隔符 |

示例：`日志编号_20260908_086_WebAuthn生物特征认证实现.md`

> 序号与日期之间**必须**有下划线分隔。历史上存在 `日志编号_20260617001_...`（无分隔）
> 的紧凑格式，新日志不得使用。

---

## 二、序号取号规则

序号 `NNN` 是**全局单调递增**计数器（跨天累加，不按日重置），3 位零填充。

1. 新序号必须等于「当前最大序号 + 1」，不得跳号、不得复用已用序号
2. 一次开发只占用一个序号，不得拆成多个序号
3. 序号一旦写入文件，除执行经用户确认的正式重编号整理外，不得单独改动
4. 历史跳号（如 022）保留原状，不回填

具体取号动作见第三节。

---

## 三、并发取号规则（多会话场景）

多个会话可能同时写日志，且彼此无通信。因此不得依赖「协调者分配序号」（协调者不存在），
必须在文件系统层做**原子占位**。

取号必须调用脚本，不得手工 `ls` 估算：

    sh 项目文件/scripts/claim_log_number.sh
    # 输出被占用的序号，如 088；该序号在本次开发期间归本会话独占

脚本原理：用 `mkdir` 对同名目录做原子占位——POSIX 保证多个会话同时抢占同一序号时
恰好只有一个成功，不需要任何会话间通信。遗留锁按目录 mtime 判定（默认 24 小时），
崩溃会话留下的锁可被自动回收。

必须遵守：

1. **先占位，再写日志**
2. **写完即释放**：日志 `git add` 后执行 `rm -rf 项目开发日志/.locks/<序号>`
3. 一次开发只占一个序号
4. **提交前复核**：再扫一次目录，确认不存在第二个同序号日志；若发现，停止并向用户
   报告，不得自行改号
5. 若脚本输出为空或报错，停止并报告，不得手工编一个序号

**冲突兜底**：若历史遗留或人为错误导致同序号，保留日期较早者，日期较晚者重新占位一个新序号。

**已知边界**：本机制依赖同一文件系统上的原子 `mkdir`。若多个会话运行在不同机器或不同
git 克隆上，锁文件不共享，本机制失效——此时必须改为串行写日志，或由一位维护者统一编号。

---

## 四、正文模板

以下模板中的 `[日志编号]` **必须替换为实际序号**（3 位零填充），不得保留方括号占位符。
替换后形如 `## [日志编号 086] - 2026-09-08 10:30`。
