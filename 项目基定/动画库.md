# 动画库

> 本文档定义项目中所有动画效果，供前端开发时统一引用。每种动画包含 keyframes 定义、使用方式、参数说明和注意事项（避坑）。

---

## 1 入场动画

### 1.1 菜单项飞入（menuItemFlyIn）

**效果**：元素从左侧模糊飞入，逐渐清晰并滑入最终位置。

**适用场景**：侧边栏菜单项首次加载、列表项逐条入场。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 统一时长 | `300ms` | 每个元素的动画时长 |
| 交错延迟 | `40ms` | 相邻元素的播放间隔 |
| 缓动曲线 | `ease-out` | 先快后慢，入场自然 |
| 初始模糊 | `6px` | `filter: blur(6px)` |
| 水平偏移 | `-16px` | `transform: translateX(-16px)`，向左偏移 |

**keyframes**：

```css
@keyframes menuItemFlyIn {
  0%   { opacity: 0; filter: blur(6px); transform: translateX(-16px); }
  100% { opacity: 1; filter: blur(0);   transform: translateX(0);      }
}
```

**使用方式（CSS Modules + :global）**：

```css
/* 初始状态：隐藏 + 模糊 + 偏移 */
:global(.your-container .your-item) {
  opacity: 0;
  filter: blur(6px);
  transform: translateX(-16px);
}

/* 触发类添加后播放动画 */
:global(.your-entered .your-item) {
  animation: menuItemFlyIn 400ms ease-out forwards;
}

/* 交错延迟 */
:global(.your-entered .your-item:nth-child(1))  { animation-delay: 0ms; }
:global(.your-entered .your-item:nth-child(2))  { animation-delay: 60ms; }
:global(.your-entered .your-item:nth-child(3))  { animation-delay: 120ms; }
/* ... 继续到所需数量 */
```

**JS 触发（React）**：

```tsx
const [entered, setEntered] = useState(false);
useEffect(() => {
  const timer = setTimeout(() => setEntered(true), 100);
  return () => clearTimeout(timer);
}, []);

<div className={entered ? 'your-entered' : ''}>
  {/* items */}
</div>
```

**注意事项**：
- 需要 JS 配合：组件挂载后等待一帧（~100ms）再添加触发类，确保 DOM 已渲染
- `forwards` 填充模式确保动画结束后元素保持最终状态，不回弹
- 交错延迟 = 统一时长 / 元素数量 × 调节系数，当前 40ms 适用于 22~25 个元素
- 如果同时有 `.ant-menu-item` 和 `.ant-menu-submenu-title`，两者都需要在选择器中覆盖
- **首次挂载只触发一次**：不要复用 `entered` 状态到路由切换等场景

### 1.2 列表逐条浮入（widgetFadeUp）

**效果**：列表项从下方淡入，不含位移（避免与拖拽库的 transform 冲突）。

**适用场景**：首页小组件、卡片网格、表格行、任何有拖拽（react-dnd / dnd-kit）的列表。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 统一时长 | `350ms` | 每个元素的动画时长 |
| 交错延迟 | `100ms` | 相邻元素的播放间隔 |
| 缓动曲线 | `ease-out` | 先快后慢 |

**keyframes**：

```css
@keyframes widgetFadeUp {
  0%   { opacity: 0; }
  100% { opacity: 1; }
}
```

**使用方式**：

```css
.your-list > * {
  animation: widgetFadeUp 350ms ease-out both;
}

.your-list > *:nth-child(1) { animation-delay: 0ms; }
.your-list > *:nth-child(2) { animation-delay: 100ms; }
.your-list > *:nth-child(3) { animation-delay: 200ms; }
/* ... */
```

**注意事项（关键）**：
- **`animation-fill-mode: both` 必须使用**：`backwards` 填充使元素在动画开始前保持 `opacity: 0`，避免闪烁；`forwards` 使元素在动画结束后保持 `opacity: 1`
- **不要在 keyframes 中加 `transform`**：react-dnd、dnd-kit 等拖拽库通过 inline style 设置 `transform` 控制拖拽位置。如果动画 keyframes 包含 `transform: translateY(...)`，结束后的填充值会覆盖拖拽库的 transform，导致拖拽无动画
- 同样适用：任何通过 JS 控制 `transform` 的场景（滚动视差、缩放拖拽等）

---

### 1.3 路由渐入（routeFadeIn）

**效果**：路由切换时页面内容从下方淡入。

**适用场景**：所有路由切换（包裹 `<Outlet />`）。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 时长 | `300ms` | 单次路由切换动画时长 |
| 缓动曲线 | `ease-out` | |
| 垂直偏移 | `8px` | `translateY(8px)` |

**keyframes**：

```css
@keyframes routeFadeIn {
  0%   { opacity: 0; transform: translateY(8px); }
  100% { opacity: 1; transform: translateY(0);   }
}
```

**使用方式**：

```css
.transitionWrapper {
  animation: routeFadeIn 300ms ease-out;
}
```

```tsx
<div key={location.pathname} className={styles.transitionWrapper}>
  <Outlet />
</div>
```

**注意事项**：
- 必须用 `key={location.pathname}` 包裹 `<Outlet />`，否则 React 不重新挂载，动画不触发
- 适合页面级切换；组件内的小范围切换（如 Tab 切换）不适合，会因 key 变化重建所有状态
- **不与同时使用 `transform` 的 JS 库共用**：动画结束后 `transform: translateY(0)` 的填充值会覆盖 JS 设置的 transform（同 widgetFadeUp 的陷阱）。仅在纯页面过渡场景使用

---

### 1.4 登录卡片放大淡出（loginCardOut）

**效果**：登录卡片放大并淡出，背景同步消失，为工作台入场做铺垫。

**适用场景**：登录成功后跳转前、任何"完成操作→跳转新页面"的过渡场景。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 时长 | `400ms` | 卡片放大淡出时长 |
| 缓动曲线 | `ease-in` | 先慢后快，出场自然 |
| 缩放倍数 | `1.05` | `scale(1) → scale(1.05)`，轻微放大 |
| 容器淡出 | `400ms ease-out` | 背景同步淡出 |

**keyframes**：

```css
/* 卡片放大淡出 */
@keyframes loginCardOut {
  0%   { opacity: 1; transform: scale(1);   }
  100% { opacity: 0; transform: scale(1.05); }
}

/* 容器背景淡出 */
.containerLeaving {
  transition: opacity 400ms ease-out;
  opacity: 0;
}
```

**使用方式**：

```tsx
const [transitioning, setTransitioning] = useState(false);

const handleSubmit = async (values) => {
  // ... login API call ...
  if (success) {
    setTransitioning(true);
    setTimeout(() => navigate('/'), 400);
  }
};

<div className={`${styles.container} ${transitioning ? styles.containerLeaving : ''}`}>
  <Card className={`${styles.card} ${transitioning ? styles.cardLeaving : ''}`}>
    {/* form */}
  </Card>
</div>
```

**注意事项**：
- `setTimeout` 延迟必须 ≥ 动画时长（400ms），否则页面可能在动画播完前就跳转了
- 容器和卡片使用不同的缓动（`ease-out` vs `ease-in`），产生层次感
- 卡片 `transform: scale(1.05)` 在 keyframes 中定义，动画结束后不保留（无 fill-mode），不影响后续渲染

### 1.5 工作台浮入（appFloatIn）

**效果**：整个工作台界面从下方浮入，与登录卡片的放大淡出衔接形成完整的登录过渡。

**适用场景**：登录后工作台首次挂载、任何整页级别的入场场景。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 时长 | `500ms` | 浮入动画时长 |
| 缓动曲线 | `ease-out` | 先快后慢，入场自然 |
| 垂直偏移 | `24px` | `translateY(24px)`，从下方浮入 |
| 触发延迟 | `100ms` | 组件挂载后延迟触发，确保 DOM 就绪 |

**keyframes**：

```css
@keyframes appFloatIn {
  0%   { opacity: 0; transform: translateY(24px); }
  100% { opacity: 1; transform: translateY(0);     }
}
```

**使用方式（CSS Modules）**：

```css
/* 初始状态：隐藏 */
.appLayout {
  opacity: 0;
}

/* 触发类添加后播放 */
.appEntered {
  animation: appFloatIn 500ms ease-out forwards;
}
```

```tsx
const [entered, setEntered] = useState(false);

useEffect(() => {
  const timer = setTimeout(() => setEntered(true), 100);
  return () => clearTimeout(timer);
}, []);

<Layout className={`${styles.appLayout}${entered ? ` ${styles.appEntered}` : ''}`}>
  <Header>...</Header>
  <Content>...</Content>
</Layout>
```

**注意事项**：
- `forwards` 填充模式确保动画结束后工作台保持可见，不回弹
- 与 `menuItemFlyIn` 共享同一个 `entered` 状态（均 100ms 后触发），使侧边栏飞入和工作台浮入同时进行
- 使用 CSS Modules 局部类名（`.appLayout` / `.appEntered`），不与全局样式冲突
- **首次挂载只触发一次**：`useEffect([], [])` 确保仅登录后首次进入工作台时播放

---

### 1.6 登录→工作台完整过渡流程

**时序**：

```
用户点击登录
    │
    ├─ 登录中（button loading）
    │
    ├─ 登录成功
    │   ├─ setTransitioning(true)
    │   │   ├─ 卡片放大淡出 400ms (loginCardOut)
    │   │   └─ 背景淡出 400ms (containerLeaving)
    │   │
    │   └─ setTimeout 400ms → navigate('/')
    │
    ├─ MainLayout 挂载
    │   └─ useEffect 100ms → setSidebarEntered(true)
    │       ├─ 侧边栏逐项飞入 (menuItemFlyIn, 60ms 交错)
    │       └─ 工作台浮入 (appFloatIn, 500ms)
    │
    └─ 过渡完成，用户进入工作台
```

**协调要点**：
- 登录页的 `setTimeout(400ms)` 与 `loginCardOut` 时长一致
- 工作台的 `useEffect(100ms)` 给 React 渲染一帧缓冲区
- 两个组件不直接通信，通过路由切换自然衔接
- 总过渡时间 ≈ 400ms（登录）+ 100ms（缓冲）+ 500ms（工作台）= ~1s

### 1.7 锁屏页逐项入场（lockPageEnter）

**效果**：锁屏页头像、名称、锁图标、"已锁定"提示 4 个元素从模糊到清晰依次入场。

**适用场景**：锁定后看到锁屏页面时、任何需要元素 stagger 入场的居中页面。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 统一时长 | `500ms` | 每个元素的动画时长 |
| 交错延迟 | `60ms` | 相邻元素的播放间隔 |
| 缓动曲线 | `ease-out` | |
| 初始模糊 | `8px` | `filter: blur(8px)` |

**keyframes**：

```css
@keyframes lockPageEnter {
  0%   { opacity: 0; filter: blur(8px); }
  100% { opacity: 1; filter: blur(0);   }
}
```

**使用方式（CSS Modules）**：

```css
.enterElement {
  opacity: 0;
  filter: blur(8px);
  animation: lockPageEnter 500ms ease-out forwards;
}

.enterElement:nth-child(1) { animation-delay: 0ms;   } /* avatar */
.enterElement:nth-child(2) { animation-delay: 60ms;  } /* name   */
.enterElement:nth-child(3) { animation-delay: 120ms; } /* lock   */
.enterElement:nth-child(4) { animation-delay: 180ms; } /* subtitle */
```

**注意事项**：
- `forwards` 填充模式确保元素动画结束后保持清晰可见
- 元素本身已有 `opacity: 0; filter: blur(8px)` 初始状态，动画从不可见过渡到可见
- 交错延迟 = 180ms / 4 × 2（最后元素延迟为总时长约1/3，照顾尾部元素动画在用户注意范围内）

### 1.8 工作台模糊退出（workbenchBlurOut）

**效果**：整个工作台 Layout 逐渐模糊，为跳转到目标页面做铺垫。

**适用场景**：锁定（跳转锁屏页）、任何需要"离开工作台→进入其他页面"的过渡。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 时长 | `480ms` | 模糊过渡时长 |
| 缓动曲线 | `ease` | 线性感加速，退出自然 |
| 最大模糊 | `14px` | `filter: blur(14px)` |

**keyframes**：

```css
@keyframes workbenchBlurOut {
  0%   { filter: blur(0);   }
  100% { filter: blur(14px); }
}
```

**使用方式**：

```css
.locking {
  filter: blur(0);
  animation: workbenchBlurOut 480ms ease forwards;
}
```

```tsx
const [locking, setLocking] = useState(false);
// 触发锁定：setLocking(true) + setTimeout(500ms) → navigate('/lock')
<Layout className={locking ? styles.locking : ''}>...</Layout>
```

**注意事项**：
- `forwards` 填充后保留 `blur(14px)` 模糊态，跳转后自然消失
- setTimeout 延迟需 ≥ 480ms（比动画时长多 20ms 缓冲），确保动画播完再跳转
- 模糊动画只作用在 Layout 容器上，不嵌套在内部子元素中，避免多重模糊叠加严重影响性能

---

### 1.9 工作台模糊进场（workbenchBlurIn）

**效果**：工作台从模糊、缩小、半透明状态恢复清晰，与退出动画对称反向。

**适用场景**：解锁后跳回工作台、任何需要"从 X 页面进入工作台"的过渡。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 时长 | `480ms` | 模糊恢复时长（与 exit 完全对称） |
| 缓动曲线 | `ease-out` | 先快后慢，进场自然 |
| 初始模糊 | `14px` | 与 workbenchBlurOut 终点值一致 |
| 初始缩放 | `0.95` | `scale(0.95)`，略带缩小感 |
| 初始透明度 | `0.4` | 半透明 |

**keyframes**：

```css
@keyframes workbenchBlurIn {
  0%   { filter: blur(14px); opacity: 0.4; transform: scale(0.95); }
  100% { filter: blur(0);    opacity: 1;   transform: scale(1);    }
}
```

**使用方式**：

```css
.welcoming {
  filter: blur(14px);
  opacity: 0.4;
  transform: scale(0.95);
  animation: workbenchBlurIn 480ms ease-out forwards;
}
```

```tsx
// 解锁页 dissolve → navigate → MainLayout 检测 sessionStorage 标记
const welcoming = sessionStorage.getItem('workbench_just_unlocked') === '1';
if (welcoming) sessionStorage.removeItem('workbench_just_unlocked');

<Layout className={welcoming ? styles.welcoming : ''}>...</Layout>
```

**注意事项**：
- 初始状态 `blur(14px); opacity: 0.4; scale(0.95)` 必须写在 CSS 类中（非 keyframes），确保动画开始前元素已在正确初始态
- 与 `appFloatIn`（登录→工作台用）是两个独立的进场动画，不可互相替代：
  - `appFloatIn`：适用于**首次登录**，工作台从下方浮入（translateY 24px），伴随侧边栏飞入
  - `workbenchBlurIn`：适用于**解锁后返回**，工作台在当前位置恢复清晰（无位移），不重复播放菜单飞入

---

### 1.10 锁屏页逐项出场（lockPageExit）

**效果**：lockPageEnter 的完全反向——"已锁定"文字、锁图标、名称、头像 4 个元素从清晰到模糊依次消失。

**适用场景**：解锁成功到页面跳转前的退出动画。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 时长 | `500ms` | 与 lockPageEnter 对称 |
| 交错延迟 | `60ms` | **逆向**：subtitle(0ms) → lock(60ms) → name(120ms) → avatar(180ms) |
| 目标模糊 | `8px` | 与 lockPageEnter 初始值一致 |

**keyframes**：

```css
@keyframes lockPageExit {
  from { opacity: 1; filter: blur(0);   }
  to   { opacity: 0; filter: blur(8px); }
}
```

**使用方式**：

```css
/* 覆写 enterElement 的入场动画为出场动画 */
.container.exiting .enterElement {
  opacity: 1;
  filter: blur(0);
  animation: lockPageExit 500ms ease-out forwards;
}
.container.exiting .enterElement:nth-child(1) { animation-delay: 180ms; } /* avatar — exits last */
.container.exiting .enterElement:nth-child(2) { animation-delay: 120ms; }
.container.exiting .enterElement:nth-child(3) { animation-delay: 60ms;  }
.container.exiting .enterElement:nth-child(4) { animation-delay: 0ms;   } /* subtitle — exits first */
```

**注意事项**：
- 关键：`.container.exiting .enterElement` 中必须显式覆写 `opacity: 1; filter: blur(0)`，否则移除 `lockPageEnter` animation 时底层样式 `opacity: 0` 会暴露一帧造成闪白
- 最终元素出场延迟 = 180ms（avatar）+ 500ms（动画）= 680ms → JS setTimeout 用 700ms 缓冲
- 与 lockPageEnter 使用同一组元素和同一套 nth-child 选择器，仅通过容器 `.exiting` 类区分方向

### 1.11 离开工作台过渡（通用）

**效果**：从工作台跳转到任何其他页面时，工作台先模糊退出，再跳转目标页面。

**时序**：

```
触发离开（锁定 / 跳转页面）
    ├─ setLocking(true)
    │   └─ workbenchBlurOut 480ms
    │       └─ Layout 逐渐模糊到 blur(14px)
    │
    └─ setTimeout 500ms → navigate('/target')
        ├─ 过渡遮罩（可选）淡入
        └─ 目标页面播放自身的入场动画（如 lockPageEnter）
```

**协调要点**：
- 离开时只需加 `.locking` 类触发 `workbenchBlurOut`，无需修改目标页面的代码
- 如果目标页面的入场动画有自己的延迟（如 lockPageEnter 的 stagger），两者通过 navigate 切换自然衔接
- `ease` 缓动（非 ease-out）是为了让模糊加速度在前半段更均匀，避免末尾过于缓慢

---

### 1.12 进入工作台过渡（通用）

**效果**：从任意页面跳回工作台时，工作台从模糊恢复清晰，无元素飞入（与首次登录的 appFloatIn 区分）。

**时序**：

```
解锁成功
    ├─ lockPageExit 逆向 stagger 出场 (700ms)
    │   └─ sessionStorage.setItem('workbench_just_unlocked', '1')
    │
    └─ setTimeout 700ms → navigate('/')  { replace: true }
        ├─ MainLayout 挂载，检测 workbench_just_unlocked 标记
        │   └─ workbenchBlurIn 480ms（blur 14px→0 + scale 0.95→1）
        │
        └─ 工作台恢复清晰
```

**进入工作台的两个动画选择**：

| 来源 | 使用动画 | 原因 |
|------|---------|------|
| 登录页 | `appFloatIn`（1.5） | 首次进入，从下方浮入 + 侧边栏飞入 + 路由淡入，全套入场体验 |
| 锁定页（解锁后） | `workbenchBlurIn`（1.9） | 已登录用户返回，工作台在原地恢复清晰，不重复播放元素飞入 |
| 任何其他页面 | `workbenchBlurIn`（1.9） | 复用解锁返回模式，保持一致的"回到工作台"过渡体验 |

## 2 动画参数速查

| 动画名 | 时长 | 缓动 | 交错延迟 | fill-mode | 包含 transform | 场景 |
|--------|------|------|---------|-----------|---------------|------|
| `menuItemFlyIn` | 300ms | ease-out | 40ms | forwards | 是 | 侧边栏入场 |
| `widgetFadeUp` | 350ms | ease-out | 100ms | **both** | 否 | 拖拽列表入场 |
| `routeFadeIn` | 300ms | ease-out | 无 | 无 | 是 | 路由切换 |
| `loginCardOut` | 400ms | ease-in | 无 | 无 | 是 | 登录卡片退出 |
| `appFloatIn` | 500ms | ease-out | 无 | forwards | 是 | 工作台首次整页入场 |
| `lockPageEnter` | 500ms | ease-out | 60ms | forwards | 否 | 锁屏页元素 stagger 入场 |
| `lockPageExit` | 500ms | ease-out | 60ms(逆) | forwards | 否 | 锁屏页逆向 stagger 出场 |
| `workbenchBlurOut` | 480ms | ease | 无 | forwards | 否 | 工作台模糊退出（离场） |
| `workbenchBlurIn` | 480ms | ease-out | 无 | forwards | 是 | 工作台模糊进场（返回） |

## 3 使用原则

1. **优先 GPU 合成属性**：只动画 `opacity` 和 `transform`，避免 `width/height/left/top/margin/padding` 等触发重排的属性
2. **拖拽场景只用 opacity**：任何有 `transform` 动画的元素不能同时被 JS 控制 `transform`（react-dnd 等）。拖拽列表只用 `widgetFadeUp` 模式
3. **首屏动画只播一次**：入场动画只应在用户首次看到时播放，路由切换、Tab 切换等不应重复触发
4. **`both` vs `forwards`**：
   - 需要防闪烁 → `both`（backwards 填充在延迟期间保持初始透明度）
   - 无延迟或不需要防闪烁 → `forwards`
5. **交错延迟计算**：延迟 ≈ 总时长 / 元素数 × 0.6（确保最后一个元素在总时长内播完）
