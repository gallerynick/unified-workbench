# 《一站式工作台》TestPage 使用与开发文档

------

## 1. 概述

TestPage 是写入工作台前的**组件验证沙箱**，用于在新组件正式集成到工作台页面之前进行隔离验证。它位于 `/dev/testpage`，仅在调试模式（SiteSettings）开启时可访问。

| 项目         | 内容                                             |
| ------------ | ------------------------------------------------ |
| **页面路径** | `/dev/testpage`                                  |
| **代码位置** | `项目文件/frontend/src/pages/dev/TestPage.tsx`    |
| **访问限制** | 仅调试模式开启时可访问，且仅限管理员             |
| **数据隔离** | 只做组件渲染验证，不读写生产数据                 |
| **适用范围** | 前端组件开发、验证、深浅色模式检查、回归测试     |

**设计理念：**

- **组件先行**：新组件先在沙箱中独立验证交互与样式，不与业务数据耦合
- **快速迭代**：注册即用，无需为每个新组件搭建临时页面
- **规范沉淀**：每个组件提供源码参考，便于复用与评审
- **隔离安全**：调试页面不进入生产路由，避免未验证组件暴露给正式用户

------

## 2. 访问方式

TestPage 仅在**调试模式**开启时可访问，访问链路为：

**系统设置 → 站点设置 → 调试模式 → 开启 → 访问 `/dev/testpage`**

### 2.1 开启调试模式

1. 使用**管理员账号**登录系统
2. 进入「系统设置 → 站点设置」（路径 `/settings/site`）
3. 找到「调试模式」卡片
4. 打开「开启调试模式」开关
5. 点击「保存配置」

> 注意：调试模式仅管理员可以开启。开启后普通成员访问系统将显示测试提示页，无法进入系统；只有管理员可以正常访问。

### 2.2 访问 TestPage

调试模式开启后，浏览器访问：

```text
/dev/testpage
```

**访问条件（缺一不可）：**

- 已登录管理员账号
- 调试模式（`site_config.debug_mode`）已开启

条件不满足时页面不可访问，不会展示任何测试组件。

### 2.3 关闭调试模式

在站点设置中关闭「开启调试模式」开关并保存，TestPage 随即不可访问。验证完成后应及时关闭调试模式，恢复普通成员的正常访问。

------

## 3. 功能说明

TestPage 采用三栏布局：

### 3.1 左侧：组件选择器

- 列出 `COMPONENT_DEMOS` 数组中注册的所有可测试组件
- 以组件名称（label）展示，点击切换当前测试对象
- 未注册的组件不会出现在列表中

### 3.2 右侧：预览区

- 实时渲染当前选中的组件
- 组件的交互、样式、深浅色模式表现均在此处直接观察
- 预览区独立于工作台布局，不受页面容器影响，便于聚焦组件本身

### 3.3 底部：代码区

- 展示当前选中组件的源码参考
- 便于开发者在验证的同时对照实现细节
- 支持复制代码，集成到正式页面时直接复用

------

## 4. 添加新测试组件的方法

### 4.1 注册位置

在 `TestPage.tsx` 顶部的 `COMPONENT_DEMOS` 数组中注册新条目。

### 4.2 条目字段

每个条目包含四个字段：

| 字段        | 类型              | 必填 | 说明                                 |
| ----------- | ----------------- | ---- | ------------------------------------ |
| `key`       | string            | 是   | 唯一标识，不可重复                   |
| `label`     | string            | 是   | 组件名称，显示在左侧选择器中         |
| `description` | string          | 是   | 组件说明，描述用途与验证要点         |
| `component` | React.ReactNode   | 是   | 要渲染的组件实例                     |

### 4.3 示例代码

```tsx
import { Card, Button } from 'antd';
import { useState } from 'react';

// 示例：带状态的计数器组件
function Counter() {
  const [count, setCount] = useState(0);
  return (
    <Space>
      <Button onClick={() => setCount((c) => c + 1)}>加一</Button>
      <span>当前值：{count}</span>
    </Space>
  );
}

interface DemoEntry {
  key: string;
  label: string;
  description: string;
  component: React.ReactNode;
}

const COMPONENT_DEMOS: DemoEntry[] = [
  {
    key: 'counter',
    label: '计数器',
    description: '验证点击计数与按钮状态切换',
    component: (
      <Card title="计数器示例" style={{ width: 320 }}>
        <Counter />
      </Card>
    ),
  },
  // 在此追加新的测试组件条目
];
```

### 4.4 注册后

- 保存文件，刷新 `/dev/testpage` 页面
- 新组件出现在左侧选择器中，点击即可预览
- 如需调整，仅需修改对应条目或组件源码，保存后刷新即可生效

------

## 5. 开发规范

### 5.1 开发流程

1. 开发新组件
2. 在 TestPage 中注册并验证
3. 验证交互、样式、深浅色模式适配均无误
4. 确认无误后集成到工作台正式页面
5. 按需保留或移除 TestPage 中的注册条目（建议保留，便于后续回归验证）

### 5.2 强制约束

- 组件开发完成后**必须先**在 TestPage 中验证，确认无误后再集成到工作台正式页面
- **禁止**将未验证的组件直接放入生产路由
- TestPage 只做渲染验证，不承载任何业务数据读写
- 新增组件必须同时适配深浅色模式，验证时两种模式均需检查

------

## 6. 注意事项

- **访问控制**：调试模式关闭后该页面不可访问；访问条件不满足时不会展示任何测试组件
- **权限**：仅管理员可开启调试模式，普通成员无法开启，也无法访问 TestPage
- **数据隔离**：测试数据不与生产数据混合，TestPage 中禁止调用会产生真实数据的接口
- **调试模式副作用**：调试模式开启期间普通成员无法进入系统，验证完成后应及时关闭调试模式
- **注册规范**：`COMPONENT_DEMOS` 中条目 `key` 必须唯一，`label` 应使用中文名称，`description` 写明验证要点
