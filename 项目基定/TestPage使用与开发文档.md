# 《一站式工作台》TestPage 使用与开发文档

------

## 1. 概述

TestPage 是写入工作台前的**组件验证沙箱**，用于在新组件正式集成到工作台页面之前进行隔离验证。它是一个**全屏独立页面**（无工作台侧边栏/顶栏），位于 `/dev/testpage`，仅在调试模式开启时可访问。

| 项目         | 内容                                             |
| ------------ | ------------------------------------------------ |
| **页面路径** | `/dev/testpage`                                  |
| **代码位置** | `项目文件/frontend/src/pages/dev/TestPage.tsx`    |
| **访问限制** | 仅调试模式开启时可访问，需已登录                 |
| **数据隔离** | 只做组件渲染验证，不读写生产数据                 |
| **适用范围** | 前端组件开发、验证、深浅色模式检查、回归测试     |

**设计理念：**

- **组件先行**：新组件先在沙箱中独立验证交互与样式，不与业务数据耦合
- **分区注册**：通过 `SECTIONS` 注册表新增分区，框架固定、分区内容自由开发
- **快速迭代**：注册即用，无需为每个新组件搭建临时页面
- **隔离安全**：调试页面不进入生产路由，避免未验证组件暴露给正式用户

------

## 2. 访问方式

TestPage 仅在**调试模式**开启时可访问，访问链路为：

**系统设置 → 站点设置 → 调试模式 → 开启 → 访问 `/dev/testpage`**

### 2.1 开启调试模式

1. 使用**管理员账号**登录系统
2. 进入「系统设置 → 站点设置」（路径 `/settings/site`）
3. 找到「调试模式」卡片
4. 打开「开启调试模式」开关
5. 点击「保存配置」

> 说明：调试模式仅控制调试面板与 TestPage 的可用性，**不影响普通成员的访问**。若需临时阻止普通成员进入系统，请使用「维护模式」开关（`maintenance_mode`），两个开关相互独立。

### 2.2 访问 TestPage

调试模式开启后，浏览器访问：

```text
/dev/testpage
```

**访问条件（缺一不可）：**

- 已登录账号
- 调试模式（`site_config.debug_mode`）已开启

条件不满足时页面不可访问，不会展示任何测试组件。

### 2.3 关闭调试模式

在站点设置中关闭「开启调试模式」开关并保存，TestPage 随即不可访问。验证完成后应及时关闭调试模式。

------

## 3. 页面结构说明

TestPage 为**全屏主从布局**，由固定的框架与可扩展的分区内容两部分组成：

### 3.1 顶部：标题栏（topbar）

- 显示页面标题「组件测试页」与「返回工作台」按钮
- 该区域为**固定框架**，开发调试内容时不可修改

### 3.2 左侧：分区列表（sider）

- 列出 `SECTIONS` 数组中注册的所有分区
- 以分区名称（label）展示，点击切换到对应分区内容
- 未注册的分区不会出现在列表中
- 该区域为**固定框架**，不可修改

### 3.3 右侧：分区内容区（content）

- 实时渲染当前选中分区的 `render` 输出
- 组件/控件的交互、样式、深浅色模式表现均在此处直接观察
- 该区域为**唯一允许开发的位置**——开发者只在此分区内编写与展示测试内容

**分区结构示意：**

```text
┌─────────────────────────────────────────────┐
│  topbar：标题 + 返回工作台按钮（固定框架）     │
├──────────────┬──────────────────────────────┤
│  sider       │  content                     │
│  （固定框架） │  （分区内容，唯一可开发区）     │
│  ├ 分区A     │  当前选中分区的 render 输出     │
│  ├ 分区B     │                              │
│  └ 分区C     │                              │
└──────────────┴──────────────────────────────┘
```

## 4. 添加新测试分区的方法

### 4.1 注册位置

在 `TestPage.tsx` 的 `SECTIONS` 数组中注册新条目。

### 4.2 条目字段

每个条目包含四个字段：

| 字段     | 类型             | 必填 | 说明                           |
| -------- | ---------------- | ---- | ------------------------------ |
| `key`    | string           | 是   | 唯一标识，不可重复             |
| `label`  | string           | 是   | 分区名称，显示在左侧列表中     |
| `icon`   | React.ReactNode  | 是   | 分区图标（`@ant-design/icons`）|
| `render` | () => React.ReactNode | 是 | 返回该分区要渲染的内容     |

### 4.3 示例代码

```tsx
import { Button, Card, Space } from 'antd';
import { AppstoreOutlined } from '@ant-design/icons';
import { useState } from 'react';

// 示例：带状态的计数器组件（在分区内开发）
function Counter() {
  const [count, setCount] = useState(0);
  return (
    <Space>
      <Button onClick={() => setCount((c) => c + 1)}>加一</Button>
      <span>当前值：{count}</span>
    </Space>
  );
}

interface Section {
  key: string;
  label: string;
  icon: React.ReactNode;
  render: () => React.ReactNode;
}

const SECTIONS: Section[] = [
  {
    key: 'counter',
    label: '计数器',
    icon: <AppstoreOutlined />,
    render: () => (
      <Card title="计数器示例" style={{ width: 320 }}>
        <Counter />
      </Card>
    ),
  },
  // 在此追加新的测试分区条目
];
```

### 4.4 注册后

- 保存文件，刷新 `/dev/testpage` 页面
- 新分区出现在左侧列表中，点击即可查看
- 如需调整，仅修改对应分区条目或 `render` 内容，保存后刷新即可生效

------

## 5. 开发规范

### 5.1 开发流程

1. 开发新组件
2. 在 `SECTIONS` 中注册新分区并编写 `render` 内容
3. 验证交互、样式、深浅色模式适配均无误
4. 确认无误后集成到工作台正式页面
5. 按需保留或移除 TestPage 中的注册条目（建议保留，便于后续回归验证）

### 5.2 强制约束

- 组件开发完成后**必须先**在 TestPage 中验证，确认无误后再集成到工作台正式页面
- **禁止**将未验证的组件直接放入生产路由
- TestPage 只做渲染验证，不承载任何业务数据读写
- 新增组件必须同时适配深浅色模式，验证时两种模式均需检查
- **框架不可动**：topbar、sider 及 `SECTIONS` 数组本身（注册表结构）为固定框架，开发期间只允许在分区内容（`render`）内编写与展示，禁止修改框架结构

------

## 6. 注意事项

- **访问控制**：调试模式关闭后该页面不可访问；访问条件不满足时不会展示任何测试组件
- **权限**：仅管理员可开启调试模式；调试模式不影响普通成员访问（维护模式才影响）
- **数据隔离**：测试数据不与生产数据混合，TestPage 中禁止调用会产生真实数据的接口
- **维护模式区别**：如需阻止普通成员进入系统，使用「维护模式」开关（`maintenance_mode`），与「调试模式」（`debug_mode`）相互独立
- **注册规范**：`SECTIONS` 中条目 `key` 必须唯一，`label` 应使用中文名称，`icon` 使用 `@ant-design/icons`，`render` 返回要展示的内容
