# 《一站式工作台》开发测试页使用与开发文档

## 1. 概述

开发测试页（TestPage）是写入工作台前的**组件验证沙箱**，用于在新组件正式集成到工作台页面之前进行隔离验证。它是一个**全屏独立页面**（无工作台侧边栏/顶栏），位于 `/dev/testpage`，仅在调试模式开启时可访问。

| 项目         | 内容                                             |
| ------------ | ------------------------------------------------ |
| **页面路径** | `/dev/testpage`（索引页）/ `/dev/testpage/:key`（单项页） |
| **代码位置** | `项目文件/frontend/src/pages/dev/TestPage.tsx`    |
| **访问限制** | 仅调试模式开启时可访问，需已登录                 |
| **数据隔离** | 只做组件渲染验证，不读写生产数据                 |
| **适用范围** | 前端组件开发、验证、深浅色模式检查、回归测试     |

**设计理念：**

- **组件先行**：新组件先在沙箱中独立验证交互与样式，不与业务数据耦合
- **分区注册**：通过 `SECTIONS` 注册表新增分区，索引页自动收录，单项页纯渲染
- **快速迭代**：注册即用，无需为每个新组件搭建临时页面
- **隔离安全**：调试页面不进入生产路由，避免未验证组件暴露给正式用户

## 2. 访问方式

开发测试页仅在**调试模式**开启时可访问，访问链路为：

**系统设置 → 站点设置 → 调试模式 → 开启 → 访问 `/dev/testpage`**

### 2.1 开启调试模式

1. 使用**管理员账号**登录系统
2. 进入「系统设置 → 站点设置」（路径 `/settings/site`）
3. 找到「调试模式」卡片
4. 打开「开启调试模式」开关
5. 点击「保存配置」

> 说明：调试模式仅控制调试面板与开发测试页的可用性，**不影响普通成员的访问**。若需临时阻止普通成员进入系统，请使用「维护模式」开关（`maintenance_mode`），两个开关相互独立。

### 2.2 访问开发测试页

调试模式开启后，浏览器访问：

```text
/dev/testpage
```

该地址为**索引页**，列出所有已注册的测试分区，点击任意分区即可跳转到对应的单项测试页（`/dev/testpage/:key`）。

**访问条件（缺一不可）：**

- 已登录账号
- 调试模式（`site_config.debug_mode`）已开启

条件不满足时页面不可访问，不会展示任何测试组件。

### 2.3 关闭调试模式

在站点设置中关闭「开启调试模式」开关并保存，开发测试页随即不可访问。验证完成后应及时关闭调试模式。

## 3. 页面结构说明

开发测试页由**索引页**与**单项页**两种视图组成：

### 3.1 索引页（`/dev/testpage`）

- 显示标题「开发测试页」与「返回工作台」按钮
- 列出 `SECTIONS` 数组中注册的所有分区，每项包含图标、标题、描述
- 点击任意分区跳转到 `/dev/testpage/:key`
- 该区域为**固定框架**，不可修改

### 3.2 单项页（`/dev/testpage/:key`）

- **纯渲染输出**：直接渲染该分区的 `render()` 结果，无任何额外 UI（无标题栏、无按钮、无边框）
- 若 `key` 不存在，显示 404 提示并附带返回索引按钮
- 该区域为**唯一允许开发的位置**——开发者只在此分区的 `render` 内编写与展示测试内容

**结构示意：**

```text
/dev/testpage                          /dev/testpage/example
┌────────────────────────┐             ┌────────────────────────┐
│  开发测试页     [返回]  │             │ [组件纯输出，无额外UI] │
├────────────────────────┤             └────────────────────────┘
│                        │
│  ├ [图标] 分区A 描述    │
│  ├ [图标] 分区B 描述    │
│  └ [图标] 分区C 描述    │
└────────────────────────┘
```

## 4. 添加新测试分区的方法

### 4.1 注册位置

在 `TestPage.tsx` 的 `SECTIONS` 数组中注册新条目。

### 4.2 条目字段

每个条目包含五个字段：

| 字段          | 类型             | 必填 | 说明                           |
| ------------- | ---------------- | ---- | ------------------------------ |
| `key`         | string           | 是   | 唯一标识，不可重复，决定访问路径 `/dev/testpage/{key}` |
| `label`       | string           | 是   | 分区名称，显示在索引页         |
| `icon`        | React.ReactNode  | 是   | 分区图标（`@ant-design/icons`）|
| `description` | string           | 是   | 分区描述，显示在索引页标题下方 |
| `render`      | () => ReactNode  | 是   | 返回该分区要渲染的内容         |

### 4.3 示例代码

```tsx
import { Button, Card, Space } from 'antd';
import { AppstoreOutlined } from '@ant-design/icons';
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <Space>
      <Button onClick={() => setCount((c) => c + 1)}>加一</Button>
      <span>当前值：{count}</span>
    </Space>
  );
}

interface Section {
  key: string;
  label: string;
  icon: React.ReactNode;
  description: string;
  render: () => React.ReactNode;
}

const SECTIONS: Section[] = [
  {
    key: 'counter',
    label: '计数器',
    icon: <AppstoreOutlined />,
    description: '状态管理测试',
    render: () => (
      <Card title="计数器示例" style={{ width: 320 }}>
        <Counter />
      </Card>
    ),
  },
];
```

### 4.4 注册后

- 保存文件，刷新 `/dev/testpage` 页面
- 新分区出现在索引页列表中，点击跳转至 `/dev/testpage/counter` 即可查看
- 单项页将**纯渲染**该组件，无任何额外 UI 干扰
- 如需调整，仅修改对应分区条目或 `render` 内容，保存后刷新即可生效

## 5. 开发规范

### 5.1 开发流程

1. 开发新组件
2. 在 `SECTIONS` 中注册新分区并编写 `render` 内容
3. 访问 `/dev/testpage` 索引页，点击分区进入单项页验证
4. 验证交互、样式、深浅色模式适配均无误
5. 确认无误后集成到工作台正式页面
6. 按需保留或移除 TestPage 中的注册条目（建议保留，便于后续回归验证）

### 5.2 强制约束

- 组件开发完成后**必须先**在开发测试页中验证，确认无误后再集成到工作台正式页面
- **禁止**将未验证的组件直接放入生产路由
- 开发测试页只做渲染验证，不承载任何业务数据读写
- 新增组件必须同时适配深浅色模式，验证时两种模式均需检查
- **框架不可动**：索引页的 topbar 与列表结构为固定框架，开发期间只允许在分区内容（`render`）内编写与展示，禁止修改框架结构
- **单项页零框架**：单项页 `/dev/testpage/:key` 只输出 `render()` 的内容，不含任何标题栏、按钮、边框等额外 UI

## 6. 注意事项

- **访问控制**：调试模式关闭后该页面不可访问；访问条件不满足时不会展示任何测试组件
- **权限**：仅管理员可开启调试模式；调试模式不影响普通成员访问（维护模式才影响）
- **数据隔离**：测试数据不与生产数据混合，开发测试页中禁止调用会产生真实数据的接口
- **维护模式区别**：如需阻止普通成员进入系统，使用「维护模式」开关（`maintenance_mode`），与「调试模式」（`debug_mode`）相互独立
- **注册规范**：`SECTIONS` 中条目 `key` 必须唯一且不含特殊字符（用于 URL 路径），`label` 应使用中文名称，`icon` 使用 `@ant-design/icons`，`description` 使用中文简述，`render` 返回要展示的内容
