# 数据库设计概览

## 概述

系统使用 PostgreSQL 15 作为唯一关系型数据源，SQLAlchemy 2.0 异步 ORM（`async_session` + `select`）承载全部访问。数据库层承担三类职责：业务数据存储、可见性约束（字段级默认私有）、以及导入导出的数据一致源。时区统一采用 Asia/Shanghai，数据库、容器与 Python 三层保持一致。迁移由 Alembic 管理，当前共 34 个迁移文件（编号 001-033 共 33 个，外加 1 个哈希命名迁移）。

## ORM 基础

- 数据库引擎与会话工厂：`app/core/database.py`（`Base`、`get_db` 依赖、`get_session_factory`）。
- 所有业务模型继承 `Base`，主键统一为 `uuid.UUID`（`UUID(as_uuid=True)`）。
- 时间字段使用 `DateTime(timezone=True)` 与 `server_default=func.now()`。
- 所有表分布在 `app/models/` 下，模型列表见 `app/models/__init__.py`。

## visibility 模式

可见性以"字段级默认私有"为核心约定，数据库层只存储声明，授权判定在应用层完成。下文分字段约定与覆盖范围说明。

### 字段约定

可见性相关表统一采用以下三字段（迁移 `015_add_visibility_to_form_vote_topology.py` 与 `027_add_visibility_to_eleven_tables.py` 实现）：

- `visibility VARCHAR(20) NOT NULL DEFAULT 'private'`：字段级默认私有，落实"默认私有，自主公开"。
- `restricted_users JSONB DEFAULT '[]'`：授权用户 ID 列表。
- `restricted_tags JSONB`：授权标签名称列表。

### 覆盖范围

- 15 张业务表带 `visibility` + `restricted_users` 字段：迁移 027 的 11 张表（inventory、contacts、budget、subscription、tasks、notes、calendar_events、secrets、secret_categories、templates、reminders）+ 迁移 015 的 3 张表（form、vote、topology）+ content 表。
- 其中 content、form、vote、topology 4 张表同时具备 `restricted_tags` 字段，支持标签维度授权。
- `calendar_event` 另含 `restricted_users`，但日历通过 `reminder_enabled` 等字段承载提醒语义。

### 判定逻辑

数据库只存储声明，判定在应用层 `app/core/permissions.py` 的 `check_visibility` 完成（详见 [权限模型设计](./权限模型设计.md)）。

## 审计日志

`audit_log` 表由迁移 `002_p1_tables.py` 创建、`005_p4_indexes.py` 补充索引，语义上**只增不改不删**：

- 仅 INSERT，无 UPDATE/DELETE 入口。
- 记录操作人、时间、操作类型、操作对象、IP 与变更 diff。
- 该表不参与数据导出，属于运行期审计数据。

## 自引用与级联

systems 表的自引用支撑服务器三级层级，外键级联保证删除的一致性。二者共同构成服务器管理模块的数据库骨架。

### System 自引用（两级层级）

`systems` 表的 `parent_system_id` 自引用外键实现 Server → System → VM 的两级结构：

- `parent_system_id IS NULL`：深度 0，直接挂载于 `servers` 表。
- `parent_system_id IS NOT NULL`：深度 1（VM），禁止再嵌套
- 关系定义于 `app/models/system.py`：`parent_system`（remote_side=[id]）+ `child_systems`，均带 `cascade="all, delete-orphan"`。

### CASCADE 删除链

- `servers` → `systems`：`System.server_id` 外键 `ondelete="CASCADE"`，`Server.systems` 关系 `cascade="all, delete-orphan"`。
- `systems` → `services`：`Service.system_id` 外键 `ondelete="CASCADE"`，`System.services` 关系 `cascade="all, delete-orphan"`。
- 删除服务器即级联删除其下所有系统与服务（`app/services/server.py` 的 `delete_server` 依赖该约束）。

## 时区策略

- Celery：`app/tasks/__init__.py` 中 `timezone="Asia/Shanghai"`、`enable_utc=True`。
- 容器：docker-compose 为 PostgreSQL / 应用容器配置 `TZ=Asia/Shanghai`。
- 应用：时间字段统一 `DateTime(timezone=True)`，导出时序列化为 ISO 字符串，导入时 `_parse_datetimes` 还原（`data_import.py`）。

三层统一避免日历事件、提醒触发时间在跨容器转换时产生偏移。

## 安全约束

- 可见性字段默认 `private`，防止新增表遗漏授权。
- 密钥相关表（secret、secret_category）不设 visibility，强制私有。
- 审计日志表只增不改不删，无修改入口。
- JSONB 授权字段（restricted_users / restricted_tags / member_ids / maintainer_ids）由服务层校验后才能作为权限依据，数据库不直接执行授权判定。
