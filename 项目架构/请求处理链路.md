# 请求处理链路

> 本文档描述一次 HTTP/WebSocket 请求从入口到数据库的完整生命周期：Nginx 代理、FastAPI 中间件、认证依赖、业务路由、服务层与 ORM 会话管理。适用于新增端点、调试认证问题与理解统一响应约定。

## 概述

外部请求统一经 `nginx` 容器进入，按路径分发到 `frontend`（静态资源）或 `backend`（API/WebSocket）。后端 `app/main.py` 中创建的 FastAPI 应用挂载了 CORS 中间件，所有 API 路由统一挂载在 `/api/v1` 前缀下。受保护端点通过 `app/core/deps.py` 提供的依赖链完成 JWT 认证与角色校验，最终由 Service 层调用 SQLAlchemy 模型访问数据库，响应统一封装为 `{ code, msg, data }` 格式。

## 核心设计

### 请求生命周期

```
浏览器/客户端
   │  HTTPS
   ▼
nginx 容器 (nginx/nginx.conf + includes/shared.conf)
   ├─ /api/*      → http://backend:8000  (proxy_pass, 60s 超时, client_max_body_size 1G)
   ├─ /ws         → http://backend:8000  (Upgrade/Connection 头, 7 天长连接)
   ├─ /live/*     → http://mediamtx:8889 (HLS/WebRTC 直播)
   ├─ 静态资源     → http://frontend:80   (缓存策略区分 JS/HTML)
   └─ /health     → http://backend:8000/api/v1/health
   ▼
FastAPI (app.main.py)
   ├─ CORSMiddleware (allow_origins / credentials / methods / headers)
   ├─ lifespan: create_initial_admin (启动时幂等 seed)
   ▼
app.api.router → api_router (prefix="/api/v1")
   ├─ Router 函数参数中的 Depends(...) 解析依赖
   ├─ Depends(get_db)      → AsyncSession（事务边界）
   ├─ Depends(get_current_user) / require_admin → 认证与鉴权
   ▼
Service 层 (app/services/*) — 业务逻辑
   ▼
Model 层 (app/models/*) — SQLAlchemy 2.0 Mapped 映射
   ▼
PostgreSQL / Redis
```

路由注册在 `app/api/router.py`：`api_router` 聚合各业务子路由，`app.include_router(api_router, prefix="/api/v1")`，WebSocket 路由 `app.api.ws` 单独挂载（`app.include_router(ws_router)`，路径 `/ws`）。

### 认证依赖链（deps.py）

`app/core/deps.py` 定义了认证依赖族，全部基于 `fastapi.security.HTTPBearer`：

```
HTTPAuthorizationCredentials (Authorization: Bearer <jwt>)
   │  Depends(security)
   ▼
get_current_user
   ├─ decode_token(credentials.credentials)      → app/core/security.py
   ├─ payload: sub=user_id, jti=session_id, role, exp
   ├─ jti 黑名单检查：查 user_session 表是否存在 is_revoked=True 的记录
   │    （会话撤销后 jti 进入黑名单，该令牌立即失效）
   ├─ 按 user_id 查询 User；不存在 → 401 "用户不存在"
   └─ 任何解码/查询异常 → 401 "无效的令牌"
   │  Depends
   ▼
require_role(*roles)  →  检查 current_user.role ∈ roles，否则 403 "权限不足"
   ▼
require_admin = require_role(UserRole.ADMIN)  →  管理员专用端点
```

各依赖职责：

- `get_current_user(credentials, db)`：核心认证依赖。解码 JWT 后先做 jti 撤销检查（会话踢出功能依赖此机制），再查用户，返回 `User` 对象。异常统一转为 401。
- `get_current_user_optional(request, db)`：可选认证，用于公开端点（如文件分享预览）。无令牌时返回 `None` 而不是抛 401；令牌来源同时支持 Cookie `access_token` 与 `Authorization` 头。
- `require_role(*roles)`：依赖工厂，返回 `role_checker`，基于 `get_current_user` 做角色校验。
- `require_admin`：`require_role(UserRole.ADMIN)` 的实例，`admin` 专属端点使用。

### 会话撤销与设备管理

- 登录时 `create_access_token` 生成唯一 `jti`（见 `app/core/security.py`），同时写入 `user_session` 表（见 `app/services/auth.py` 的 `login`）。
- 用户可在 `/auth/me/sessions` 查看会话、`DELETE /auth/me/sessions/{session_id}` 撤销会话（见 `app/api/user_sessions.py`）：置 `is_revoked=True`。
- 之后该 jti 对应的令牌在 `get_current_user` 中被拒绝，实现"踢下线"。

### 错误处理与统一响应

- 统一响应模型 `app/schemas/common.py` 的 `UnifiedResponse`：

```
{ "code": 0, "msg": "", "data": {} }
```

  `code=0` 成功，非 0 失败；`data` 为载荷。所有端点通过 `response_model=UnifiedResponse[...]` 声明。
- 业务错误通过 `HTTPException` 抛出（携带 `status_code` 与中文 `detail`），框架将响应状态码映射为 HTTP 状态；应用层未注册全局异常处理器，但依赖链中 `get_current_user` 已自行 catch 兜底为 401。
- 示例：`app/api/auth.py` 登录失败抛 `HTTPException(401, "用户名或密码错误")`；`app/core/deps.py` 权限不足抛 `HTTPException(403, "权限不足")`。
- 部分业务路由（如 `app/api/system.py` 的 reset/repo 校验）在返回体内使用 `code=1` + 中文 `msg` 表达校验失败，而非 HTTP 状态码，调用方需同时兼容两种约定。

### CORS 中间件

`app/main.py`：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.CORS_ORIGINS,   # 逗号分隔字符串，来自 .env
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

注意 `allow_origins` 传入的是逗号分隔字符串（`CORS_ORIGINS` 配置项），若存在空格需在配置层清洗；生产环境收紧为实际前端域名。

### 数据库会话（get_db）

`app/core/database.py` 的 `get_db` 是每个请求的会话边界：

```python
async def get_db() -> AsyncGenerator[AsyncSession, None]:
    factory = get_session_factory()
    async with factory() as session:
        try:
            yield session
            await session.commit()   # 路由正常返回后自动提交
        except Exception:
            await session.rollback()
            raise
        finally:
            await session.close()
```

- 引擎惰性初始化：首次调用 `get_engine()` 时基于 `DATABASE_URL` 创建 `AsyncEngine`，`pool_size=20 / max_overflow=10 / pool_pre_ping=True`。
- `expire_on_commit=False`，提交后对象属性仍可读取。
- 注意：若 Service 层自行 `commit()`（如登录、重置），外层 `get_db` 再次 commit 是空提交，无副作用。

### 日志 / 审计注入点

- FastAPI 应用层未全局挂载审计中间件；审计日志依赖具体业务端点显式写入（审计数据持久化于各业务表，不通过统一 middleware）。
- 登录、刷新令牌、修改密码等认证事件发生在 `app/services/auth.py`；登录成功/失败路径均可在该处扩展审计。
- `app/api/system.py` 的 `/system/reset`、`/system/repo`、`/system/token` 等管理操作以管理员为前置，适合作为审计埋点。
- 应用启动 seed（`create_initial_admin`）在 `app/main.py` 的 `lifespan` 中执行。
- WebSocket 端点 `app/api/ws.py` 在 `manager.connect` / `disconnect` 处可扩展连接审计。

### WebSocket 认证

`app/api/ws.py` 的 `/ws` 端点通过 query 参数 `?token=<jwt>` 传递令牌，使用 `jwt.decode` + `SECRET_KEY` 验证；失败则以 4001 关闭连接。连接建立后由 `app/core/websocket.py` 的 `manager` 管理连接集合，心跳采用客户端 `ping` 服务端回复 `pong` 的简单模式。

|------|------|
| `项目文件/nginx/includes/shared.conf` | /api、/ws、/live 路径代理与安全头 |

| `项目文件/backend/app/main.py` | FastAPI 应用、CORS、lifespan、路由挂载 |

| `项目文件/backend/app/services/auth.py` | 登录业务、限流、设备解析 |

## 配置示例

受保护端点标准写法（参考 `app/api/system.py`）：

```python
@router.get("/check-update")
async def api_check_update(
    db: AsyncSession = Depends(get_db),
    admin=Depends(require_admin),          # 需要管理员角色
):
    result = await check_update(db)
    return {"code": 0, "msg": "", "data": result}
```

可选认证端点写法（参考 deps.get_current_user_optional 使用场景）：

```python
async def public_endpoint(
    current_user: User | None = Depends(get_current_user_optional),
):
    if current_user is None:
        return {"visitor": True}
    return {"visitor": False, "user": current_user.username}
```
