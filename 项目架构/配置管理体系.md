# 配置管理体系

> 本文档描述系统的双层配置机制：文件级环境变量配置（Pydantic Settings）与数据库运行时配置（system_config 表），以及两者在容器、迁移、任务中的注入与读取方式。适用于新增配置项、排查配置不生效、理解配置优先级。

## 概述

系统采用两层配置：

| 层 | 载体 | 生命周期 | 读取时机 | 变更方式 |
|----|------|----------|----------|----------|
| 静态层 | `.env` 文件 → 环境变量 → Pydantic `Settings` | 进程生命周期 | 首次调用 `get_settings()`（lru_cache 单例） | 改 `.env` + 重启容器 |
| 动态层 | `system_config` 表（key VARCHAR + value JSONB） | 持久化于数据库 | 每次请求/任务即时读取 | 运行时 API/代码写入 |

静态层承载启动即需的配置（数据库连接、密钥、存储路径）；动态层承载运行时可变的业务配置（备份策略、通知配置、GitHub 仓库、`setup_complete`、`data_export_pepper`）。

## 核心设计

### 静态层：Pydantic Settings

`backend/app/core/config.py`：

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,
    )
    APP_NAME: str = "一站式工作台"
    DEBUG: bool = False
    DATABASE_URL: str = "postgresql+asyncpg://..."
    REDIS_URL: str = "redis://localhost:6379/0"
    SECRET_KEY: str = "your-jwt-secret-key-change-in-production"
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 30
    REFRESH_TOKEN_EXPIRE_DAYS: int = 7
    CORS_ORIGINS: str = "http://localhost,http://localhost:3000"
    INITIAL_ADMIN_USERNAME: str = "admin"
    INITIAL_ADMIN_PASSWORD: str = "admin123"
    NAS_FILES_PATH: str = "/data/files"          # 向后兼容
    FILE_STORAGE_PATH: str = "/data/files"
    FILE_BACKUPS_PATH: str = "/data/backups"     # 由 .env 提供，Settings 未声明字段也透传
    RESERVED_DISK_SPACE_GB: int = 10
    MAX_SHARE_FILE_SIZE_GB: int = 1
    ENCRYPTION_MASTER_KEY: str = "7433...eb"

    @field_validator("DATABASE_URL")
    @classmethod
    def validate_database_url(cls, v):
        if not v.startswith("postgresql+asyncpg://"):
            raise ValueError("DATABASE_URL 必须使用 postgresql+asyncpg:// 前缀")
        return v
```

字段说明（`.env.example` 中均有对应项）：

| 字段 | 默认值 | 用途 |
|------|--------|------|
| SECRET_KEY | 示例值（生产必须修改） | JWT 签名 |
| ACCESS_TOKEN_EXPIRE_MINUTES | 30 | 访问令牌有效期 |
| REFRESH_TOKEN_EXPIRE_DAYS | 7 | 刷新令牌有效期 |
| DATABASE_URL | 本地 asyncpg 示例 | 数据库连接，校验必须 `+asyncpg` |
| REDIS_URL | localhost | Celery broker/backend 与限流 Redis |
| FILE_STORAGE_PATH | /data/files | 文件存储目录（容器内挂载点） |
| FILE_BACKUPS_PATH | /data/backups | 备份目录 |
| RESERVED_DISK_SPACE_GB | 10 | 保留磁盘空间，低于此拒绝上传 |
| MAX_SHARE_FILE_SIZE_GB | 1 | 文件分享单文件上限 |
| CORS_ORIGINS | localhost | 允许的前端域名（逗号分隔字符串） |
| INITIAL_ADMIN_USERNAME/PASSWORD | admin/admin123 | seed 初始管理员 |

### lru_cache 单例模式

```python
@lru_cache
def get_settings() -> Settings:
    return Settings()
```

- **仅首次调用**执行 `Settings()` 读取 `.env`（容器内工作目录下的 `.env`），后续调用直接返回缓存实例。
- 运行时修改 `.env` 不会热生效，必须重启 backend/celery 进程。
- 所有模块统一通过 `from app.core.config import get_settings` 获取，禁止各处自行实例化 `Settings()`。

### 动态层：system_config 表

`backend/app/models/system_config.py`：

```python
class SystemConfig(Base):
    __tablename__ = "system_config"
    key: Mapped[str] = mapped_column(String(100), primary_key=True, comment="配置键")
    value: Mapped[dict] = mapped_column(JSONB, nullable=False, comment="配置值")
```

读写服务 `backend/app/services/system_config.py`：

- `get_config(db, key) -> dict | None`：按主键读取，返回 `value` dict。
- `update_config(db, key, value) -> SystemConfig`：不存在则创建、存在则覆盖，`flush` 不 commit（事务边界由调用方控制）。

典型键：

| key | value 结构 | 写入方 |
|-----|-----------|--------|
| setup_complete | `{"complete": true}` | /auth/initial-setup、/auth/setup-complete |
| backup_config | `{"enabled", "backup_dir", "max_backups"}` | 备份管理 API，`app/tasks/backup.py` 读取 |
| notification | `{"smtp_host", "smtp_port", "smtp_user", ..., "feishu_webhook_url", ...}` | 通知配置 API，`app/api/system.py` 测试通知读取 |
| github_repo / github_token | `{"repo"}` / `{"token"}` | /system/repo、/system/token（`app/services/updater.py`） |
| data_export_pepper | `{"pepper": "<hex>"}` | `app/services/data_export.py` 的 `get_or_create_pepper`（首次自动生成并落库） |

### docker-compose 环境变量注入

`docker-compose.yml` 结合 `${VAR:-default}` 语法，把 `.env` 或默认值注入容器：

- 服务级：`env_file: .env` 注入全部变量到 backend/celery/celery-beat。
- 展开式：`POSTGRES_USER: ${POSTGRES_USER:-workbench}`、`${FILE_STORAGE_PATH:-./data/files}:/data/files`（bind mount 路径）、`MTX_WEBRTCADDITIONALHOSTS: "${HOST_IP:-host.docker.internal}"`。
- 显式环境项：`RESERVED_DISK_SPACE_GB=${RESERVED_DISK_SPACE_GB:-10}`、`MAX_SHARE_FILE_SIZE_GB=${MAX_SHARE_FILE_SIZE_GB:-1}`、`TZ=Asia/Shanghai`。
- 注意：compose 的 `${VAR}` 展开发生在 `docker compose up` 时，读取的是**宿主 `.env`**；容器内 Pydantic Settings 的 `env_file=".env"` 读的是**容器内工作目录**的 `.env`（由 `env_file` 注入或构建时拷贝）。两处保持一致的唯一途径是维护根目录 `.env` 并避免修改容器内副本。

### 环境变量模板（.env.example）

`项目文件/.env.example` 按功能分组：数据库（POSTGRES_USER/PASSWORD/DB、DATABASE_URL）、Redis（REDIS_URL）、应用（APP_NAME/DEBUG/SECRET_KEY/令牌有效期）、CORS（CORS_ORIGINS）、存储（FILE_STORAGE_PATH/FILE_BACKUPS_PATH/RESERVED_DISK_SPACE_GB/MAX_SHARE_FILE_SIZE_GB）、Celery（CELERY_BROKER_URL/CELERY_RESULT_BACKEND，历史保留字段）、初始管理员（INITIAL_ADMIN_*）、流媒体（HOST_IP 注释示例）。

`start.sh` / `start.bat` 在首次运行时自动 `cp .env.example .env`，之后不会覆盖已有 `.env`。

## 关键文件引用

| 文件 | 职责 |
|------|------|
| `项目文件/backend/app/core/config.py` | Settings 定义、DATABASE_URL 校验、get_settings 单例 |
| `项目文件/backend/app/models/system_config.py` | system_config 表（key + JSONB value） |
| `项目文件/backend/app/services/system_config.py` | get_config / update_config |
| `项目文件/backend/app/services/data_export.py` | data_export_pepper 获取/生成 |
| `项目文件/backend/app/tasks/backup.py` | 读取 backup_config |
| `项目文件/backend/app/services/updater.py` | 读取 github_repo / github_token |
| `项目文件/docker-compose.yml` | ${VAR:-default} 注入与 env_file |
| `项目文件/.env.example` | 环境变量模板 |
| `项目文件/start.sh` / `start.bat` | 首次复制 .env |

## 配置示例

新增一个静态配置项的标准流程：

```python
# 1. config.py 添加字段
    NEW_FEATURE_FLAG: bool = False

# 2. .env.example 添加注释与默认值
# NEW_FEATURE_FLAG=false

# 3. 使用处
settings = get_settings()
if settings.NEW_FEATURE_FLAG:
    ...
```

新增动态配置（运行时读写）：

```python
# 读
config = await get_config(db, "my_feature")
# 写
await update_config(db, "my_feature", {"enabled": True})
```
