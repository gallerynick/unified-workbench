# 系统初始化与重置

> 本文档描述系统的生命周期管理：冷启动初始化流程、应用内数据重置端点、脚本级彻底重置、以及基于加密 ZIP 的数据恢复。适用于首次部署、故障恢复与数据迁移场景。

## 概述

系统区分两个层级的"重置"：

1. **应用内重置**：管理员通过 API `/system/reset` 清空业务数据、重建管理员，容器与卷不受影响。
2. **脚本级重置**：`reset.sh` / `reset.bat` 删除容器、数据卷与文件目录，回到未初始化状态。

初始化状态由一个关键标记控制：`system_config` 表中的 `setup_complete` 配置项（值为 `{"complete": true/false}`）。

## 核心设计

### 冷启动流程

首次启动（空卷）的完整流程：

```
docker compose up -d --build        (start.sh)
   │
   ├─ db 容器先健康（pg_isready），backend 等待 service_healthy
   │
   ├─ backend 容器 CMD：
   │     Base.metadata.create_all(engine)          # 建全表（见数据库演进与迁移）
   │     uvicorn app.main:app                      # 启动应用
   │
   ├─ lifespan（app/main.py）：
   │     create_initial_admin(db)                  # 幂等 seed 初始管理员（INITIAL_ADMIN_* 配置）
   │
   └─ 前端访问任意页面 → 跳转 /welcome
         ├─ GET  /auth/setup-status                # 读 setup_complete → {complete: false}
         ├─ POST /auth/initial-setup               # 创建正式管理员（清空 seed 用户）+ 置 setup_complete=true
         └─ 完成后登录
```

关键端点（均在 `app/api/auth.py`）：

- `GET /auth/setup-status`：公开接口，返回 `{complete: bool}`。响应头强制 `Cache-Control: no-store`，防止 Safari/Edge 对 `{complete: false}` 做启发式缓存导致初始化完成后仍跳 Welcome 页。
- `POST /auth/initial-setup`：公开接口。请求体 `{username, password, nickname}`。若 `setup_complete` 已为 true 则拒绝；否则 `DELETE FROM "user"` 清除 seed 用户、校验用户名（3-50 字符）与密码强度（≥8 位含字母数字）、创建 `UserRole.ADMIN` 账号、置 `setup_complete=true`。
- `POST /auth/setup-complete`：需登录，任何已认证用户可调用，手动补标完成标记（替代早期仅管理员的 system-config PUT）。

> 说明：初始管理员由 `INITIAL_ADMIN_USERNAME`/`INITIAL_ADMIN_PASSWORD` 配置（`.env.example`）seed 创建，用户可自行修改密码；初始化流程设计为以 `setup_complete` 标记为准，而非"是否有用户"。

### 应用内重置端点

`POST /system/reset`（`app/api/system.py`），请求体 `{keep_files: bool, password: str}`，需管理员权限。执行顺序：

1. **密码验证**：查 `"user"` 表 `admin` 用户的 `password_hash`，用 `verify_password` 校验；失败返回 `code=1, "密码错误"`。
2. **逐表清空**：按依赖顺序（先子表后父表）对 23 张业务表执行 `DELETE FROM`：

```
vote_record, vote, content, file_share, form_response, form,
calendar_event, note, inventory, contact, reminder, budget,
subscription, task, template, secret, secret_category,
topology, stream_room, announcement, notification,
refresh_token, user_tag, system_config, "user"（含管理员）
```

   使用 `DELETE FROM`（非 TRUNCATE），由外键约束保证依赖顺序正确；`"user"` 表加引号以规避保留字。
3. **可选删除文件**：`keep_files=false` 时 `shutil.rmtree(FILE_STORAGE_PATH, ignore_errors=True)`。
4. **重建管理员**：`create_initial_admin(db)`（`app/utils/seed.py`）按 `INITIAL_ADMIN_*` 配置重建初始管理员，然后 `commit`。

注意：重置会清空 `system_config`（包括 `setup_complete`、`github_repo`、通知配置等运行时配置），文件分享清理记录随之丢失；返回消息区分"文件已保留/未保留"。

### 脚本级彻底重置（reset.sh / reset.bat）

`项目文件/reset.sh`（macOS/Linux）与 `reset.bat`（Windows）流程一致：

1. 警告 + 输入 `YES` 确认。
2. `docker compose -p unified-workbench down --remove-orphans`，再单独删除残留 mediamtx 容器。
3. 删除命名卷：`unified-workbench_pg_data`、`unified-workbench_redis_data`；并用 `docker volume ls --filter "name=unified-workbench"` 清理遗留卷。
4. 删除文件数据：`rm -rf data/files/*`、`rm -rf data/backups/*`。
5. 提示回到未初始化状态，用 `./start.sh` 重新初始化。

与 `stop.sh` 的区别：`stop.sh` 只 `down` 保留卷与文件；`reset.sh` 是**不可逆**的彻底清除。

### 数据恢复（加密 ZIP 导入）

系统支持从加密 ZIP 恢复全量数据（`app/api/data_import.py` + `app/services/data_import.py`）：

- `POST /transfer/import`：管理员上传加密 ZIP + `password` 短语 + `salt`（hex）。PBKDF2-HMAC-SHA256(passphrase + pepper, salt, 600000, dklen=32) 派生 AES 密钥解密。`pepper` 从 `system_config` 的 `data_export_pepper` 读取/生成（见 `app/services/data_export.py` 的 `get_or_create_pepper`）。
- `POST /transfer/import/preview`：仅解析 manifest（版本、表数、行数、文件数、导出时间），不执行导入；版本高于当前时拒绝导入。
- `GET /transfer/import/{import_id}/status`：查询导入进度（无需管理员，task_id 即访问凭据）。

**紧急备份与回退**（`data_import.py` 第 3.5 节起）：导入流程在清空现有数据前先导出全部表到 `backup_dir` 作为紧急回退点；若导入任一步骤失败（`errors` 非空），自动从备份回退（`rollback=True`），保证导入失败不丢数据。导入状态返回 `{imported_tables, imported_rows, total_tables, file_count, errors, backup_size, rollback}`。

### 状态检查

- `GET /auth/setup-status` → `{complete: bool}`：前端据此决定渲染 Welcome 初始化页还是登录页。
- `GET /health` / `GET /health/db`（`app/api/health.py`）：进程与数据库连通性检查，`/health/db` 失败时返回 `code=1` + 中文原因。
- `GET /system/check-update`（`app/api/system.py`）：通过 `git ls-remote` 对比远程 tag 与 `__version__`（`app/services/updater.py`），返回是否有新版本。

## 关键文件引用

| 文件 | 职责 |
|------|------|
| `项目文件/backend/app/api/auth.py` | setup-status / initial-setup / setup-complete |
| `项目文件/backend/app/api/system.py` | /system/reset（密码验证 + 逐表删除 + 重建 admin） |
| `项目文件/backend/app/utils/seed.py` | create_initial_admin（幂等 seed） |
| `项目文件/backend/app/main.py` | lifespan 启动时 seed |
| `项目文件/backend/app/core/config.py` | INITIAL_ADMIN_USERNAME / INITIAL_ADMIN_PASSWORD |
| `项目文件/backend/app/services/system_config.py` | get_config / update_config（setup_complete） |
| `项目文件/backend/app/api/data_import.py` | 加密 ZIP 导入 / 预览 / 状态查询 |
| `项目文件/backend/app/services/data_import.py` | 导入编排（紧急备份与回退） |
| `项目文件/backend/app/services/data_export.py` | data_export_pepper 获取/生成 |
| `项目文件/reset.sh` / `reset.bat` | 脚本级彻底重置 |
| `项目文件/start.sh` / `start.bat` | 冷启动入口 |

## 配置示例

`/system/reset` 请求（管理员调用）：

```json
POST /api/v1/system/reset
Authorization: Bearer <admin_jwt>
{
  "keep_files": true,
  "password": "admin的登录密码"
}
```

`/auth/initial-setup` 请求（首次初始化页面）：

```json
POST /api/v1/auth/initial-setup
{
  "username": "admin",
  "password": "Admin123",
  "nickname": "管理员"
}
```
