# 权限模型设计

## 概述

本系统遵循"默认私有，自主公开"的设计理念（见《项目基定/开发基准文档.md》3.1 节）。权限模型由三部分组成：**三态可见性枚举**（控制内容类资源谁能看）、**纯私有模块隔离**（owner_id 行级隔离）、**管理员全权**（角色级覆盖）。此外服务器管理系统引入 `member_ids` / `maintainer_ids` 协作机制，允许通过显式授权把资源开放给团队其他成员。

权限判定统一收敛到两个后端核心文件：`app/core/visibility.py`（枚举定义）与 `app/core/permissions.py`（可见性判定函数）。

## 三态 Visibility 枚举

`项目文件/backend/app/core/visibility.py` 定义唯一的可见性枚举：

- `Visibility.PUBLIC = "public"`：所有登录用户可见。
- `Visibility.PRIVATE = "private"`：仅资源所有者可见。
- `Visibility.RESTRICTED = "restricted"`：指定用户与指定标签可见。

判定逻辑集中在 `app/core/permissions.py` 的 `check_visibility(user, visibility, owner_id, restricted_users, restricted_tags)`：

- public 直接放行；
- private 仅 `user.id == owner_id` 通过；
- restricted 依次检查所有者、`restricted_users` 用户 ID 集合、以及用户标签（`user.tags`）与 `restricted_tags` 标签集合是否有交集，命中任意一项即通过。

## 纯私有模块隔离

以下 14 个模块为纯私有模块，数据行通过 `owner_id` 字段与 `user.id` 对齐实现隔离，不参与可见性三态：

servers、systems、services、notes（笔记）、reminders（提醒）、secrets（密钥）、secret_categories（密钥分类）、tasks（任务）、inventory（物品）、contacts（联系人）、calendar_events（日历）、budget（预算）、subscription（订阅）、notifications（通知）。

以服务器为例，`app/services/server.py` 的 `list_servers` 直接以 `Server.owner_id == user_id` 过滤查询；`get_server` 额外放行管理员与 `maintainer_ids` 中的维护者。提醒模块（`app/services/reminder.py`）的 `get_reminder` 同样校验 `reminder.creator_id != current_user.id` 时返回 404，避免暴露资源存在性。

密钥模块强制私有，`secret` 表不设 visibility 字段，从模型层杜绝公开路径。

## 可见性模块

以下模块支持三态可见性，表结构含 `visibility` 字段（数据库层面说明见 [数据库设计概览](./数据库设计概览.md)）：

- content（内容，含 `restricted_users` / `restricted_tags`）
- forms（表单）、votes（投票）、topology（拓扑）：由迁移 `015_add_visibility_to_form_vote_topology.py` 补充三字段
- 另有 11 张表（inventory、contacts、budget、subscription、tasks、notes、calendar_events、secrets、secret_categories、templates、reminders）由迁移 `027_add_visibility_to_eleven_tables.py` 增加 `visibility` 与 `restricted_users` 字段，适配功能型页面的"仅自己可见 / 全站可见"选择。

注：早期规划中的 records 模块已演进为 projects（迁移 `023_rename_project_document_to_project.py`，`025_drop_record_table.py` 删除旧 record 表），项目模块通过 `member_ids` 机制协作，详见下文。

## 管理员全权规则

管理员（`UserRole.ADMIN`，`app/models/user.py`）拥有对全部用户数据的查看、编辑、删除权限：

- 依赖层：`app/core/deps.py` 提供 `require_role(*roles)` 工厂与 `require_admin = require_role(UserRole.ADMIN)`，任意需要管理员能力的端点声明 `Depends(require_admin)`。
- 业务层：如 `app/services/server.py` 的 `get_server` 在校验"所有者或维护者"之外，额外放行 `UserRole.ADMIN`；其余模块服务层同样优先判定管理员。
- 系统配置层：`app/api/system.py`（系统更新、数据重置、仓库配置）所有端点均以 `require_admin` 保护；系统配置 `system_config` 表同样仅管理员可写。

## Project member_ids 机制

项目模块（projects）通过 `member_ids`（JSONB）记录参与成员 ID 列表。迁移 `027` 中新增该字段。成员被列入 `member_ids` 后可访问对应项目，实现比"可见性三态"更细粒度的协作文档场景。前端项目详情页基于该字段渲染参与者列表。

## Server maintainer_ids 机制

服务器、系统、服务三级资源（servers、systems、services 表）均含 `maintainer_ids`（JSONB）字段，记录维护者 UUID 列表：

- `app/models/server.py` / `system.py` / `service.py` 中 `maintainer_ids` 为 `JSONB, default=list`。
- 后端校验：`server.py` 的 `get_server` 在所有者校验失败后继续检查当前用户是否位于 `maintainer_ids`。
- 前端约束：`ServerFormModal.tsx` 的维护人员下拉框通过 `listUsers` 加载工作台成员，保证只能从系统成员中选择维护者，维护者必须是工作台成员。

## 数据库层面约束

可见性相关字段统一遵循以下约定（迁移 `015`、`027` 实现）：

- `visibility`：`VARCHAR(20) NOT NULL DEFAULT 'private'`，字段级默认私有，符合"默认私有"原则。
- `restricted_users`：`JSONB`，存储被授权用户 ID 列表。
- `restricted_tags`：`JSONB`，存储被授权标签名称列表（content / form / vote / topology 具备）。

## 前端实现

前端将可见性能力封装为可复用组件，并在全部管理页提供统一的权限说明入口，保证权限语义在各模块间一致呈现。

### VisibilitySetting 组件

`frontend/src/components/VisibilitySetting/VisibilitySetting.tsx` 是统一的可视化可见性选择器：

- 使用 Ant Design `Segmented` 展示 public / private / restricted 三态。
- 选择 restricted 时展开两个多选 `Select`：指定用户（实时从 `/users` 接口加载）与指定标签（来自 `TagContext`）。
- 通过 `onChange` / `onRestrictedUsersChange` / `onRestrictedTagsChange` 回调将选择结果写回表单。
- `hideRestricted` 属性可隐藏 restricted 选项（供强制私有/公开场景使用）。
- 前端可见性常量定义于 `frontend/src/utils/visibility.ts`（`VISIBILITY_MAP`、`getVisibilityConfig`、`getVisibilityOptions`）。

### 权限说明浮窗

18 个管理页面（content、notes、reminders、secrets、servers、systems、tasks、inventory、contacts、calendar、budget/finance、subscription、forms、votes、topology、templates、projects、announcements、streaming、file-share 等）在页面头部提供 `QuestionCircleOutlined` 图标按钮，点击后打开"权限说明" `Modal`，向用户解释当前模块的可见性规则。实现模式以 `frontend/src/pages/notes/NoteManagement.tsx` 与 `ServerManagement.tsx` 为代表：

```tsx
<Tooltip title="权限说明">
  <Button type="text" size="small" icon={<QuestionCircleOutlined />}
          onClick={() => setPermissionVisible(true)} />
</Tooltip>
```

## 安全约束

- 密钥模块强制私有，无 visibility 字段。
- 私有模块查询在 SQL 层以 `owner_id` 过滤，防止越权遍历。
- 资源不存在与无权限统一返回 404，避免信息泄露。
- 管理员能力仅通过 `require_admin` 依赖注入，业务端点不得自行判断角色。
- 维护者 / 成员必须为工作台已存在用户，前端通过成员接口约束选择范围。
