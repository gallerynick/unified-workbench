# 状态指示演示开关 — 开发者文档

状态指示内置一个**纯前端**的演示开关：在不触碰后端、不改真实探测逻辑的前提下，
按需触发任意组合的状态告警，用于演示、验收与视觉确认。

实现位置：

- src/hooks/useStatusDemo.ts    开关本体（URL 解析、Console 入口、条目表）
- src/hooks/useStatusProbes.ts  接入点，`demoIssues ?? merged` 覆盖真实探测

---

## 一、前提：必须先开启调试模式

演示开关**只在调试模式开启时生效**，这是刻意设计，避免演示入口在交付环境被误触。

开启路径：**登录后 → 系统设置 → 站点设置 → 打开「调试模式」→ 保存**

调试模式是全站统一开关，字段 `debug_mode`，由后端 site-config 接口下发，
前端经 `isDebugModeEnabled()`（src/pages/settings/SiteSettings.tsx）读取，
带模块级缓存——一次读取，进程内复用。

未开启时的表现：

- URL 带 `?status_demo=...` → 参数照写，但**不显示**任何演示条目
- Console 调 `__statusDemo(...)` → 先打印写入结果，随后打印警告：
  `[状态指示演示] 调试模式未开启 → 不会显示`

> 注意：调试模式的值来自缓存。如果演示过程中后端重启导致配置拉取失败，
> 会回退到默认值 `debug_mode: false`，此时演示失效。
> 因此演示顺序应是：**先确认调试模式已开 → 再设参数 → 再制造故障**。
> 已加载过的页面里缓存仍在，断网本身不会让演示失效。

## 二、用法一：URL 参数（推荐演示用，可分享）

    https://localhost/?status_demo=all             全部 16 条
    https://localhost/?status_demo=public,db        指定条目，逗号分隔
    https://localhost/login?status_demo=ws,lock     登录页同样生效
    https://localhost/?status_demo=off              显式关闭（等价于去掉参数）

说明：

- 参数写在**任意路径**上都生效（header、登录页、锁定页共用同一取数入口）
- 参数可省略 `all` 简写之外的任何形式；无效键名会被静默过滤
- `all` 展开为全部 16 个键
- 只接受键名，不支持「按等级筛选」之类的语法（要红点组合就手列键名）

## 三、用法二：DevTools Console（演示中途实时切换）

    __statusDemo('all')             全部
    __statusDemo('public,db')       逗号分隔字符串
    __statusDemo(['ws', 'lock'])    数组
    __statusDemo(null)              关闭，回到真实探测

`__statusDemo` 在模块加载时注册到 `window`，任何页面任何时机都能调用。
返回值是被接受的键名数组。它会用 `history.replaceState` 改写地址栏，
**不刷新页面**，改动即时生效。

## 四、测试项参数表

等级：critical 为红点 + 呼吸动画；warning 为黄点 + 静止。

| 键 | 等级 | 显示文案 | 对应的真实检测项 |
|---|---|---|---|
| backend | critical | 网络已断开 | A1 — 浏览器 offline 事件，或 /api/v1/health 连续 3 次失败 |
| latency | warning | 网络延迟较高 | A2 — 延迟采样窗口内超 800ms 的样本 ≥ 2 |
| insecure | warning | 未启用 HTTPS | B1 — location.protocol 非 https |
| unsafe | critical | 非安全环境，直播等能力不可用 | B2 — 非安全上下文（影响媒体设备与通知能力） |
| public | warning | 正在通过公网访问 | B3 — 访问 host 不在内网地址段 |
| maintenance | critical | 系统维护中 | C1 — site-config 的 maintenance_mode 为真 |
| db | critical | 数据服务暂时不可用 | C2 — /api/v1/health/db 连续 2 次异常 |
| version | critical | 版本不匹配，请刷新 | D1 — 健康检查返回的版本号与前端不一致 |
| clock | warning | 本机时间不准 | D2 — 与服务端时间偏差超过 5 分钟 |
| browser | warning | 浏览器能力不完整 | D3 — 缺 WebSocket / mediaDevices / Notification / PublicKeyCredential |
| ws | warning | 实时提醒不可用 | A3 — WebSocket 断开累计超过 10 秒 |
| storage | critical | 文件服务暂时不可用 | C3 — /system/status 中 storage 服务异常 |
| stream | warning | 直播服务暂时不可用 | C4 — /system/status 中 stream 服务异常 |
| tasks | warning | 提醒服务暂时不可用 | C5 — /system/status 中 tasks 服务异常 |
| lock | warning | 即将自动锁定 | E1 — 距离闲置自动锁定不足 30 秒 |
| concurrent | warning | 账号在其他设备登录 | F1 — /system/status 中 30 分钟内存在其他设备或其他 IP 的在线会话 |

## 五、常用演示组合

    # 多条异常轮播 + 悬停完整列表
    ?status_demo=all

    # 检验 240px 省略号（文案 13 字，超出限宽）
    ?status_demo=unsafe

    # 一红一黄对照，看两种等级视觉差异
    ?status_demo=db,public

    # 登录页 / 锁定页右下角浮层
    /login?status_demo=ws,lock

    # 只留一条，检验单条状态下悬停仍能弹出列表
    ?status_demo=version

    # 并发登录黄点（真实触发方式见设计规格 F1）
    ?status_demo=concurrent

    # 现场切换：先开一半，再补到全量，再关
    __statusDemo(['db', 'public'])
    __statusDemo('all')
    __statusDemo(null)

## 六、行为说明

1. **覆盖而非追加。** 开启演示时，演示条目**替换**真实探测结果，
   不被本机真实网络状态污染，演示内容确定可复现。
   真实探测仍在后台运行（定时器不拆），关闭演示立即回到真实结果，无需刷新。

2. **轮播与排序。** 条目按等级排序（critical 在前），多于一条时每 2 秒轮播，
   悬停暂停轮播并弹出完整列表。系统开启「减少动态效果」时停止轮播与动画，
   固定显示最严重一条。

3. **id 前缀。** 演示条目 id 统一为 `demo-` 前缀，与真实条目（`a1-backend`、
   `c2-db` 等）不冲突，不与真实状态互相去重。

4. **演示不写任何后端状态。** 不创建维护模式、不写数据库、不发请求模拟故障，
   演示数据完全在前端内存中生成。

## 七、已知限制

- 调试模式读取依赖后端可达。若在断网状态下**首次加载**页面，
  配置拉取失败回退为 `debug_mode: false`，演示失效。
  已在网时加载过的页面缓存有效，断网不影响已生效的演示。
- 演示开关是长期保留的调试入口，未做构建时剔除。
  若日后判定不应出现在交付版本中，可用 `import.meta.env` 条件移除。
- 不支持按等级批量选取（如「所有 warning」），需手列键名。
