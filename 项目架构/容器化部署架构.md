# 容器化部署架构

> 本文档描述一站式工作台的 Docker Compose 容器化部署方案：服务构成、网络与卷、构建与启动流程、健康检查与端口映射。适用于部署、排障与二次开发时的容器层理解。

## 概述

系统采用 Docker Compose 单机编排，项目名为 `unified-workbench`。共 8 个服务，覆盖应用四层职责：

- 数据层：`db`（PostgreSQL 15）、`redis`（Redis 7）
- 应用层：`backend`（FastAPI）、`celery`（Celery Worker）、`celery-beat`（Celery Beat 调度器）
- 展示层：`frontend`（Nginx 静态资源）
- 接入层：`nginx`（反向代理与 TLS 终结）、`mediamtx`（WebRTC/RTMP/HLS 流媒体）

所有服务位于同一自定义 bridge 网络 `workbench` 内，通过服务名互相访问；对外仅暴露必要端口，统一由 `nginx` 收口 HTTP/HTTPS 流量。

## 核心设计

### 服务定义

编排文件位于 `项目文件/docker-compose.yml`。各服务要点如下：

| 服务 | 镜像/构建 | 对外端口 | 关键配置 |
|------|-----------|----------|----------|
| db | postgres:15-alpine | 5432 | TZ=Asia/Shanghai，卷 `pg_data:/var/lib/postgresql/data` |
| redis | redis:7-alpine | 6379 | `--appendonly yes` 持久化，卷 `redis_data:/data` |
| backend | ./backend/Dockerfile | 8000 | `env_file: .env`，挂载文件/备份目录，健康检查依赖 db/redis |
| celery | ./backend/Dockerfile | 无 | `celery -A app.tasks worker`，仅挂载文件目录 |
| celery-beat | ./backend/Dockerfile | 无 | `celery -A app.tasks beat`，`PYTHONPATH=/app`，调度文件放 /tmp |
| frontend | ./frontend/Dockerfile | 3000→80 | Nginx 静态托管 dist 产物 |
| mediamtx | bluenviron/mediamtx:1 | 1935/8554/8888/8889/8189/8890 | 卷挂载 `mediamtx.yml`，WebRTC 附加主机来自 `HOST_IP` |
| nginx | ./nginx/Dockerfile | 80/443 | 反向代理，TLS 自签名证书 |

启动顺序依赖关系：`backend`/`celery`/`celery-beat` 均通过 `depends_on` 等待 `db` 与 `redis` 的 `service_healthy` 状态；`nginx` 依赖 `backend` 与 `frontend`。

### 网络

- 网络名：`workbench`（`driver: bridge`）。
- `docker-compose.yml` 顶层 `networks.workbench` 声明，各服务加入该网络。
- 服务间通信使用服务名作为 DNS：`backend:8000`、`redis:6379`、`db:5432`、`mediamtx:8889`。
- 容器创建时以 `-p unified-workbench` 指定项目名，保证容器名带 `unified-workbench-` 前缀，跨主机迁移或重装后容器命名一致。

### 数据卷

`docker-compose.yml` 顶层 `volumes` 定义两个命名卷：

- `pg_data`：PostgreSQL 数据目录，保证删除容器后数据不丢失。
- `redis_data`：Redis AOF 持久化目录（`--appendonly yes`）。

文件数据不放入命名卷，而是通过 bind mount 挂载宿主目录（路径由 `.env` 控制，默认 `./data`）：

- `backend`：`${FILE_STORAGE_PATH:-./data/files}:/data/files` 与 `${FILE_BACKUPS_PATH:-./data/backups}:/data/backups`。
- `celery`：仅挂载 `${FILE_STORAGE_PATH:-./data/files}:/data/files`（文件清理任务需要访问物理文件）。

### 构建策略

后端与前端均使用多阶段 Dockerfile：

- `backend/Dockerfile`：builder 阶段安装 `build-essential` 并 `pip install --prefix=/install .`（使用清华镜像加速），生产阶段仅安装 `libpq5/curl/git` 运行时依赖，`COPY --from=builder /install /usr/local`，创建非 root 用户 `workbench`，最终启动前先执行 `Base.metadata.create_all` 建表再启动 uvicorn。
- `frontend/Dockerfile`：直接基于 `nginx:1.25-alpine`，使用本地预构建的 `dist` 产物（`COPY dist /usr/share/nginx/html`），解决容器内网络不可达时无法在线构建的问题。构建前需先在宿主执行 `npm run build` 生成 `dist`。
- `nginx/Dockerfile`：复制 `nginx.conf`、`includes/`、`ssl/` 到镜像，创建非 root 用户后以 `daemon off` 前台运行。

热更新策略：

- `start.sh` 与 `start.bat` 使用 `docker compose up -d --build`，每次启动强制重建有 `build` 声明的服务（backend/frontend/nginx），适合日常迭代。
- 若仅修改宿主机文件而希望避免重建，可通过 `docker cp` 或重挂载卷热更新；正式流程仍以 `--build` 保证镜像与代码一致。

### 启动 / 停止 / 重置脚本

统一入口（禁止手动执行裸 `docker compose` 命令，必须通过脚本）：

| 脚本 | 行为 |
|------|------|
| `项目文件/start.sh` / `start.bat` | 检测局域网 IP（WebRTC ICE 用）→ 导出 `HOST_IP` → 检查 Docker 运行 → 无 `.env` 则从 `.env.example` 复制 → `docker compose -p unified-workbench up -d --build` → 打印访问地址 |
| `项目文件/stop.sh` / `stop.bat` | `docker compose -p unified-workbench down` 停止容器（保留卷），再单独清理可能残留的 mediamtx 容器 |
| `项目文件/reset.sh` / `reset.bat` | 确认后 `down --remove-orphans` → 删除 mediamtx 容器 → 删除 `unified-workbench_pg_data`、`unified-workbench_redis_data` 卷 → `rm -rf data/files/* data/backups/*`，回到未初始化状态 |

### 环境变量

- 服务通过 `env_file: .env` 注入，模板见 `项目文件/.env.example`。
- 支持 `${VAR:-default}` 语法提供默认值（如 `POSTGRES_USER:-workbench`、`FILE_STORAGE_PATH:-./data/files`）。
- 时区统一为 `TZ=Asia/Shanghai`，db/backend/celery/celery-beat 均显式设置。
- `HOST_IP` 由启动脚本注入到 mediamtx 的 `MTX_WEBRTCADDITIONALHOSTS`，用于 WebRTC 多候选项。

### 健康检查

| 服务 | 检查方式 | 间隔 |
|------|----------|------|
| db | `pg_isready -U workbench`（compose 内联） | 10s |
| redis | `redis-cli ping`（compose 内联） | 10s |
| backend | Dockerfile `HEALTHCHECK`，`curl -f http://localhost:8000/api/v1/health` | 30s |
| frontend | Dockerfile `HEALTHCHECK`，`wget -q --spider http://localhost:80` | 30s |
| nginx | Dockerfile `HEALTHCHECK`，`wget -q --spider http://localhost:80/health` | 30s |
| celery / celery-beat | 无自定义检查 | - |

`backend`/`celery`/`celery-beat` 通过 `depends_on` 的 `condition: service_healthy` 确保数据库与缓存就绪后再启动。

### 端口映射

| 端口 | 服务 | 用途 |
|------|------|------|
| 80 / 443 | nginx | HTTP / HTTPS（TLS 终结） |
| 8000 | backend | 开发直连（生产走 nginx `/api`） |
| 3000 | frontend | 前端容器映射（生产走 nginx） |
| 5432 | db | 数据库（生产建议关闭对外） |
| 6379 | redis | 缓存/队列（生产建议关闭对外） |
| 1935 | mediamtx | RTMP 推流 |
| 8554 | mediamtx | RTSP |
| 8888 | mediamtx | HLS（`hlsAddress: :8888`） |
| 8889 | mediamtx | WebRTC TCP（`webrtcAddress`） |
| 8189/udp | mediamtx | WebRTC UDP |
| 8890/udp | mediamtx | SRT |

### Nginx 双层结构

- **第一层 frontend 容器**：自身内置 Nginx，托管 React `dist` 静态文件，`frontend:80` 提供服务。
- **第二层 nginx 容器**：作为统一入口，配置见 `nginx/nginx.conf` + `nginx/includes/shared.conf`：
  - `location /api` → `http://backend`（proxy 到 `backend:8000`），含安全头、`client_max_body_size 1G`、60s 超时。
  - `location /ws` → `http://backend`，WebSocket Upgrade/Connection 头，长连接超时 7 天。
  - `location /live/` → `http://mediamtx:8889/`（HLS/WebRTC 直播流）。
  - `location ~* \.(css|js|...)` → `http://frontend`（静态资源长期缓存）。
  - `location /` → `http://frontend`（HTML 禁用缓存，`no-store`，保证新构建即时刷新）。
  - `location /health` → `http://backend/api/v1/health`（健康检查，不记 access log）。
  - `location ~ /\.` → `deny all`（隐藏文件防护）。
- HTTPS 使用 `ssl/selfsigned.crt` 自签名证书，`TLSv1.2 TLSv1.3`。

## 关键文件引用

| 文件 | 职责 |
|------|------|
| `项目文件/docker-compose.yml` | 服务、网络、卷、端口、健康检查编排 |
| `项目文件/start.sh` / `start.bat` | 一键启动（检测 IP、注入 HOST_IP、`up -d --build`） |
| `项目文件/stop.sh` / `stop.bat` | 停止容器、保留卷 |
| `项目文件/reset.sh` / `reset.bat` | 彻底重置（删卷 + 清文件） |
| `项目文件/nginx/nginx.conf` | 上游与 80/443 server 块 |
| `项目文件/nginx/includes/shared.conf` | 代理、安全头、WebSocket、body size、缓存策略 |
| `项目文件/nginx/Dockerfile` | nginx 镜像构建与健康检查 |
| `项目文件/backend/Dockerfile` | 后端多阶段构建、create_all、启动命令 |
| `项目文件/frontend/Dockerfile` | 前端静态镜像（拷贝本地 dist） |
| `项目文件/mediamtx/mediamtx.yml` | 流媒体协议端口与路径配置 |
| `项目文件/.env.example` | 环境变量模板 |

## 配置示例

启动脚本核心流程（`start.sh`）：

```bash
LAN_IP=$(ifconfig 2>/dev/null | grep "inet " | grep -v 127.0.0.1 | awk '{print $2}' | head -1)
export HOST_IP="${LAN_IP},host.docker.internal"
# 无 .env 时从模板复制
if [ ! -f .env ]; then cp .env.example .env; fi
docker compose -p unified-workbench up -d --build
```

mediamtx 环境注入（`docker-compose.yml`）：

```yaml
environment:
  MTX_WEBRTCADDITIONALHOSTS: "${HOST_IP:-host.docker.internal}"
```
